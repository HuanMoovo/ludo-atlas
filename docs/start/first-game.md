# Ludo Atlas · 入门 · 第一个游戏

> **入门**。目标不是做出好游戏，而是**做出一个做完的游戏**。「做完」这个能力，比任何单个技术点都值钱。本页给一个 30 天、每天 2-3 小时的完整计划。

## 1. 先定规矩

- 体量：一个人 2-6 周能做完的规模。上限写进一页纸：核心机制 1 个、关卡 3-5 个、总时长 15-30 分钟。
- 资产：第一个游戏允许全部使用免费素材（见[资源大全](../../resources/README.md)）。
- 标准：能玩、能通关、有音效、有标题画面、有结束画面、能分享给朋友。
- 禁令：不做联机、不做开放世界、不做自己的梦想企划（那是第二个游戏的事）。

## 2. 选题

从下面挑一个，不要发明新的：

| 题目 | 难度 | 会练到 |
| --- | --- | --- |
| 打砖块 / 太空 invaders | ★ | 输入、碰撞、循环 |
| 平台跳跃（3 个关卡） | ★★ | 手感、关卡节奏 |
| 俯视角射击（波次生存） | ★★ | 敌人生成、数值 |
| 推箱子式解谜（10 关） | ★★ | 机制设计、撤销 |
| 无尽跑酷 | ★★ | 程序生成、难度曲线 |
| 小体量塔防（5 波） | ★★★ | 数值、UI、状态机 |

## 3. 30 天日历

**第 1 周：最小可玩**

| 天 | 任务 |
| --- | --- |
| 1 | 装引擎、跑通官方入门教程、建仓库 |
| 2 | 角色能移动 + 一个核心动作（跳/射/推） |
| 3 | 第一个敌人或障碍 + 胜负条件 |
| 4 | 主循环完整：开始、玩、死、重来 |
| 5-7 | 把核心机制调到「自己愿意重复玩」 |

**第 2 周：内容与节奏**

| 天 | 任务 |
| --- | --- |
| 8-10 | 做 3-5 关/波次，难度递增 |
| 11-12 | 过关条件、计分、进度保存 |
| 13-14 | 第一次给别人玩，记录所有卡点与困惑 |

**第 3 周：表现与打磨**

| 天 | 任务 |
| --- | --- |
| 15-16 | 音效与音乐（素材即可），补齐反馈（受击、得分） |
| 17-18 | 屏幕适配、标题画面、暂停菜单 |
| 19-20 | 按测试反馈修问题；性能检查（在目标设备上玩） |
| 21 | 冻结内容，只修 Bug |

**第 4 周：发布**

| 天 | 任务 |
| --- | --- |
| 22-23 | itch.io 页面：名称、简介、3 张截图、1 个 GIF |
| 24-25 | 打包 Windows 版（有余力加 Web 版）；写操作说明 |
| 26-27 | 小范围分享，收集反馈，修最后一批问题 |
| 28-30 | 发布；写复盘（用[复盘模板](../../templates/postmortem.md)）；开始想下一个 |

## 4. 「做完」验收清单

- 新玩家 5 分钟内能学会操作（不用你在旁边讲）。
- 从启动到通关，全程没有卡死与崩溃。
- 有标题界面与结束界面，知道「赢了/输了」。
- 有声音，且能关掉。
- 能在别人的电脑上运行（不是只有你的开发环境能跑）。
- 有一个可分享的链接或文件。
- 你为它写了复盘。

以上全打勾，第一个游戏就算完成。缺一两项就去补齐，别开新坑。

## 5. 常见失败模式与对策

| 失败模式 | 症状 | 对策 |
| --- | --- | --- |
| 范围爆炸 | 「再加个联机吧」 | 想法全部记进「下一个游戏」清单 |
| 教程地狱 | 看教程 3 小时，写码 5 分钟 | 每天先写 1 小时再允许看教程 |
| 换引擎成瘾 | 第三周还在选引擎 | 回头读[引擎选型指南](engine-choice.md)最后一节 |
| 完美主义 | 反复重画主角 | 素材冻结日：第 15 天 |
| 不发 | 「再打磨打磨」 | 发布日写进日历，和朋友的约定一样不可商量 |
| 无人问津就放弃 | 首作没热度 | 首作的目标是「学会做完」，不是「成功」 |

## 6. 发布之后

1. 写复盘（数据 + 感受 + 下次的调整），存进[复盘区](../postmortems/README.md)。
2. 把复盘里最想改的三件事，作为第二个游戏的练习目标。
3. 第二部作品体量翻倍以内。循序渐进，直到能驾驭梦想企划。
