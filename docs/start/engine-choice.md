# Ludo Atlas · 入门 · 引擎选型指南

> **入门**。这一页帮你把引擎选定，然后永远不再纠结。结论先行：任何主流引擎都能做完一款游戏，切换引擎的成本远低于「一直在选」的成本。

## 1. 先回答四个问题

1. **目标平台**：PC / 主机 / 手机 / 小游戏 / Web？桌面 Steam 和微信小游戏的工程要求完全不同。
2. **2D 还是 3D**：还是混合？这是最大的分水岭。
3. **你的编程基础**：零基础、会一点脚本、熟练程序员？
4. **团队与周期**：一个人做三个月，还是五个人做一年？

## 2. 决策路径

按顺序走这条判断链：

1. 做视觉小说或纯文字叙事 → Ren'Py 起步，别多想。
2. 做像素/2D 小体量、想快速上手 → Godot 或 GameMaker。
3. 做 2D 且未来想上手机、生态需求大 → Unity 或 Godot。
4. 做 3D 写实、大团队、想进大厂管线 → Unreal。
5. 做 3D 中等体量独立游戏 → Unity 或 Godot（视美术风格）。
6. 只做浏览器可玩的小体量 Web 游戏 → Phaser / PixiJS；3D 展示型 → Three.js / Babylon.js。
7. 想「用代码手搓一切」学习底层 → raylib / LÖVE / Pygame 等框架。
8. 以上都不是，或者有非标需求 → 先回到第 1 条重新问自己；自研引擎是最后选项。

## 3. 主要路线对照表

| 引擎/框架 | 定位 | 主要语言 | 强项 | 许可与成本要点 |
| --- | --- | --- | --- | --- |
| Godot | 全能开源引擎 | GDScript / C# | 2D/3D 均衡、轻量、完全开源 | MIT，无分成无版权费 |
| Unity | 商业全能引擎 | C# | 生态最大、移动与 2D 工具链成熟 | 个人免费档存在，商业条款以官网为准 |
| Unreal | 3A 级引擎 | C++ / 蓝图 | 画面天花板、影视级管线 | 免费下载，超过营收门槛后按比例分成 |
| GameMaker | 2D 快速开发 | GML | 原型快、适合像素与 2D 小体量 | 免费版受限，商业发布需授权 |
| RPG Maker | RPG 专用 | 脚本 | 回合制 RPG 开箱即用 | 付费软件，注意素材授权 |
| Ren'Py | 视觉小说专用 | Python 系 | 分支叙事、存档回看开箱即用 | 免费开源 |
| Web 系（Phaser / PixiJS / Three.js / Babylon.js） | 浏览器游戏 | JavaScript / TypeScript | 零安装分发、Web 3D | 开源，注意引擎各自许可 |
| 轻量框架（raylib / LÖVE / Pygame） | 代码优先 | C / Lua / Python | 学原理、完全掌控 | 宽松开源许可 |
| Bevy | Rust 数据驱动引擎 | Rust | ECS 架构、性能与安全 | 开源，生态在成长中 |
| 自研引擎 | 定制 | 任意 | 完全掌控 | 成本极高，通常不是第一选择 |

## 4. 分场景推荐

| 场景 | 首选 | 备选 | 说明 |
| --- | --- | --- | --- |
| 第一次做游戏（2D 小体量） | Godot | GameMaker | 复杂度低，社区教程多 |
| 手机商业项目 | Unity | Godot | 移动平台工具链与插件生态 |
| 3D 写实 | Unreal | Unity | 渲染与内容管线优势 |
| 视觉小说 | Ren'Py | Godot + 插件 | 专用工具省掉一半工作 |
| 微信/抖音小游戏 | 先读[小游戏手册](../publishing/minigame/README.md) | 视平台方案定 | 包体与性能约束特殊 |
| 浏览器即玩 | Phaser（2D）/ Babylon.js（3D） | Three.js | 免安装传播 |
| 程序学习向 | raylib / LÖVE | Pygame | 手写循环，理解每个像素 |

## 5. 常见纠结，直接给答案

- **Unity 还是 Godot**：个人 2D 小项目选 Godot；目标是行业求职或移动商业项目选 Unity。两者都会是最好的状态。
- **Unity 做 2D 会不会浪费**：不会。2D 工具链成熟，缺点只是启动略重。
- **Unreal 能不能做 2D**：可以，但生态与教程偏向 3D，2D 项目没必要。
- **Web 引擎能不能做商业游戏**：能。Web 分发是独立游戏的一条真实渠道，性能预期要对。
- **自研引擎值得吗**：除非引擎本身就是你的产品，或者团队规模大到被商业引擎条款制约，否则不值得。

## 6. 选定之后的纪律

1. 选定即承诺：至少做完一个完整的可发布作品再考虑更换。
2. 学习期只看一个来源的教程（官方文档优先），拒绝教程跳岛。
3. 版本管理从一开始就上，目录结构按引擎官方模板走。
4. 把「换引擎」当作一次搬迁而不是重学：概念（节点、组件、场景、生命周期）是通用的。
