# Ludo Atlas · 入门 · 游戏开发全貌

> **入门区**（第 ㉛ 轮扩展）。这一页回答四个问题：游戏是怎么做出来的、团队里每种人在干什么、钱从哪来、以及新手最常见的六个想当然。读完再决定往哪个方向走。

## 1. 一个游戏是怎么做出来的

成熟团队的流程大致如下。独立开发会做减法，但先后顺序基本不变：

| 阶段 | 在干什么 | 典型产物 | 耗时参考 |
| --- | --- | --- | --- |
| 概念 | 想清楚「给谁玩、玩什么、凭什么好玩」 | 一页纸立项书、原型目标清单 | 几天到几周 |
| 原型 | 用最粗糙的方式验证核心循环 | 能玩但难看的可玩原型 | 1-4 周 |
| 垂直切片 | 把「一小段完整体验」做到接近成品质量 | 一个可展示的完整关卡 | 1-3 个月 |
| 量产 | 批量生产关卡、资产、系统 | 全部游戏内容 | 独立 3 个月起，团队 1 年起 |
| 打磨 | 手感、平衡、性能、Bug 修复 | 可发布的版本 | 1-3 个月 |
| 发布 | 商店页、宣发、上架审核 | 已上架的产品 | 1-2 个月 |
| 运营 | 更新、修 Bug、社区维护、后续内容 | 长期收入与口碑 | 持续 |

每一步的细则分散在本仓库的各手册里，这里只给地图：

| 代码、架构、性能 | [技术实现手册](../fundamentals/programming/README.md)（⑩） |
| 美术与音频生产 | [美术与音频手册](../fundamentals/art-audio/README.md)（⑪） |

| 关卡 | [关卡设计手册](../fundamentals/level-design/README.md)（㉑） |

## 2. 团队里都有谁

游戏行业的分工可以粗分为八条线。每个岗位的完整技能栈与入门路径见[岗位与技能地图](role-map.md)，这里先给一行版本：

| 线 | 岗位 | 一句话职责 |
| --- | --- | --- |
| 程序 | 玩法 / 引擎 / 工具 / 服务端 | 把设计变成能运行的现实，并保证它流畅不崩 |
| 设计 | 系统 / 数值 / 关卡 / 叙事 / 战斗 | 决定「玩什么」与「为什么好玩」 |
| 美术 | 原画 / 2D / 3D / 动画 / 特效 / UI / TA | 决定游戏长什么样，以及看到的一切怎么动 |
| 音频 | 音效设计 / 作曲 / 音频实现 | 决定游戏听起来什么样，含手感一半的功劳 |
| 制作 | 制作人 / 项目经理 | 让正确的人在对的时间做对的事，砍掉多余的 |
| 测试 | QA | 在玩家之前找到问题，守住质量底线 |
| 发行 | 市场 / 商务 / 平台关系 | 让目标玩家知道并买到这款游戏 |
| 运营 | 社区 / 数据分析 / 商业化 | 上线后让玩家留下来、玩得久 |

独立开发者通常一个人覆盖程序、设计、部分美术；小团队会先补齐「程序 + 美术 + 设计」三件套。

## 3. 钱从哪来

| 商业模式 | 怎么赚钱 | 常见于 |
| --- | --- | --- |
| 买断制 | 一次性付费 | PC、主机、精品独立 |
| 内购 | 皮肤、道具、抽卡、通行证 | 手游、部分 PC 网游 |
| 广告 | 激励视频、插屏 | 小游戏、超休闲 |
| 混合 | 买断 + DLC / 内购 + 广告 | 大量商业作品 |
| 订阅 | 会员制内容服务 | 少量产品与平台服务 |
| 众筹 / 补助 | 预售或资助先行 | 独立项目启动期 |

平台与形态的差异（PC、主机、移动、小游戏、Web）会直接影响商业模式和开发预算，展开见[全平台上架手册](../../playbooks/platform-launch/README.md)（⑧）与[法务手册](../publishing/legal/README.md)（⑦）。

## 4. 三种规模，三种打法

| 规模 | 人数 | 流程特点 | 最大风险 |
| --- | --- | --- | --- |
| 独立开发 | 1-2 人 | 无会议，边做边定；速度优先，用现成资产 | 范围失控，做不完 |
| 小团队 | 3-10 人 | 轻流程，周迭代；岗位兼着干 | 沟通损耗，方向漂移 |
| 公司 | 10 人以上 | 专职分工，阶段评审；文档与管线先行 | 成本高，决策慢 |

规模越大，越依赖流程与文档；规模越小，越依赖选对范围。团队与协作的展开内容随《团队与规模》区持续扩充。

## 5. 中国大陆与出海要额外注意的事

- 国内发行涉及版号、防沉迷、渠道分成与备案，细节见[法务手册](../publishing/legal/README.md)（⑦）。
- 小游戏是独立的工程形态（包体、性能、平台规则都不同），见[小游戏手册](../publishing/minigame/README.md)（㉒）。

## 6. 六个常见误解

1. 「会玩游戏就能做游戏」：玩是消费，做是生产。中间隔着 Engine、流程和一万次调试。
2. 「美术不行就做不了游戏」：美术可以买、可以合作、可以风格化。真正卡人的是完成度。
3. 「引擎选错就完了」：任何主流引擎都能做完一款游戏。切换成本远低于「一直不做」的成本。
4. 「独立开发自由又轻松」：自由是真的，轻松是假的。它是高强度的自我管理。
5. 「先想一个爆款点子最重要」：点子不值钱，把它做出来并推出去才值钱。
6. 「AI 来了，一个人能做 3A」：AI 显著加速了编码与资产生产，但它不替你做取舍。见 [AI 工作流手册](../ai/README.md)（⑲）。
