# GameDev Atlas · 小游戏开发手册

> **迭代第 ㉒ 轮**。微信、抖音为主的小游戏生态实操：工程限制、平台能力、变现设计、买量与审核。
> 配套：《全平台上架手册》§6（⑧，资质与流程）·《运营与增长手册》（⑬）·《避坑大全》（⑥）。
> **时效声明**：小游戏平台规则调整频繁，本文事实核实于 2026-10。包体限制、费率、支付政策动手前必查官方最新文档（入口见 §10）。

## 1. 小游戏是什么生意

小游戏是"点开即玩"的游戏形态，跑在超级 App 里，没有安装过程。它和 App 游戏的核心差异：

| 维度 | 小游戏 | App 游戏 |
| --- | --- | --- |
| 获取用户 | 平台流量池（社交/内容推荐） | 应用商店 + 买量 |
| 包体 | 首包 4MB 级，总包 20-30MB 级 | 数百 MB 起 |
| 技术环境 | JS/WASM 运行时，能力受平台限制 | 原生，接近无限制 |
| 变现 | 广告（IAA）为主，内购（IAP）为辅 | 内购为主 |
| 生命周期 | 短平快，首日数据定生死 | 长线运营为主 |

小游戏的本质是流量生意加轻量内容。做惯 App 或 PC 的团队进场，最容易低估两件事：包体的硬约束，和"首日留存低就再也买不到量"的残酷节奏。

## 2. 平台一览

| 平台 | 流量来源 | 变现 | 主体与资质 |
| --- | --- | --- | --- |
| 微信小游戏 | 社交流（分享/群）、搜索、小游戏中心 | IAA + 虚拟支付 | 个人主体可发免费（广告）游戏；付费需企业主体 + 版号 |
| 抖音小游戏 | 内容流（短视频、直播挂载） | IAA + 虚拟支付 | 企业主体，软著；（虚拟支付需）版号 |
| 快手小游戏 | 内容流，用户盘与抖音有差异 | 同上 | 同上 |
| 硬件渠道（小米/OPPO/vivo 等，含快游戏联盟） | 应用商店内小游戏入口 | IAA + 渠道支付 | 各渠道规则，多数要求软著 |
| 海外 Web（Poki、CrazyGames 等） | 平台自然量 | 广告分成 | 无国内版号要求，见 ⑧§7 |

先想清楚自己的内容适合哪种流量：分享驱动（微信）、内容驱动（抖音快手）、还是搜索与栏目驱动（硬件渠道）。同一款游戏在不同平台的投放策略完全不同。

## 3. 工程红线：包体与性能

### 3.1 包体限制（核实时点 2026-10）

| 平台 | 主包（首包） | 总包 | 备注 |
| --- | --- | --- | --- |
| 微信小游戏 | 不超过 4MB | 主包+分包合计不超过 30MB | 单个普通分包不限制大小；单个独立分包不超过 4MB |
| 抖音小游戏 | 不超过 4MB | 整体不超过 20MB | 单个分包不超过 20MB |
| 硬件渠道（rpk 标准） | 不超过 4MB | 合计不超过 30MB | 快游戏联盟标准，Cocos/Laya/Unity 导出支持 |

工程含义只有一句话：**首包只放启动必需的内容，其余全部走分包与 CDN**。首包大小直接决定冷启动下载时间，而冷启动每多一秒，流失是肉眼可见的。

### 3.2 分包与资源策略

- 按玩法阶段拆分包：启动包、核心玩法包、后期内容包，边玩边下。
- 大资源（贴图、音频）走 CDN，配压缩（gzip/brotli）与缓存策略。
- 弱网与首次下载要有进度展示，用启动画面或小循环动画兜住等待。
- 资源版本管理要做：缓存命中旧版本资源是小游戏线上事故的常见来源。

### 3.3 性能与适配

- **内存**是小游戏最大的敌人。低端安卓机上，内存超限直接闪退，且难复现。用真机（不是模拟器）盯内存曲线。
- **渲染**：WebGL 能力有限，纹理尺寸与压缩格式按平台要求处理；DrawCall 和粒子数量按低端机定预算。
- **适配**：屏幕比例五花八门，刘海与圆角要留安全区；触摸交互的点击热区要比视觉大一圈；切后台回来要能恢复。
- **音频**：自动播放策略限制普遍存在，首音效需要玩家第一次交互后解锁。
- **调试**：微信开发者工具、抖音开发者工具，都支持真机预览与性能面板。上真机测，且至少测一台低端机。

### 3.4 引擎路线

| 引擎 | 路线 | 说明 |
| --- | --- | --- |
| Cocos Creator | 原生支持导出 | 国内小游戏生态最成熟，文档与案例多 |
| LayaAir | 原生支持导出 | 同为国内引擎，小游戏方向积累深 |
| Unity / 团结引擎 | 转换方案 | 官方转换方案：`minigame-unity-webgl-transform`（微信）；团结引擎直接支持抖音小游戏导出 |
| 原生 JS/TS | 手写或轻量框架 | 适合超轻量玩法，包体最可控 |

Unity 项目转小游戏的评估要点：包体（WebGL 产物体积）、内存峰值、第三方插件兼容性（含原生代码的插件不可用）。转换方案官方有兼容性评估流程，先评估再投入。

## 4. 平台能力接入

- **登录**：用平台账号体系做静默登录，游客模式先跑起来，需要时再引导绑定。
- **分享/转发**：微信的分享链路是核心传播引擎，但分享设计要玩法化（晒成绩、求助、炫耀），不要做"转发才能复活"式的滥用，会被处理也会伤留存。
- **排行榜**：微信关系链排行榜通过开放数据域实现；也可以自建全局榜。
- **云存档**：平台云能力（如微信云开发）或自建服务端，存档冲突策略要提前定。
- **广告组件**（IAA 的本体）：激励视频（玩家主动看，拿奖励）、插屏（间隙弹出）、Banner（常驻小条）、原生模板。激励视频是收益大头，插屏和 Banner 要克制，它们是差评的主要来源。
- **虚拟支付（IAP）**：重要更新是 iOS 端通道已经打通。2025 年底苹果推出"小程序合作伙伴计划"，微信官宣接入 iOS 虚拟支付，过去"iOS 不能虚拟支付、引导外部支付"的历史彻底翻页。要点：虚拟支付需版号与企业主体；费率结构（含苹果分成与平台服务费）以官方最新公告为准；历史上各种绕行方案现在属于违规操作，不要再采用。
- **能力开通**：微信侧通过公众平台"能力地图"按需开通；抖音侧在开放平台申请。别等上线前一天才发现某个能力没开。

## 5. 变现设计

- **激励视频的节奏**：放在"玩家刚好想要的时刻"（复活、翻倍、解锁、补奖励），转化率最高、体验伤害最小。频次控制比位置更重要：每局 2-3 次是常见的安全线。
- **混合变现**：IAP 做去广告、礼包、通行证；IAA 做日常收益。两者要有主次，不然价值体系互相打架。
- **数据模型**：小游戏看首日与 7 日留存、人均时长、eCPM、LTV。数值差就快速调，小游戏没有"慢工出细活"的窗口。
- **两条经典路线**：社交裂变型（一波流，赌传播，如羊了个羊式的全民话题）和长线 IAA 休闲型（稳定更新、靠买量和自然量滚动）。两条路的能力要求完全不同，先选再投入。

## 6. 审核与合规

与 ⑧§6 的口径一致，这里给小游戏视角的补充：

- **资质**：软著是基础；开通虚拟支付需版号；微信免费（纯广告）游戏个人主体可发，付费必须企业主体。版号办理周期按月起算，要排进开发计划。
- **防沉迷与实名**：开通虚拟支付的企业须在实名认证系统完成企业注册与游戏绑定，并与平台同步（入口见 ⑧§6.1）。
- **内容审核**：类目选择一次成型不可改；名称、图标、截图、玩法说明都会审；抽奖式设计（概率不公示、可兑换现金的结构）是禁区重灾区。
- **隐私**：用户信息采集最小化，隐私协议按平台模板接入，别多拿不该拿的数据。

## 7. 买量与运营

- **抖音侧**：短视频素材是弹药。素材迭代速度决定投放天花板，同一玩法准备 10 组以上素材 A/B。直播挂载适合带操作展示的玩法。投放模型看 ROI，首日回本线以下就砍。
- **微信侧**：社交裂变（分享动机设计）、搜一搜关键词、小游戏中心推荐位。裂变要真实价值驱动（成绩炫耀、好友互助），硬性强制分享会被处罚。
- **版本节奏**：周更内容或活动，保持回到游戏的动机。小游戏用户的遗忘速度比 App 快得多。
- **数据看板**：新增、留存（1/3/7 日）、时长、eCPM、ARPU、LTV、分享率。每个指标对应一个可动的手术位，没有对应动作的指标不要看。

## 8. 发布清单

1. 资质材料齐全（软著/版号/主体信息），实名与防沉迷已对接。
2. 首包体积达标，真机冷启动时间实测达标（低端机）。
3. 全部广告点位验收：频次、遮挡、误触检查。
4. 分享链路真机走通（安卓 + iOS）。
5. 隐私协议与信息采集清单核对。
6. 提审材料：名称、图标、截图、玩法说明、资质文件。
7. 灰度或体验版先跑一轮，收集崩溃与卡点。
8. 上线后第一周每日看板巡检。

## 9. 常见坑

1. 按 App 思维估算包体，首包超限返工。
2. 只在模拟器测试，低端机闪退率爆炸。
3. 历史教程还在教你"绕过 iOS 支付"，照做等于违规。
4. 激励视频点位过密，留存与评分双杀。
5. 分享设计强制化，被平台处理。
6. 类目选错，上线后发现不可改。
7. 版号没进排期，万事俱备卡在资质。
8. 内存不盯真机曲线，上线后神秘闪退。
9. 资源缓存版本混乱，用户玩到旧版本内容。
10. 忘了首音效解锁，游戏静音上线。
