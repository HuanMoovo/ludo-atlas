# Ludo Atlas · 法务、专利与竞争手册

> 定位：游戏开发者在著作权、商标、专利、合同、出海合规与市场竞争六个方面的实用地图。
> **免责声明**：本文为科普整理，**不构成法律意见**；涉及纠纷、合同签署、诉讼等重大事项请咨询执业律师。法律法规与平台政策持续变化，行动前请以最新官方文本为准（法规原文可在文末数据库查询）。
> 配套：《避坑大全》、《全平台上架手册》、《资源大全》（含工具站点清单）。

## 1. 游戏涉及的法律领域地图

| 领域 | 什么时候会撞上 | 关键动作 |
| --- | --- | --- |
| 著作权（版权） | 全程：代码/美术/音乐/文案的归属与侵权 | 权属书面化、素材台账、开源合规（§2） |
| 商标 | 立项取名、宣传前、周边开发 | 查询 + 注册（§3） |
| 专利 | 借鉴机制、被告知侵权、机制创新保护 | 检索 + 绕行 + 留证（§4） |
| 合同法 | 发行协议、外包、合伙、平台协议 | 关键条款审查（§5） |
| 数据与隐私 | 用户数据收集、分析 SDK、儿童用户 | 政策 + 同意 + 最小化（§6） |
| 内容与发行监管 | 国内上架、版号、防沉迷、抽卡公示 | 合规前置（§6.3、《全平台上架手册》§7） |
| 税法 | 收到海外平台收入时 | W-8BEN/VAT/代扣税（§6.4） |

## 2. 著作权（版权）实务

### 2.1 什么受保护、什么不受

- **受保护**：代码、美术（哪怕简单）、音乐、音效、文案剧情、UI 表达、角色形象，这些都属于"表达"。
- **通常不受保护**：玩法规则、机制、数值思路（"思想"层面）；但**具体表达**（独特的关卡布局、美术风格组合、文案）受保护。
- **结论**：抄玩法一般合法（行业普遍如此），抄表达（美术/代码/文案）违法。参考时保留"从机制出发的再设计"过程文档。

### 2.2 权属：书面文件比什么都重要

| 场景 | 风险 | 必须做的事 |
| --- | --- | --- |
| 外包美术/音乐/代码 | 未书面约定时，著作权可能仍属创作者 | 合同写明"**著作权转让**"（财产权全部转让）+ 交付物清单 + 源文件 |
| 员工创作 | 职务作品归属需按法律与合同明确 | 劳动合同或补充协议中约定职务作品归属与署名 |
| 合伙人共同开发 | 分手后代码/美术归属纠纷 | 合伙协议写明贡献与权利分配、退出机制 |
| 众筹/委托粉丝创作 | 权利链条不清，商业化受阻 | 投稿即授权条款（范围明确） |

### 2.3 常见侵权雷区

- 临摹/描图他人美术（哪怕改色）→ 实质性相似判定风险高。
- 素材站许可误用（"免费"≠可商用；不同素材许可分层）。
- 音乐"翻唱/改版"未获授权；商用 BGM 授权范围不含游戏。
- 截图/形象使用第三方 IP（同人素材进了正式版）。
- 字体文件内嵌进游戏包（字体是独立作品，商用需授权）。

### 2.4 开源许可证合规（程序必读）

| 许可证 | 传染性 | 游戏场景注意 |
| --- | --- | --- |
| MIT / BSD / Apache-2.0 | 无 | 可闭源商用；Apache 需保留 NOTICE、含专利授权条款 |
| MPL | 弱（文件级） | 修改的 MPL 文件需开源 |
| LGPL | 弱（库级） | 动态链接一般可用；改动库本身需开源 |
| GPL | 强 | 链接 GPL 代码通常要求整个游戏开源 |
| AGPL | 强 + 网络条款 | **服务器端使用也触发开源义务**（联机游戏重点排查） |
| UE/Unity 等引擎 | 特殊许可 | 按引擎商业条款（分成/收入门槛）执行，不是开源许可 |

- 做法：维护依赖清单（SBOM）→ 用工具扫描许可证 → 逐一核对兼容性；引擎插件同样要查。
- 反例代价：闭源游戏打包 GPL 库被要求开源/重构；使用 AGPL 后端组件未开源被追责。

### 2.5 字体与音乐（高发区）

- **字体**：国内维权高发。只用"免费商用"字体清单内字体（见《资源大全》§5.6），并保留字体授权说明。
- **音乐**：三种模式：定制买断（权利最干净）、免版税库（看清范围：全球/永久/商用/视频平台）、CC（逐条核对条款）。合同写明：商用、全球、永久、可改编、含宣传用途。

## 3. 商标

- **为什么**：游戏名=最大无形资产；被抢注后可能被迫改名（沉没成本极高）；应用商店、微信、主机平台都可能要求商标或授权证明。
- **类别策略**：第 **9 类**（计算机软件/游戏程序）、第 **41 类**（娱乐服务/在线游戏）、第 **42 类**（软件开发），预算允许加 **16/25 类**（周边）、**35 类**（推广）。
- **时机**：立项定名后、任何公开宣传前，先查询后注册；主力市场（中国 + 出海目标国）同步布局。
- **查询**：中国商标网 https://sbj.cnipa.gov.cn/（商标查询入口 https://sbj.cnipa.gov.cn/trademark-query）；海外用当地商标局或 WIPO 马德里体系。
- **被抢注应对**：在先使用证据（宣传、销售记录）→ 异议/无效宣告/撤三；越早处理证据越全。
- **注意**：注册前先查近似（读音/含义/图形），别只看完全同名。

## 4. 专利（重点）

### 4.1 游戏能被专利保护吗

- **可以**：交互机制、系统设计、技术方案（如渲染/匹配/反作弊技术）在世界多数辖区都可能获得专利；软件相关发明的可专利性各国标准不同（中国要求"技术方案"；美国在判例后要求"显著多于抽象概念"）。
- **期限**：发明专利通常 **20 年**（自申请日起）。
- **对独立开发者的现实**：被游戏专利起诉是小概率、高伤害事件；**防御靠"检索 + 绕行 + 留证"三件套**，而非恐惧。

### 4.2 著名游戏专利案例（公开报道）

| 案例 | 概要 | 启示 |
| --- | --- | --- |
| 加载画面小游戏（Namco，1990s→2015 到期） | 加载时玩小游戏的机制曾被专利覆盖，到期前业界普遍避让 | 机制专利真实存在；到期后成为公共资源 |
| 箭头导航（世嘉《疯狂出租车》1998→2018 到期） | 用箭头指引玩家前往目标点的显示机制 | 街头导向类玩法设计需注意 |
| 节奏游戏音符判定（科乐美，2000 年代） | 下落式音符判定相关专利曾影响同类音乐游戏 | 音乐游戏机制借鉴需检索 |
| 《中土世界》Nemesis 系统（华纳，2021 获批） | 程序化的"宿敌"角色关系系统获批专利，引发业界讨论 | 复杂系统设计也可能被专利覆盖 |
| 任天堂诉《幻兽帕鲁》（2024 起诉，进行中） | 涉及捕捉等机制的专利组合诉讼（据报道）；尚未终审 | 机制热点（捕捉/宠物对战）专利风险集中；关注头部厂商专利池 |

> 以上为公开报道整理；专利状态、诉讼进展请以官方公告为准。

### 4.3 防御策略（独立开发者可执行）

1. **FTO 心态**：参考一个热门机制前，花 30 分钟检索相关专利（是否存在、是否有效期内、地域）。
2. **设计绕行**：不照搬具体实现（输入方式、判定逻辑、UI 呈现），用不同方案达成相近体验。
3. **记录独立开发过程**：设计文档时间线、提交历史（git log）、草图，若被指侵权，这是"独立创作"的关键证据。
4. **关注开源许可的专利条款**：Apache-2.0 含专利授权（用着安心）；GPLv3 含专利反制条款；MIT 无专利条款（注意）。
5. **收到警告函（cease & desist）**：冷静：不回复、不承认、不删证据；**第一时间找律师**；评估无效检索（prior art）与设计绕行空间。多数游戏专利警告可通过绕行解决。
6. **别怕到不敢做**：绝大多数独立游戏从未接触专利纠纷；真正的风险集中在"复制头部厂商标志性机制"时。

### 4.4 专利检索工具箱

| 工具 | 覆盖 | 用途 |
| --- | --- | --- |
| Google Patents | 全球（含翻译） | https://patents.google.com/ 关键词 + CPC 分类检索 |
| 国家知识产权局 | 中国 | https://www.cnipa.gov.cn/ 专利检索与状态查询 |
| USPTO Patent Public Search | 美国 | https://ppubs.uspto.gov/pubwebapp/ |
| Espacenet | 欧洲/全球 | https://worldwide.espacenet.com/ |
| WIPO PATENTSCOPE | 国际申请 | https://patentscope.wipo.int/ |

- 检索技巧：游戏相关专利多归 **CPC 分类 A63F**（含 A63F13 视频游戏）；中英关键词（game mechanic / 交互方法）双检索；重点看**权利要求（claims）**而不是标题。

### 4.5 自己申请专利？

- **何时值得**：可被对手也用的"标志性机制"、技术壁垒类创新（网络/渲染/反作弊）；公司做长期 IP 资产布局时。
- **流程概述**：撰写申请文件 → 提交（可先申请临时/优先权）→ 实质审查 → 授权（通常 2-4 年）。
- **成本量级**：代理费 + 官费，单件从数千到数万元（视辖区与复杂度）。
- **个人建议**：独立开发者优先把精力放在产品与商标上；专利在"机制被抄会让游戏失去竞争力"时才值得投入。

## 5. 合同实务

### 5.1 发行合同：八个必看条款

| 条款 | 看什么 | 典型坑 |
| --- | --- | --- |
| 分成基数 | "净收入"的定义（扣除哪些成本） | 净收入定义模糊，分成被无限稀释 |
| 预付款 | 是否可回收（recoup）与回收顺序 | "预付"其实是无息贷款，回收前没钱拿 |
| IP 归属 | 游戏 IP 是否转移给发行商 | 签字后 IP 不再属于你，续作受限 |
| 续作/优先谈判权 | 发行商对续作的优先权利范围 | 被绑定下一部作品 |
| 独占与期限 | 平台/区域独占范围与时长 | 全平台永久独占锁死后续收入 |
| 终止条件 | 表现不达标时的终止与 IP 回收机制 | 无终止权，烂发行商锁死产品 |
| 审计权 | 能否查账 | 无法验证分成真实性 |
| 交付义务 | Milestone 与付款节点、验收标准 | 模糊验收标准导致尾款悬空 |

### 5.2 外包与自由职业

- 必备：交付物清单（格式/规格/源文件）、里程碑与付款比例、**著作权转让条款**、保密条款、延期与修改次数上限。
- 附件：参考图/规格表（防止"不是我想要的"扯皮）。

### 5.3 合伙与股权

- 股权分配：按贡献（人力/资金/IP）书面固定；**vesting（成熟期）**机制（4 年 +1 年 cliff 常见）防止早期成员拿了股份就跑。
- 明确决策机制（谁拍板）与退出机制（回购价格公式）。

### 5.4 NDA 与竞业

- 与发行商/平台沟通前可先签 NDA；注意自己签过的 NDA 是否限制后续同类项目。
- 竞业限制需有对价（补偿），玩家视角的"跳槽"多数不适用；但注意带走代码/资产的边界。

## 6. 出海与合规

### 6.1 隐私与数据

| 法规 | 适用 | 要点 |
| --- | --- | --- |
| GDPR（欧盟） | 面向欧盟用户 | 合法性基础、告知、被遗忘权、数据出境 |
| CCPA/CPRA（加州） | 加州用户 | 出售/共享告知与退出机制 |
| COPPA（美国） | 面向儿童（<13） | 儿童数据采集需家长同意（https://www.ftc.gov/legal-library/browse/rules/childrens-online-privacy-protection-rule-coppa） |
| PIPL（中国） | 中国用户 | 同意、最小化、儿童个人信息特殊保护 |
| 平台规则 | 全平台 | 隐私标签（App Store）/数据安全表单（Google Play）必须与实际一致 |

### 6.2 年龄分级

- IARC（一键多地区评级）https://www.globalratings.com/；ESRB（北美）、PEGI（欧洲）、CERO（日本）等按目标市场办理；分级问卷必须如实（含内购、抽卡、社交、暴力元素）。

### 6.3 内容与消费合规趋势

- **抽卡/战利品箱**：概率与保底公示已是国内硬性要求；比利时、荷兰等地对 loot box 有严格判例，出海需逐市场核对。
- **广告**：不可虚假宣传（"全球最好玩"类表述风险）；涉及"限时""免费"等承诺要真实。
- **用户协议/隐私政策**：上线前必备文件包（见《全平台上架手册》§2）。

### 6.4 税务与收款（简述）

- 美国平台收入：填 **W-8BEN**（个人）声明非美国纳税人身份，避免 30% 预扣。
- 欧洲：VAT 由部分平台代缴（按平台政策）；自行销售需处理当地 VAT。
- 收款：关注平台支持的收款方式与手续费；收入结构复杂时咨询会计师。

## 7. 竞争分析（市场与竞品）

### 7.1 竞品拆解框架（一页表法）

对每个直接竞品填写六维表：**核心循环**（玩家在前 30 分钟做什么）→ **卖点**（商店页主图/预告在喊什么）→ **内容量**（时长/关卡数）→ **价格与折扣史** → **评价分析**（好评差评关键词、最近 30 天评价）→ **销量估算区间**。产出：定位坐标图（价格 × 复杂度 / 受众 × 卖点）。

### 7.2 数据工具（均为估算，交叉验证）

| 工具 | 维度 |
| --- | --- |
| SteamDB | 在线人数、标签、即将发售榜（查竞品与档期） |
| Gamalytic / VG Insights | 销量与收入估算、竞品对比 |
| SteamSpy | 销量区间估算 |
| 七麦 / 点点数据 | 移动端榜单、下载与收入估算 |
| Sensor Tower / Newzoo | 市场级报告（付费） |
| 社区信号 | 愿望单数据（开发者后台）、Reddit/Discord 讨论热度 |

- 经验法则（谨慎使用）：Steam 评测数 × 30-50 ≈ 销量量级；愿望单转化率与首周销量关系因品类差异大，用同品类对标。

### 7.3 判断市场空间

- 看**饱和度**：近 12 个月同类新品数量与头部集中度（前 5 名吃掉大部分收入 → 谨慎）。
- 看**长尾机会**：细分受众（某题材/某玩法组合）是否被满足；差评集中在哪些未被解决的问题（你的机会点）。
- 看**定价带**：同类质量的常见价格区间；定价锚定"竞品 + 你的完成度"。

### 7.4 差异化策略工具箱

1. **组合创新**：X meets Y（如"农场 + 卡牌""肉鸽 + 音游"），但确保两套系统真正互相咬合。
2. **深度换广度**：少而精（一个机制做到极致 > 十个半成品机制）。
3. **受众占位**：服务被忽视的群体（语言/文化/无障碍/平台）。
4. **卖相壁垒**：独特美术风格、强叙事、强音乐，这是独立团队最现实的可感知差异。
5. **节奏策略**：同类大作空档期发行；抢先者优势（尤其轻量玩法）。

### 7.5 面对竞争与"被抄"

- 抄袭（合法玩法层面）：加速迭代与社区绑定是最好防御（速度 + 品牌 + 玩家关系）。
- 侵权（表达层面）：固定证据 → 律师函 → 平台投诉（DMCA/商店侵权通道）→ 诉讼；参见 §2。
- 大厂跟进同类玩法：不要打正面战；改变赛道/强化垂直社群/做"大厂不屑于做"的深度体验。

## 9. 法务行动清单（按阶段）

| 阶段 | 必做事项 |
