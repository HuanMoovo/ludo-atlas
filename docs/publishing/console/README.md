# Ludo Atlas · 主机开发手册

> 主机平台的开发与发行实操：开发者入口、开发机、移植工程、认证（Certification）、发行方式。
> 配套：《全平台上架手册》（含中国国行审批）·《技术实现手册》·《法务、专利与竞争手册》·《制作管理手册》。
> **诚实声明**：主机平台的大部分技术细节受 NDA 保护，公开渠道永远只有一部分。本文只写公开信息与通用流程，具体条款、认证清单、SDK 细节一律以平台官方文档和合同为准。

---

## 1. 主机和 PC、移动有什么不同

主机是封闭平台：开发要资格审核，发布要认证，硬件是专用的，条款是保密的。四件事和别的平台根本不同：

| 维度 | 主机 | PC（Steam 等） |
| --- | --- | --- |
| 开发资格 | 平台审核 + 签约 | 注册即可 |
| 硬件 | 官方开发机（借用或购买） | 随便什么电脑 |
| 发布 | 认证制，每次更新也要认证 | 自由上传 |
| 商业条款 | 保密合同，分成逐案谈 | 平台标准分成 |

为什么还做主机：客厅场景与手柄体验、平台订阅服务（Game Pass、PS Plus）的曝光机会、品质背书，以及一份不能不答的现实：很多品类的主流受众在主机上。

代价也要认：申请周期、移植工作量、认证成本、更新不自由。主机不是"顺手多一个平台"，它是一个独立的小项目。

## 2. 三大平台开发者入口

| 平台 | 公开入口 | 关键步骤 | 要点 |
| --- | --- | --- | --- |
| Xbox | ID@Xbox（developer.microsoft.com/en-us/games/） | 注册 → 提报项目 → 签约 → 开发机 | 自发行流程成熟；Game Pass 曝光通道 |
| PlayStation | PlayStation Partners（partners.playstation.net） | 注册（法人主体，部分地区接受个体）→ 项目简述 → 签 GDPA → DevNet 与 SDK → 开发机（借用，按期归还） | 官方博客有完整的"如何向 PlayStation 展示你的游戏"流程说明 |
| Nintendo | Nintendo Developer Portal（developer.nintendo.com） | 注册（个人也可）→ 接受 NDA 与条款 → Switch 开发资格单独申请 → 开发机 | 支持自助发行，eShop 上线；审核周期要有心理预期 |

三个通用建议：

1. **提前申请**。审核、签约、开发机物流加起来按月算，别等游戏快做完才启动。
2. **项目简述要像电梯演讲**。平台看的是"谁在做、做什么、什么时候、凭什么"，不是完整设计文档。
3. **NDA 从注册那天就生效**。不要在任何公开场合（包括社交账号）谈论未公开内容，包括你能拿到什么硬件。

## 3. 开发机与工程环境

- 开发机（devkit）和测试机（testkit）是两类硬件，用途不同：开发机跑调试，测试机模拟零售环境。多数平台对合格项目提供借用，条件是按时归还、遵守保密流程。
- 工程环境要按平台要求配置：专有 SDK、加密工具、证书体系。为此建议独立的构建机和独立账号，别和日常开发机混用。
- 引擎支持现状（公开信息）：Unity 和 Unreal 对三大平台都有一方支持；Godot 没有官方主机导出，需要第三方移植服务或发行商协助；自研引擎的移植成本最高。选引擎时把这一条算进决策。
- CI 与主机结合的两条纪律：构建产物带保密属性，流水线和制品库要隔离；认证构建可复现（同样的提交、同样的工具链、同样的产物）。

## 4. 移植工程要点

从 PC 移植到主机，工作的真正大头是下面五块，按踩坑概率排序：

1. **输入**：手柄按键映射、死区调参、操作提示图标随设备切换、体感与震动。手感参数全部要重调。
2. **存档与用户系统**：平台账号、云存档、多用户档案切换。存档损坏和跨设备冲突是玩家投诉重灾区。
3. **成就与奖杯**：硬性要求，必须实现，且设计不能是敷衍的"完成第一章"。
4. **系统行为**：待机与恢复（suspend/resume）、断网、账户登出、手柄断连。这些场景在 PC 上可以不管，在主机上不过认证别想上线。
5. **性能**：硬件固定是好事也是压力。帧率稳定性优先于绝对画质，发热与功耗也要考虑。

附加项：HDR、可变刷新率、环绕声、无障碍选项、家长控制。主机审核对这些的完整度要求比 PC 高得多。

## 5. 认证：主机世界的入场考试

三家的技术合规清单各有名字（Sony 的 TRC、Nintendo 的 Lotcheck、Microsoft 的 Xbox Requirements），细节全部保密，但公开的共性可以拿来准备：

**认证普遍测什么**（公开描述与从业者共识层面的归纳）：

- 系统功能完整性：存档、成就、好友、邀请、语音、商店跳转。
- 家长控制与账号边界：年龄分级与内容限制联动。
- 待机恢复与异常场景：断电、断网、存储拔插。
- 性能底线：加载时间、帧率、崩溃率。
- 文本与图标规范：操作提示、系统术语的官方写法。
- 网络行为：掉线处理、重连、多人异常退出。

**流程**：提交候选构建 → 平台认证测试 → 出具报告（通过 / 带条件通过 / 不通过）→ 修复重提 → 预约上架档期。首次提交一次过（"first cert pass"）是团队工程能力的硬指标，做不到就多留两轮预算。

**准备建议**：认证前 2-3 个月开始跑内部清单；把踩过的坑写成团队 checklist；每次更新同样要过期认证，节奏要排进版本计划。

## 6. 发行方式

- **自发行**：三家都支持独立开发者自行发行（Xbox 生态尤其成熟），你保留 IP 和定价权，平台分成以合同为准（业内常见口径约三成，实际逐案逐档位不同）。
- **发行商发行**：发行商负责资金、认证协调、实体版、地区化，代价是分成和部分决策权。选择标准与谈判要点见《法务、专利与竞争手册》§5。
- **评级**：主机商店上架必须有内容评级（ESRB、PEGI、CERO 等，数字版多走 IARC 问卷流程）。中国国行主机是另一套审批体系，详见《全平台上架手册》。
- **订阅服务**：Game Pass、PS Plus 等有独立的送审与商务入口，对独立团队来说既是收入也是曝光，可以主动申请。
- **实体版**：限量实体发行（Limited Run 这类模式）是长尾收入，也是一次营销事件，适合已有粉丝基础的作品。

## 7. 上市节奏

- 商店页素材（截图、预告片、文案）各家规范严格，格式与内容都要按模板过。
- 预购与上市日期一旦公布，向平台承诺后改动成本高，排期留缓冲。
- 首日补丁也要认证。所以"先上市再修"在主机行不通，打包时就要接受这件事。
- 多平台同步发行的排期建议：认证最早、最严的平台先跑，其余跟进。

## 8. 常见坑

1. 低估移植工时。输入、存档、成就三座山，按原计划的两倍算。
2. 认证排期没留缓冲，错过旺季发行日。
3. 忘了每次更新也要认证，热修习惯带进主机被打回。
4. 开发机保密流程出问题（晒硬件、外借、截图泄露）。
5. 操作提示图标没做设备适配，认证一轮游。
6. 待机恢复场景没测全，这是高频认证失败项。
7. 成就设计敷衍，上市后被玩家差评。
8. 网络异常场景没处理，多人游戏认证必挂。
9. 税务与分成结构没算清，到账才发现少一截。
10. 把主机当"顺手多一个平台"，资源没单独排。
