# Ludo Atlas · 团队与规模 · 工作室（10 人以上）

> **团队与规模批次**（第 ㉜ 轮扩展）。定位：10 人以上工作室的组织手册，覆盖部门与评审机制、管线与规范、阶段模型与风险控制，把「大厂流程」拆成可执行的动作。
> 配套：《制作管理手册》（⑫）·《美术与音频手册》（⑪）·《全平台上架手册》（⑧）·《避坑大全》（⑥）。

---

## 1. 定位与适用

一句话定位：工作室是**用流程换确定性**的组织形态。10 人是分水岭：过了这个规模，全员的「当面同步」不再成立，协作开销开始吃掉个人产能，必须用部门结构、资产规范与阶段节奏接住复杂度。

本页的「工作室」指 10 人以上、多职能（设计、程序、美术各自成线）并行、项目周期以年计的组织。两种情况不在此列：

| 场景 | 建议去处 |
| --- | --- |
| 2-8 人的小团队 | 《制作管理手册》（⑫ §4.1）的最小流程 |
| 单人开发 | ⑫ §7 单人开发专章、《独立开发生存手册》（⑱） |

规模带来的三个变化：

- 沟通从「当面说」变成「文档化」：信息必须有单一事实来源，口头决定不算数。
- 决策从「一个人拍板」变成「分层评审」：每一层只为自己的范围负责。
- 质量从「感觉对」变成「可验收」：能用清单与标准描述的东西全部写下来。

## 2. 核心挑战与对策

### 2.1 协作成本：从加法变乘法

- 人越多，沟通链路越多：n 个人之间有 n(n-1)/2 条链路，10 人约 45 条，30 人约 435 条。工作室的大部分流程设计，本质都是在管住这些链路。
- 对策一：按部门收口。跨部门信息只在接口人之间流动，组内细节不上升为全员议题。
- 对策二：决策落在文档。每项决定写「背景、选项、决定、后果」并存进共享空间（做法同⑫ §4.1 的决策记录）。
- 对策三：会议人数设上限。决策会建议控制在 7 人以内，更多人的意见走书面预审。

### 2.2 管线先行：资产规范与自动化

小团队靠手艺扛住规模，工作室必须靠管线：人数与资产量同时上涨时，手工流程的成本是乘法级增长。量产之前先立好四件事（规范细节见《美术与音频手册》（⑪））：

| 事项 | 内容 | 落地位置 |
| --- | --- | --- |
| 命名规范 | 类别_主体_动作_序号；SM_/SK_/T_ 等前缀 | ⑪ §2.3、§3.1 |
| 规格表 | 分辨率、面数、贴图尺寸与压缩、动画帧率 | Art Bible 加技术预算（⑩） |
| 导入自动化 | 引擎导入设置、图集打包、压缩参数脚本化 | 引擎侧脚本 |
| 检入校验 | 提交前自动检查命名与规格，违规阻断入库 | CI 或提交钩子 |

验收判据只有两条：新人第一周能独立产出符合规范的资产；同一种资产换个人做，规格一致。

### 2.3 生产阶段模型与里程碑

阶段模型（原型 → 垂直切片 → Alpha → Beta → RC，各阶段的冻结与验收标准）见《制作管理手册》（⑫ §2.2），不在此重复。工作室语境下补三条：

- 切片前先完成管线验证：工具链能批量产出达标资产，切片才作数；管线没跑通，测出的工时不作数。
- 冻结是部门之间的合同：Feature Lock 锁功能清单，Content Lock 锁内容清单；锁后新增走变更流程，不走「顺手加」。
- 里程碑交付物等于可玩构建加各部门清单。验收逐条对照⑫ §2.2 的可验收定义，不靠汇报材料过会。

### 2.4 风险登记与砍内容流程

风险登记表沿用⑫ §6 的框架，工作室版补两列：触发条件（如「切片工时超估 50%」「外包连续两次验收不达标」）与负责人。到点即执行预案，不重新辩论。

常见的工作室级风险：

| 风险 | 触发信号 | 预案 |
| --- | --- | --- |
| 关键岗位单点 | 某人缺席即阻塞一条线 | 关键系统至少两人可维护，文档随代码走 |
| 部门间依赖阻塞 | 下游反复等待上游交付 | 接口契约先行，接口人每日对齐 |
| 外包质量不达标 | 两次验收不通过 | 换供应商或收回自研（流程见⑫ §4.3） |
| 排期乐观 | 连续两周进度落后 | 启动砍内容预案，不启动加班预案 |

砍内容由制作人/总监拍板，不走票选；顺序沿用⑫ §3（外观皮肤 → 支线内容 → 附加模式 → 系统深度 → 内容量，核心循环排在末位）。工作室补充一条：每砍一项，同步评估哪个部门释放了工时、哪个部门要返工，并把结果公示全员。

### 2.5 与发行商和平台的关系

- 有发行商时，里程碑一般与付款和验收挂钩：Demo、垂直切片、Alpha、发布候选各要交付什么，写进合同附件的交付清单，并和内部验收标准对齐（⑫ §2.2）。
- 平台认证要提前做：主机平台认证（cert）涉及的存档异常处理、手柄支持、暂停恢复、崩溃上报等要求，要在 Alpha 前进入需求清单，否则 Beta 后返工（口径与准备清单见《全平台上架手册》（⑧））。
- 商店素材、多语言文案、宣传片按⑧ §2 的通用准备包提前制作母版，量产后统一导出；国内渠道的版号与审核周期长，要在立项时就计入排期（⑧）。
- 对外演示讲可玩构建与数据，不讲 PPT。

## 3. 工作流与节奏

### 3.1 三层节奏

| 周期 | 动作 | 产出 |
| --- | --- | --- |
| 每日 | 组内站会 15 分钟，只答「昨天/今天/阻塞」 | 阻塞项当天上报 |
| 每周 | 周五可玩构建加组间同步 | 构建与三行简报 |
| 每月 | 风险登记复核加范围声明复核 | 更新后的风险表 |

构建纪律：主干随时可玩，每天至少一次自动构建；构建坏了立即停线修复，优先级高于任何新功能。

### 3.2 评审机制

评审分三层，频率与输出固定：

| 评审 | 对象 | 频率 | 输出 |
| --- | --- | --- | --- |
| 需求评审 | 新功能/新内容进入排期前 | 每周固定窗口 | 做 / 不做 / 简化，三选一 |
| 里程碑评审 | 阶段出口（原型、切片、Alpha、Beta、RC） | 每阶段一次 | 逐条验收、复盘与后续重估 |
| 构建评审 | 每周可玩构建 | 每周 | 体验问题清单（只谈体验，不谈代码） |

需求评审由设计、程序、美术共同参加，确认玩法价值、成本与依赖，避免「程序接到需求才发现做不了」。评审纪律：每场先定决策人；同一议题只辩一轮，新意见走变更流程；结论写进决策记录并公开。

## 4. 协作与分工

### 4.1 部门结构

| 部门 | 负责范围 | 主要交付物 | 主要对接 |
| --- | --- | --- | --- |
| 设计 | 系统、关卡、数值、叙事 | 设计文档、数值表、关卡 | 程序、美术 |
| 程序 | 玩法、引擎、工具链、服务端 | 可玩构建、工具、性能报告 | 设计、美术、QA |
| 美术 | 概念、角色、场景、动画、UI、技术美术 | 资产与规范 | 设计、程序 |
| 音频 | 音乐、音效、配音与实现 | 音频资产与响度规范 | 美术、程序 |
| QA | 测试计划、回归、设备矩阵 | 缺陷清单与质量报告 | 全体 |
| 制作 | 范围、进度、风险、外包 | 排期、风险表、验收记录 | 全体 |

分工原则：

- 每项资产与系统有唯一负责人；评审可以多人，拍板只有一个。
- 接口写契约：程序给设计的数据格式、美术给程序的交付规格，以文档固定。
- 知识无单点：构建、发布、绑定、动画状态机等关键流程，至少两人会用。

### 4.2 信息流动与文档纪律

- 单一事实来源：一个主题只有一份权威文档，其余全部引用（⑫ §4.1）。
- 决策不上锁：决策记录对全员可读，组会纪要在 24 小时内公开。
- 反漏斗：不在一对一私聊里做决定；任何口头结论当天补进文档。
- 变更公示：砍掉与新增的功能，每周随构建简报一起公示。

### 4.3 外包与外援的接口

- 外包按⑫ §4.3 流程（需求包 → 试单 → 里程碑合同 → 分批验收 → 归档），并设专职对接人，否则沟通成本会吃掉主美或主程。
- 验收标准量化：尺寸、风格比对图、动效时长、交付格式一次说清，不接受「感觉不对」式往返。

## 5. 工具与技术栈建议

工具是流程的固化；先定流程，再选工具，选定后不要频繁更换。按用途给默认档位：

| 用途 | 默认选择 | 备注 |
| --- | --- | --- |
| 任务与进度 | HacknPlan / Codecks / Jira / 飞书 | 大项目要求需求与任务两层结构，外加里程碑视图 |
| 文档与决策 | Notion / Confluence / 语雀 | 单一事实来源，禁止多源同写 |
| 版本与资产 | Git 加 LFS；资产量很大时用 Perforce | 二进制资产配提交钩子校验 |
| 构建与 CI | Jenkins / GitHub Actions / 自建构建机 | 每日自动构建并分发测试机 |
| 缺陷管理 | 与任务同系统，配 S1-S4 分级 | 分级定义见⑫ §5 |
| 沟通 | IM 加每周构建简报与录屏评审 | 关键会议必须有纪要 |
| 遥测（上线后） | 自建或第三方分析服务 | 事件设计先行，隐私合规见⑦ |

选型硬标准：能否自动校验资产与构建。靠人肉检查的环节，规模一上来必然失守。

## 6. 常见坑

1. **协调成本被低估**：加人不等于加产能，沟通链路平方增长；向已经延期的项目加人通常更延期。先砍范围，再考虑加人。
2. **过长的垂直切片**：切片没有时间盒，做一年还没结束，预算被吃光。切片是校准工具，超时先缩范围，再重估全量工期（⑫ §2.2）。
3. **质量门槛随进度摇摆**：验收标准模糊或中途下调，返工与延期在后面等着。门槛公布后，下调必须走变更流程并公示。
4. **信息漏斗**：决策留在会议室和私聊里，下游按旧信息开工，返工时才发现。单一事实来源加决策公示是最便宜的保险。
5. **管线后置**：先量产再补规范，资产返工量倍增；美术与外包资产尤其明显，规范要在量产前冻结（⑪）。
6. **评审没决策人**：会开完没人拍板，同一议题反复开会。每场评审定决策人与截止时间，只辩一轮。
7. **流程过重**：10 人团队照搬大规模流程，层层文档、周会套周会，管理开销反超产能。流程按规模裁剪，能删的会都删。
8. **关键知识单点**：只有一个人懂构建系统或绑定流程，人一休假就阻塞。文档化加备份人，把单点消灭在平时。
9. **认证返工**：把平台认证当收尾工作，Beta 后才发现存档、手柄等不达标，挤占打磨期（⑧）。
10. **外包失控**：没有专职对接与量化验收标准，外包变成往返拉扯，质量和周期一起崩。
