# Ludo Atlas · 游戏设计手册

> 定位：从"有想法"到"验证好玩"的设计方法论与实操手册，覆盖设计流程、核心循环、系统、数值、关卡、手感、UX、叙事与验证方法。
> 配套：《制作管理手册》（排期与切片）·《避坑大全》·《资源大全》（工具与课程）· `docs/genres/`（112 类型 Playbook 各自的设计要点）。
> 本文为方法论整理：框架是拐杖不是圣经，最终以"你的玩家测出来好玩"为准。

---

## 1. 设计流程：从想法到可玩

| 阶段 | 产出物 | 核心问题 | 通过标准 |
| --- | --- | --- | --- |
| 概念期 | 一句话概念（High Concept）+ 一页纸 | "这游戏是什么？谁玩？为什么好玩？" | 10 秒内让人眼睛一亮；能用 3 句话讲清 |
| 纸面原型 | 规则/循环的草图（纸、卡片、表格） | 核心循环成立吗？ | 纸面玩 3 轮就想继续 |
| 数字原型（玩具） | 白盒 demo：只有核心玩法，无美术 | "有趣"是否来自玩法本身？ | 自己反复玩不腻；给 3 个人测试有 1 个人想继续 |
| 垂直切片 | 达到最终质量标准的一小段体验 | 质量标杆与工作量预估 | 质量达发售水准；用于排期校准（见《制作管理手册》） |
| 量产 | 全部内容 | 保持质量、控制范围 | 见《制作管理手册》 |

**设计文档体系（按规模选用，模板见 `templates/`）**：

- **一页纸**（任何项目）：概念、玩家幻想、核心循环、目标平台、竞品与差异、风险。
- **Mini GDD**（Jam/小项目）：+ 操作、系统清单、关卡列表、美术/音频方向。
- **完整 GDD**（量产项目）：+ 系统详设、数值基准、内容规划、技术约束。**注意：GDD 是"活文档"，不是合同**：每两周随验证结果更新，过期章节直接删。

**迭代循环（贯穿全程）**：假设 → 最小原型 → 玩家测试 → 决策（保留/调整/砍掉）。铁律：**未经玩家测试的假设不算数**；"我觉得好玩"没有证据价值。

## 2. 核心循环与体验目标

### 2.1 核心循环（Core Loop）

- 画法：用动词连成环：`探索 → 战斗 → 收获 → 升级 → 探索（更深）`。写不出动词环 = 还没有游戏。
- **循环嵌套**：秒级（操作反馈：跳跃-落地）、分钟级（挑战-奖励）、小时级（关卡-成长）、长期（周/季：赛季、目标）。各层都要有"钩子"（下一层的期待）。
- 检查：每个循环的开头是否"想再来一次"？循环的奖励是否尽快兑现（尤其分钟级）？

### 2.2 体验目标与支柱（Pillar）

- 写 2-4 个**体验支柱**（如"紧张但公平""荒诞的欢乐""孤独的探索"），每个决策（机制/美术/音乐）都要能回答"服务哪个支柱"。
- 从体验反推机制（experience-first）：先写"玩家此刻应该感到什么"，再设计产生该感受的规则。

### 2.3 MDA 框架（速用版）

**机制（Mechanics，规则）→ 动态（Dynamics，玩法涌现）→ 美学/体验（Aesthetics，感受）**。调参时从 M 端动手、D 端观察、A 端验收；玩家评测反馈（"无聊/沮丧"）要反推回 M 端找原因。

## 3. 系统与机制设计

- **机制三要素**：规则（能做什么）· 反馈（做了什么会怎样）· 成本/代价（做它要失去什么）。缺少"代价"的机制≈白送乐趣。
- **系统互锁**：让两个系统互为对方资源（如："探索产出素材 → 素材强化探索能力"），涌现的故事与策略由此产生。
- **复杂度预算**：把玩家的学习带宽当预算：新机制一次只教一个；用"认知负荷清单"检查每关新增概念数 ≤2。
- **设计模式库（常用范式）**：

  | 范式 | 机制模板 | 适用 |
  | --- | --- | --- |
  | 风险回报 | 更大收益需冒更大风险（撤出/深潜） | Roguelite、搜打撤 |
  | 资源转换 | A→B→C 的合成链 | 建造、生存 |
  | 集合收集 | 收集-集齐奖励 | 图鉴、宠物 |
  | 时间压力 | 限时任务改变决策权重 | 节奏、街机 |
  | 双资源对抗 | 两套资源互相牵制（血/热、光/暗） | 潜行、解谜 |
  | 可见进度 | 进度条即动力（XP、成就） | 全域 |

- **操作映射**：动词→输入 1:1 优先；组合键、长按、双击是"高级语法"，只在熟练后引入。

## 4. 数值与平衡

### 4.1 数值表方法论

- **先表后码**：所有可调数值进 CSV/表格（列：参数/初值/单位/备注/测试记录），代码只读表。
- 表格结构建议：玩法定值、成长曲线、敌人属性、掉落表、经济定价 分开在独立 sheet。

### 4.2 成长曲线

| 曲线 | 形状 | 用于 | 注意 |
| --- | --- | --- | --- |
| 线性 | 匀速 | 兜底、短期数值 | 长期会失去提升感 |
| 指数 | 越升越快 | 战力、等级需求 | 易爆炸，需配"软上限/衰减" |
| 对数/根号 | 先快后慢 | 属性收益 | 适合"堆叠递减"设计 |
| S 型 | 慢-快-慢 | 熟练度、采集效率 | 阶段反馈自然 |
| 阶梯 | 离散跳变 | 装备档位、境界 | 每档需有质变感知 |

### 4.3 伤害与公式（示例思路）

- 乘法/加法混用要有理由：伤害 = 基础 × 攻防修正 × 暴击 × 技能。**护甲减免用 `伤害 × (1 - 护甲/(护甲+K))` 类曲线**避免负伤害与无限减伤。
- 公式改动前问：会不会产生"无敌配置"？极端值（全堆一项）会发生什么？

### 4.4 经济系统

- **源与汇（faucet & sink）**：每种货币必须有等量级的产出与消耗；画"货币流向图"，标出所有源汇与速率。
- 通胀控制：随版本追加剧消耗（外观/消耗品/税）+ 限制无限产出。
- 货币分层：主货币（通用）/高级货币（限职责）/社交货币，层级少而清晰。

### 4.5 平衡方法论

1. **锚点法**：定基准单位（1 点伤害=？秒=？金币），所有数值相对锚点表达。
2. **相对平衡**：不做绝对平衡，做"每项在特定情境下最优"（剪刀石头布的成本）。
3. **数据+体感双校验**：先纸上推演 → 实测 → 调参 → 再测；记录每次改动，防止反复横跳。
4. **元游戏检查**：算最强的 3 种打法是否同一套；给"套路陷阱"留反制。

### 4.6 随机性设计

- 方差与体验：随机性强 → 刺激但易挫败；弱 → 稳定但平淡。按支柱选。
- 手段：伪随机分布（防连续坏运气）、保底（抽卡/掉落）、权重表、动态权重（冷门补偿）。

## 5. 关卡设计

- **要素**：空间（路径/视野/掩体）· 引导（视觉/音频/光照）· 节奏（强度起伏）· 奖励（探索回报）。
- **教学关（零文字教学）**：安全环境 → 引入危险（无致命）→ 组合应用；用"环境无法说谎"原则塑造玩家预期（看得到的都可达）。
- **节奏曲线**：张力-释放交替（紧绷遭遇 → 安全区/叙事点心）；Boss/高潮前必有"呼吸点"。
- **度量标准**：定义游戏内度量单位（如"跳跃=1 单位"），所有跳跃距离/平台间距用单位表达并留容错（正常跳跃可达 ×1.2 设计余量）。
- **迭代流程**：纸面布局 → 白盒可玩 → 引导测试（观察玩家迷路点）→ 美术通过 → 打磨。**每次改动后重新观察而不是重新提问**。
- **结构化工具**：门槛/路径/地标（tease 远景区）、单向门、回环捷径；开放空间用"兴趣点密度"分布节奏。

## 6. 难度、手感与可访问性

### 6.1 难度

- 难度曲线：整体渐难 + 周期性"小高潮"；给"落后/领先"动态微调的空间（慎用强制 DDA，透明或可关）。
- 为不同玩家提供选项：难度档位、辅助模式、官方"作弊"开关（代价：成就禁用等），比强制统一体验更现代。

### 6.2 手感（Game Feel）清单

| 项 | 方法 | 说明 |
| --- | --- | --- |
| 输入缓冲 | 排队 100-200ms 内的输入 | 落点跳跃/攻击不丢指令 |
| 土狼时间 | 离开平台后 80-150ms 仍可跳 | 宽容期减少"明明按了"挫败 |
| 速度曲线 | 加速/减速/空中控制参数独立 | 手感调参的三大旋钮 |
| 屏幕反馈 | 震屏、顿帧（hitstop）、缩放脉冲 | 打击感三件套，需可关闭 |
| 音效强化 | 操作音/命中音/层次音 | 音频是手感的一半（见《美术与音频手册》） |
| 粒子与轨迹 | 拖尾、命中火花、尘土 | 低成本高感知 |

### 6.3 可访问性（Accessibility）

- 基础项：按键重映射、字幕（大小/背景/说话人）、色盲模式、界面缩放、亮度/对比、无 QTE 替代、镜头晃动关闭。
- 参考：Game Accessibility Guidelines（https://gameaccessibilityguidelines.com/ ）与平台无障碍指南；主机平台有各自的无障碍标签体系，送审前对照。
- 商业价值：可访问性设计同时惠及所有玩家（尤其字幕/重映射）。

## 7. UX 与引导

- **首分钟体验（FTUE）**：前 60 秒必须发生"一次爽点 + 一次决策"；前 10 分钟教会核心循环。
- **信息层级**：HUD 只显示"此刻需要决策的信息"；可展开/可隐藏。
- **反馈三原则**：及时（同帧到 200ms 内）· 明确（改变的是什么）· 适度（不遮挡不疲劳）。
- **教程模式对比**：情境化教学（在做中学）＞ 强制弹窗；必须弹窗时一屏一概念。
- **默认值即教程**：合理默认（自动寻路开、辅助关）+ 设置项解释文案。

## 8. 叙事设计

- **结构选型**：线性（成本低、体验可控）· 分支（选择感，成本随分支数乘方增长）· 沙盒/涌现（系统产出故事）· 混合（主线线性 + 支线分支）。
- **分支成本管理**：用"汇聚点"收敛分支；重内容（动画/配音）放主干，轻内容（文本/差分）放分支；"选择性感知"（选择影响态度 NPC 台词而非全局）。
- **世界观呈现层次**：环境叙事（场景物件/布局）→ 收集物（碎片文本）→ 对话（最多，但最易被跳过）；重要的放前面。
- **对话设计**：每个角色一张"声音表"（用词/句长/禁忌）；选项设计避免"三选一都是同一结果"的假选择（要做就做真差分，不做就省掉）。
- **玩法即隐喻**：机制与主题共振（如"背包管理 = 记忆负担"），这是独立游戏最大的叙事优势。

## 9. 玩法验证与设计评审

### 9.1 测试方法

| 方法 | 时机 | 要点 |
| --- | --- | --- |
| 自测 | 全程 | 记录"卡住/想跳过的瞬间"，都是信号 |
| 内部互测 | 原型后 | 观察者闭嘴，只记录（别提示） |
| 外部试玩 | 切片后 | 目标玩家 5+ 人；看行为不看问卷 |
| 数据埋点 | 有量之后 | 通过率/时长/放弃点；原型期轻量即可 |

**三条铁律**：别问"你觉得好玩吗"（问意愿答不准）；问"你刚才想做什么/哪里最无聊"；行为观察 > 口头反馈。

### 9.2 设计评审清单（每次大改前过一遍）

- 与体验支柱对齐？核心循环更清晰还是更复杂？新增成本（学习+制作）值不值？
- 数值表已更新？对经济/平衡的连锁影响评估过？砍掉什么来买单？
- 玩家验证计划是什么？（谁、何时、怎么测）

- **系统建模**：Machinations（https://machinations.io/ ，经济/循环的可视化模拟）。
- **模板**：一页纸/GDD/试玩计划 → `templates/`（见设计文档 §9）。
- **逐类型设计要点**：`docs/genres/`（112 类型，每类 `design.md`）。
- **理论阅读**：MDA 论文、"心流"理论、Jesse Schell《游戏设计艺术》、Raph Koster《快乐之道》。完整书目见《资源大全》§3。
- **继续设计学习的路径**：拆解一款你爱的游戏（写出它的动词循环与经济图）→ 用纸面原型验证一个新机制 → 进入《制作管理手册》做第一个竖切。
