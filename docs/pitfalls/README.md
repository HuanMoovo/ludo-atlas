# Ludo Atlas · 避坑大全（Pitfalls & Anti-patterns）

> 定位：把游戏开发全流程中最常见、代价最大的坑集中成册，按"现象 → 后果 → 规避"三栏速查。
> 每坑标注**代价等级**：🔴 高危（可能毁项目/毁公司）· 🟠 中危（大量返工或错失窗口）· 🟡 低危（局部返工）。
> 来源：行业公开复盘、社区共识与公开案例；本文为经验整理，不构成法律或商业意见。使用建议：立项评审与里程碑复盘时逐表过一遍。
> 相关配套：《法务、专利与竞争手册》、《全平台上架手册》。

## 1. 立项与方向

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 第一个项目做"梦想之作"（MMO/开放世界/带联机的 RPG） | 范围远超个人能力，99% 弃坑；第一作的目标应是"完整发布" | 先做 2-3 个可发布的小项目；梦想项目拆成阶段，用前作练手 | 🔴 |
| 范围蔓延（Scope Creep）：功能只加不减 | 开发时间指数增长；永不上线 | 立项时写"不做什么"清单；每次加功能必须砍一个；用"能否在 1 分钟内说清玩法"过滤 | 🔴 |
| 忽视市场验证：做完才想"谁买" | 冷启动无愿望单积累，上线即死亡 | 立项时做竞品/受众调研（见《法务、专利与竞争手册》竞争篇）；开发中期开始公开曝光 | 🟠 |
| 平台选择拍脑袋（PC/移动/主机/小游戏混着来） | 平台决定操作方式、商业模式、审核周期、技术栈，中途换=重做一半 | 立项即锁定首发平台与第二平台；参考同类型游戏的分发数据 | 🔴 |
| 商业模式后置（先做完再想买断/内购/广告） | 免费+内购需要完全不同的数值与经济系统设计，后补=推翻重做 | 立项文档必须写明商业模式；内购/广告玩法在原型期就验证 | 🟠 |
| 追热点与风口（某类型忽然爆火就全力跟进） | 制作周期 6-24 个月，上线时风口已过；跟随者拿不到头部流量 | 问自己"这个类型我提前两年会不会做"；组合创新优于裸跟风 | 🟠 |
| 参考与抄袭的界限失控 | 美术/代码/文案的"过度参考"可能构成侵权（见《法务、专利与竞争手册》） | 参考玩法机制（合法），绝不临摹具体美术表达；保留设计过程文档 | 🔴 |
| 没有"为什么是我做"的回答 | 无差异化卖点 = 与海量同类竞争曝光位 | 用一句话回答：玩点/受众/与竞品的差异 | 🟡 |

## 2. 设计与玩法

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 先搭系统框架，最后才验证"好不好玩" | 框架再优雅，核心循环无聊就是 0 | 先做"玩具原型"（白盒/纸面）：只测核心乐趣，10 分钟内能玩到 | 🔴 |
| 过早打磨：花两周优化第一关的手感 | 玩法未定型时打磨=白费；后期玩法改动会推倒重来 | 打磨只发生在核心循环冻结后；前期用占位资源 | 🟠 |
| 数值拍脑袋、不进表格 | 平衡问题无法系统性修复；上线后玩家发现数值崩坏 | 所有数值进表（CSV/资产文件），可批量调整、可回归对比 | 🟠 |
| 内容量严重低估（"再做 20 关就完成"） | 关卡制作常是代码的 2-3 倍时间；内容是长尾成本 | 先做 1 个"标杆关卡"并计时，再乘以关卡系数；内容是剪刀差 | 🟠 |
| 不做新手引导/教程设计 | 数据上大量玩家 5 分钟内流失，无法体验核心乐趣 | 用"边做边学"的关卡设计代替文本墙；找 3 个陌生人试玩观察 | 🟠 |
| 难度曲线失控（没有难度测试） | 反馈两极：太简单=无聊，太难=差评 | 记录每关死亡/失败率；目标：多数玩家在"略吃力但能过"区间 | 🟡 |
| 过早做"深度系统"（天赋树/合成/声望） | 边际乐趣低但成本高，稀释核心循环 | 深度系统只在外围，核心循环 1 屏内完成 | 🟡 |
| 单人开发忽视"设计自嗨" | 自己觉得有趣 ≠ 玩家觉得有趣 | 每个里程碑找外部试玩；公开发布试玩版 | 🟠 |

## 3. 程序与架构

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 过早优化（还没跑起来就抠性能） | 浪费时间且优化方向错误（没测量无优化） | 先做出来 → 用 Profiler 测量 → 再优化热点 | 🟠 |
| 为"未来大团队"做过度架构 | 单人/小团队维护不了过度抽象，迭代变慢 | 按当前规模设计，预留扩展点而非预建扩展 | 🟠 |
| 硬编码与魔法数字散落各处 | 改一个数值要翻十个文件；无法数据驱动迭代 | 数值/配置外置（表格/资源），代码只读配置 | 🟠 |
| 全局单例/静态状态滥用 | 单元测试无法隔离；模块耦合；协作冲突高发 | 依赖注入或显式传参；单例仅限真正的全局设施 | 🟠 |
| 没有自动化测试和回归 | 每次改动靠手测，越到后期越不敢改 | headless 引擎 + 单元/冒烟测试进 CI（如 gdUnit4/GameCI） | 🟠 |
| 存档兼容问题：更新后老玩家坏档 | 差评第一来源类事故；修复成本极高 | 存档带版本号 + 迁移函数；上线前测"旧档→新版本"路径 | 🔴 |
| 帧率依赖逻辑（用帧数计时、物理跟帧率绑定） | 不同设备表现不一致，高刷设备行为异常 | 固定时间步物理 + delta time 逻辑；帧率无关化测试 | 🟠 |
| 单机思维 + 后加联机 | 网络同步需要从架构层重做（状态/确定性/回滚），等于重写 | 立项即定网络模型（见 §8）；不可后补 | 🔴 |
| 平台适配后置（手柄/分辨率/多语言/存档路径） | 上线前才发现全平台问题，延误发售 | 早期就接入：输入抽象层、分辨率适配、本地化字符串外置 | 🟠 |
| 引擎选择误区（只看热度，不看生态/平台/人才） | 中途换引擎=重做；冷门引擎缺教程与插件 | 选型看：目标平台支持、生态插件、社区活跃度、招聘市场 | 🔴 |
| 内存与资产加载没有预算（移动端 OOM 闪退） | 低端机崩溃率飙升，商店评分受损 | 设定内存预算表；分场景加载/卸载；低端机降级策略 | 🟠 |
| 没有日志/崩溃上报/版本号体系 | 线上问题无法定位，玩家反馈无据可查 | 接入崩溃监控（Bugly/Crashlytics/Sentry）；版本号规范 | 🟠 |
| 资源路径大小写敏感问题（Windows 开发 → Linux/安卓崩溃） | 只在上线平台爆炸，本地无法复现 | 全小写命名规范 + CI 在多平台构建验证 | 🟡 |
| 不写提交规范、仓库管理混乱（大文件进 git） | 仓库膨胀、协作冲突、回滚困难 | Git LFS 管二进制资产；提交信息规范；分支策略（见 pipelines/version-control） | 🟡 |

## 4. 美术与内容

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 美术工作量低估（"画风简单很快"） | 美术常占总工时 50%+；风格越简单越容易显得丑 | 先做资产清单与单张耗时估算；用免费素材搭骨架再替换 | 🔴 |
| 风格不统一（拼盘感） | 一眼廉价，卖相受损 | 立 Art Bible（色板/线条/光影规范）；每个新资产对照标杆图 | 🟠 |
| 规格不统一（尺寸/朝向/锚点/命名混乱） | 引擎里对齐爆炸，动画与特效返工 | 资产规格表 + 命名规范 + 导入检查清单 | 🟠 |
| 版权素材误用（字体/贴图/音乐来源不可靠） | 收到维权函甚至下架索赔（国内字体维权高发） | 只用许可链清晰的素材；记录每项来源（素材台账）；免费商用字体清单见《资源大全》 | 🔴 |
| AI 素材使用无记录、未替换占位资产 | 上线后发现未披露/占位素材残留（公开翻车案例多次） | 建立 AI 资产台账（工具/模型/修改程度）；上线前全量审查替换 | 🔴 |
| AI 生成风格漂移（一套资产越做越不统一） | 需要大量人工修补，反而更慢 | 固定风格锚点 + LoRA/参考图工作流；批量生成批量筛选 | 🟡 |
| 图集/加载策略失控（上千散图直接打包） | 加载慢、包体大、内存高 | 图集规划 + 压缩规范 + 包体预算表 | 🟡 |
| UI/UX 最后做（"功能完了再画皮"） | 交互问题暴露太晚，重做成本高 | UX 低保真先行；UI 规范与美术风格同步定义 | 🟠 |

## 5. 音频

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 响度不统一（BGM 安静、音效爆炸） | 玩家体验极差，被迫调低音量后听不到关键反馈 | 项目响度标准（如 -14 LUFS 附近统一）；播放时总线限幅 | 🟠 |
| 循环点处理不当（爆音/断点） | 细节暴露廉价感 | 所有循环音频必须做无缝循环测试；工具链固定 | 🟡 |
| 音频格式与体积失控（WAV 直塞包体） | 包体暴涨，移动端下载转化下降 | 压缩规范（ogg/mp3 策略）+ 音频包体预算 | 🟡 |
| 音乐授权范围不清（买了"使用权"却上不了 Steam） | 发行期才发现授权不覆盖商用/全球/永久 | 合同写明：商用、全球、永久、可修改、可用于续作与宣传 | 🔴 |
| 音效数量低估（一个动作需要 3-5 个变体） | 后期补音效拖进度 | 立项列音效清单（按交互事件枚举） | 🟡 |

## 6. 项目管理与团队

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 没有里程碑与验收标准（"90% 完成"陷阱） | 最后 10% 花掉 90% 的时间；进度永远乐观 | 里程碑=可玩的构建（可点可玩），不是"代码写完" | 🔴 |
| 完美主义与无限打磨 | 项目永不发布；测试时间被挤占 | 设"足够好"标准；到点即冻结；打磨列独立清单排优先级 | 🟠 |
| 常态 Crunch（长期加班） | 研究一致表明长期加班输出下降且错误率上升；人离职 | 拒绝常态化加班；用范围控制而非时间堆叠 | 🔴 |
| 任务不可见（无看板/无周会节奏） | 卡点靠感觉，协作互相阻塞 | 轻量看板（HacknPlan/Codecks/飞书）+ 每周 30 分钟同步 | 🟡 |
| 口头协议：合伙人分成、外包约定靠微信聊天 | 纠纷时无凭据，关系与项目双输 | 一切经济约定书面化（见《法务、专利与竞争手册》合同篇） | 🔴 |
| 外包管理失控（无验收标准、无中间交付） | 返工无上限，钱花了拿不到可用资产 | 分里程碑付款；每期交付物明确定义（格式/规格/源文件） | 🟠 |
| 招人/扩张太早 | 沟通成本上升，现金流断裂 | 能外包不招人；能自动化不加流程 | 🟠 |
| 单人开发倦怠（孤立、无正反馈） | 弃坑主因之一 | 加入社区/jam；公开 devlog 获取反馈；固定休息节奏 | 🟠 |
| 团队沟通事故（重要决策只在私聊，无人知晓） | 重复劳动、决策矛盾 | 决策记录（ADR）；文档集中（单一事实来源） | 🟡 |

## 7. 测试与发布

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 商店页和愿望单启动太晚 | Steam 愿望单是复利资产；太晚=首发无曝光 | 商店页在"可玩 demo"阶段就上线；持续积累愿望单 | 🔴 |
| 没有外部测试直接上线 | 首发 bug 差评雪崩；差评不可逆 | 封闭测试 → 公开 demo → 发售；建立问题反馈通道 | 🔴 |
| 审核周期低估（主机认证/苹果审核/版号） | 错过发售窗口；联动营销白做 | 提前 2-3 个月预留审核缓冲；主机认证预留 2-6 周 | 🟠 |
| 设备兼容盲区（只在开发机测试） | 低端机崩溃、分辨率错乱、外设问题 | 建立设备矩阵（低/中/高端 + 主流分辨率）；云真机测试（WeTest/Testin） | 🟠 |
| 发布日撞车（和头部大作同天发售） | 曝光被完全吞噬 | 关注发售日历（Steam 即将发售榜）；避开同类型大作 | 🟠 |
| 首发没有热修预案（改不动、不敢改） | 严重 bug 挂一周，评分暴跌 | 预演热修流程（分支/构建/上传）；准备回滚方案 | 🟠 |
| 机翻直接上线，无 LQA | 差评重灾区（尤其文本量大的类型） | LLM 翻译 + 术语表 + 人工精读抽样；母语者校对关键 UI | 🟠 |
| 忽略平台必备能力（成就/云存档/手柄/Steam Deck 评级） | 平台要求返工；错过推荐位 | 对照各平台检查清单逐项打勾（见《全平台上架手册》） | 🟡 |

## 8. 联机与网络游戏

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 网络模型选错（P2P 做竞技、锁步做实时） | 架构级重写；延迟/作弊问题无法救 | 立项定模型：状态同步 / 帧同步 / 服务器权威；参照同类型成熟方案 | 🔴 |
| 反作弊上线才想 | 上线即被外挂淹没，经济体系崩坏 | 关键逻辑服务器权威化；反作弊系统早期接入（见《资源大全》§8.4） | 🔴 |
| 服务器成本无模型（免费玩家按能付费估） | 爆量时月账单失控；限流导致体验崩坏 | 做 CCU 成本表（含峰值与 DDoS 余量）；压力测试后再开放 | 🔴 |
| 实时性预期错配（跨区延迟当本地玩） | 玩法体验目标与网络现实不符 | 设计时就谈延迟预算：回合/异步玩法对网络要求低，优先考虑 | 🟠 |
| 账号体系与存档设计草率（合服/迁移困难） | 运营期无法合服/改经济；玩家资产纠纷 | 账号与角色数据分离；服务器 ID 与角色 ID 设计预留合服路径 | 🟠 |
| 更新承诺过多（路线图吹牛） | 承诺无法兑现引发信任危机（公开案例多起） | 路线图只写"确定能做"的；用"计划+可能"分层表述 | 🟠 |
| 忽略国内网游专项合规（版号/防沉迷/实名） | 违规运营=下架/处罚；无版号不得收费 | 见《全平台上架手册》§7 网络游戏专项流程（版号、wlc.nppa.gov.cn 实名系统） | 🔴 |
| 停服与退款无预案 | 停服公告义务与玩家补偿处理不当引发舆情/诉讼风险 | 运营前写好停服预案（公告期、补偿、数据导出） | 🟠 |
| 测试期收费踩线（无版号先卖"测试包"） | 明确违规，可能被要求下架整改 | 无版号期间只做免费测试；收费必须等版号（小游戏虚拟支付同理） | 🔴 |

## 9. AI 工作流

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 未按平台要求披露 AI 内容（Steam 等） | 违反平台协议，可能下架；玩家信任危机 | 按 Steam 内容调查要求区分"预生成/运行时生成"披露；内部工具豁免也要留档（见《AI 工作流手册》§8） | 🔴 |
| 放任 AI 代理自动整夜改工程（MCP 写权限全开） | 工程被污染、场景损坏、无法回溯 | 权限分级（读/写/危险）；操作前提交；工作分支隔离 | 🟠 |
| 幻觉 API / 不懂引擎生命周期 | 生成代码"能编译不能运行"或埋性能雷 | 生成代码必须过评审清单：生命周期、性能、错误处理；小步验证 | 🟠 |
| AI 生成的资产风格漂移、修图成本超过自绘 | 产出不可用，白花时间 | 固定风格锚点与工作流模板；批量筛选合格率统计 | 🟡 |
| 大量 AI 代码无人理解（维护灾难） | 出 bug 无人能修，团队能力空心化 | 关键系统的人类可读文档；核心逻辑要求人工重写/精读 | 🟠 |
| 素材来源与许可未记录（AI 生成的输出也可能有第三方权利争议） | 维权或平台审查时无法自证 | 资产台账（工具、模型、日期、人工修改程度）；见《法务、专利与竞争手册》 | 🟠 |

## 10. 运营与社区

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 定价失误（过低不救口碑、过高无转化） | 收入直接受损；打折空间锁死 | 参考同质量同类型定价带；首发折扣 10-15% 常规 | 🟠 |
| 与玩家吵架 / 报复性回应差评 | 公关灾难，截图永流传 | 对外永远冷静、具体、感谢反馈；负面响应有专人模板 | 🔴 |
| 更新节奏断裂（承诺周更变年更） | 社区流失，口碑逆转 | 只承诺"可持续的节奏"；小更新也算更新 | 🟠 |
| 遥测与隐私不合规（收集数据无同意/无政策） | 商店下架、监管处罚（GDPR/PIPL） | 隐私政策覆盖所有采集项；最小化采集；儿童相关尤其谨慎 | 🔴 |
| 客服与退款无流程 | 纠纷积累成舆情 | 提前准备 FAQ/退款指引；按平台政策执行 | 🟡 |
| 忽视社区运营（只卖不聊） | 无自来水与 UGC 传播 | 固定阵地（Discord/QQ/贴吧选一主两辅）；开发者亲自回帖 | 🟡 |
| 内容更新方向被差评绑架（谁声音大听谁的） | 核心用户流失 | 建"意见权重"机制：数据 + 核心玩家 + 自身愿景 | 🟡 |

## 11. 法务与合规（详见《法务、专利与竞争手册》）

| 坑（现象） | 为什么致命 | 规避方法 | 等级 |
| --- | --- | --- | --- |
| 游戏名未查商标就上线宣传 | 被抢注/侵权投诉，被迫改名（沉没成本巨大） | 立项即查询中国商标网；关键市场尽早注册（9/41/42 类） | 🔴 |
| 外包未签书面著作权转让 | 法律上著作权可能仍归创作者，无法主张权利 | 合同必须含"著作权转让"书面条款与交付物清单 | 🔴 |
| 使用 GPL/AGPL 代码闭源发行 | 违反许可证=侵权；被迫开源或重构（AGPL 对服务器端也有约束） | 依赖清单（SBOM）+ 许可证扫描；引擎与库逐一核对 | 🔴 |
| 隐私政策缺失或与实际采集不符 | 应用商店拒审；监管处罚 | 用真实数据流生成隐私政策；上线前审计 | 🔴 |
| 无版号先商业化运营（含小游戏虚拟支付） | 明确违规 | 见《全平台上架手册》网游专项 | 🔴 |
| 抽卡/开箱概率未公示或不合规 | 违规处罚；多国监管（概率与保底须透明） | 概率公示页面 + 合规审查；注意各地 loot box 监管趋势 | 🔴 |
| 音乐/字体许可链条断裂（代理转授权问题） | 索赔或下架 | 只接受可核实的授权文件；保留购买凭证 | 🔴 |
