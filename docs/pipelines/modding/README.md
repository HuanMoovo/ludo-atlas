# GameDev Atlas · Mod 与 UGC 手册

> **迭代第 ㉕ 轮**。给游戏加 mod 支持与用户生成内容（UGC）的完整决策与实操：支持层级、架构原则、Steam 创意工坊与 mod.io 集成、社区运营、法律合规。
> 配套：《技术实现手册》（⑩）·《运营与增长手册》（⑬）·《法务、专利与竞争手册》（⑦）·《避坑大全》（⑥）。
> 一句话结论放在开头：mod 支持是一个需要提前一年架构决策的战略问题，不是上线后加的功能。

---

## 1. 先判断：你的游戏该不该支持 mod

值不值得做，看三个信号：

- **内容消耗速度**：玩家把内容吃完就走（短叙事），mod 救不了；玩家会反复玩、想造东西（模拟、建造、生存、沙盒、肉鸽），mod 是长尾发动机。
- **系统开放性**：系统本身就是乐趣来源（数值、组合、自动化），玩家有"我想试试别的"的冲动。
- **社区特征**：已经有玩家在问"能不能做 mod"、在拆你的数据文件，这就是信号。

参考数据（mod.io 官方宣传口径）：上线 mod.io 两年以上的游戏，平均日活能保持在峰值的一半左右；主机平台不到 2% 的游戏支持 UGC，属于差异化空间。

代价也提前说清：兼容性维护、审核人力、法律条款、部分性能与反作弊的复杂度，都会随 mod 生态一起涨。

## 2. 支持层级：从 L0 到 L3

不是只有"完整 mod 支持"和"不支持"两个选项。按投入递进的四层：

| 层级 | 做什么 | 团队投入 | 适合 |
| --- | --- | --- | --- |
| L0 数据开放 | 参数、数值、皮肤走外部数据文件（JSON/表格），允许玩家改 | 极小 | 所有游戏，顺手的事 |
| L1 官方 API/SDK | 暴露脚本接口与工具链，玩家能做玩法级修改 | 中 | 系统向游戏 |
| L2 平台化分发 | 接入创意工坊或 mod.io，订阅、版本、审核一条龙 | 中 | 有社区基础后 |
| L3 完整编辑器 | 官方关卡/玩法编辑器，玩家造内容 | 大 | 平台型长线产品 |

绝大多数团队的正确路线是 L0 现在就做，L1 随架构设计预留，L2 看社区，L3 只适合平台野心。

## 3. 架构原则：mod 支持成败在代码之前

1. **数据驱动**：把内容（物品、关卡、规则）和逻辑分离。玩家改数据不动逻辑，稳定性大半就保住了。
2. **稳定接口加版本号**：给 mod 的 API 从第一天就标版本，破坏性修改要公告和过渡期。
3. **沙盒与权限**：L1 以上的 mod 意味着执行玩家代码。脚本层选受限环境的语言（Lua 这类常见选择），文件系统与网络访问按最小权限给。
4. **冲突处理**：多个 mod 改同一数据是常态。设计加载顺序、覆盖规则、冲突提示，别让玩家靠猜。
5. **存档兼容**：带 mod 的存档要标记依赖；缺 mod 时能读、能提示，不能崩。
6. **反作弊边界**：多人游戏里，带 mod 的玩家和不带的按池分开匹配；服务端权威的规则不能被客户端 mod 改写。

## 4. Steam 创意工坊集成

Steam 平台有完整的官方方案（Steamworks 创意工坊）：

- **技术侧**：通过 ISteamUGC API 实现上传、订阅、下载；监听物品安装回调（ItemInstalled），从安装目录读数据；官方的 SpaceWar 示例涵盖最常用的调用路径。
- **内容验证**：官方建议只接受游戏客户端能加载的格式，并提供官方工具限制可改动的范围。"给玩家和你自己用同一套工具"，是最省事的审核策略。
- **版本地狱的官方解法**：创意工坊支持物品版本控制，模组可以声明自己支持的游戏版本范围；配合游戏分支（测试分支）管理，游戏更新前先让 mod 作者在测试分支上适配，更新炸 mod 的事故能大幅减少。这是高价值功能，上工坊时优先启用。
- **法律与品牌**：工坊内容需要平台侧的协议覆盖，品牌资产使用有指引文档，按官方文档走。

## 5. mod.io：跨平台 UGC 方案

主机上支持 mod 的最大障碍是平台限制，mod.io 是目前工业化程度最高的跨平台方案：

- 覆盖 PC、主机、移动、VR；提供 Unity、Unreal 插件与 C++ SDK、REST API。
- 带审核与内容管理工具（对主机合规很关键）、分析数据、可选变现与白标集成。
- 真实案例：Baldur's Gate 3 的主机与跨平台 mod 支持就是基于 mod.io 白标方案；SnowRunner 用跨平台 mod 撑长了生命周期。
- 主机 mod 的特殊纪律：所有内容先审后发，运行时行为受限，内存与体积预算比 PC 严格，方案本身考虑到了这些约束。

结论性建议：PC 优先用创意工坊（用户基数与习惯都在那）；要覆盖主机与移动，直接评估 mod.io 或用它补充。

## 6. 工具链与生态常识

- **Nexus Mods** 是 PC 端 mod 社区重镇，即使你不官方支持，玩家也可能把 mod 发在那里。与其对抗，不如把格式设计得让他们能做。
- **Unity 项目的现实**：玩家社区有成熟的注入式 mod 框架（BepInEx、MelonLoader 这类），你挡不住。聪明的做法是拥抱：给数据格式、给接口、给文档。
- **官方工具就是 mod 工具**：把内部做的关卡/数值编辑工具修一修发给社区（Steam 官方文档也是这个建议），比自己另做一套省，也更稳。
- **示例 mod 是最好的文档**：官方出 2-3 个源码级示例（一个改数值、一个加内容、一个改玩法），mod 作者的入门率会成倍上升。

## 7. 社区运营

- **创作激励**：精选推荐位、早期体验邀请、官方转发。付费分成要谨慎（见 §9），但可以给荣誉、给内测资格、给致谢。
- **兼容性公告纪律**：破坏性更新提前公告、给测试分支、给适配期。mod 作者是义务劳动，你欠他们透明度。
- **审核与治理**：恶意内容与侵权内容的处理流程要公开（下架标准、申诉通道）。主机平台的内容审核责任在发行方，人手要提前配。
- **数据看板**：订阅量、活跃 mod 数、依赖 mod 的玩家占比，这些数字决定你该给 mod 生态投多少资源。

## 8. 法律与合规要点

- **EULA 写清楚**：允许什么（非商业 mod、署名）、禁止什么（盗用素材、商业化、恶意代码）、IP 归属（mod 归作者，但运行在你的 IP 之上）。
- **付费 mod 的历史教训**：2015 年 Steam 创意工坊付费 mod 实验因社区强烈反对数日内撤回；后来有 Creation Club 等订阅式尝试。结论：付费 mod 的社区接受度稀缺且脆弱，做之前先想清楚谁付费、谁分成、谁提供支持。
- **DMCA 流程**：准备好侵权的下架响应流程，同时保护你自己的内容被别人盗用。
- **中国运营的 UGC 合规**：国内运营时，用户生成内容有法定的审核与管理责任，平台侧也有对应要求。上线前把审核机制、举报通道、处置流程建起来（相关法规要点见《法务、专利与竞争手册》⑦与《全平台上架手册》⑧）。

## 9. 案例速写

- **Minecraft**：从数据到代码全面开放的极致案例，mod 生态成为产品生命力的一部分。
- **上古卷轴 5**：单机 mod 生态的常青树，说明"工具+格式+社区"三件套的持久威力。
- **泰拉瑞亚**：把社区 mod 加载器（tModLoader）收编为官方免费 DLC，是"拥抱社区"的标杆动作。
- **星露谷物语**：单人开发者对 mod 保持开放姿态，SMAPI 生态反过来延长了产品寿命。
- **Baldur's Gate 3**：大厂用工业级 UGC 方案（mod.io）把 mod 支持做到主机，证明主机 mod 是可行的。
- **Factorio**：官方 mod 门户加严格版本机制，把"更新炸 mod"问题管理得最好的一档。

## 10. 常见坑

1. 架构不留接口，上线后想支持 mod 只能重做数据层。
2. 没有版本机制，一次更新炸掉全社区 mod，评分骤降。
3. 给了 mod 任意代码执行权限，安全事件一波带走口碑。
4. 主机想照搬 PC 的 mod 方案，忽略先审后发的平台约束。
5. 官方工具藏着掖着，社区逆向成本高，生态长不起来。
6. 更新不公告，mod 作者集体撂挑子。
7. 付费 mod 设计草率，引爆社区情绪。
8. EULA 没写清楚，IP 纠纷时无据可依。
9. 只支持一个分发渠道，主机与移动玩家被排除在外。
10. 把 UGC 审核当小事，国内合规与主机合规两头挨打。
