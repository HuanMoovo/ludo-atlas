# Ludo Atlas · 管线 · 美术资产管线

> **管线批次**（第 ㉟ 轮扩展）。定位：把美术资产从创作者的工作台稳定运到游戏里——源文件不丢、规格不走样、换台机器能重建，靠规范、自动化与冻结节点，而不是记性和口头交接。
> 配套：《美术与音频手册》（⑪）·《技术实现手册》（⑩）·《制作管理手册》（⑫）·《避坑大全》（⑥）。
> 适用：有外包、多人协作或资产量上百的团队；单人小品可以裁剪，但「源文件与导出物分离」「命名与目录规范」两条从第一天就该有。

---

## 1. 定位与适用

美术资产管线（asset pipeline）是一条运输与质检通道：资产从创作者手里出发，经过规范、制作、导出、导入，以可用的形态抵达玩家屏幕上的每一帧。它不负责「画得好不好」，那是《美术与音频手册》（⑪）的领地；它负责「运得稳不稳」：

- **不丢**：任何资产都能回答三个问题：源文件在哪、谁做的、授权是什么。
- **不错**：规格从规格表里来，不靠记忆，不靠口头传达。
- **不返工**：能自动查的绝不靠人眼看，错误在流程里最便宜的那一环拦下。

四个概念先分清，后文反复使用：

| 概念 | 例子 | 归属 |
| --- | --- | --- |
| 源文件 | 分层图工程、3D 工程、动画工程、音频工程、UI 设计稿 | 必须保管，进大文件库或专用归档 |
| 导出物 | 位图、模型交换格式、音频成品 | 可随时重建，构建时再生成 |
| 导入物 | 引擎内的资产条目与导入设置 | 与导出物一起进版本控制 |
| 导入设置 | 压缩、采样、锚点、缩放等选项 | 视作代码，必须版本化 |

什么时候值得把管线立起来：外包超过一人、资产数超过百件，或者已经吃过「找不到源文件、导入效果对不上、上线前补授权」这三种亏里任何一种的时候。规范的建立成本随资产量上涨，越早立越便宜；为三五张图搞一整套流水线，则是另一种浪费。

## 2. 工具链

工具链按流水线五段铺开，每段只留一件主力工具，链路越短越好维护：

| 环节 | 工具类型 | 常见选择 | 选型注意 |
| --- | --- | --- | --- |
| 创作 | 源工具 | 2D：Aseprite、Krita 一类；3D：Blender 一类；音频：宿主软件 | 出口格式要能脚本化，不靠手工点 |
| 版本控制 | 二进制友好方案 | 大文件扩展的版本库，或专门的资产版本工具 | 二进制要能锁文件，防两人同改一份 |
| 导出与转换 | 批处理 | 源工具导出加脚本、图集打包、音频转码与响度检测 | 导出参数写进配置，不进对话框 |
| 导入 | 引擎导入管线 | 导入预设加批量重建 | 设置文件与资产同库同行 |
| 校验 | 检查脚本 | 命名、尺寸、预算、引用完整性扫描 | 接进提交与构建，不靠自觉 |

选型三条纪律：能脚本化的环节才有资格长期当瓶颈；大文件要有专门方案，别让版本库主库被二进制撑爆；工具宁少勿多，每多一件就多一份维护与培训成本。

外部素材（购买与免费）走同一条通道，但入口单独设：先登记来源与授权，再进只读目录，任何人不直接改。许可核对的做法见《美术与音频手册》（⑪）。

## 3. 流程与规范

### 3.1 五段流水线：规范 → 制作 → 导出 → 导入 → 验证

固定五段，每段有明确出口物，上一段不通过不进入下一段：

| 阶段 | 做什么 | 出口物 | 通过标准 |
| --- | --- | --- | --- |
| 规范 | 定规格表、命名、目录、冻结节点与责任人 | 规格表、模板工程 | 制作方确认可执行 |
| 制作 | 按规格在源工具里生产，含中途自检 | 源文件、制作记录 | 对照规格表自检通过 |
| 导出 | 按导出规范批量产出中间物 | 待导入区里的导出物 | 扫描脚本零错误 |
| 导入 | 导入引擎，套用团队导入预设 | 导入物、导入设置、预览 | 引用完整，效果与样张一致 |
| 验证 | 实机检查、预算核对、评审留痕 | 验收记录、台账更新 | 评审通过，可冻结 |

回环纪律：任何一段发现规格本身有问题，改规格表再重走该段；就地为单件资产打补丁，等于给未来埋一次不一致。

### 3.2 命名与目录规范

命名是一套团队级约定，写死在仓库里，只有一份，新成员第一天读到。示例方案：类别在前、主体居中、动作与序号在后，如 `char_hero_idle_01`、`env_forest_rock_03`、`ui_icon_sword`。

- 全小写、下划线分隔、只用 ASCII 字母数字；空格、中文、大小写混排在检索与脚本里全是雷。
- 序号补零；变体后缀统一：法线加 `_n`、自发光加 `_e`、高倍图加 `@2x`。
- 禁止「final」「最新」「最终确认」这类词留在文件名里；版本交给版本库与冻结记录，不交给文件名。
- 前缀与目录同源：看到前缀就知道该进哪个目录，看到目录就推断得出前缀怎么写。

目录按「谁产生、给谁用」分四区：

| 目录 | 放什么 | 纪律 |
| --- | --- | --- |
| 源文件区 | 分层图、模型、动画、音频、UI 工程 | 走大文件方案与备份，不进运行时构建 |
| 导出区 | 从源文件产出的中间物 | 可清空重建，不作为交付物本身 |
| 资产区（引擎内） | 导入物与导入设置 | 进版本控制，按功能分类，不按作者分类 |
| 外部素材区 | 购买与免费素材 | 只读，附来源与授权登记 |

目录结构一旦开工就冻结；要调整先做一次全员同步，别让一半人用旧结构、一半人用新结构，两套并行比任何一套都贵。

### 3.3 源文件与导出物分离

一条主原则：**导出物永远可重建，源文件不可再生**。丢一张导出图是十分钟的事，丢一个源工程是整件资产报废重做。

- 什么算源文件：分层位图工程、3D 工程（含未应用的修改、材质节点与动画曲线）、音频工程、UI 设计文件、字体工程与授权文件。
- 怎么存：源文件进大文件版本库或专用归档，配离线冷备，至少两份、其中一份异地；导出物不进长期库，构建时重建，少了就重建一次。
- 外包交付的验收硬条件：源文件必须交付，格式与命名写进需求包；只交一包成品位图或模型文件的，不算交付。
- 反面对照：源文件散落于个人机器，等于把全团队的资产押在「没人离职、硬盘不坏」这个假设上。

### 3.4 格式与规格

规格表是唯一事实来源。每类资产至少覆盖下列几行，数值由项目定，一经定下就全局统一：

| 资产类 | 必须统一的规格项 | 不统一的后果 |
| --- | --- | --- |
| 2D 图 | 比例与像素密度、透明边距、描边宽度 | 混进非整数缩放，画面发糊 |
| 图集 | 页面尺寸档、留边、分组规则 | 采样毛边、边缘溢出 |
| 3D | 单位、朝向、枢轴、命名前缀 | 导入后比例不对、朝向反了 |
| 贴图 | 尺寸档、通道打包、压缩档 | 压缩伪影，返工重导 |
| 音频 | 格式、采样率、响度目标、循环点 | 音量忽大忽小、循环爆音 |
| 字体 | 授权范围、子集化、回退 | 商用授权缺失，上线前补票 |

数值与做法细则在《美术与音频手册》（⑪）里有底稿，本篇只管「统一」本身：一份规格表、一次评审确认、一条改动记录。图集分组要按功能与使用场景一次规划到位，临近打包临时往里塞图，是爆边的第一来源。

### 3.5 导入设置版本化

导入设置不是界面上的随手选项，而是资产行为的一部分：压缩档、采样方式、锚点、材质映射一改，画面与手感都会变。

- 导入设置（引擎侧的资产描述文件、导入预设、转换配置）必须与资产一起进版本控制，禁止「只存在于某人机器上」的设置。
- 团队级预设优先：每类资产收敛到一套默认值，个人差异要么被合并进预设，要么被拒绝。
- 合格线是「能复现」：清空导入物后，能按库里的导出物与设置一键重建，且效果与冻结批次一致。
- 变更走评审：改导入设置与改代码同级，谁改、为什么改、影响哪些资产，留记录；引擎升级后做一次全量重建，检查画面、体积与行为的漂移。

### 3.6 评审与冻结节点

四个节点：草稿 → 评审 → 终稿 → 冻结。每个节点的出口标准提前说好，评的是「对照规格表与风格基准」，不是个人口味。

- 评审怎么做：全检形式项（尺寸、命名、格式），抽检风格一致性；记录谁、何时、过了哪一版。
- 冻结的含义：某个里程碑之后，该批资产停止接受非缺陷修改；要改走变更单，写清影响面、重建代价与批准人。
- 冻结与排期：美术冻结通常早于代码冻结，给集成、打磨与送审留出窗口。
- 冻结后复检：构建前跑一遍全量资产体检（见第 4 节），确认「冻结批次」就是「构建批次」，两者对不上，验收作废。

## 4. 自动化与验收

分工很清楚：机器查形式，人查味道。下列检查全部脚本化，接在提交与构建之间：

| 检查项 | 触发时机 | 不通过的处理 |
| --- | --- | --- |
| 命名与目录合规 | 提交前与持续集成 | 拒绝合并 |
| 尺寸、比例、透明边距 | 导出后 | 打回导出 |
| 图集爆边与采样溢出 | 打包时 | 拒绝打包 |
| 贴图尺寸与压缩档 | 导入后 | 告警，超硬线则失败 |
| 音频响度与循环点 | 导出后 | 打回重做 |
| 引用缺失与占位资产 | 构建时 | 构建失败 |
| 面数、材质数与贴图预算 | 导入后 | 告警并登记台账 |

验收看三件事，全部可观察：

- 新资产从源文件到进游戏，全程不需要口头交接与口头解释。
- 清空导出物与导入物后，能一键重建出与冻结批次一致的资产。
- 随机抽十件资产，每一件都能当场说出源文件路径、作者与授权。

给自己看的四个指标：首次导入通过率、返工轮次、丢失件数、因资产失败的构建次数。任一指标连续上升，说明规范正在松动，先查流程，再查执行。

资产台账是兜底的保险：每件资产一条记录，含来源、作者、授权、源文件路径、冻结版本。它同时是审计与法务的底稿，外包协作时与《制作管理手册》（⑫）的验收流程共用。

## 5. 常见坑

1. **命名混乱**：靠记忆找文件，自动化无从下手，接手的人先花一周考古。
2. **只存导出物**：源文件散落在个人机器与聊天记录里，人员一变动就断供。
3. **规格不统一**：两套描边、三种像素密度、各说各话的响度，画面一看就是拼的。
4. **丢源文件**：没有归档与异地备份，一次硬盘故障报废一批资产。
5. **导入设置不在版本控制**：换台机器重新导入，效果与评审时对不上。
6. **外部素材无台账**：上线前才发现授权不明，补票来不及。
7. **冻结形同虚设**：冻结后继续改，构建批次与评审批次不一致，验收作废。
8. **图集临时拼**：分组没有规划，每加一张图爆一次边，打包一次次返工。
9. **大文件硬塞主库**：没有大文件方案，版本库膨胀到没人愿意克隆。
10. **全凭人肉检查**：规范只活在文档里，没有脚本与构建关卡背书。

## 延伸阅读

- 《美术与音频手册》（⑪）：规格、风格与生产方法的底稿，本篇是它的物流与质检层。
- 《技术实现手册》（⑩）：导入管线、资源预算与构建流程的技术侧展开。
- 《制作管理手册》（⑫）：外包、里程碑与验收流程，与第 3.6 节冻结节点直接衔接。
- 《避坑大全》（⑥）：美术与协作章节的实例，可与第 5 节对照阅读。
