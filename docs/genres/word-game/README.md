# Ludo Atlas · 类型手册 · 文字游戏（Word Game）

> **类型手册 P2 批次**（第 ㊳ 轮扩展）。定位：把「语言本身」做成第一材料的类型。玩家在格子里拼、在链上接、在线索里填，用词库与判定规则换来一次次「我想到了」；本页覆盖词库工程、每日谜题、提示与难度曲线、无剧透成绩分享与多语言词库。
> 配套：《游戏设计手册》（⑨，核心循环与反馈）·《技术实现手册》（⑩，词库管线与判定实现）·《运营与增长手册》（⑬，每日节奏与留存）·《案例研究集》（⑳，每日谜题产品拆解）。
> 本文不放外链；标杆只列大众熟知的作品与传统玩法，词库规模等数字为常见量级，落到项目里以实测为准。

## 1. 定位与核心循环

一句话定位：文字游戏是**以字与词为第一材料**的类型。玩家用拼写、选字、接龙、填格与语言规则打交道，乐趣来自「我想到了那个词」；画面与叙事都是外壳，词库与判定才是本体。

核心循环用动词环写：`看题面（格子／线索／链头） → 检索与联想 → 输入候选 → 判定与反馈 → 排除或确认 → 再输入一次`

这个环以秒到分钟计：一次作答十几秒，一局几分钟到十几分钟，每日模式再把它拉成一天一次的仪式。它成立的前提只有两条：词库要干净（§3.1），每次输入都能排除（反馈必须缩小答案范围，而不是只回一个「错」，§3.3）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 逻辑解谜 | 逻辑解谜的规则与语言无关；文字游戏的规则长在语言里，答案要从词库中取出（§3.1） |
| 问答测验 | 问答考「知不知道一条知识」，答案躺在题库里；文字游戏要在语言材料里拼、猜、接、填，考的是构造与检索 |
| 文字冒险 | 文字冒险里文本是叙事介质，输入推动剧情；文字游戏里文本是玩法材料，输入只兑换判定与分数 |
| 网格逻辑（数独类） | 同属填格推理，材料换成数字或图案；文字游戏把材料换成字与词，难度同时来自语言与推理 |

一个自检问题：把材料换成无意义的符号再玩，游戏还成立吗？答案若为「不成立」，你做的就是文字游戏。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **想通的瞬间**：输入被判定正确的一刻是主爽点。验收的观察点是玩家说「我就知道是这个」，而不是「蒙的」。
2. **公平可解释**：每次被拒都有理由，答案都在常用范围内；输只能输在想不出，不能输在词库刁难。
3. **仪式与炫耀**：固定时刻、统一题面、一天一次；连击与成绩卡把稀缺感变成可炫耀的进度，分享是设计的一部分（§3.2、§3.4）。
4. **零门槛**：认得字就能上手，规则一句话讲完，输入方式不构成门槛。

反面感受（出现任意一条都是红灯）：被刁难（答案生僻或有歧义）、被耍（判定前后不一）、等不起（一天只有一题干等）、被剧透（开玩之前答案已经泄露）。

标杆作品（均为大众熟知的作品与传统玩法，建议亲手玩过再拆）：

| 作品或形态 | 可学的点 |
| --- | --- |
| Wordle | 每日一题、无剧透成绩分享、三色反馈的信息设计、极简规则 |
| 填字游戏（Crossword） | 线索写作的措辞刻度、语言与知识的双重检索、每日仪式的原型 |
| 拼字游戏（Scrabble） | 字块分布与分值设计、从词到局面的策略空间、词库争议的仲裁传统 |
| 成语接龙 | 中文口头的链式玩法：尾字约束、成语数据、可群玩的社交性 |
| 灯谜与字谜 | 中文特有的字形字义玩法：谜面措辞的分寸、揭晓的仪式感 |
| 看图猜成语类手机玩法 | 图片给语义线索、成语作答，适配碎片时间的移动端形态 |

## 3. 设计要点

### 3.1 词库与语言数据：中文的特殊账

词库是本体。先把三层分开，再谈规模：

| 层 | 内容 | 口径 |
| --- | --- | --- |
| 答案池 | 常用、无歧义、大众都认识的词 | 数千条量级，宁可小而干净 |
| 猜测池 | 可被判定为合法的输入 | 答案池的数倍，接受非常用词 |
| 屏蔽表 | 敏感词、歧视语、品牌与人名 | 单独维护，定期更新 |

- 分词：中文没有空格，词的边界要人为定义，「电脑」算一个词还是两个词，直接决定它能不能进答案池；答案池必须是人工校订的词表，不能拿原始语料机械切分凑数。
- 拼音：同音字极多，重码率远高于英文。做拼音猜词玩法时，多音字与声调要提前定规则；做汉字输入玩法时，字形相近字与输入法候选是新的坑。
- 成语：四字为主但不全是；误写、异形写法与简繁映射要单列；成语的典故与褒贬色彩决定它适不适合当答案。
- 字集与清洗：用《通用规范汉字表》一类权威字表圈定范围（全表 8105 字，一级字表 3500 个为常用字），生僻字不进答案池；去重、异形词归一、屏蔽过滤与词频分级写成可重跑的脚本，每条词条带来源与级别字段，分级只认词频数据不认作者偏好，手工维护的五千条词表撑不过两个版本。

### 3.2 每日谜题模式：为传播服务

每日模式的目标不是「限制」，是造一件所有人同时经历的事：同一时刻的所有玩家面对同一个答案，一天一次，固定时刻更新。

- 机会次数常见在 6 次上下：少到让每次输入有重量，多到让推理能够收敛；改次数要同步调词长与词频，不要只拧这一个旋钮。
- 统一题面与更新时刻：讨论与分享需要共同坐标，题面不同步等于把社交价值扔掉；以本地零点或全球统一点为界，选定后写进规范不再改。
- 连击与宽容：连续天数是留存发动机，断签规则要给宽恕（保留历史最好成绩）；每日模式之外留练习模式或往期回顾，但练习用独立词池、不上连击，避免稀释稀缺感。
- 排期与剧透纪律：一年的题一次排完并冻结，节日彩蛋提前标注；官方渠道在换日之前不发答案，产品内若有聊天与评论，当日答案要进屏蔽词。

### 3.3 提示与难度曲线

难度旋钮只有四个，全部可控：

| 旋钮 | 低难度方向 | 高难度方向 |
| --- | --- | --- |
| 词长与形态 | 两字词、常见四字成语 | 长词、语义相近的干扰答案 |
| 词频 | 高频常用 | 中频，仍属「认识」范围 |
| 线索 | 直接释义 | 字形拆解、谐音、灯谜式措辞 |
| 反馈 | 开场即给足约束 | 要求从零收敛 |

- 反馈即提示：每次判定要给出可用的排除信息，三态结果一眼可辨；颜色加符号双通道显示，不靠色觉。
- 曲线纪律：第一天的题必须简单，第一印象决定留存；关卡制按「词频分级加线索类型」排关，前若干关只给直接线索，之后逐步换更费脑的措辞；生僻词永远只作彩蛋。
- 卡住出口：每日模式常只留「认输看答案」一个出口；关卡制按级别提示，从范围、到结构（首字或拼音首字母）、到直接揭晓，用过的提示要有记录，且与无提示成绩分开展示；提示文案不作评判，居高临下的语气是把玩家往外推。

### 3.4 分享机制：无剧透的成绩卡

成绩分享是设计的一部分，不是发布日再补的功能。它的职责：让玩过的人炫耀，让没玩的人好奇，同时不毁掉任何人的当日体验。

一份合格的成绩卡：

```text
第 128 题 · 4/6 · 连击 12
●○○·○
·●●○○
●○●●○
●●●●●
```

图例（页内说明）：● 对位，○ 错位，· 不存在；每行对应一次猜测，卡片本身不含任何词条字符。

- 第一红线：卡里不出现答案与猜测用字，色块矩阵只传递过程形态，好成绩是形状好看，不是内容泄漏。
- 一行文本、纯文本复制，任何聊天软件里都能贴；由本地对局记录生成，不依赖网络；日期或题号加次数与连击，同日玩家能对暗号。
- 分享率是设计出来的：复制按钮放在结算动线上，卡片随时可再生成；格式一旦发布就冻结，改版会让老玩家的历史卡对不上。

### 3.5 本地化与多语言词库

多语言不是翻译，是每个语言一份独立的「语言包」，四件事一套都少不得：

| 模块 | 每语言要做的 |
| --- | --- |
| 词库 | 答案池与猜测池各自清洗、分级、屏蔽 |
| 判定 | 字符集规则、大小写与变音符号、重复字符处理 |
| 输入 | 键盘布局、输入法与候选行为、触屏适配 |
| 内容 | 谜题生成、线索文案、分享卡格式 |

- 中文的简繁映射、多音字、成语数据不适用于英文版，英文版的字母分布与词长结构也不适用于中文版；词库是语言资产，只能由母语者审核，机器翻译会把「不存在的词」带进答案池。机制可以共享，资产不能移植。
- 难度对齐与排产：不同语言的词长与字符集不同，要用各自语言的词频数据重新分级；先做完一门语言的完整体验再做第二门，同时铺五门语言的结果通常是五门都不干净。

## 4. 技术要点

工程门槛低，难点集中在数据与判定；网页、移动与桌面都能承载，以下与引擎无关。

**词库管线**

- 词库文件进版本控制，字段第一天冻结（词条、拼音、词频级、长度、标签、来源、状态）；改词走脚本，手工改库做不长；词库发布与游戏发布分开节奏，改词不动代码。
- 校验器是第一个要写的工具：字段完整、答案全在同一词池、无重复、屏蔽表生效、分级分布合理。

**判定**

- 判定规则写成显式规格与测试用例。最常错的是重复字符：先逐位判对位，再按剩余出现次数判错位（两遍扫描），必须覆盖「两个相同字只有一个命中」类用例。
- 中文输入要处理输入法组合事件：候选未上屏时不抢键，上屏后统一校验；自定义键盘与系统输入法两种方案分别测。
- 答案的接受范围写进判定表：别名、繁简、常见误写认不认，逐条决定并留日志，不写死在代码分支里。

**每日题与时间**

- 日期到题号的映射要确定性：题号加词表索引生成种子，同一日期全球同一题；排期表随版本发布并冻结。
- 答案下发是权衡题：随包的词表一定会被拆包，常见做法是混淆或加密后再用、或当日由服务器下发；完全防不住，目标是降低挖掘收益。重置时间与统计口径写死：以设备本地零点或服务器时间为准，连续天数先存本地，跨设备同步再上账号。

**分享卡与埋点**

- 分享卡由本地记录生成，配一条自动化检查：生成文本不含当日答案的任一字符。埋点看五个数：开局率、完成率、认输率、分享率、猜测次数分布，其中次数分布是难度校准的主数据，直接决定词池该往哪个频段调。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 原型 | 数百词，一种模式 | 1 到 2 周 | 验证循环与判定，词库手挑 |
| 小型完整作品 | 数千词，两到四种模式 | 1 到 3 个月 | 词库清洗占大头 |
| 每日运营型 | 数千题排期加维护产线 | 持续投入 | 排期与词库是月费 |

换算口径：

- 一个语言的干净答案池常见数千条；清洗、分级与屏蔽清单常见一到两周；一年排期用脚本抽取加人工复核，常见数天量级，之后每周留固定维护窗口。
- 模式、提示与分享卡都是轻工作量，但词库字段要预留（来源、级别、状态）；每新增一门语言约等于半个新项目，词库与输入适配是主要成本（§3.5）。
- 范围纪律：先做透一门语言与一个模式。这个类型的死法不是做不完，是词库没洗干净就铺模式。

## 6. 第一个原型怎么起步

目标：一到两周，回答一个问题：这个循环烦不烦。不碰美术、账号与服务器。

1. **第 1 到 2 天：一份干净的小词库。** 手挑 200 到 500 条常用词，逐条标记答案池与猜测池；不写清洗管线，人工先过一遍。
2. **第 3 到 5 天：判定与反馈。** 汉字输入一种方案，三态反馈给出排除信息；重复字符规则写成测试用例。丑是应该的。
3. **第 6 到 9 天：每日骨架。** 题号等于日期，一天一题，6 次机会；本地记录连击与次数分布；加一张纯文本分享卡。
4. **第 10 到 14 天：盲测两轮。** 找 5 个人连玩三天，记录第二天的回访率、平均用了几次、有没有人主动晒卡；第二轮只修词库与判定。

成功标准（全部可观察）：

- 五名测试者中至少三人第二天主动回来；每日模式的引擎是回访，不是单次通关。
- 全程没出现「这词根本不算词」的争议；出现过的争议记录在案并进入清洗清单。
- 至少一人主动分享成绩卡且卡片不含答案字符；失败者能用「是我没想到」而不是「这游戏瞎判」解释结果。

## 7. 常见坑

1. **答案池不干净**：生僻词、异形词、敏感词与昵称混进公共题面，翻车一次损失一批玩家（§3.1）。
2. **判定规则没写清**：重复字符、别名、繁简与误写的处理前后不一，玩家记住的是「按了不算」的委屈（§4）。
3. **泄底与泄漏**：分享卡带上猜测用字，或客户端明文存放全年答案，被拆包后当日剧透只是时间问题（§3.4、§4）。
4. **连击与干等**：断签即清零且无补救，把仪式感做成罪感；每日模式之外没有可玩内容，玩家当天玩完即无事可做（§3.2）。
5. **难度靠生僻**：拿专业名词、方言与生僻字当难度旋钮，是刁难不是难（§3.3）。
6. **提示两难失守**：要么没有出口让卡住的人流失，要么一键给答案把挑战清零（§3.3）。
7. **本地化只做翻译**：机制直搬，字符集、词长与输入方式全不匹配；同时铺多门语言，每一门都不干净（§3.5）。
8. **直接搬别家的词库与排期**：来源与授权都交代不清，出事时没有任何缓冲（§3.1）。
9. **中途改题**：上线后修改当天答案，同一题出现两个版本（§3.2）。
