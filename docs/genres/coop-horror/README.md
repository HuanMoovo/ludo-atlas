# Ludo Atlas · 类型手册 · 联机恐怖（Co-op Horror）

> **类型手册 P3 批次**（第 ㊶ 轮扩展）。定位：把「和朋友一起被吓」做成核心体验的多人类型。恐惧在人群里换了运行规则：会被分享、被传染、被放大，也会被扎堆与闲聊稀释；设计者的一半工作，是让恐惧的供给跑赢队友带来的安全感。
> 配套：《游戏设计手册》（⑨，核心循环与节奏）·《技术实现手册》（⑩，网络基础与性能）·《联机与后端深入手册》（㉖，同步、语音与后端全流程）·《运营与增长手册》（⑬，更新节奏与社区运营）。
> 本文不放外链；标杆只用大众熟知的作品，数字为常见量级，按自己项目的实测校准。恐惧的通用机制（氛围、声音、追逐）见《恐怖》页，本页只写「人一多，恐惧变了什么」的那部分。

## 1. 定位与核心循环

一句话定位：联机恐怖是**把「一起被吓」做成产品**的类型。它卖的不是一个人的恐惧，是「几个人同时尖叫、同时大笑、活着回来还要复盘」的一整套现场；怪物只是生产这场现场的机器。

核心循环用动词环写：

`接单进图 → 分头调查或搜刮 → 取证与加码风险 → 决定撤离 → 带出结算 → 换更大的赌注`

这个环以 15-40 分钟一局计，成立的前提有三条：目标不是击杀威胁，而是在它眼皮底下完成一件事（§3.2）；撤离比到达更紧张（§3.2）；死亡有价，重到不敢浪、轻到敢再来（§3.4）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 单机恐怖 | 单机是一个人被编排惊吓；联机是几个人互相吓、互相救，队友本身就是最大变量 |
| 合作闯关 | 合作闯关的默认假设是「能做成」；联机恐怖默认做不干净，撤退常是正解 |
| 非对称对抗 | 非对称是玩家对玩家的追猎，一方演怪物；联机恐怖全员同阵营，威胁由系统扮演 |
| 生存建造 | 生存建造的成长最终消除威胁；联机恐怖要求威胁在成长后依然成立 |
| 撤离射击 | 搜打撤的对手是别的玩家；联机恐怖的对手是系统与自己的胆量，事故多来自失误与运气 |

与单机《恐怖》（P2 批次）的边界一句：那页的恐惧由编排一对一投喂，本页的恐惧由队伍现场生产——谁掉队、谁慌了、救不救，都是新增的恐惧源。

一个自检问题：静音全部语音再玩一遍，威胁本身还站得住吗？站不住，说明你卖的是「朋友」而不是恐怖；两种生意都成立，但要知道自己在做哪一种。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **共同的尖叫**：恐惧被分享出去才成为记忆与谈资；好局的标准是结束后有人忍不住复盘「刚才那下」。
2. **带得出去才算数**：赢法是完成目标并活着回来，不是清空地图；火力再足也要有不敢碰的东西。
3. **彼此的需要**：每个玩家都有一件别人替不了的事（扛相机、管电闸、救人），依赖是恐惧的放大器。
4. **叫与笑的同频**：被吓到大叫与笑到停不下来是同一根神经的两端；这个类型不排斥喜剧，但喜剧必须由恐惧垫底。
5. **幸存者叙事**：谁引的怪、谁忘了关门、谁差点没出来，本身就是故事；结算要把一局讲成一个事故报告。

标杆作品（建议组一个约 4 人的小队各开几局再拆；这类游戏的体验半靠队伍化学反应，看录像学不到）：

| 作品 | 可学的点 |
| --- | --- |
| 恐鬼症 | 调查-证据-撤离的标准骨架；证据工具即分工；卡车充当安全屋与商店；恐惧靠「等」不靠跳吓 |
| 致命公司 | 配额经济与死亡掉落的心理账；废弃设施的压迫感；四人混乱里叫与笑同频的化学反应 |
| 求生之路 2 | 四人合作的完整词汇：导演系统调节节奏、安全屋结构、倒地救援、特感与配合 |
| 内容警告 | 拍摄-上传-结算的极简循环；把「拍得越险、播放越高」折成收益；小体量的高重玩性 |
| 逃生试炼 | 把血腥追逐压进可重复的试验任务：任务制与长期养成，让单次逃脱变成可反复的局 |

## 3. 设计要点

### 3.1 恐惧在人群里的力学：谁在放大，谁在稀释

多人不是「单人恐怖乘四」。恐惧在人群里同时被两股力量拉扯：

| 变量 | 放大恐惧 | 稀释恐惧 |
| --- | --- | --- |
| 站位与分工 | 任务强制分头；孤立段落；会合本身成为事件 | 四人贴行，整队变成移动安全区 |
| 语音 | 近场距离与死亡静音；队友的呼吸与沉默都是信息 | 全程闲聊，恐怖片三分钟变相声 |
| 死亡代价 | 掉落与回收、配额损失把压力传染给全队 | 免费复活，紧张感清零 |
| 目标结构 | 撤离比到达难；时限与配额制造取舍 | 目标只是杀光，做完即走 |
| 信息 | 证据与异象只有部分人看得到，转述会走样 | 攻略一背，鬼变成流程图 |

三条设计纪律：

- **分头是恐惧的生产线**：编排出「一个人拉闸、一个人守门」这类必须分开的时刻；两个人一起做同一件事，恐惧就被平摊。分头要给时限与会合点，否则走散会变成无聊。
- **语音要机制化**：给「谁在什么时候能被谁听到」定规则（近场衰减、隔墙、死亡频道），让说话带上风险与收益；第三方语音永远存在，内置语音要有机制价值才有人用。
- **减员是压力曲线**：人数下降要立刻改变处境（更静、更慢、更怕），而不是只剩「重开吧」；被抓走、倒地、掉队都要留下可行动的残局（§3.4）。

### 3.2 核心循环：调查、证据与撤离

三种常见的局内骨架，先选结构再谈皮：

| 结构 | 目标 | 对标 | 气质 |
| --- | --- | --- | --- |
| 调查取证 | 收集固定数量的证据，辨认威胁 | 恐鬼症 | 慢热、重等待 |
| 搜刮配额 | 收集有价值物并满足配额，带出结算 | 致命公司 | 贪心驱动、风险自选 |
| 任务清单 | 完成数个任务目标后撤离 | 逃生试炼 | 关卡化、重配合 |

共同纪律：

- **撤离是第二高潮**：回程要留变数（电量将尽、威胁升级、背货拖慢速度），出门前给一次「要不要再拿一件」的选择；没有返程压力的撤离等于结算按钮。
- **带得出去才算数**：局内收益接进局外进度（升级装备、解锁工具），死亡损失有下限；至少让「这局学到了什么」落地，否则失败只剩罚站。
- **单局 15-40 分钟**：超过这个量级，恐惧变成体力活；一晚连打 3-6 局是常见场景，内容必须能随机复排（§3.6）。
- 走调查线时，证据要能被转述（语音里讲得清）、分散在多个位置（逼分头）、允许误判（证据不全时就得下判断，张力才成立）。

### 3.3 分工、语音与信息

分工沿用合作类型的互补三层（能力、信息、时机），再加本类型特有的一层：**恐惧任务也要分工**。胆大的探路与放诱饵，心细的管证据与时间，胆小的守后方接应；每个人的怕法不同，恐惧的分配就不该平均。

- 工具即角色：每件装备对应一个动词与一段责任（照明的管视野、拍摄的管收益、仪器的管判断），工具互相需要，单人扛不齐全套。
- 信息分两层：共享层（任务进度、队友位置与状态）不占喊话带宽；私有层（手里的证据、看到的异象）必须值得喊出来；非语音兜底要做全（标记与快捷短语，借《合作闯关》的纪律）。

### 3.4 减员、救援与死亡的去处

- 减员的强度是双向的：人少更怕（火力与效率下降），但也更静、更专注；好的减员设计让剩下的人各有活路。
- 死亡后的去处比死亡本身更重要：留在局里（幽灵、监控、电台）比踢回大厅好，看得见、帮不上，参与感与压迫感都在；这个选择决定整个游戏的情绪底色。
- 救援必须有代价（放弃手里的活、冒风险、烧资源），否则救援变成免费续命；全灭结算做成一次可讲述的事故（复盘死因、保留部分产出），而不是断头台。

### 3.5 节奏与安全区

- 张弛沿用《恐怖》页的锯齿曲线，联机版多出一拍：出发房间（卡车、基地、大厅）负责登记、整理与社交，出发后压力单调上升、回程兑现；安全屋的信任边界更严，绝对安全只留给出发房间，局内不设或只设极短的安全点，否则人多时安全区会变成聊天室，压力泄空。
- 传播要给设计让路：直播与视频是这个类型的主要获客渠道，事故要可理解、高光要可剪辑，动线要让观众看得懂「他们在怕什么」。

### 3.6 内容单位与更新节奏

内容按四件套管理：**地图、威胁、道具、规则**（挑战与难度档）。

- 一张图是一个舞台：布局、资产、声音、交互点、平衡点位各算一笔；同场景靠光照、道具与声音改组成多种状态，「改妆」管线优先投资（借《恐怖》页的复用纪律）。
- 一个威胁是一套行为原型（巡逻、猎杀、感知、欺骗、环境）加皮肤与参数；做可复用的原型，不做一次性怪物。
- 玩家吃得快：一晚 3-6 局，一周吃完初见内容。更新节奏按自己的产能定（《运营与增长手册》（⑬））：以「图加威胁加活动」为一个内容包，穿插周挑战与难度开关，用重排与新增威胁续命；承诺产能达不到的频率，是这类游戏最常见的死因。
- 老玩家必然脱敏：对抗方式只有轮换与新增，把它写进更新计划，而不是假装它不会发生。

## 4. 技术要点

工程分两块：网络与语音。玩法层的联机纪律可参考《合作闯关》第 4 节；同步选型与后端全流程见《联机与后端深入手册》（㉖）。

**网络与同步**

- 规模事实：常见房间 2-4 人，选型比大逃杀宽松得多。起步按主机权威加房间码（成本接近零，好友局体验最好），公开匹配与专用服务器后置，再照（㉖ §1）的选型表与（㉖ §8）的成本账评估。
- 最小同步集合：位置与朝向、动作状态、手持物、门与开关、可拾取物、威胁的位置与状态机（权威端跑）、随机种子。能不同步的一律不同步。
- 威胁 AI 跑在权威端，客户端只做表现平滑；追逐与躲藏先判定、再演出，宁可接受一点延迟，也不要出现「看着躲进去了却被判死」。
- 断线与加入按高频路径设计：断线后角色别立刻消失（挂起或简化 AI），重连还原背包、任务进度与倒计时；中途加入的公平规则先定。
- 安全与治理：私密房间、踢人、举报先做（队友恶意破坏比外挂更常见）；公开匹配再补信誉与封禁体系（㉖ §7）。

**语音**

- 内置语音要有机制价值：近场衰减、隔墙与遮挡、死亡频道与存活频道隔离、谁在说话的可视化。
- 语音中继用现成 VoIP 服务（Vivox、Photon Voice 或引擎内置方案一类）或自建，重点测回声消除、串音与移动网络抖动；通道切换不能硬切。
- 把语音当玩法资源：说话引怪、隔门听不清、死人给不了活人情报，让「安静」成为主动策略；非语音玩家走标记与快捷短语的兜底通道，报点与求救必须能全部完成。

**调试与测试**

- 第一版内置网络模拟开关（延迟、丢包、抖动）；跨区双人局是常规测试项。
- 多人工具：本地多开客户端、一键开局与跳段、任意触发威胁事件；对局记录与回放从原型期就存，供复盘、平衡取样与举报取证三用。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 原型 | 1 张图、1 个威胁、一条完整循环 | 2-4 周 | 联机加语音已跑通，其余全白盒 |
| 小型完整作品 | 2-4 张图、3-5 个威胁、基础道具池 | 3-8 个月 | 局外升级与匹配从简 |
| 常见独立发行体量 | 4-8 张图、6-10 个威胁、活动与挑战 | 1-3 年 | 更新能力决定生命周期 |
| 长线运营体量 | 10 张图以上，威胁与模式持续追加 | 多年 | 内容管线与社区运营是主体 |

- 单图成本：布局与动线、资产（含「改妆」多态）、声音、交互点、平衡点位、联机测试；白盒快、氛围细，放大比例常见三到五倍。
- 单威胁成本：行为原型加动画骨架（复用）、音效（最划算的投入）、反制设计（玩家要知道怎么办，或至少知道怎么跑）。
- 联机测试成本高于同体量单人项目：改动按人数与搭档组合过一遍，真人组队的组织成本按 1.5 到 2 倍预留。
- 复用杠杆在随机化：布局、威胁池、物品与目标位置决定重玩价值；一张好图的复用率比多做一张平庸的图值钱。

## 6. 第一个原型怎么起步

目标：2-4 周做出「一张白盒小图、一个威胁、一条完整循环、2 人联机带语音」，验证三件事：循环跑不跑得通、威胁压不压得住、两个人玩比一个人玩好在哪。不碰正式美术与局外成长。

| 里程碑 | 做什么 | 验收（看行为，不看问卷） | 参考工期 |
| --- | --- | --- | --- |
| M1 循环骨架 | 白盒图里跑通「进图、找物、带出、撤离」 | 一个人盲测也不无聊，有取舍 | 3-5 天 |
| M2 一个威胁 | 巡逻与感知、一次追逐、一个躲点 | 被追时能说清规则；卡死为零 | 4-6 天 |
| M3 联机与语音 | 房主开房、好友加入、近场语音 | 跨网连打 30 分钟不掉链子 | 5-7 天 |
| M4 恐惧检查 | 最低配置的灯光与声音 | 关语音独行会紧张；开语音会尖叫也会笑 | 3-5 天 |
| M5 小队测试 | 约 4 人的队伍连打三局 | 结束后主动要求「再来一局」 | 3-5 天 |

三条规矩：

1. 先验证「多人让这件事更好」，再扩图；单机都成立的恐怖，别靠联机拯救。
2. 语音尽早真做：临时方案会漏掉近场设计，给出错误的测试结论。
3. 每轮测试只记三样：谁在什么时候喊了什么、哪里笑、哪里静；拿掉全部美术，威胁的规则与压力仍在才算过。

成功标准（全部可观察）：测试小队两局内出现自然喊话（报点、求救、开玩笑）；结束后能复述「谁干了什么、为什么死」，讨论的是「下次怎么配合」。

## 7. 常见坑

1. **扎堆即无敌**：四人贴行走，威胁失压；分头段落与孤立处境是必修课（§3.1）。
2. **闲聊吃掉恐惧**：语音三分钟变相声；机制要让谈话既有价值又有风险（§3.1）。
3. **死亡免费**：没有代价的死亡让紧张感清零；代价要留「回收得回来一半」的余地（§3.4）。
4. **撤离没有戏**：目标点走两步就到门口；返程要留变数与一次取舍（§3.2）。
5. **威胁只咬一个人或卡墙**：AI 卡死比追不上更伤沉浸；目标选择要给可解释的规则。
6. **被攻略吃穿**：威胁与诡计不轮换，老玩家三天看穿底牌；靠新图、新怪与难度开关续命（§3.6）。
7. **把随机匹配当主路径**：陌生人局素质不可控；好友房与房间码是主场景，踢人与私密房间先做。
8. **强制语音**：没有标记与快捷短语兜底，等于把非语音玩家挡在门外。
9. **服务器成本拍脑袋**：先跑通主机权威，再按（㉖ §8）算专用服务器的账；四人间不等于零成本。
10. **恐怖只是包装**：威胁换成贴纸、流程照跑，说明目标结构与恐惧脱节；自检题在 §1。

- 《类型手册 · 合作闯关》（P2 批次）：互补、救援与沟通设计的通用方法，第 3、4 节多处引用。
- 《联机与后端深入手册》（㉖）：同步选型（§1、§2）、服务分层（§3）、匹配（§4）、反作弊（§7）、成本与运维（§8）；第 4 节的完整展开。
- 《运营与增长手册》（⑬）：发售节奏、活动与社区运营的账，第 3.6 节的配套。
- 《游戏设计手册》（⑨）：核心循环与数值表方法，第 1、3 节的底稿。
- 《避坑大全》（⑥）：联机与内容生产类坑位，与第 7 节对照。
- 作业：约 3 个朋友打一晚《恐鬼症》或《致命公司》，记录两个时刻——全场音量最高的一分钟与所有人突然安静的一分钟，分别发生在什么机制下；再用白盒做一张 10 分钟的小图，让小队连跑三遍，看每一遍大家怕的东西有什么变化。

联机恐怖最终只考验两件事：威胁给不给得起持续的压力，队伍会不会自己长出故事。两件都成立，朋友既是这个类型最好的恐惧源，也是最好的安全网。
