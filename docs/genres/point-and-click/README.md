# Ludo Atlas · 类型手册 · 点击式冒险（Point-and-Click Adventure）

> **类型手册 P1 批次**（第 ㉞ 轮扩展）。定位：在手工场景里「看、拿、用、说」的叙事冒险。谜题与故事互为骨肉，本页覆盖两条腿的咬合结构，以及由它决定的美术、对白与本地化账目。
> 配套：《游戏设计手册》（⑨，叙事结构与核心循环）·《美术与音频手册》（⑪，场景绘制与动画规格）·《关卡设计手册》（㉑，引导与空间动线）·《独立开发生存手册》（⑱，范围与排期）。
> 本文不放外链。标杆只列大众熟知的作品；文中数字为常见量级，按自己项目的实测校准。

## 1. 定位与核心循环

一句话定位：点击式冒险是**把叙事切成一连串可操作谜题**的类型。故事负责让玩家「想做」，谜题负责让玩家「动手」；只剩故事，它滑向视觉小说；只剩谜题，它滑向密室逃脱。

核心循环用动词环写：

`观察场景 → 拾取物品、记下线索 → 与 NPC 对话 → 组合或使用 → 破解谜题 → 剧情推进 → 走进新场景`

节拍器是场景：一个场景通常承载一个目标、一到两个障碍与一条新线索；解开之后，故事给出回报，再放出下一个钩子。环唯一会停转的状态是玩家被卡住，所以防卡死优先于谜题的精妙程度（§3.3）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 视觉小说 | 玩家在文本里做选择；点击式冒险在空间里做操作，推进权握在谜题手里 |
| 逻辑解谜 | 谜题是抽象规则；点击式冒险的谜题长在世界里，线索来自物品、对白与场景 |
| 密室逃脱 | 单空间、机关密集、剧情多为包装；点击式冒险跨场景、有 NPC 与人物弧线，剧情是真身 |
| 文字冒险 | 文本输入驱动，没有可视场景；点击式冒险把同样的探索做成可点击的画面 |

一个自检问题：把谜题拿掉，故事还让人想看吗？把故事拿掉，谜题还让人想解吗？两个答案都成立，才是点击式冒险。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **点击的回报**：点向任何东西都有像样的回应，世界处处有手感。这是最基础也最贵的一条，文案量的大头在这里。
2. **顿悟的瞬间**：线索早已摆在眼前，玩家自己把它们接上线的那声「啊哈」。
3. **故事的牵引**：每解开一个谜题吃到一段剧情，让玩家带着「然后呢」关机又开机。
4. **角色的口吻**：幽默、性格与世界观从对白里长出来，这是它和逻辑解谜最大的气质差异。
5. **卡不死的安全感**：不会走进死局、有提示可求、随时能存，玩家才敢大胆乱试。

标杆作品（大众熟知名单，建议亲手通关再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 猴岛小英雄 1/2 | 幽默对白、谜题与剧情的咬合、「不设死局、玩家不会死」的设计哲学 |
| 断剑 1 | 悬疑叙事的组织、跨场景线索链、对话树的经典做法 |
| 机械迷城 | 无文字叙事、手绘美术、内置提示书，分级提示的教科书 |
| 触手也疯狂 | 三主角、三条时间线并行解谜，LucasArts 后期界面的成熟形态 |
| 冥界狂想曲 | 成人题材与美术方向，也记录了 3D 化与操作方式换代的一课 |
| 锈湖系列 | 短篇节奏、系列联动、氛围叙事与移动端友好的规模控制 |
| 纸嫁衣 | 中国民俗题材、移动端短篇、系列化连载的发行方式 |

玩家对这一类作品的预期是「读一个能动手的故事」：可以慢、可以被打断、随时保存，但绝不能走到一半被告知「你早先那步做错了，重来吧」。

## 3. 设计要点

### 3.1 两条腿：叙事与解谜的咬合

先定结构，再写内容。常见三种结构形状：

| 结构 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| 线性链条 | 解开前一场景的谜题才进入下一场景 | 叙事节奏可控，制作顺序清楚 | 一处卡住，全盘停转 |
| 枢纽式 | 一个主基地加多个可自由往返的分支地点 | 玩家有自主感，卡一处可以换线 | 状态组合变多，对白要兼容乱序访问 |
| 并行目标 | 同一阶段内多个目标同时开放 | 中后期显体量，天然反卡死 | 目标之间互相影响，收束点要设计干净 |

动手之前先画一张谜题依赖图：节点是「玩家获得的信息与物品」，连线是「谁解锁谁」。它有三个用途：找出永远用不上的孤岛节点；检查每个节点是否至少有一条前置线索；给测试与提示系统当导航图。

每个谜题先登记五件事，再进引擎实现：动机（玩家为什么要解）、障碍（卡住了什么）、线索（在哪里能发现）、解法（用哪些已建立的联系）、产出（解锁什么）。登记表写不满的谜题，先别做。

谜题的动机就是叙事的一部分：同样是开门，放在「逃亡」与「赴约」两种情境里，玩家的投入完全不同，先回答「为什么要开这扇门」，再回答「怎么开」。解开谜题的回报是剧情前进一段，不是迎面再来一个更难的谜题；大谜题之后安排一段情绪回报，让张力有起伏。

检查表：

- 每个谜题的动机能用一句话说清，且与主线有关？
- 依赖图上有几个节点没有任何前置线索？答案应为零。
- 每个场景收尾时，玩家手上至少有两条「下一步可以试」的路线？
- 卡关段与舒适段是否交替出现？

### 3.2 物品、环境与 NPC：交互三角

玩家的全部手段只有三样：物品栏里的东西、场景里的物件、以及人。所有谜题都是这个三角的一次连线，连线用的动词就是玩家要学会的全部语言。

先说交互模型，它决定玩家的手感与你的文案成本：

| 模型 | 做法 | 成本 | 适用 |
| --- | --- | --- | --- |
| 动词栏 | 每个物件配一排动词（看、拿、用、推、说等），组合执行 | 每种无效组合都要写反馈，文案随动词数翻倍 | 喜剧密度优先、经典风格 |
| 上下文游标 | 单击执行最合理的动作，不给选择 | 文案最省、节奏最快 | 移动端、轻量叙事 |
| 折中方案 | 两到四个动词加游标状态，常用「看 / 用 / 谈」 | 可控 | 多数新项目的起点 |

物品规则六条：

- 来源要说得清：玩家要能指着物品说出「我在哪拿的」。
- 去处要可推：设计物品时就确定它用在哪个谜题、怎么退场。
- 消耗即退场：用完的东西自动离开物品栏；日记、地图这类永久工具另置，不进谜题链条。
- 容量纪律：活跃物品封顶 8-15 件，再多玩家就要靠穷举过关。
- 组合克制：允许 A 加 B 等于 C，但只做两步以内、结果可预期；组合的乐趣来自合理，不来自意外。
- 无效交互必须回应：分三档给反馈，可用的组合给正向反馈，明显不搭的给幽默文案，接近正确的让角色自言自语一句暗示。

对话是三角的第三个顶点，也是谜题接口：NPC 负责给信息、给物品、以及当裁判（确认玩家对世界的理解）。用对话树加主题列表承载，主题随进度增长、允许反复问；写对白前给每个角色立一张声音表（口头禅、句长、称呼方式、说不出口的话题），多人合写时靠它防串音。

### 3.3 引导、提示与防卡死

点击式冒险的差评最常见于一句话：「我卡住了，然后我查了攻略。」把这个句子当敌人，本节的每条设计都是为了杀死它。

伏笔先于解法：

- 公平性铁律：做出解法所需的信息，必须在需要它之前就出现在世界里。锁先露面，钥匙后出现；机关先被看见工作一次，玩家才会想到拆它。
- 线索要有回响：埋下的伏笔分「开卷」与「回收」两类，做一张回收表，每个伏笔都要有兑现时刻；审计时把没有回收的删掉或补上。
- 解法只用已建立的联系：玩家在别处见过的因果关系，才可以拿来出题；现教一个新规则再立刻考试，是「解法靠猜」的常见来源。

分级提示系统：

| 层级 | 给什么 | 时机 |
| --- | --- | --- |
| 一级 | 观察提示：把注意力引回某个场景或某个热点 | 玩家主动点开提示入口，或卡住太久后入口微微变亮 |
| 二级 | 方向提示：说明缺什么、和谁或哪里有关 | 在提示界面里继续展开 |
| 三级 | 解法提示：具体到「把谁用在什么上」 | 仍由玩家自己点开 |

- 提示永远由玩家索取，不自动弹出；入口安静地待在界面上，不打断心流、不评判语气。「你再想想」是挑衅，「试试去别处看看」是帮助。
- 经典参照是机械迷城：把分步攻略做成游戏里的手绘提示书。全量攻略并不可耻，真正的问题是玩家在游戏内找不到兜底手段。

防卡死审计（死局四查）：

- 物品是否可能永久丢失或不可逆地消耗？
- 场景状态是否存在不可逆且无替代路径的破坏？
- NPC 是否可能带着必需信息离场？
- 进度是否依赖「只有一次机会」的事件？

设计纪律：把「不可逆」从系统里拿掉。物品要么不消耗，要么在消耗前已经无用；人物永远等在原地；世界状态只增不减。这个类型在黄金时代用一代差评付过这份学费，不必再交一次。

卡点观测：给测试记录三个数，进入场景到解开的时长、无效点击次数、提示使用层级；某个位置的停留超过测试中位数三倍，先回去补线索投放与视觉引导，再考虑调整谜题本身。一个谜题的合理卡关上限按 10-15 分钟校准测试，超过就加伏笔。

### 3.4 背景与动画：美术的账

背景是这种游戏最硬的成本单位：一个场景一张达到发行完成度的图，数量与场景数一一对应。先定分辨率与构图规范：可交互物要「看起来像可以点」，动线要引导视线，再逐张产出。

- 分层与复用：背景分远景、中景、近景三层，支撑视差、开合与局部动画；白天黑夜一类的复用变体要克制，每多一版就多一整张图的成本。
- 角色动画：每个角色的动作集列最小清单（待机、行走、说话、使用，加一到两个特殊动作）；帧数按「够用」原则控制，经典时代 8-12 帧的走路循环至今可用的原因是省。
- 场景小动画：门要开、铃要响、路人要有姿态变化，这些「小动」承担「世界是活的」的承诺，也是最好的热点提示；每个场景预留一到五组的预算。
- 预算顺序：白盒把场景数与谜题链完整跑通之后，再开画第一张正式背景；玩法验证之前画完的每一张图，都可能变成沉没成本。

## 4. 技术要点

工程难点集中在四块：交互脚本体系、对白与状态、存档与工具链、本地化。四块都是通用需求，主流引擎都能落地；第一作先用现成工具，不要自研引擎。

**交互脚本体系**

- 场景即数据：背景、热点、条件、动作、反馈全部写进数据文件，引擎负责解释。黄金时代的 SCUMM 一系就已定型这个「引擎与内容分离」的架构，改一行数据就能调谜题，是迭代速度的底线。
- 热点做成固定的结构模板：可见性与可点性条件、动作（拿起、开门、移动）、反馈（成功文案、无效文案）。模板稳定，内容生产才能批量化。
- 世界状态表：全部旗标、计数、场景开关登记在一处，脚本只准引用登记过的状态；散落的条件判断是本类型最典型的技术债。
- 调试命令先于内容：跳场景、给物品、设旗标、快进对白、热重载脚本；没有它们，每次测试都要完整走流程。

**对白与状态系统**

- 对白数据用节点图或主题列表两种形态，节点携带条件与效果（改旗标、给物品、开场景）；写作与逻辑分离，写手改文本不动结构。
- 已读跳过、自动播放、对白历史、文本速度是底线功能；跳过率与重读率顺带成为写作的体检数据。
- 配音是选项不是地基：多语言全语音成本高，数据层先留钩子，做不做在范围会议上再定。
- 本地化从第一天开始：玩家可见字符串全部走字符串表；场景美术里的文字（招牌、报纸、墓碑）提前决定处理方式，改绘或贴图替换都要写进资产规范，事后返工最贵。

**存档与工具链**

- 存档结构等于「旗标集合 + 物品栏 + 场景与位置 + 对白已读表」，与剧情内容解耦；每次内容更新后用旧档实测，发布前再跑一遍。
- 自动存档覆盖进场景、解开谜题与关键对话；玩家永远不需要「为了存档重玩一段」。
- 卡点埋点用本地日志就够：场景停留时长、无效点击、提示层级；原型期就开始记，难度与提示的调参靠它。
- 冒烟脚本：用脚本自动走通一条主线（跳场景、模拟交互序列），每次改条件或旗标后跑一遍，防止「改坏一处、卡死全线」。

**平台与输入**

- 鼠标是最顺的输入：悬停可以预览动作，双击可以跑动；触屏要重建这套交互，悬停改为点按预览，跑动改为常按或短距自动寻路。
- 触屏热点按手指设计，经验值从 9 毫米见方起步；密集场景把热点拆开，或提供放大镜与高亮模式。
- 分辨率适配：背景按目标分辨率画足，缩放到小屏会损失细节；界面字号按最小目标屏测试，点击式界面元素多，手机上最先暴露字号与间距问题。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 规模 | 场景数 | 通关时长 | 工期量级 | 定位 |
| --- | --- | --- | --- | --- |
| 原型 | 3-5 个场景、一条谜题链 | 15-30 分钟 | 2-4 周 | 验证交互模型与流程 |
| 短篇 | 10-15 个场景 | 1-3 小时 | 3-6 个月 | Jam 成熟形态与小体量商业作 |
| 中型完整作品 | 25-40 个场景 | 5-8 小时 | 1-2 年 | 商业可售的常见体量 |
| 大型 | 50-80 个场景 | 10 小时以上 | 团队多年 | 黄金时代一线作品一档 |

三个换算口径：

- 单场景成本 = 背景（常见 2-5 个美术日）+ 热点与交互脚本（1-2 天）+ 对白与反馈文案 + 场景动画（1-5 组）。合计常见 1-3 周投入一个场景，美术占大头。
- 文案量级：完整作品的对白与描述文本常见 5-15 万字，其中大比例是「对一切都有回应」的热点反馈，而不是主线对白；写作速度按熟练写手每天 2000-4000 字初稿估。
- 谜题量级：一个 5-8 小时的作品常见 15-25 个核心谜题节点，依赖图上的节点数更多；按每 30-60 分钟一个「大谜题」排布，其间用小谜题、对话与探索填充。

美术总量：背景数对应场景数加变体；角色按出场人物算，每人一套最小动作集；道具图标按物品清单；最容易低估的是场景小动画，它按场景数线性叠加。一个 30 场景的作品，仅背景就是 30 张发行级画稿起步，这部分必须在立项文件里写明。

排期锚点：从零到一条完整谜题链可玩通常 2-4 周；到垂直切片（一章达到发行质量）常见 2-4 个月；之后按场景数外推。内容砍减永远比推迟安全：谜题链减一个节点只是删逻辑，背景画到一半废掉是纯亏损。

## 6. 第一个原型怎么起步

第一个原型只做一条谜题链：3-5 个场景、一个 NPC、一条「拿、用、谈」走到底的流程。2-4 周完成，不碰正式美术、配音与多语言。

1. 第 1-2 天：选工具跑通样例。现成选项里，Adventure Game Studio 是免费开源的老牌点击式引擎；Godot 阵营可用 Escoria 这类开源框架；Unity 项目常用 Yarn Spinner 或 ink 承担对白层。同时定下动词模型（§3.2），起步用折中方案。
2. 第 3-4 天：纸上画谜题依赖图，5-7 个节点；每个节点写全五件事（动机、障碍、线索、解法、产出）；列清楚每个场景的看点与热点清单。
3. 第 5-7 天：白盒实现：色块背景加文字标签、热点、物品栏、游标反馈。所有无效交互先配一句回应文案。丑是应该的。
4. 第 8-10 天：加一个 NPC 与对话树、状态旗标、存档；把三级提示入口先占位实现。
5. 第 11-12 天：加埋点日志（停留时长、无效点击、提示层级），自己完整走三遍主线，把卡住自己的位置记下来，那里是重灾区。
6. 第 13-14 天：找 3-5 个陌生人测试。不说话、不提示，记录卡点、误点与退出点；结束后只问一个问题：「你还想继续往下玩吗？」

成功标准（全部可观察）：

- 至少 3 名测试者无提示走通全链，人均卡点不超过两处、每处不超过 10 分钟。
- 每个卡点都能归因到具体设计问题（线索不够、热点不显眼、依赖超过两步），而不是「他怎么想不到」。
- 测试过程里出现自发的「我先去那边看看」，而不是沿唯一路径低头走。
- 拿掉全部美术与声音，流程仍然成立。

## 7. 常见坑

1. **谜题与剧情两张皮**：为谜题而谜题，玩家感觉在给设计师打工。修法：先写动机再写机关（§3.1），解法回指故事里已发生的事。
2. **解法靠猜**：谜题依赖设计者脑内的联系，玩家只能穷举碰撞。修法：线索先于解法；只用已建立的联系；让不熟悉项目的人验证。
3. **死局与不可逆状态**：物品永久丢失、NPC 离场、单次事件错过，玩家几小时后才发现只能重开。修法：世界状态只增不减，消耗前物品必须已无用（§3.3）。
4. **沉默的点击**：无效交互没有反馈，玩家分不清「不能用」与「没点到」。修法：所有互动至少给一句文案或一个音效。
5. **物品栏失控**：三十件存货、组合爆炸，玩家从推理切换成穷举。修法：活跃物品封顶 8-15 件，用完即走。
6. **提示的两极**：要么完全没有，要么直接剧透。修法：三级提示、玩家索取、入口安静地浮现。
7. **像素狩猎**：热点小于视觉本体，或画面根本看不出哪里能点。修法：热点大于本体、提供高亮键、统一可交互物的美术语言。
8. **美术预算低估**：场景数线性增长，单场景成本（背景、动画、交互）却成倍叠加，画到一半发现做不完。修法：白盒全链跑通再开画。
9. **对白自嗨**：内部笑话与长台词，玩家一路跳过。修法：热点回应一到三句封顶，把跳过率放进复盘指标。
10. **教程缺位**：开头十分钟没教会「看、拿、用、谈」，第一个谜题就劝退。修法：第一个谜题当教程，教的动作就是通关要用的动作。
11. **本地化推迟**：字符串硬编码、美术里的文字没留处理方案、字体没确认授权。修法：第一天起按「要翻译」组织文本与资产（§4）。
12. **只抄经典的外形**：抄了动词栏与手绘风，没抄「对一切都有回应」的文案体系，世界立刻变得又哑又薄。修法：先立回应文案件，再做界面皮。

- 《美术与音频手册》（⑪）§2、§10：2D 管线与交付规格，本文 3.4 与第 5 节的扩展账本。

- 《类型手册 · 解谜》（P0 批次）§3.4、§4：提示分级、卡关检测与求解工具，与本文 3.3 互为参照。
- 《案例研究集》（⑳）：案例拆解方法，读第 2 节标杆与第 7 节坑清单时对照。
- 《避坑大全》（⑥）：内容生产与项目管理相关坑位，与本页第 7 节交叉阅读。
- 《独立开发生存手册》（⑱）：范围控制与排期，与第 5 节互为补充。
- 作业：用纸笔为一个三场景的迷你冒险画一张谜题依赖图，标出每个节点的动机、线索与产出，再把它交给一个不玩这类游戏的朋友，看对方能否说出第一步该做什么。

点击式冒险最终只考验两件事：玩家卡住时，线索够不够用；玩家想通时，故事兑不兑现。
