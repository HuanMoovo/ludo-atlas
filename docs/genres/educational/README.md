# Ludo Atlas · 类型手册 · 教育游戏（Educational）

> **类型手册 · 第四辑**。定位：把「让玩家真的学会点东西」写进验收标准的类型。它同时欠两笔账：玩法要好玩到有人愿意玩，学习要有效到拿得出证据；本页覆盖双重目标设计、知识嵌入方式、学习效果评估、分龄与课堂场景，以及职业培训、医疗康复等严肃游戏邻接。
> 配套：《游戏设计手册》（核心循环与反馈设计）·《制作管理手册》（内容量与排期估算）·《案例研究集》（同类产品拆解）·《避坑大全》（儿童数据与合规坑位）。
> 本文不放外链；标杆只列大众熟知的作品，数字为常见量级，落到项目里以实测为准。

## 1. 定位与核心循环

一句话定位：教育游戏是**把「让玩家学会一件事」当作产品承诺的类型**。它和普通游戏的差别不在题材，在验收：普通游戏只需好玩，教育游戏还要拿得出「玩家学会了」的证据。两笔账缺一不可：好玩决定有没有人来，有效决定能不能留下并复购。普通游戏的循环走完就过去了，教育游戏的循环必须留痕：每一轮要留下玩家的能力变化，与一条可被观察的学习证据（§3.3），这是两者的工程分水岭。

核心循环用动词环写：

`接触新知识（在情境里出现） → 在玩法里用一次 → 得到反馈与解释 → 修正后再试 → 掌握度上升，难度或场景升级`

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 问答测验 | 问答测的是「会不会」的存量，答完即止；教育游戏管「从不会到会」的增量，必须带教学与纠错 |
| 游戏化应用 | 游戏化给现有流程套奖励外壳（积分、徽章、连击），流程本身不动；教育游戏把学习任务改造成核心动作 |
| 课件与网课 | 课件按「讲完」验收；教育游戏按「玩了之后会了」验收，多欠一笔趣味与动机的账 |
| 普通游戏（任意玩法载体） | 玩法可以一模一样；差别在目标与证据，教育游戏为「玩过之后还会」设计，愿意为迁移让掉一部分爽感 |

一个自检问题：用一句话写下「玩家玩过之后学会了什么、拿什么证明」。两样都写得出来，才是教育游戏；写不出，或只能写「提高了兴趣」，先别开工。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **学会的那一刻**：从不会到会的进步能被玩家自己感知，这是本类型独有的第一体验。
2. **好玩不掺水**：剥掉学习外壳，玩法本身站得住；玩家为了玩而回来，不是为了交作业。
3. **安全试错**：答错不羞辱、不公开处刑；错误是学习路径的一部分，重试以秒计。
4. **进度可见**：学到哪、掌握到什么程度、下一个目标是什么，随时看得见。
5. **学以致用**：练习与真实场景挂钩，学到的东西在游戏外还用得上（迁移，§3.3）。

标杆作品（大众熟知，建议亲手玩过再拆）。反面感受出现任意一条都是红灯：考试感、奖励绑架、难度错配、学而无证。

| 作品 | 可学的点 |
| --- | --- |
| 多邻国 | 游戏化练习的标杆：课程切成短关卡，练习本身就是玩法；连击、排行榜与每日目标再套一层习惯外壳，两层都做到位 |
| 我的世界：教育版 | 沙盒载体路线：建造与协作本身就是学习任务，教师控制台负责发任务、看进度、管课堂 |
| 俄勒冈之旅 | 教育游戏的祖师爷：历史、地理与资源决策嵌进一次西行模拟，失败讲的也是真实处境 |
| 卡门·圣地亚哥（系列） | 把地理知识藏进追捕玩法，线索本身就是要学的知识，侦探结构天然适配「查证式学习」 |
| 识字与数感启蒙应用（洪恩识字一类） | 低幼分龄标杆：一关一小知识点、每日任务与家长报告三板斧，语音优先、不设失败 |

## 3. 设计要点

### 3.1 双重目标设计：两张验收清单

教育游戏从立项起就有两个目标，各写一张清单，缺一张就是半个产品：

| 目标 | 写法（反例 → 正例） | 验收方式 |
| --- | --- | --- |
| 学习目标 | 「提高数学兴趣」→「能独立完成两位数进位加法，10 题 8 对」 | 前后测与延迟复测（§3.3） |
| 玩法目标 | 「寓教于乐」→「剥离学习内容后，盲测玩家仍愿意连玩三局」 | 无提示盲测观察 |

- 学习目标写到「可验收」为止：学什么（最小知识单元）、到什么程度（认得、说得出、用得上、换场景还能用，四档）、拿什么证明（测试与数据口径）。写不进这三格的模块不进排期。
- 掌握程度按四档递进：认得、说得出、用得上、能迁移。多数产品实际停在第二档，宣传口径却常按第四档说，这是口碑事故的高发区。
- 一个模块只扛一到两个学习目标：知识点越多，认知负荷越高，玩法越像赶场。
- 两个目标冲突时，先保玩法体验，再把知识点拆小或换嵌入方式（§3.2）；硬塞的知识既不好玩也记不住。立项时把两个目标各写成一句话给外行看，对方都能复述，才算过。

### 3.2 知识嵌入方式：玩法即学习与奖励包装

- **玩法即学习**：核心机制本身就是知识的使用动作（编程解谜里的指令就是编程、模拟经营里的账本就是经济学），玩家想通关就绕不开真正掌握，学习与玩法是同一个动作，效果最扎实，也最难做。
- **奖励包装**：玩法与知识分开，做对题目换来星星、金币与装扮，知识是关卡门票、玩法是奖励，成本低、见效快，适合低龄与习惯养成，但玩家容易看穿套路、学完即走，效果上限偏低。

| 判断问题 | 玩法即学习 | 奖励包装 |
| --- | --- | --- |
| 知识换成无意义符号，玩法还成立吗 | 不成立（知识在核心） | 成立（知识在外壳） |
| 玩家绕过学习能赢吗 | 不能 | 能，只要奖励设计周全 |
| 主要风险 | 做浅了就是普通游戏贴标签 | 做飘了就是换皮题库 |

- 嵌入位置不止「做题」一处：输入（操作本身要调用知识）、规则（约束由知识决定）、目标（通关条件即应用）、反馈（错误解释带知识点）、生成（题面与关卡由知识系统生成）。预算有限时，优先放在目标与反馈两处。
- 选择依据三件事：目标年龄、知识类型（事实记忆还是程序技能）、团队里有没有学科专家。没有学科专家，先别碰「玩法即学习」路线。

### 3.3 学习效果评估与数据

测什么：三层漏斗，从过程到效果。

| 层 | 指标示例 | 回答什么问题 | 采集方式 |
| --- | --- | --- | --- |
| 参与 | 留存、时长、关卡通过率 | 玩家愿不愿意玩 | 游戏内埋点 |
| 即时学习 | 正确率、提示使用率、错误类型分布、掌握度变化 | 过程里学到了没有 | 埋点加前后测 |
| 迁移与保持 | 延迟复测成绩、未教过同类题的正确率、真实场景使用 | 会不会用、留不留得住 | 迁移任务与测后随访 |

怎么测（可在立项时直接抄走的清单）：

- 前测与后测：同一套题间隔一天以上再做一次；配对照组（玩与不玩、新旧版本，学校场景常按班拆），没有对照，成绩变化无法归因；只测一次的叫「当场记住」，不叫学会。
- 游戏内埋点：正确率、卡点位置、提示依赖率、放弃点、会话时长；先定义「掌握」的阈值（如连续两轮 90% 正确）再开发埋点。
- 迁移任务：出没教过的同类新题，或换一个场景使用；这是唯一能区分「学会」与「记住」的测试。
- 数据纪律：过程指标（时长、留存）与效果指标（成绩变化）分开汇报，两组数字不要混着讲；儿童数据按最小化采集与家长同意处理（细节见《避坑大全》）。

### 3.4 分龄与课堂场景

分龄的常见三档（边界以目标用户为准）：

| 档位 | 设计重点 | 交互与文案 | 单次时长 |
| --- | --- | --- | --- |
| 学前（约 3-6 岁） | 感官与习惯：大按钮、语音优先、无失败设计 | 少文字多语音，先做对再求快 | 10 分钟以内一段 |
| 小学（约 6-12 岁） | 规则与竞争：目标清晰、奖励体系、轻社交 | 短句、图文并行，允许改答案 | 15-20 分钟一段 |
| 中学以上（约 12 岁起） | 系统与自主：模拟、沙盒、项目任务 | 可读长文本，鼓励自定目标 | 30 分钟起 |

- 分龄的差异是产品结构，不是皮肤：文本量、失败惩罚、社交暴露度都随年龄上调；低龄段不设公开排行榜与输的场合；跨档产品共用系统、分开节奏与引导，工作量按两套估。

课堂场景（和家用版基本是两种产品）：

- 课时约束：一节课 40-45 分钟，产品要能被切进一个完整环节（导入几分钟、练习十几分钟、总结几分钟），随时可暂停、可保存、可续。
- 设备现实：机房、平板车、学生自带设备、一块大屏；网络不稳是常态，离线可玩是常见硬要求；资源按单元分包下载，别让全班开课前一起等进度条。
- 账号纪律：批量建号与重置、班级码或图形码登录、一台设备多人轮流的档案切换；登录吃掉课堂前十分钟的产品，不会有第二节课。
- 教师工具清单（第一版就要）：班级与名单管理、任务发布、进度看板（谁卡在哪）、易错题汇总、投屏演示模式、内容白名单（关掉商店与聊天）；上手标准是五分钟内不看说明书能发布一次任务，一节课结束拿得到一张可讲的汇总（完成率与易错题）。

### 3.5 严肃游戏的邻接应用

严肃游戏指以非娱乐为首要目的的游戏，教育游戏是其中一支；同族还有职业培训、医疗康复、科普公益与应急演练。玩法与工程底子相通，差别在验收标准：教育看成绩与迁移，培训看操作合格率与失误率，医疗看临床指标。

**职业培训**

- 飞行员与机组训练大量依赖模拟机，模拟器是这个行业的老家；驾驶、工程机械、电力与化工应急演练、手术与内镜模拟都有成熟形态。
- 保真度按训练目标分配：与考核相关的传感器与操作台要做到位，风景可以省；操作全程留痕，生成与上岗考核挂钩的评估报告。
- 允许昂贵错误：在模拟里搞砸的成本远低于现实，这是模拟训练最硬的卖点。

**医疗康复**

- 重复与枯燥是康复训练的底色，游戏化解决的是「愿意练」的动机问题；常见形态有卒中后的手部与步态训练、认知与注意力训练、VR 暴露疗法。
- 注意力训练方向已有处方级先例：EndeavorRx 在美国获监管批准，用于 8-17 岁儿童；涉及治疗主张的产品可能被按医疗器械监管，路径要立项前问清。

**共用纪律**

- 先定验收指标，再定玩法：培训先问「考核什么、什么算合格」，康复先问「哪个指标可量化」；指标写不出，项目不立。
- 专业人士全程参与：学科专家、教官与医生既是需求方也是验收方，开发团队不能自己定义「有效」。
- 小团队的切入口是垂直场景与机构合作（学校、培训机构、医院），按客户的验收标准交付；先做一个闭环，再谈平台。

## 4. 技术要点

工程难点集中在三块：内容管线、学习数据与课堂基础设施。以下与引擎无关；教育游戏没有手感类技术风险，风险都在「内容改得动吗、数据测得准吗、课堂用得起来吗」。

**内容管线（学科专家要能直接改内容）**

- 知识点、题目、关卡脚本、难度标签全部数据化（表格或 JSON，方法见《游戏设计手册》），代码只读表；内容进版本控制，改题留痕可回滚，审校记录随内容走。
- 参数化出题器：同一知识点用模板加随机数值生成变体，题面与答案同源计算，配校验器保证答案唯一、可解、不歧义；变体入库前跑一遍自动检查。
- 多学段与多语言复用同一套内容结构：题干、选项、解释、语音全部分离，术语表先立。

**学习数据与评估**

- 事件埋点在开发早期就位：答题、提示、错误类型、重试、会话起止；先定「掌握」的口径再埋点，否则数据回来什么也证明不了。
- 掌握度模型：知识点按图组织（含前置关系），掌握度用滚动统计或概率估计维护，驱动解锁与教师报表；复习按间隔重复排程，长期保持靠机制，不指望玩家自觉回头。
- 数据链路本地优先：校内网络不稳定，事件本地攒批、联网补传，断网也要能完整上一节课；学习数据按人、按班分级授权（合规见《避坑大全》）。

**课堂基础设施**

- 账号：批量导入与重置、班级码或图形码登录、共享设备的档案切换与快速重开。
- 教师后台：任务发布、进度看板、错误分布、投屏演示、功能白名单；资源按单元分包、支持课前预载；后台的完成度直接决定复购。
- 无障碍：语音朗读、色盲友好配色、字幕、读屏兼容；既是合规要求，也是低龄与特殊教育场景的功能需求。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 玩法原型 | 1 个知识单元、十几道练习 | 2-4 周 | 只验证嵌入方式与前后测工具，不碰账号与后台 |
| 小型完整作品 | 1 个学科或技能、1 个学段 | 3-6 个月 | 小团队常见起点，含完整的教师或家长报告 |
| 课堂产品 | 一学期内容（按课时切成 30-60 个环节）加教师后台 | 6-12 个月 | 后台、账号与设备适配是隐藏工作量 |
| 平台型产品 | 多学段多学科、数百小时内容 | 团队 1-3 年 | 内容是月费：产线、审校与更新是长期账单 |

- 成本大头常不在程序：知识点拆解、题目与关卡脚本、学科审校加起来常与程序相当或更高；先给「一个知识单元」计时，再乘单元数。
- 单位成本量级：一个知识单元的教学与练习关卡组 3-10 天（含审校）；一套教师后台核心功能 2-6 周；前后测套件与一轮数据分析按总预算 10%-20% 预留。
- 两套节奏分开排：玩法迭代以周计，学习效果以月计（要隔期复测）；把效果验证写进排期表，否则项目会停在「上线即结束」。

## 6. 第一个原型怎么起步

第一个原型只验证一件事：知识嵌入方式成不成立。2-4 周完成，不碰正式美术、账号与后台。

1. **选一个最小知识单元**：十几分钟能学会、十道题能测出来的那种；把学习目标与验收证据各写成一句话。
2. **先做剥离知识的玩法核心**：把内容换成中性符号（色块、字母），先让玩法本身站得住；玩法不成立，加回知识也救不回来。
3. **把知识放回核心动作**：按 §3.2 选嵌入方式；走玩法即学习路线，就把知识放进输入、目标、反馈中的一个位置，先做一处，别贪多。
4. **配一套前后测**：十道题的前测、玩十五分钟、立刻后测、隔一天延迟复测；再备两道没教过的迁移题。
5. **找 6-10 个目标用户盲测，并写一页纸结论**：不提示、不解释，记录主动继续玩的意愿、当场正确率变化、延迟复测还剩多少；把测试者「用自己的话说出知识点」的原话记下来，那是结论里最硬的证据。

成功标准（全部可观察）：

- 测试者主动要求再来一局，而不是被请求再玩。
- 后测正确率高于前测，且延迟复测仍高于前测。
- 十个人里至少三人能用自己的话复述核心知识点。

## 7. 常见坑

1. **双目标缺验收**：「提高兴趣」「寓教于乐」这类目标没法验收，结果只剩感觉；两个目标各写成可测的一句话（§3.1）。
2. **知识硬塞**：玩法与知识两层皮，玩家玩得爽却学不到，或者做题像罚站；回到 §3.2 选嵌入方式，先保玩法再拆知识。
3. **用时长冒充效果**：「每天玩 30 分钟」是过程指标，不是学会的证据；两组数字分开汇报（§3.3）。
4. **只测即时记忆**：不测延迟保持与迁移，数据好看但不可信；隔天复测是底线（§3.3）。
5. **学段错配**：一套文本、惩罚与社交设计打天下；分龄的差异是结构问题，不是换皮肤（§3.4）。
6. **教师工具缺失**：教师五分钟上不了手、一节课拿不到汇总，产品进不了第二节课（§3.4）。
7. **效果验证无预算**：学校合作、前后测与数据分析没人没工时，到头来没有证据可讲；这笔预算要写进立项（§5）。
8. **合规踩线**：儿童数据、医疗主张、内容授权，先问清监管路径再立项（§3.5、§4）。
9. **课程脱节**：内容与学校教学进度对不上，教师没法把它排进课表；先对齐一份可用的课程清单再谈铺量。

## 延伸阅读

- 《游戏设计手册》：核心循环、反馈与难度曲线，第 1、2 节的底稿。
- 《制作管理手册》：内容量估算与范围控制，配第 5 节使用。
- 《案例研究集》：同类产品的拆解方法，验证双目标设计时对照。
- 《避坑大全》：儿童数据、内容授权与合规坑位，立项与复盘时对照。
- 《类型手册 · 问答测验》（第三辑）：题库工程、抽题公平与难度校准，与 §3.2、§3.3 交叉。
- 练习：给一个你熟悉的学习应用写两张验收清单（学习目标与玩法目标，各加一列「拿什么证明」），再为同一个知识点写三种嵌入点子（放进输入、目标与反馈各一个），选一个做两周灰盒。

教育游戏最终只考验两件事：玩家是不是真的学会了，以及他愿不愿意自己回来学下一课。
