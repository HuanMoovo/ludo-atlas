# Ludo Atlas · 类型手册 · 怪物收集（Creature Collector）

> **类型手册 · 第四辑**。定位：以宝可梦为原型的收集培养系列。玩家在收集、培育、对战、交换四条线上同时获得驱动：图鉴的完成度给长期目标，队伍的所有权感给情感投入，对战是成果的校验，交换是社交的出口。
> 配套：《游戏设计手册》（核心循环与数值表）·《技术实现手册》（数据管线与战斗结算）·《案例研究集》（拆解与复盘方法）·《独立开发生存手册》（内容量核算与范围控制）。
> 本文不放外链；标杆只用大众熟知的作品，数字为常见量级，落到项目里以实测为准。

---

## 1. 定位与核心循环

一句话定位：怪物收集是**把「收服、培育、对战、交换」四件事锁进一个循环**的类型。收集是采集线，培育是投入线，对战是检验线，交换是社交线，四条线互为弹药；只做其中一条都会塌。

核心循环用动词环写：`探索 → 遭遇 → 削弱 → 捕获 → 入队培养 → 对战检验 → 进化与配招调整 → 探索新区域`，交换环挂在收集与培育之间，随玩家需要插入。

四环各司其职：

| 环节 | 玩家在做什么 | 黏性来源 |
| --- | --- | --- |
| 收集 | 遭遇、削弱、捕获、填图鉴 | 「又多一格」的确定回报、稀有度分级 |
| 培育 | 升级、学招式、进化、调定位 | 所有权与投入感，队伍是「我的」 |
| 对战 | 属性克制、行动顺序、队伍搭配 | 以弱胜强的复盘感，养成成果的验收 |
| 交换 | 用重复换缺失、稀有互换 | 社交与互补，收集环的捷径（可选，但回报高） |

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| JRPG | JRPG 用固定角色与剧情驱动；本类型里怪物本身就是角色，队伍可换，策略围绕捕获与搭配展开 |
| 养成 | 养成的对象是人与关系，成长本身就是内容；这里的成长有明确的战斗出口 |
| 集换式卡牌 | 卡牌的收集是纸面资产；这里收集的是会成长、会进化、有生态位的实体，多一条交换线 |

一个自检问题：把图鉴、进化与交换全部删掉，只留战斗与升级，游戏还成立吗？答案若为「不成立」，你做的就是怪物收集。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **发现的惊喜**：新区域有新怪物，遭遇本身是奖励；稀有与特殊个体是「今天运气不错」的来源。
2. **收集的确定回报**：图鉴每填一格都有记录、奖励与进度感，完成度看得见。
3. **培育的所有权**：个体差异、昵称、配招与进化路线让玩家说「我的队伍」，而不是「当前阵容」。
4. **对战的复盘性**：胜负可解释（属性、速度、配招、道具），赢要明白，输也要明白。
5. **交换的社交**：重复物有去处，稀有物有归宿，补图鉴有捷径。

反面感受（出现任意一条都是红灯）：被随机戏弄（概率黑箱、连续失手无交代）、练了白练（培养成果不可见、不可转移）、图鉴陷阱（缺的那一只永远不知道去哪找）。

标杆作品（均为大众熟知的作品，建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 宝可梦系列 | 四环闭环的教科书：捕获、进化、克制矩阵与交换对战的完整形态；但不要拿它的体量当起点 |
| 幻兽帕鲁 | 收集与生存建造、劳作系统的融合；怪物除战斗外还有生产价值 |
| 数码宝贝系列 | 进化树与育成机制的演进线：分支进化、条件进化与电子宠物的谱系 |
| 洛克王国 | 国产网页端的收集养战范式：轻量化收集与长线运营下的图鉴扩张 |

玩家对这个类型的默认期待：可见的捕获概率与图鉴进度、队伍管理的批量操作、误操作有确认且部分可恢复（进化、招式遗忘）、随时存档与安全的中断体验。缺失它们，差评会来得很快。

## 3. 设计要点

### 3.1 怪物设计：生态位、属性克制矩阵与进化链

先定四个维度，再画形象、写数值：

| 维度 | 要回答的问题 | 常见做法 |
| --- | --- | --- |
| 生态位 | 在哪里、什么时候出现 | 地形、时段、天气与稀有度分层 |
| 战斗定位 | 解决什么战术问题 | 输出、肉盾、控制、辅助、速攻，每只至少一个岗位 |
| 属性组合 | 攻防两面是什么 | 单属性到双属性；双属性提供辨识度，也放大克制风险 |
| 成长位置 | 在进化链的哪一段 | 两段或三段进化；低阶常见、中阶过渡、终阶稀有 |

属性克制矩阵（本类型的数值地基）：

- 属性数量：小项目 6-10 个，中型 12-18 个；超过 12 个之后，逐项检查「每个属性在攻防两侧都有存在感」，没有存在感的属性是负债。
- 倍率约定：常见三档，克制 2 倍、被克 0.5 倍、免疫 0 倍（简化项目可用 1.5 与 0.67）；双属性倍率相乘，4 倍与 0.25 倍的极端值天然存在，极端值总占比是矩阵设计的一部分。
- 矩阵与平衡纪律：每个属性都要能回答「谁怕我、我怕谁、我对谁无效」，克制表游戏内可查，不做隐藏倍率；跑模拟统计任意两属性的胜率差，出现单一霸主属性就调矩阵，而不是继续加怪。

进化链设计：

- 进化要改变定位或强化定位，不做「数值放大 1.5 倍」的换皮；三段进化给两个质变节点，玩家才有期待。
- 进化条件从简：等级、道具、条件各选其一为主；分支进化是低成本高回报的重复可玩性，用稀有道具或不同条件分岔两条线。
- 低阶怪物负责前期速成（门槛低、即时可用），终阶负责长线目标；图鉴的层次感一半来自进化链。
- 设计顺序：先写「它解决什么战术问题」与「它在哪出现」，再定属性与数值，形象留到末尾；反过来先画形象再硬塞数值，属性矩阵必然失衡。

### 3.2 捕获机制：把战斗变成控制

捕获是收集环的闸门，也是玩家记账最细的一处数值。通用公式结构（各家实现不同，骨架相近）：

`捕获成功率 = 基础捕获率 × 血量修正 × 状态修正 × 道具倍率 × 等级修正`

- 血量修正：血量越低越好抓，压血与「打死」只差一刀，这一刀就是捕获玩法的全部紧张感；常见形式是按当前血量比例线性映射到 1-3 倍的修正区间（满血最难、残血最易）。
- 状态修正：睡眠、麻痹一类异常状态给固定倍率（常见 1.5-2 倍），「控血加控状态」由此成为捕获前的固定仪式。
- 道具倍率：捕获道具分档（普通、进阶、特化），倍率拉出档差，是经济系统的出口；不搞隐藏修正。
- 等级与稀有度：高等级、稀有与传说个体单独定基础率；传说的期望尝试次数写进表里，按道具成本折算给玩家。

透明度与防挫败：

- 概率要可见：图鉴记录每只怪的基础捕获率；捕获过程给摇晃次数一类的过程反馈；连续失手要有代价上界，别让玩家在「就差一点」里空转。
- 保底与补救：多次失手后隐藏递增，或提供更贵的必中道具；误杀目标要有再遭遇的补救路径（刷新点、图鉴追踪），失败惩罚是「多花时间」，不是「永远错过」。
- 复利设计：让捕获率随图鉴完成度或事件进度小幅提升，使收集本身反哺收集效率，这是收集环最便宜的正反馈。

### 3.3 培养系统：成长曲线与简化取舍

培养是投入感的主体。四个旋钮，按项目体量取二到三：

| 旋钮 | 经典做法 | 简化建议 |
| --- | --- | --- |
| 等级 | 全队吃经验，后备位吃部分 | 保留；共享经验与批量补级是体验底线 |
| 招式表 | 升级学招式、道具教招式、遗忘可恢复 | 保留；按功能分槽：输出、控制、辅助、被动 |
| 个体差异 | 个体值加努力值双轨 | 小项目砍掉，用性格、特性或天赋一项替代 |
| 进化 | 等级、道具、条件三类 | 保留；进化条件是内容量的调节阀 |

- 成长曲线：经验曲线的形状决定「练级」是门槛还是背景；目标把练级时间压到总时长的一半以内，收集与探索才是主菜。
- 招式学习表与个性：每只怪 8-20 条可学招式，其中 2-3 条设为独占（别的怪学不到）；与其给每只怪配全能招式池，不如让每只怪有一两个「人无我有」的点，配一个可见的定位标签。
- 不可逆操作要有确认：进化、招式覆盖、道具消耗是三个最容易产生毁档感的动作；确认弹窗与「遗忘可恢复」是标配。

### 3.4 对战与交换：成果的验证与互补

对战是养成成果的验收，规模从简开始：

- 队伍形态：单打（1v1）加轮换是最小方案；双打与联机对战是扩展项，排期单列。
- 行动顺序与时长：按速度（含修正）排序的回合制，同速规则固定且可见，行动顺序可视化，玩家才能做「这回合该不该换人」的决策；常规遭遇 2-4 回合（30-90 秒内），精英与首领战 5-15 回合，捕获目标在场时战斗目标从「赢」变成「控制」，这个双目标是本类型独有的张力。
- 配队与可见性：队伍规模与属性覆盖是玩家自己解的数独，要鼓励按区域调整队伍，一队通关说明矩阵太窄；伤害区间、克制倍率、速度先手都游戏内可查，隐藏机制只留彩蛋。
- 交换：先做本地或离线交换（密码、局域网），联机交换需要服务器、合法性校验与防复制，成本量级完全不同（对照《联机与后端深入手册》）。

### 3.5 叙事框架：「成为大师」的旅程模板

这个类型的叙事有固定骨架，照着填比自创省力：

| 阶段 | 玩家目标 | 叙事锚点 |
| --- | --- | --- |
| 出发 | 拿到第一只伙伴，学会捕获 | 小镇、导师、初始三选一 |
| 成长 | 挑战分区域节点目标 | 每个节点绑定一个新地形与一批新怪 |
| 转折 | 遇见对手与反派 | 对手队伍随玩家进度成长，形成镜像 |
| 登顶 | 挑战终局考验 | 对玩家队伍的全属性检验 |
| 收尾 | 图鉴、稀有怪、隐藏区域 | 把「还没有的怪物」变成长期钩子 |

- 模板的功能是给收集提供地理与情绪动机：为什么去下一个区域？因为那里有新怪、有新考验、有故事；「分区域考验加终局考验」是骨架，试炼制、锦标赛制、开放区域制是三种常见变体，按地图结构选。
- 对手与传说怪是叙事线的两端：对手负责张力，传说怪负责收集线的终局奖励，两者各控制在个位数，演出预算留给少数节点；叙事的最小值是每到一个新区域，给一个「这里为什么值得来」的理由和一段本地生活侧写，没有叙事锚点的区域，收集动机很快耗尽。

## 4. 技术要点

**数据驱动与引用完整性**

- 五张核心表：怪物（属性、数值、进化链、图鉴文本）、招式（效果、威力、命中、学习条件）、属性矩阵、遭遇（区域、时段、概率）、道具。全部进 CSV 或 JSON，代码只留公式，禁止手改生成物；引用校验进 CI：进化前后 ID 存在、招式学习表引用的招式存在、遭遇表引用的怪物存在、每只怪有图鉴文本（表上千行后，拼写错误是最大 bug 来源，方法见《技术实现手册》）。

**战斗与捕获的结算分层**

- 把一回合先算成事件列表（谁对谁、多少伤害、是否捕获、是否倒下），再按列表播放演出；跳过与倍速只影响播放器，不影响结算。捕获在事件层是独立事件，日志与回放都挂在它上面；遭遇、捕获、暴击走可播种的确定性 RNG，异常能一键复现。
- 战斗状态机与场景解耦：遭遇 → 指令 → 顺序结算 → 事件播放 → 捕获判定 → 胜负与奖励 → 回场；每个状态可单测，图鉴与存档功能才挂得稳。

**存档与个体数据**

- 每只怪物的个体数据（等级、经验、招式、个体差异、昵称、捕获地）要可序列化、可迁移；存档 = 玩家队伍 + 图鉴 + 世界状态 + 版本号，版本迁移从第一天做。图鉴即数据库：捕获记录、分布信息、完成度奖励都从同一张图鉴表派生。
- 只要涉及联机交换或对战，怪物数据需要服务端校验（数值上界、招式合法性、来源标记）；单机项目也留好字段位，后补的成本高一个量级。

**内容管线与工具**

- 怪物工作台：改一张表就能在游戏内预览图鉴卡片、战斗形象与招式列表的调试工具。内容量越大回报越高，这是本类型最值得早投的工具。
- 美术规格先冻结：立绘、图标、战斗形象（动作帧或骨架）、叫声的尺寸与命名规范进资产台账，后期换规格等于全员返工；本地化从第一天做：怪物名、招式名、图鉴文本是文本量前三，全部字符串 ID 化，术语表先立后写。

## 5. 内容量与工作量参考

本类型的成本公式是乘法，不是加法：

`总内容量 ≈ 怪物数 × 每怪资产 + 招式数 × 每招资产 + 怪物 × 招式的学习表条目 + 场景与遭遇配置`

- 每只 2D 怪物一套资产（立绘、图标、战斗形象与动作、叫声、图鉴文本），小团队按天计价，常见一套 2-5 人日，3D 翻倍以上；每条招式 0.5-2 人日。学习表条目是隐形大头：150 只怪 × 平均 15 条可学招式 = 2250 条配置，每条都要过引用校验与平衡检查。
- 体量阶梯（常见量级，用于估算范围，不构成承诺）：

| 体量档 | 怪物数 | 招式数 | 属性数 | 定位 |
| --- | --- | --- | --- | --- |
| 原型 | 10-20 | 20-40 | 4-6 | 验证四环，白盒资产 |
| 小型完成品 | 50-80 | 80-120 | 6-10 | 图鉴初见规模，单人到小组 6-12 个月 |
| 常见独立作品 | 100-150 | 150-250 | 10-14 | 需要专职内容生产与工具链 |
| 大型作品 | 300 以上 | 500 以上 | 16-18 | 团队多年量产，靠系列化摊成本 |

- 对标风险：头部作品上千只怪物的体量是数十年、多代团队累积的结果，不要当第一作的目标；先按「50-80 只怪、一套循环打磨到好玩」立项，再按产能扩表。
- 排期与纪律：四环原型 3-5 周；垂直切片（一个区域、30-50 只怪、完整捕获与进化）3-6 个月；之后按内容量外推，扩图鉴比加系统便宜。怪物数是可加可减的旋钮，属性矩阵与招式系统是骨架：先冻结骨架，再按产能决定图鉴规模；砍怪物安全，砍循环危险。

## 6. 第一个原型怎么起步

目标：3-5 周做出「能抓、能养、能进化、能打、有图鉴」的最小四环，不碰联机交换、不做完整叙事、不做精美美术。

- 第 1 周：战斗与捕获闭环。3 只怪、4 个属性、8 条招式、一套捕获判定（含状态与血量修正），纸面推演加游戏内日志。
- 第 2 周：收集与培育。一张 10-15 只怪的遭遇表、升级与学招式、一条三段进化链、一张最简图鉴界面。
- 第 3 周：微缩内容。一个区域（3-4 种地形）、稀有度分层、一个区域考验节点、完成度奖励。
- 第 4-5 周：试玩与判断。找 5 个人玩到「抓到 10 只、进化 1 次、通过考验」。

成功标准（全部可观察）：

- 测试者在无人催促的情况下主动去抓第三只之后的怪（收集驱动成立）。
- 测试者能说出一只怪「为什么留在队里」（培育驱动成立），能说清净胜或惨败各自的败因（对战可复盘），并能复述两只怪之间的克制关系（矩阵被感知）。
- 改一个数值（捕获率或某条克制倍率）能在 10 分钟内量化影响，前提是日志与模拟脚本已就位。

决策门：四环里任何一环在试玩中断掉，先修那一环再谈扩表；「一怪一套资产」的量产一旦开始，返工成本会随图鉴规模放大。

## 7. 常见坑

1. **图鉴贪大**：立项就按上百只规划，做到第 40 只时美术与配置双双告急。规避：先用 30 只怪把四环打磨立住，量产能扩，循环不能省（§5、§6）。
2. **属性矩阵过密**：十几个属性配不足百只怪，克制关系互相稀释，玩家记不住也用不上。规避：先 6-10 个属性，每个属性在攻防两侧都有戏份（§3.1）。
3. **捕获黑箱**：不公布概率、没有过程反馈，连续失手半小时，玩家把账记在游戏头上。规避：概率可见、过程有反馈、失手有代价上界（§3.2）。
4. **培养无所有权**：个体差异不可见、不可转移，练了半天只是数值变大。规避：昵称、差异可视化、定位标签与独占招式（§3.3）。
5. **不可逆误操作**：进化、招式覆盖、道具消耗一键到底，玩家产生毁档感。规避：确认弹窗加可恢复的遗忘机制（§3.3）。
6. **招式表复制粘贴**：所有怪共用一套学习表，怪物只剩外形差异。规避：每只怪 2-3 条独占招式，按功能分槽设计（§3.3）。
7. **一队通关**：矩阵太窄或数值失衡，一个队伍吃穿全程，换怪失去意义。规避：用模拟脚本查使用率，动态调矩阵与遭遇（§3.1、§3.4）。
8. **战斗沦为过场**：遭遇十秒结束、没有决策，收集退化成捡东西。规避：让状态、控血、换人都有意义，常规战保持 2-4 回合的决策密度（§3.4）。
9. **交换与联机低估**：临时加联机交换，撞上服务器、合法性与防复制的三重工程账。规避：先做本地交换，联机单独立项（§3.4）。
10. **原创边界含糊**：玩法骨架可以借鉴，但怪物形象、名称与招式文本必须原创，不做受保护形象的换色、戏仿或高度相似设计；拿不准就查《法务、专利与竞争手册》。
