# Ludo Atlas · 类型手册 · 派对游戏（Party Game）

> **类型手册 P2 批次**（第 ㊱ 轮扩展）。定位：把「多人同乐的混乱感」做成第一体验的类型。规则看一遍就会，胜负让位给笑点；设计对象不是一个人的挑战曲线，而是一屋子人的情绪曲线。
> 配套：《游戏设计手册》（⑨，体验目标与核心循环）·《技术实现手册》（⑩，本地输入与设备管理）·《制作管理手册》（⑫，合集内容的范围与排期）·《案例研究集》（⑳，标杆拆解与复盘方法）。

## 1. 定位与核心循环

一句话定位：派对游戏是**以「一群人围着同一块屏幕又笑又叫」为第一体验**的类型。玩家为「刚才那一下」而来，不为通关而来；单局以分钟计，整场以小时计，评价标准是笑点密度而不是难度曲线。

核心循环用动词环写：

`看一遍就会 → 抢分或合作 → 混乱爆发（有人翻盘、有人翻车）→ 全场笑出声 → 结算吐槽 → 下一局`

这个环以分钟计。它成立的前提只有两条：门槛要低到任何人坐下的第一分钟就能参与（§3.1）；混乱要有边界，让人觉得「刚才是玩脱了」，而不是「这游戏在耍我」（§3.3）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 本地多人（couch-multiplayer） | 本地多人是「一屏共乐」的载体形式；派对游戏是它的内容组织方式：小游戏合集加流程导演。两者常重叠，派对更强调低门槛与笑点优先 |
| 合作闯关（co-op） | 派对可合作可对抗，核心是同乐；合作闯关的乐趣在协作解谜或共渡难关，气氛是副产品 |
| 社交推理 | 社交推理靠信息不对称撑起讨论；派对游戏的冲突发生在操作与运气层面，聊出段子发生在结算之后 |
| 竞技对战 | 竞技对抗追求公平与技巧分层；派对游戏主动引入随机与混乱，让技巧最弱的人也有赢的回合 |
| 淘汰闯关（在线综艺） | 淘汰闯关是派对游戏的一种流程骨架（§3.2）；差别在房间规模与平台，设计账目相通 |

一个自检问题：把同屏的其他人全部换成没有情绪的 AI，游戏还好玩吗？答案若为「差很多」，你做的就是派对游戏。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **零说明上手**：规则看一遍就会，第一局常常就是教学局，从坐下到开局不超过半分钟。
2. **混乱与笑点**：每一局至少产出一次「刚才那一下」；失败是表演的一部分，不是需要藏起来的羞耻。
3. **人人有事做**：从开局到结算没有长时间干等；被淘汰、被落下的玩家都有继续参与的方式（§3.2、§3.4）。
4. **输家也开心**：追赶与反转让落后者保留希望，结算的幽默感优先于严肃排名（§3.3）。
5. **再来一局**：局与局之间切换以秒计，比分悬念与新的随机把「下一局」推出来。

标杆作品（建议按客厅现场的标准亲手试，至少组织一次真人聚会再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 超级马力欧派对 | 小游戏合集加棋盘流程的标杆；单局短、回合清晰，流程层本身就是内容 |
| 胡闹厨房 | 合作混乱的教科书：沟通失败即笑点，难度曲线服务于喊叫密度 |
| 任天堂明星大乱斗 | 把格斗派对化：门槛调低（道具与舞台机关），高手技巧上限依然保留 |
| 马力欧卡丁车 | 道具制衡与追赶设计：末位玩家手里也有翻盘武器，全程没有出局者 |
| 人类一败涂地 | 物理喜剧：操作失控被设计成主要笑点，翻车比通关更有观赏性 |
| 糖豆人 | 在线淘汰综艺：把「翻车」做成可围观、可传播的公共景观 |
| 蛋仔派对 | 在线派对加 UGC：常驻流程骨架保证下限，玩家自制内容支撑内容量上限 |

## 3. 设计要点

### 3.1 低门槛与混乱设计

低门槛、高混乱是这个类型的两根柱子：门槛决定有几个人愿意坐下来，混乱决定笑点的产量。

- 门槛预算：玩家应该在看完别人玩一局之内学会操作。控制收敛到一个动词加一个方向（推、抢、跳、扔），按钮不超过两个；超出的操作要靠图标提示把它降回「看一遍就会」。
- 教学即第一局：不做独立教程关，把规则藏进一局正常游戏；目标物在视野里，第一次失误零代价，提示随设备变化（手柄、键盘、触屏三套图标，见 §4）。
- 混乱源清单：随机事件（风、落物）、道具搅局（逆转、交换位置）、物理翻滚、队友捣乱（可以推人、可以抢分）。每个混乱源回答两个问题：它制造什么笑点；它多大程度吞掉玩家的操作。
- 混乱纪律：混乱放在「结果」上，不放在「操作」上。输入要始终跟手，翻车要能被理解成「刚才我贪了」，而不是「这游戏在耍我」。
- 笑点优先：把翻车做成可见、可复述的：夸张的角色动画、音效，结算时给出一张「罪名清单」（被自己的道具炸飞三次之类）。
- 时长预算：单个小游戏一局 30 秒到 3 分钟；更长的玩法拆成两轮，聚会现场的注意力以分钟为单位流失。

### 3.2 合集结构：轮换、淘汰与计分

单个小游戏撑不起一场聚会。派对游戏的内容单位是「一场」：一组小游戏加一条把它们串起来的流程线；流程线负责制造上下文（比分、悬念、复仇理由）。

三种常见骨架：

| 骨架 | 结构 | 适合场景 | 主要风险 |
| --- | --- | --- | --- |
| 轮换式 | 固定回合数，小游戏随机或轮换抽选，围绕一条主进度（棋盘、积分榜）推进 | 客厅 4-8 人长局 | 主进度太长会把节奏拖散 |
| 淘汰式 | 每关淘汰末位若干人，直到决出冠军 | 在线大房间、直播与观战 | 被淘汰者提前离场，观战体验要单独设计 |
| 计分式 | 每个小游戏独立计分，累计排名 | 任意人数、即来即走 | 强者滚雪球，需要追赶分与补偿设计 |

流程导演层要定四件事：

- 谁来选下一个：随机抽、落后方选、赢家禁选；选择权本身就是社交货币。
- 平局与并列怎么处理：留给节目效果（同分加赛一局），别用复杂规则解释。
- 比分如何展示：常驻小计分板；终盘前让悬念可见（末轮双倍分、连环奖励）。
- 节奏切换：两局之间 5-10 秒，计分板闪一下即可；换场演出超过 10 秒就会有人开始看手机。

一条验收：拿掉流程层、只留单个小游戏，测试者玩到第几遍才腻？三遍就腻的话，说明这场聚会需要流程层供上下文，也说明你选错了第一个小游戏（§6）。

### 3.3 输家也要开心：追赶与反转

派对游戏的输赢是节目单，不是判决书。落后者是否愿意留到散场，取决于三件事：还有没有扳平窗口、失败好不好笑、结算给不给体面。

追赶机制分三档：

| 机制 | 做法 | 代价 |
| --- | --- | --- |
| 落后补偿 | 落后者拿到更多或更强的资源（道具、时间、分数系数） | 领跑者会感到不公，补偿要隐形、幅度要小 |
| 高方差事件 | 把翻盘机会集中在终盘（末轮双倍、随机大事件） | 方差过高时技巧无处证明，高手的挫败是真实情绪 |
| 无效性设计 | 领先只改变排名，不改变体验（全员同屏混乱，人人有戏份） | 需要内容量撑住，好处是无代价 |

输家的三个出口，逐条设计，缺一条就有玩家开始看手机：

1. **还有下一次**：每个时刻都要留着「下一局还我」的理由：没抽到的道具、没抽到的小游戏、差一点的比分。
2. **失败被表演**：翻车瞬间放大演出（受击动画、音效、回放），结算给出非排名奖励（最惨瞬间奖、最多次被误伤奖）。输掉的玩家拿到的是段子，不是分数。
3. **体面的退场**：淘汰式结构里，被淘汰者要有观战身份、投票权或捣乱权（观众投票加时之类）。干等是冷场最快的方式。

一条纪律：可以让人输，不能让人屈辱。惩罚做成幽默素材，不要做成羞辱动作。

验收标准：输掉整场的人在结算后 10 秒内主动提「再来一局」，或把刚才的翻车讲给旁人听，发生一件就算过；组织 5 场聚会观察，落后者中途离场次数 0-1 次为合格。

### 3.4 本地多人：设备、座位与信息分配

派对游戏的现场是一块屏幕加一堆人，设备与座位就是关卡设计：谁拿什么、谁看哪里、谁在等，都决定体验。

- 设备槽位：把「设备」与「玩家」解开。手柄、键盘半区、触屏各自注册为槽位，槽位再绑定玩家（名字、颜色、头像）；支持热插拔与中途加入，新玩家拿起手柄按任意键即可上车，离开不打断正在进行的一局。
- 手机当控制器：大屏出画面、手机出输入与私人信息的做法（Jackbox 系列是代表）。桌面或电视放主画面，玩家扫码或输入房间码打开网页，免安装；适合回合制、投票、答题、文字类玩法，实时操作类玩法对网络延迟敏感，留在本地手柄上更稳。实现档位见 §4。
- 信息分配：公开信息放大屏（比分、局势），私人信息发到手机（词条、投票、身份）。信息不对称是派对游戏最便宜的内容生成器：同一块屏幕，每个人知道的和担心的都不一样。
- 视角方案：优先共享视角（一台相机装下所有人），笑点必须发生在同一块屏幕上；分屏会把一个笑点撕成两半。共享视角要处理「装不下」：拉远、区域跟随、关键时刻强制全员同框。
- 等待的座位：等轮次的人、观战的人、排队的人，各自要有角色。超过 30 秒的等待窗口，要么缩短，要么给替代参与方式。

### 3.5 小游戏的数量与质量

- 数量账：20 个小游戏里通常只有 8-12 个真正好笑，把「能抽到就有人笑」当及格线。方案：先做 6-8 个精品，再用变体扩量（同一机制换参数、换主题、换混乱源），变体不算新机制。
- 质量分级（逐个过三问）：第一次玩笑不笑？第三次玩还笑不笑？第十次被抽到愿不愿意？有一问不过就进返工队列，别靠数量掩盖。
- 重玩性排序：人随机 > 小游戏随机 > 参数变体。一群新玩家带来的变化远大于再做一个新小游戏，先把你已有小游戏在不同人群里的表现摸清楚。
- 淘汰纪律：小样本测试里笑声密度最低的两个，直接砍，别抢救；抢救一个不好笑的小游戏，成本高于新做一个。
- 与流程层的关系：小游戏接口统一（§4）才能被流程层自由轮换、组合、加赛；每次新增小游戏只写玩法本身，不改流程代码。

## 4. 技术要点

工程难点集中在四块：输入与设备管理、小游戏框架、画面与视角、网络（要做手机控制器或在线时）。以下与引擎无关。

**输入与设备管理**

- 玩家槽位与设备解耦：设备（手柄、键盘半区、触屏、手机）先注册为槽位，槽位再绑定游戏内玩家；所有小游戏只读「玩家输入」，不关心它来自哪个设备。热插拔、中途加入、设备互换都只动登记层。
- 混合设备矩阵全部测到：手柄加键盘分半是客厅常态，每个小游戏声明自己需要的输入类型（方向、按钮数），框架负责过滤与提示。
- 按键提示随设备切换：同一个动作在手柄、键盘、触屏上显示对应图标；提示错设备是新手最大的挫败源。
- 中途加入与退出：加入从下一小局生效，不打断进行中的一局；退出用机器人托管或直接跳过，不暂停全场。

**小游戏框架**

- 统一接口是第一个要写的系统：每个小游戏实现「初始化、输入映射、每帧更新、结算上报、清理」五件事，流程层只认识接口，不认识具体玩法。没有这层，第五个小游戏之后的排期会全线爆炸。
- 记分板与小游戏解耦：小游戏只上报原始结果（名次、分数、用时），流程层负责换算与展示。
- 每个小游戏独立可运行：调试时跳过流程直接进单个小游戏；参数（时长、难度、混乱频率）进配置文件，可热改。
- 机器人玩家与单人自测模式在第一个小游戏里就留接口；没有机器人，你测不了四人流程。

**画面与视角**

- 共享视角的相机要保证：全员在框内、关键物可读、混乱时刻不丢主要角色。测试方法：乱斗最激烈时截图，检查有没有玩家出画。
- 大屏适配：客厅电视与投影的观看距离远，字号、图标、颜色对比按「几米外能读」设计，教程与提示文字全部图标优先。
- 性能预算：混乱场景里粒子与物理对象设上限；掉帧会同时毁掉手感与笑点，低配档位的帧率单独设线。

**网络（手机控制器与在线）**

- 手机控制器起步做法：局域网内自建房间加网页控制器，房间码或扫码进入；协议与容错的完整方案以《联机与后端深入手册》（㉖）为准。
- 实时操作类玩法不要放到手机网络输入上：延迟会让「操作失误」与「网络卡顿」无法区分；回合制、投票、文字类是手机输入的主场。
- 掉线与离开：房间里任何人掉线，流程要能继续（跳过、托管、重新入座），派对现场没有耐心的等待。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 单小游戏原型 | 1 个小游戏加一个记分板 | 2-4 周 | 验证「看一遍就会」与笑点，先别做合集 |
| 小型派对包 | 6-10 个小游戏加一条流程骨架 | 单人或小团队 3-6 个月 | 独立团队最常见的起点形态 |
| 完整商用派对游戏 | 20-30 个小游戏、多模式、本地加在线 | 团队 1-3 年 | 内容与打磨占大头，流程层往往反复重做 |
| 在线派对加 UGC | 上述再加服务器、房间与创作工具 | 2 年起步 | 内容更新与运营是长期账单 |

内容账的两条暗线：

- 每个小游戏的隐藏成本接近本体：教学演出、结算画面、音效、失败动画、平衡参数、全设备组合的回归测试。按「本体一半、配套一半」记账；20 个小游戏就是 20 套演出管线，框架化（§4）是把这笔账压下来的唯一办法。
- 变体是性价比最高的扩展：一个好笑的小游戏加三个变体（换主题、换参数、换混乱源），比新做一个原型便宜得多，笑点还已经被验证过。

排期锚点：从零到「一个小游戏让测试者笑了」通常 2-4 周；到「六个小游戏加流程骨架的垂直切片」通常 3-5 个月；之后按小游戏数量外推，并预留流程层的返工时间。数量不是目标：12 个「每个都值得抽到」的小游戏好过 30 个「抽到就烦」的小游戏。

## 6. 第一个原型怎么起步

第一个原型只做一个小游戏加一个粗糙的记分板，2-4 周完成，不碰在线、UGC、美术与剧情。

**第 1 周：选一个混乱源，做一个四人同屏小游戏。** 一个动词、一个目标、一处混乱（随机事件或道具）。设备层先跑通四个槽位（手柄加键盘分半），把输入登记与按键提示做出来，它们是小游戏的地基。

**第 2 周：用真人验证「看一遍就会」。** 找四个没玩过的人，不给说明，让他们直接上手。记录三件事：多少秒后开始有操作；第一次笑声出现在什么时刻；谁在什么时候安静了下来。安静比骂声更危险，它意味着没参与感。

**第 3 到 4 周：加上最粗的流程层。** 记分板、三个小游戏（后两个可以是第一个的变体）、结算画面、再来一局按钮。验证流程层能否把「下一局」推出来。

成功标准（全部可观察）：

- 陌生人无解释 30 秒内开始玩，第一局内至少出现一次全场笑声。
- 输掉的人主动说「再来一局」，或把刚才的翻车讲给别人听。
- 四人同屏全程不掉帧到影响操作，全员始终在画面内。
- 单人加三个机器人也能把流程跑完（为了自测，不是为了好玩）。

验收不通过就不做第二个小游戏。这个类型的第一要务是把「笑点配方」炼出来：第一个小游戏好笑之后，把配方复制成第二、第三个，而不是开新机制赌博。

## 7. 常见坑

1. **用文字讲规则**：说明书、长教程、大段提示。改成看一遍就会：一个动词、图标提示、第一局即教学。
2. **把派对做成竞技**：追求公平与技巧深度，笑声消失。派对游戏的平衡目标是「没有人被碾压到失去笑声」。
3. **人数只按四人设计**：2 人、3 人、5-8 人、奇数人数、中途加入退出，全部要有预案；客厅人数从来不由设计决定。
4. **干等窗口失控**：淘汰、轮流操作、回合制里有人长时间旁观。超过 30 秒的等待要么缩短，要么给替代参与。
5. **小游戏数量虚胖**：堆到 30 个，一半不好笑，抽到就是惩罚。砍到「每一个都值得抽到」为止。
6. **随机性吞掉操作**：混乱过头，输入不跟手，玩家把账记到游戏头上。混乱放在结果上，别放在操作上。
7. **追赶设计失衡**：强者恒强没人跟，补偿太露骨（专打第一名）又引发真实情绪。补偿要隐形，翻盘机会放在终盘。
8. **设备矩阵没测全**：只测了开发机上的两只手柄。型号、热插拔、加入退出、提示图标，建矩阵逐项过。
9. **笑点不可见**：翻车发生在分屏角落或各自屏幕里，笑不起来。优先共享视角，把笑点放上同一块屏幕。
10. **流程与结算粗制**：开场、计分、颁奖全是默认 UI。这些界面承担一半笑点，按与一个小游戏同级的预算做。
11. **过早上联机**：本地还没笑够就上网络，延迟与掉线先把气氛掐死。笑点配方在本地炼成之后，再考虑在线化。
