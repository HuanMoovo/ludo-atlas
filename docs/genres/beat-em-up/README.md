# Ludo Atlas · 类型手册 · 清版动作（Beat'em up）

> **类型手册 · 第三辑**。定位：把「以一对多」的群架做成第一乐趣的横版动作类型。玩家在包围圈里读站位、切连段、用投技解围，一段一段清场推进。
> 配套：《游戏设计手册》（核心循环与手感清单）·《技术实现手册》（战斗判定与同屏性能）·《关卡设计手册》（波次编排与节奏曲线）·《独立开发生存手册》（范围与排期）。
> 本文不放外链，交叉引用用手册名与轮次编号；文中数字均为参考值，以你自己项目的实测与试玩为准。

## 1. 定位与核心循环

清版动作（Beat'em up，街机时代也译作横版过关、清版游戏）从《双截龙》与《快打旋风》一路定型：固定视角的横版推图，敌人成组出场，玩家用连段、投技与必杀把包围圈一次次打开。它和格斗游戏共用一套动作词汇，解决的问题却不同：格斗是两个人的读帧博弈，清版是一个人读一群人的站位。

一句话定位：清版动作是**把「以一敌多」的身体对抗做成第一乐趣**的类型。单挑打赢没有意义，怎么在人群里打出空间、打出回合感，才是它的题目。

核心循环用动词环写：

`读站位 → 切入连段 → 击飞或投掷制造空档 → 转身处理包抄 → 清场 → 解锁推进`

这个环以一场交锋为单位，10 到 30 秒跑一圈。节拍器是卷动锁定（scroll lock）：向前走到触发点，镜头锁住，波次登场，清完才解锁，压力与呼吸都由「锁、清、推」的循环分配。它成立的前提有两条：群战结构要公平（§3.1），打击反馈要到肉（§3.2）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 格斗游戏 | 格斗是 1 对 1 的帧数据博弈；清版是一对多的空间管理，难度来自包围与包抄，不来自读帧 |
| 无双（割草） | 无双用敌人数量撑场面，一击扫倒一片；清版同屏三五个敌人，每次交手都要求攻防读解 |
| 动作 RPG | 动作 RPG 把成长与掉落缝进战斗，变强靠数值；清版的主角强度整局基本不变，变的是玩家的招式语汇 |
| 横版跑轰 | 跑轰主打远程与机动；清版的战斗在贴身距离发生，抓取与投技是核心工具 |

一个自检问题：把同屏敌人减到一个，游戏还成立吗？答案若是「成立」，你做的更接近格斗；清版的乐趣必须长在「多」上面。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **群战掌控**：每个方向的威胁可见、可读、可处理，输了怪自己，不怪背后那一下。
2. **打到有肉**：连段的每次命中都有重量，反馈三件套（§3.2）一个不缺。
3. **推进节奏**：锁屏、清场、前进的节拍干脆利落，压力有起有落。
4. **招式表达**：连段、投技、必杀构成玩家的招式语汇，玩得久了能打出个人风格。
5. **并肩作战**：双人合作是原生配置，混乱与默契都是乐趣本身。

标杆作品（建议亲手玩过再拆，群战的节奏只看视频学不到）：

| 作品 | 可学的点 |
| --- | --- |
| 双截龙（1987 起的系列） | 双人合作的起点；敌我同源的动作设计（敌人也能抓、也能投）；友军误伤留下的传统 |
| 快打旋风（1989） | 波次清场与锁屏推进的行业模板；抓取投掷的攻防读解；敌兵职能分工 |
| 怒之铁拳 2（1992） | 连段与必杀的成熟形态、Boss 与配乐的记忆点、难度曲线 |
| 怒之铁拳 4（2020） | 现代像素清版的完成度标杆：帧数打磨、连段延续、难度分层与联机 |
| 恐龙快打（1993） | 武器与枪械的拾取使用、投掷物互动、街机式的密度与节奏 |
| 忍者神龟：施莱德的复仇（2022） | 多人联机的现代实现、经典模板的当代完成度、像素美术的工程量级 |

## 3. 设计要点

### 3.1 群战结构：包围圈、锁定与受击保护

清版的核心矛盾：玩家一次只能朝一个方向输出，敌人却从四面八方围上来。设计的大半工作是在「压力」与「公平」之间配平，压力小了变割草，公平失守变围殴。四个工具：

| 工具 | 做法 | 解决的问题 |
| --- | --- | --- |
| 攻击配额 | 同一时刻只放一两个敌人获准出手，其余在包围位踱步或逼位 | 全员扑上来把玩家连死；让攻防有回合感 |
| 包围槽位 | 敌人在玩家周围维护几个战位（正前、侧翼、背后），出手后让位换人 | 群战有编排感，玩家读得出下一个威胁方向 |
| 锁定取向 | 出招自动转向最近的敌人，玩家输入方向可覆盖；不做手动锁定 | 「打不中身边的怪」的挫败；键盘与手柄都要打得准 |
| 受击保护 | 我方受击后 0.3-1 秒无敌加闪白（参考），期间再受击只出小硬直、不结算伤害 | 被围殴无限连死；给玩家一个能操作的脱出窗口 |

两条纪律：

- 数值分开建表：我方无敌（受击后、起身、必杀）与敌方受击硬直是两套参数，混在一个值里，改哪边都会伤另一边；敌方硬直还要撑得住一段连击，短于连段总时长，连段打到一半对手就还手，压制感全丢（做法见《技术实现手册》）。
- 背身压力可以有，但要有预告：绕后的敌人先给位移或音效提示，无预警的背刺是差评来源。同时给玩家一到两个随时可用的脱出工具（解围技、位移或抓取），没有脱出手段的围殴不成立。

### 3.2 打击感三件套：命中停顿、震屏、音效

打击感是清版的门面。动画与特效是预算问题，真正决定「打到没打到、打得狠不狠」的是三件装置，全部与判定帧同步：

| 装置 | 做法 | 参考量级 |
| --- | --- | --- |
| 命中停顿 | 命中瞬间攻守双方一起冻结几帧，重击更长，必杀最长 | 30-100ms，按招式分档 |
| 震屏 | 镜头小幅位移，方向可跟随攻击方向，按伤害档分级 | 轻击极小，重击与投技上探，幅度盖不过读招 |
| 音效 | 分层：挥空破风、命中皮肉或金属、暴击破防、敌兵惨叫与应声 | 每个角色一套音色；并发设上限 |

三条纪律：

- 调校顺序：停顿与受击反应在前，震屏与粒子在后。顺序反了会变成烟花表演，玩家读不出打没打中。
- 停顿是连段节奏的一部分：快刀与重拳的停顿帧数不同，一套连击才有轻重缓急；全程一个值，手感会平。
- 击飞、浮空、倒地、追打是清版的反馈链条：段尾按击倒或击飞收招，让玩家在「安全」与「追打」之间做选择，命中反馈就长出了决策。

### 3.3 波次设计：推进、锁屏与压力曲线

一段关卡由战斗段与连接段交替组成：连接段负责走路、拾取与场景叙事，战斗段由锁屏点触发。前进到触发线，镜头锁住，敌人分批进场，清完解锁。参数先建表：

| 参数 | 参考 | 说明 |
| --- | --- | --- |
| 单波人数 | 2-4 | 开场 1-2，标准段 2-4，高潮段 4-6 并分批进场 |
| 同屏上限 | 4-6 | 先按目标机型与可读性定死，波次设计在预算内做 |
| 批次 | 1-3 批 | 分批进场维持压力波峰；一波清太快，段落会显得空 |
| 进场方式 | 走入、跳入、破门、上下层 | 同一场景的波次换着出场，重复感就低 |
| 兵种配比 | 基础、干扰、压制、精英 | 每波至少两种职能，组合才构成「问题」 |

组合方法：把每一波当成一道题。基础兵负责填充与教学，跳跃兵逼玩家做垂直应对，远程兵逼玩家先处理位置，精英兵负责承伤与压节奏。新兵种先单独登场两次，再放进混编波次。

强度旋钮有四个：数量、职能组合、地形（窄巷、桥面、电梯）、场景道具与投掷物，只拧数量旋钮，得到的是无聊的堆怪。节奏曲线：一段关卡放 3 到 5 个战斗段，中间用连接段呼吸；高潮放高密度群战或 Boss，Boss 前留一段空场。强度不能单调递增，要有落点，玩家才有余力把招式用出来。

### 3.4 招式骨架：连段、投技与必杀

玩家的招式语汇收在三层里（参考键位：攻击、跳跃、特殊三键起步，抓取用接触触发或专用键）：

| 层 | 内容 | 设计要点 |
| --- | --- | --- |
| 连段 | 3-4 段普攻，段尾击倒（安全）或击飞（续接） | 连段窗口与取消规则进数据表，动画与逻辑共用一份 |
| 抓取与投技 | 抓小兵、打两下摔出去、投掷砸到第三人 | 清版的招牌工具：既是输出，也是解围与群体控制 |
| 必杀与解围 | 一键对周围敌人击退或击倒的解围技 | 常带代价（前摇、资源或少量体力），把「用不用」变成决策 |

角色差异做在三个轴上：速度、范围、力量，再加一个专属动作。差异要可感，但共用同一套骨架，否则每个角色都等于一关的内容量。防御要不要做是取向问题：经典作品大多没有独立的格挡键，用走位、抓取与解围技替代；加入防御会显著改变围殴压力的形状，先想清楚再动。

### 3.5 双人合作：经典玩法与现代实现

双人同屏是这个类型的原生产品形态：双截龙把「两个人一起打」做成卖点，共享镜头、共享锁屏、共享混乱。经典零件今天仍然适用：

- 共享镜头：两人都不能出画；掉队用边缘约束、追赶加速或短暂无敌追进处理，不让任何一个人被拽着走。
- 友军误伤：双截龙留下的误伤传统制造笑料也制造摩擦，现代作品通常默认关闭，或做成可选项。
- 敌量缩放：两人时把波次人数与同屏上限上调（参考：三成到一倍），保证两个人都有仗打；照搬单人曲线，会变成抢怪或一个人看戏。
- 死亡与复活：倒地后等待救援，或按命数复活；两人全灭才失败；复活的无敌时间要能撑过混战。

现代实现分两条路：

- 本地同屏：工程量最小、体验最稳，仍是首选；两个输入设备的分流与界面分配做清楚即可。
- 在线联机：重头不在玩法，在同步、延迟、断线重连与匹配，测试成本远高于本地；预算不足时，平台的远程同乐类功能可以低成本覆盖一部分异地双人的需求。无论选哪条路，双人都要单独测试：单人的平衡数据在双人局里不成立，节奏、压力与目标感是另一套账。

## 4. 技术要点

工程难点集中在四个系统：战斗判定、群战 AI、同屏性能与手感基础设施。以下与引擎无关，点名的是概念与结构。

**战斗判定**

- 近战攻击用「攻击帧挂判定盒」实现：前摇、判定帧、后摇、判定盒形状全部进数据表，判定帧在调试工具里可视化。
- 同一次攻击对同一目标只结算一次命中：记录已命中目标的列表；多段攻击拆成分段列表单独配置。
- 投技用状态绑定实现：抓住后双方进同一状态机，挣脱计时、摔投方向与砸到第三人时的伤害都在这里分流；投技是判定与视觉不一致的重灾区，要单独测。
- 受击结果分三层：小硬直（连段中）、击飞（段尾）、倒地（可追打、起身无敌）。谁打断谁、什么状态可被抓，写成明确的表，不要散在代码分支里。

**群战 AI**

- 三层结构：行为层管单个敌人的状态机（逼近、包围、出手、受击、倒地、脱出）；导演层管攻击配额、战位分配与压力节奏；数据层管每个兵种的参数（速度、出手欲望、硬直）。
- 包围与分离：给敌人分配环绕玩家的目标点，彼此做分离避免堆成一坨；出手过的敌人让位回到后场重新排队。
- 屏幕外规则：画面外的敌人不做出手决策，或先走位进画；远程兵进场先给音效或画面预告，禁止无预警偷袭。
- 把战位、配额与状态做成可视化调试层：AI 的问题多半是看不见才调不出来。

**同屏性能**

- 同屏上限先做压测再定死（按目标机型），波次与特效设计在预算内做，不靠事后砍。
- 对象池覆盖敌人、特效、伤害数字与投掷物，像素动画走图集与合批、控制材质切换；音频并发设上限与优先级，命中音优先于环境音，否则混战会糊成一锅粥（见《技术实现手册》）。

**手感基础设施**

- 输入缓冲、连段窗口与固定步长：后摇结束前按下的下一段要被记住并消费，窗口值进数据表、动画与逻辑共用一份配置；击飞、倒地与受击保护用固定步长（常用 60Hz）计时，混战里才可复现、可调参。
- 关卡脚本数据化：波次与锁屏用脚本文件描述出场时点、位置、兵种与条件，让非程序也能调关卡。

## 5. 内容量与工作量参考

先记一条乘数法则，它也是这个类型最大的内容量陷阱：成本是乘出来的。敌兵种类乘以关卡段数乘以出场组合，一个敌兵要在每个关卡段里验证一遍（地形、包围、投掷物、与其他兵种的组合）；再乘以可玩角色数，每个角色都要对全部敌人与关卡再做一遍平衡。Boss 单独乘一层：一个 Boss 的招式、脚本与演出调试量，通常等于 3 到 5 个普通敌兵。动画量级（参考）：一个普通敌兵的动作集（待机、走、两三种攻击、受击、击飞、倒地、起身、被抓、死亡、特殊行为）通常 15 到 25 组；可玩角色更多，含连段、必杀与投掷通常 25 到 35 组。像素动画按帧手绘时，这些数字直接换算成人月。

| 项目形态 | 敌兵种类 | 关卡量级 | 周期量级 | 备注 |
| --- | --- | --- | --- | --- |
| 群战原型 | 2 种 | 1 个单屏房间 | 2-4 周 | 只验证群战结构与打击感 |
| 首作 / 小型完整作品 | 6-10 种（含变体） | 6-8 关 | 6-12 个月 | 3-4 个主题，敌兵用变体填密度 |
| 常见独立作品 | 10-20 种 | 8-12 关 | 1-2 年 | 多可玩角色与联机各吃掉一大块预算 |
| 商业规模 | 20 种以上 | 12 关以上 | 2 年以上 | 分阶段发布内容 |

小团队的现实切面：

- **敌兵做变体，不做新品种**：换武器、换体型与速度、加一招核心行为，就是新兵；新骨架留给招牌兵与 Boss。
- **关卡主题收在 3 到 5 个**：靠布局与波次配置做出差异，而不是不停开新美术。
- **可玩角色 1 到 2 个起步**：第二个角色的成本约等于「一个角色的动画与平衡账乘以全部关卡」，加人前先算这笔账。
- **首作砍掉四样**：在线联机、多分支路线、多结局、角色养成系统，任意一样都够再吃几个月。

排期锚点：群战手感原型 2-4 周；到「一关达到发行质量」的垂直切片通常 2-4 个月；之后按内容量乘打磨系数外推。这个类型的大头预算在敌人动画与关卡美术，以及打磨时长。

## 6. 第一个原型怎么起步

第一个原型只做一个单屏房间：一个可玩角色、两种敌兵（一只基础兵加一只包抄兵）、一次锁屏清场。不碰美术、剧情、存档与菜单，2-4 周。

**第 1 周：连段与击倒。** 3 段普攻、击退、受击硬直、击倒与起身无敌；判定帧可视化与数据表先搭起来。这个阶段丑是应该的。

**第 2 周：群战结构。** 三个包围战位、攻击配额（同时最多一两人出手）、受击保护与锁屏流程（清完才解锁）。这一步没通过之前，不要加第三种敌人。

**第 3 周：打击感三件套。** 命中停顿、震屏、音效分层（占位素材即可）。每装一件录一次屏做对比，参数全部可热改。

**第 4 周：一次测试。** 找 3 到 5 个没玩过的人，单人一遍、双人一遍，记录被包抄时的反应、连段被打断的次数、清场后多久继续前进。不提示、不解释。

成功标准（全部可观察）：

- 灰盒加占位音效，测试者仍愿意反复打同一波 10 分钟以上。
- 受击与死亡，测试者能自己说出原因（被包抄了、贪刀了、起身太慢），而不是「莫名其妙就死了」。
- 双人测试时两人都有事做；全灭后有人主动说「再来一局」。
- 改一个手感参数（命中停顿帧数或无敌帧时长），5 分钟内能在运行的游戏里看到差别。

群战结构与打击感验收不过，就不要开始铺内容：地基上的返工，会乘以全部关卡与敌兵（§5）。

## 7. 常见坑

1. **群战规则失守**：全员同时扑上来，或画面外的敌人无预警出手，玩家被围殴到无法操作；攻击配额与背身预告缺一不可（§3.1）。
2. **打击感只做动画**：没有命中停顿与震屏，连击像放幻灯片（§3.2）。
3. **无敌帧与受击保护混成一个值**：缺了被连死，长了打不痛；我方无敌与敌方硬直分开建表。
4. **判定与视觉不一致**：拳脚判定比画面长太多或短太多，玩家读不出距离；判定以视觉为准，宽容留在判定一侧。
5. **波次只拧数量旋钮**：六只同款敌人不如三种兵各两只，压力要来自职能组合（§3.3）。
6. **双人是单人的加法**：敌量不随人数缩放，两个玩家抢怪或一个人看戏；双人必须单独配曲线、单独测试（§3.5）。
7. **内容量按线性估**：敌兵乘关卡乘组合乘角色（§5），超支通常超在乘号上。
8. **只调单人平衡**：上架前没测过双人，节奏与难度全是盲区。
9. **首作范围超载**：四人联机、多分支、养成系统一起上，一个都做不完；清版的完成度在打磨里，收范围是唯一解（见《独立开发生存手册》）。
