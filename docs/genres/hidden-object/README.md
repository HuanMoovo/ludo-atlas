# Ludo Atlas · 类型手册 · 寻物找茬（Hidden Object）

> **类型手册 P3 批次**（第 ㊵ 轮扩展）。定位：把「在密集画面里找到目标」做成第一乐趣的观察类休闲游戏。玩家用眼睛完成主要内容：扫视、辨认、点击；每一幅手绘场景就是一张考卷，本页覆盖找物动态、场景美术成本、叙事结合、变体谱系与移动端变现结构。

## 1. 定位与核心循环

寻物找茬（Hidden Object，含找不同与互动寻物两支近亲）是休闲游戏的支柱品类。它的前身是绘本与杂志上的寻找游戏（威利在哪里那一支），PC 时代由大鱼的 Mystery Case Files 系列（2005 年起）撑起产业，移动时代又被《找你妹》（2012）与《June's Journey》（2017）带到了更大的用户面前。会看就会玩，几乎没有前置门槛。

一句话定位：寻物找茬是**把「自己看到」做成第一乐趣**的类型。目标就摊在画面里，答案不在逻辑里，而在眼睛与注意力里；设计工作围绕一件事展开：把「发现」做得频繁、响亮、便宜。

三个尺度的核心循环：

| 尺度 | 循环 | 玩家得到什么 |
| --- | --- | --- |
| 一次点击（1-3 秒） | 扫视 → 辨认 → 点击 → 命中或落空 | 一次确认：是它，或者不是 |
| 一幅场景（2-15 分钟） | 读清单 → 分区扫视 → 逐个找到 → 完成结算 | 清空清单的完成感 |
| 一条主线（数天到数周） | 章节推进 → 解锁新场景 → 收集与装饰 → 下一章 | 前进感与长期目标 |

循环成立的三个前提：画面要经得起「看」，因为场景就是全部内容，密度、主题与细节决定玩家愿不愿意多盯两秒（§3.2）；找到的瞬间要兑现，命中反馈是全品类唯一的爽点货币（§3.1、§4）；卡住要有出口，提示是安全网，没有它，收尾的目标会变成流失点（§3.1）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 逻辑解谜 | 解谜的进度来自推导规则；寻物的答案已经全部给出，进度只来自视觉辨认，考注意力，不考推理 |
| 点点点（Point-and-Click） | 点点点要玩家自己判断用什么道具、用在哪里；寻物只需找出清单上的一切；两者在 HOPA（寻物解谜冒险）里合流 |
| 找不同 | 同一家族的另一半：一个对照清单找目标，一个对照两幅图找差异；共用反馈设计与生产管线（§3.4） |
| 放置与收集 | 物品自动收取、玩家只负责确认与升级时，乐趣已从「发现」转成「积累」，那是放置类的内容包装，不是寻物 |

自检问题：把目标物全部高亮、清单撤掉，游戏还剩下什么？若是空无一物，你做的就是寻物；若还玩得下去，说明你的核心其实是别的机制，先按对应的类型手册立项。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **发现的瞬间**：目标从背景里「跳」出来的一刻，是全品类唯一的核心爽点；命中要即刻、响亮、可累积。
2. **低门槛与无压力**：不读规则就能开始，随时可以停下；主线不设失败，限时与提示都是可选压力阀，赶时间的有成绩可拼，慢慢看的不会被催促。
3. **值得凝视的画面**：找不到的时候也不无聊，密度、主题与可点的小互动让「看」本身有趣。
4. **有理由看下一幅**：剧情悬案、地图解锁或收集清单，给「再来一幅」一个牵引。

标杆作品（建议亲手玩过再拆，各产品解「找不到」的方式完全不同）：

| 作品 | 可学的点 |
| --- | --- |
| 威利在哪里（绘本） | 品类的直观原型：密集手绘场景里找特定角色；「找谁」比「找什么」更有记忆点 |
| Hidden Folks（隐藏的家伙） | 黑白手绘加全场景互动；无时限、无分数，证明「找」本身可以独立成立 |
| 大家来找茬 | 找不同的国民记忆：两图对比、限时比快 |
| 找你妹 | 2012 年的国产爆款：搞怪清单、限时关卡与道具的组合，验证了轻度寻物的传播力 |
| Mystery Case Files 系列（大鱼） | HOPA 的定型者之一：一集一案，用寻物场景推进悬案，连载二十余年 |
| June's Journey（琼的旅程） | 移动端长线结构：寻物、剧情、装饰经营与团队竞赛；长期位列品类收入头部 |

共同点：核心动词只有一个「找」；场景美术就是竞争力本身；反馈的打磨优先级高于难度设计；长期留存来自画面之外（剧情、收集、竞赛）。四条都做到，作品不会差。

## 3. 设计要点

### 3.1 找物机制与动态

一个场景里能动的旋钮只有五个：区分度、时限、提示、连击、反馈。全部做成可调参数进数值表（方法见《游戏设计手册》（⑨）），别散落在代码里。

| 旋钮 | 作用 | 设计口径 |
| --- | --- | --- |
| 区分度 | 决定单次寻找的难度 | 藏得合理：被遮挡、被伪装、色调相近；难度来自遮挡关系，不来自分辨率（§7） |
| 时限 | 制造紧张与重玩动机 | 主线默认宽松（按测试平均用时给足余量），限时放进独立模式或挑战关；到时降档成提示，不清空进度 |
| 提示 | 卡住的出口 | 分三级：冷热探测（接近时音效与光标变化）→ 圈定区域 → 直接圈出；主线永远保留免费路径，付费与广告买的是加速（§3.5） |
| 连击 | 奖励「找得快」 | 连续命中累加成绩、点错断连；只奖励，不惩罚 |
| 反馈 | 兑现发现的瞬间 | 命中：动画、音效、清单勾选；点错：轻反馈（摇晃、低音），不弹窗、不罚款 |

补充口径：

- 两种节奏先选边：找茬类是限时比快的街机节奏（一轮一图、重玩刷分）；HOPA 是数分钟一张的放松节奏（不限时或宽限时）。同一套基础机制，两套数值取向。
- 目标数与难度分布：单张场景常见 8 到 15 件，低于 8 件结束太快，高于 15 件「寻找」退化成「清点」（§7）；分布上多数目标送分建立节奏，少数需要细看，一到两件压轴，全是硬骨头玩家会中途放弃。
- 清单与点错：清单用文字加图标双轨，图标让低龄与外语玩家免翻译上手，画风与场景统一；点错要便宜，它是信息（这里没有），不是错误，最多断连击，不叠加惩罚。

### 3.2 场景美术成本

手绘密集场景是这个类型唯一躲不开的大额资产：程序、UI、音频都可以便宜，玩家盯着看的场景没法省。一张发布级场景的成本结构：

- 背景底图：构图、主题、光照一次到位。它是玩家停留最久的一张图，验收标准是缩到目标设备上构图仍然可读。
- 目标物：每件都必须是独立图层或独立图元，要能单独动、单独点，所以画的时候就要拆开；画完再拆的返工成本常常高于重画。
- 遮挡与互动层：可掀的帘子、可开的柜门、可拨开的草丛。互动细节把静态画面升级成可探索的场景，每一项都是美术与脚本的联合工作量；命中动效、点位与提示数据按件计入配置成本。

参考量级：单幅场景从草图到实装，常见要一名插画师一到两周，成熟插画师的稳定产能约每月二到四幅，风格越写实、细节越密，上限越高；制作流程与外包管理见《美术与音频手册》（⑪）。省钱要顺着类型省：场景是主菜，先减章节数与演出规格，砍场景就是砍内容本身。

复用有四条纪律：

- 变体优先于新画：昼夜、季节、节日、修缮前后，同构图的修改版成本远低于新画；但变体要排进节奏，连续同图会消耗新鲜感。
- 找不同天生一稿两版：原图与改动图共用构图，单张成本被两个模式分摊。
- 跨场景物件库要有审美纪律：同一把钥匙到处出现会穿帮，局部元素复用优于整图复用。
- 外包设验收清单：缩图看构图、放大看点选、按目标设备做点选测试；风格一致靠参考包与验收流程，不靠外包方自觉（⑪）。

### 3.3 与叙事的结合

寻物与剧情有天然接口：找到的物品可以就是线索。HOPA 的标准推进结构：

`章节开场（对话或过场）→ 2 到 4 幅寻物场景 → 关键道具解锁轻解谜或新地点 → 章节收束与悬念钩子`

- 道具分两类：剧情道具（找到后进入道具栏、能用于解谜、串起场景）与氛围物件（只为找而找）。剧情道具的占比决定叙事质量；最忌清单是一张随机名词表，与剧本两张皮（§7）。
- 场景是节拍器：一章用场景数控制节奏，场景之间穿插对话、轻解谜与地图移动，寻物负责内容密度，剧情负责前进动机；章尾留一个钩子（新线索、新地点、新人物），把「再找一幅」变成「想知道接下来怎么了」。
- 剧情向产品不设失败：找得慢不影响推进，最多影响星级与奖励；进度永远向前，这是休闲品类的底线。
- 排期两条线同步：先画章节流程图（场景节点与推进条件），再拆场景清单与剧本；场景等剧本或剧本等场景，都是排期事故。

### 3.4 变体谱系

| 变体 | 核心考法 | 生产差异 | 常见代表 |
| --- | --- | --- | --- |
| 隐藏物件（清单式） | 对照清单在单幅密集场景中寻找 | 密集场景加独立目标图层，成本基准 | Mystery Case Files |
| 找不同 | 对比两幅近似图找差异 | 一稿两版，增量成本低 | 大家来找茬 |
| 互动寻物（Hidden Folks 式） | 找角色与事件，无清单 | 全场景可点，互动脚本量大 | Hidden Folks |
| 自动寻物 | 系统扫出或自动收取，玩家确认与升级 | 可复用现有场景，机制最轻 | 多见放置与休闲混合产品 |

- 找不同与寻物共用生产管线与反馈设计，很多产品两个模式并存，同一批场景资产两吃是摊薄美术成本的主要杠杆；混合体同理：寻物加装扮经营（June's Journey）、寻物加解谜冒险（HOPA 主形态）、找不同嵌进其他品类当小游戏。
- 互动寻物删掉清单、拿掉时限，把难度放进「场景互动性」：门后、帘下、草丛里都可能有内容。Hidden Folks 用 32 张手绘场景、300 多个目标与 500 多个互动细节撑起整个游戏，密度本身就是内容。
- 自动寻物把「找」降级为收取，乐趣转向收集与成长。作为辅助功能（无障碍、减压模式、活动减负）很有价值；整品以此立项时，按放置类核算，不要套用本页的场景预算。

### 3.5 移动端变现结构

移动端长线产品的变现由四层构成，比例与顺序因产品而异；具体数值按自己的留存与卡点数据校准（运营方法见《运营与增长手册》（⑬）），这里只给结构：

- 体力制：开始一幅场景消耗体力，体力随时间恢复，不足时等待或看广告补充。它把玩家的内容消耗速度与团队的更新速度对齐；体力参数是商业与内容的枢纽，先定它再定产出。
- 广告位：提示获取、体力补充、场景结算后的插屏。红线一条：命中与结算的瞬间不打断，那几秒是全品类最贵的注意力。
- 道具付费：提示、透镜、冷热探测等消耗品，单卖加礼包；付费买的是「更快」，不是「能不能」。
- 章节与收集门槛：收集物、星星或钥匙解锁下一章，制造长期目标；免费路径必须能走通全程，付费只是加速。

买断制对照：经典 PC 形态用「先试玩后买断」（大鱼商店的招牌），在 Steam 与移动商店仍成立；选哪种，由渠道、体量与内容节奏决定。

数据纪律：卡点、流失点与转化率要进数据面板。「玩家卡住」分两种——设计卡点与变现卡点，玩家分不清时，账都记在体验上（⑬）。

## 4. 技术要点

寻物的技术栈很浅：没有物理、没有 AI、没有网络，难点集中在两处——场景数据化与点击交互的精度。工程量小不等于可以松：工具做不好，内容产能直接锁死。

- **场景即数据**：一张场景写成「背景图 + 目标列表（名称、坐标、形状、状态、提示文案）+ 干扰参数」的数据文件，代码只负责解释，第一章就要立住，它决定后面每一张图的产能；提示同样由它推导，冷热探测靠目标距离驱动音效与视觉强度，圈定靠高亮动画与镜头移动，写死脚本的路线在场景多起来后维护成本会反噬。
- **点击判定与反馈链**：用多边形或复合形状做碰撞体，不做逐像素命中，判定范围比视觉略大，向手指妥协，目标物重叠时按层序定优先级；命中即动效、音效、清单勾选与计数，点错给轻反馈，触屏再补一层按下即响应的即时视觉，总延迟压在 100ms 以内。
- **拖拽与缩放**：密集场景在手机上要能平移缩放，缩放用视口变换、点击坐标做逆变换；拖拽与点击靠位移阈值区分，阈值调到「想点不误拖、想拖不误点」。
- **分辨率适配与存档**：点位用归一化坐标，场景按目标设备最高分辨率出图、向下用纹理压缩与图集，验收设备里要有一台小屏低端机；已找到列表、用时与提示次数随场景 ID 存档，中途退出回来接着找，这些数据也是调难度与调提示的第一手原料。
- **场景配置工具**：在图上标注目标物、自动生成碰撞体与点位、一键热重载，是回报率最高的一笔技术投资；没有它，每张场景都要程序员参与，产能必崩。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 场景量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 机制原型 | 1-2 幅（用现成图） | 2-4 周 | 只验证点选反馈与提示 |
| 小型作品 | 20-40 幅 | 3-8 个月 | 单一模式，或寻物加找不同 |
| 剧情向产品（HOPA） | 6-10 章，每章 3-5 幅 | 1-2 年 | 场景、剧本、解谜三线并行 |
| 移动端长线产品 | 上线 50 幅以上 | 上线后按月补充 | 场景产能与更新节奏绑定 |

美术量级（参考）：单幅发布级场景按一名插画师一到两周计（含拆分与配置）；稳定产能约每月二到四幅；排期再留出返工余量，按八成产能预估。

工作量口径：

- 先算产能账再定章节数：场景数乘单幅人周除以团队产能，就是内容周期的物理下限（「先上线再补」在场景品类里不成立）；复用系数是最有效的范围杠杆，变体场景、一稿两版与跨场景物件库都能压低单幅均值，但要控制玩家能感知到的重复率。
- 每张场景的校对工序不能省（缩图检查、全目标点选测试、提示路径测试各一遍，验收通常吃掉半天到一天）；剧本与场景必须同节奏生产，两条产线任何一条停摆，另一条就断粮或堆库存。

范围控制：这个类型的头号死法是产量跟不上消耗。玩家一天能玩掉两周的产出；上线前砍掉弱场景只会让体验更紧凑，而「月度更新几幅」的运营承诺，先核过插画产能再签（⑬）。

## 6. 第一个原型怎么起步

目标：用 2-4 周回答一个问题：一张场景能不能让人愿意盯着看两分钟，并在找到时笑出声。用现成素材，不画新图。

1. **借一张现成图**：找一张高密度的免费插画或照片（授权情况先过一遍《法务、专利与竞争手册》（⑦））；手标 10-15 个目标物，写成数据文件。原型的任务是机制，不是美术。
2. **最小交互与反馈链**：点击命中与点错、清单勾选、完成结算，外加命中动效、音效、连击计数与一个最土的提示（点击清单项弱高亮）；没有反馈的原型只会得到「无聊」两个字，测不出真问题。
3. **走廊测试与数据收尾**：找 3 到 5 个不玩游戏的家人朋友各玩两遍，你只记录不说话：完成用时、点错次数、何时开口求助、何时笑出声、玩完有没有问「还有吗」；再记录每件目标物的寻找时长，最慢的应该是你设计的压轴，若快慢分布与预期相反，先调数据再谈画图。

成功标准（全部可观察）：

- 5 名测试者中至少 4 人不听说明就能开始，且无人因「点不到」放弃；完成时至少一人主动要下一幅。
- 你能在 10 分钟内改完一份场景数据（增删目标、调提示冷却）并让测试者复测；最慢与最快目标的用时比要落在预期区间，若所有目标都快，是区分度不够。

反馈链与数据管线验收不过，不要开始画正式场景：手绘场景是这个类型最贵的一笔采购，画错一张就要重来一张。

## 7. 常见坑

1. **难度做在分辨率上**：目标物小到要靠放大镜、颜色与背景只差半个色号。难度应该来自遮挡与伪装，且必须在目标设备上缩小验收（§3.2）。
2. **清单超载**：一张图塞二十件目标，「寻找」退化成「清点」。目标数按体验时长设计，不按「值回一张图」设计（§3.1）。
3. **清单与剧情两张皮**：找到的物品与故事无关，玩家在悬案里做识字练习。剧情向产品的清单必须多数与主题相关（§3.3）。
4. **惩罚与门槛叠加**：点错弹窗罚款、超时清空进度、体力耗尽强退，再叠上体力、提示与章节门槛的收费卡点，免费路径走不通；休闲品类的玩家是来放松的，惩罚会原样变成流失，评价区会先于财报给出判决（§3.1、§3.5）。
5. **提示缺级或全自动**：没有提示会卡死收尾的目标；提示唾手可得又会让「发现」贬值。要分级，由玩家索取（§3.1）。
6. **反馈与判定两头失守**：判定按像素卡、点偏一点就判错，反馈弱到只剩一声闷响；一个是向手指妥协的问题，一个是向眼睛兑现的问题（§4）。
7. **只有找、没有看**：场景是随机物件的堆砌，没有主题、没有彩蛋、没有互动；玩家找完即走，不复访也不截图（§2）。
8. **产能账没算**：玩家一天玩掉两周的产出，更新节奏崩掉，运营承诺无法兑现（§5）。
9. **外包无验收**：场景风格各画各的，合在一起像素材拼盘；参考包、样张与验收清单一个都不能少（⑪）。

## 延伸阅读

- 《游戏设计手册》（⑨）：核心循环、反馈设计与数值表方法，第 3.1 节的底稿。
- 《美术与音频手册》（⑪）：手绘场景的制作流程、外包管理与风格验收，第 3.2 节的完整展开。
- 《运营与增长手册》（⑬）：体力、广告与长线内容节奏的运营口径，第 3.5 节与第 5 节的配套。
- 《避坑大全》（⑥）：休闲品类与内容生产类坑位，与第 7 节对照。
- 《案例研究集》（⑳）：拆解与复盘方法，拆《找你妹》与《June's Journey》时对照使用。
- 收尾建议：先借图跑通一张场景的完整流程，再回来重读第 3.2 节与第 5 节。寻物项目的生死线是场景产能，不是点子。
