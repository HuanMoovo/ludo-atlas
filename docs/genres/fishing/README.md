# Ludo Atlas · 类型手册 · 钓鱼（Fishing）

> **类型手册 P3 批次**（第 ㊵ 轮扩展）。定位：把「抛竿、等待、咬钩、拉扯」四拍循环做成第一乐趣的类型。玩家的核心动作是读水与控线，收获是概率与技巧的共同结果；图鉴给长线目标，环境与仪式感给松弛体验。
> 配套：《游戏设计手册》（⑨，核心循环与概率设计）·《技术实现手册》（⑩，状态机与数据表）·《案例研究集》（⑳，拆解与复盘方法）·《独立开发生存手册》（⑱，范围控制与内容量核算）。
> 本文不放外链；标杆只用大众熟知的作品，数字均为常见量级，按自己项目的实测校准。

## 1. 定位与核心循环

一句话定位：钓鱼是**把「等待」也做成内容**的类型。四拍里，等待占大头，拉扯是高潮，图鉴是长尾。做不好等待，游戏退化成数值结算界面；做不好拉扯，等待就没有兑现的时刻。

核心循环用动词环写：

`选点与配装 → 抛竿 → 等待与读水 → 咬钩 → 拉扯与收线 → 入护与结算 → 图鉴与经济更新 → 换点位或换饵`

四拍的时间配比（休闲向量级参考）：抛竿 2-5 秒、等待 5-30 秒、咬钩窗口 0.5-1.5 秒、拉扯 5-60 秒。这个配比里藏着本类型最大的设计矛盾，处理办法见 §3.3。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 农场经营 / 生存建造 | 钓鱼在那里是子系统，几句话就能讲完；本类型把它扩成全部内容 |
| 街机捕鱼（捕鱼达人式） | 那类瞄准发射、即时命中，本质是射击与得分；本类型靠等待、概率与拉扯结算 |
| 放置增量 | 都卖时间，但放置把过程自动化掉；钓鱼的全部卖点就是过程本身 |

一个自检问题：把等待压缩成「点一下立刻结算」，游戏还成立吗？答案若为「差不多」，那你做的是抽卡界面，不是钓鱼。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **期待的悬念**：水面之下有未知，每一竿都可能出好货；概率可以不公开，但规律要可感知（时段、天气、饵、水层）。
2. **拉扯的博弈**：一次收线是一段 10-60 秒的拉锯，赢要赢得明白，断线要知道为什么。
3. **收集的完成欲**：图鉴、尺寸记录、稀有标本，给「再来一竿」的理由。
4. **松弛与仪式**：默认状态是平静的，环境声与光影把人安顿下来，紧张只在咬钩后出现。
5. **成长的刻度**：竿、线、钩、饵与等级，把「变强」做成看得见的曲线。

反面感受（出现任意一条都是红灯）：等得无事可做；拉扯全程长按一个键；稀有鱼永远抽不到也说不出为什么；断线纯属随机。

标杆作品（均大众熟知，建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 钓鱼星球（Fishing Planet） | 拟真钓法（浮钓、路亚）与装备升级、任务驱动的长线结构 |
| 俄罗斯钓鱼 4 | 拟真刻度的上限样本：极慢节奏与细碎装备系统的取舍，看清受众边界 |
| 星露谷物语（钓鱼系统） | 绿条式拉扯的最小博弈模型；钓鱼与农场经济的互喂 |
| 集合啦！动物森友会 | 咬钩时机的极简交互；按月开放的图鉴与博物馆式收集 |
| 荒野大镖客：救赎 2（钓鱼支线） | 把钓鱼做成世界沉浸与生存物资的一部分 |

## 3. 设计要点

### 3.1 拉扯：张力、耐力与时机

拉扯是全类型的技术核心：玩家与鱼争夺同一段进度，赢法要可解释。先选模型，再调数值：

| 模型 | 玩法 | 上手门槛 | 常见于 |
| --- | --- | --- | --- |
| 绿条式 | 控制一个条与鱼图标重合，重合累积进度 | 低 | 星露谷物语、多数休闲钓鱼 |
| 张力式 | 收线涨张力，超上限断线，松手泄力 | 中 | 钓鱼星球、俄罗斯钓鱼 4 等拟真向 |
| 时机式 | 咬钩瞬间按键，窗口内命中即得 | 极低 | 动物森友会与大量子系统的轻量版 |

- **进度条是双边拉锯**：玩家往前推，鱼在中途制造回退；失败不是进度归零，而是脱钩或断线，且原因可读。
- **鱼要有行为分档**：蓄力、冲刺、摆头分化出 2-4 种，冲刺是张力峰值，也是音效与震动的高光点；没有行为分档，拉扯就是按住不放。
- **让松手有用**：张力式的精髓是收与放的节奏交替，绿条式的精髓是预判鱼的下一跳；只会长按的拉扯撑不过三十条鱼。

数值骨架（量级参考）：

| 旋钮 | 参考区间 | 作用 |
| --- | --- | --- |
| 咬钩窗口 | 0.5-1.5 秒，休闲偏长 | 判定宽容度；低于 0.3 秒对触屏极不友好 |
| 单次拉扯时长 | 小鱼 3-10 秒、普通 10-30 秒、稀有 30-90 秒 | 稀有度在时间上的体感刻度 |
| 鱼的体力 | 随拉扯与冲刺下降 | 提供「耐心就能赢」的保底 |
| 线张力上限 | 与线强度和鱼的力量挂钩 | 断线风险的来源；预警先于断线 |

### 3.2 图鉴与稀有度：条件表与收集出口

稀有度不是四个标签，而是一张「出现条件表」；玩家研究的其实是条件，而不是概率本身：

| 稀有度（示意） | 基础权重 | 附加条件 | 体验角色 |
| --- | --- | --- | --- |
| 常见 | 六成上下 | 无 | 保证每次都有收成 |
| 少见 | 两成半上下 | 特定饵料或水层 | 中期研究目标 |
| 稀有 | 一成上下 | 时段、天气、季节的组合 | 图鉴的关键格 |
| 传说 / 巨物 | 数个百分点 | 多重条件加长线积累 | 一局的高光与谈资 |

- 条件要能被表达：未解锁的图鉴格显示轮廓与出没线索（时段、天气、水域），不做纯黑箱。
- 权重加保底：连续空竿若干次后向「符合当前条件」的目标倾斜，保底计数进存档，让努力有回音。
- 尺寸记录是长尾：同种鱼记最大尺寸，让重复钓获也有意义，成本远低于再加一批鱼种。
- 收集要有出口：图鉴完成度给奖励与称号，稀有鱼要有展示位（水族箱、博物馆、家园摆件之类的载体）；只加数字的收藏等于没有。

### 3.3 等待：仪式感与枯燥边界

等待是这个类型的双刃剑：处理好是仪式，处理不好是折磨。底线是，等待必须同时是「有事发生的」与「没事发生的」；环境在动（水流、光影、鸟、鱼跃），玩家在决策（换饵、换水层、挪点位），只是节奏是慢的。

- 咬钩有前摇，等待有信息：假咬与浮标抖动把等待的终点演成一出小戏；水下鱼影、竿尖微动、水色变化，让等待期间有东西可读。
- 节奏留变量：连续多竿短等待会腻；偶尔拉长一段再给暴击（好鱼），波动比平均值重要。
- 枯燥边界用数字卡：一轮会话（10-20 分钟）里完整循环应能跑 5-10 次；单竿等待超过 30 秒时，要么给信息，要么给事件，要么就是拟真向对受众的明示筛选。
- 自动钓鱼是减负不是替代：手游用自动模式换玩家对手动高光的珍惜；两档收益差要设计清楚，否则手动变摆设。

### 3.4 钓鱼作为子系统：与经营、生存结合

当钓鱼是子系统，评价标准从「是否好玩」变成「是否值得占玩家一天的时间」：

- 给足经济角色：食物、烹饪材料、卖钱、任务交付、装备材料，至少占一条成熟的经济循环；把钓鱼的每小时收益放进宿主游戏同一张收益表比对（方法见《类型手册 · 农场经营》§3.2）。
- 与主线互喂：鱼反哺农场与生存（食物、肥料、药剂），宿主反过来给钓鱼提供装备与解锁；只出不进的子系统会被玩家判定为可跳过。
- 时间预算写死：日程制游戏里，一次完整循环占多少游戏内时间要定死（参考：30 分钟游戏内时间上下），否则它会吃掉主线节奏。
- 入口克制与基线：子系统版的操作深度要减配，绿条式或时机式一轮到位，整套拟真装备树留给独立作品发挥；不钓鱼也能通关是正确基线，钓鱼玩家拿明显回报，但不形成硬性门卡。

### 3.5 装备与成长：四件套与修正表

四件套各管一段话语权：竿（拉力上限与抛投距离）、线（张力上限，断线的主角）、钩（咬钩与脱钩率）、饵（鱼种偏好）。四条线独立升级，「换装备换打法」，而不是换一套更大的数字。

- 修正表与获取节奏：每种钓法与鱼种给装备修正值，用模拟脚本抽查套装使用率，避免全局最优的单一套装；新装备解锁应对应「此前钓不到的鱼变得能钓」，而不是纯数值提升。
- 消耗品（饵、料）承担日常开销与回访理由，消耗速度要能被量化（一小时几包），别让经济只进不出。

## 4. 技术要点

工程难点在三处：拉扯的数值模拟、概率与内容的数据化、反馈的即时性。以下与引擎无关。

**拉扯系统**

- 拉扯是小型数值模拟加状态机：状态为等待、咬钩、拉锯、结算；鱼有力量、体力与行为脚本，玩家有收线输入与张力参数。结算用固定 tick（10-20Hz 量级）跑，不用物理引擎硬解。
- 断线判定留余量：张力接近上限时先给「线在呻吟」的视听预警，持续超限若干帧后再断；一帧超限就断的系统只会让人觉得随机。

**概率与数据表**

- 鱼种、场景、装备全部外置为数据表（CSV 或 JSON）；抽取用加权表加修正：最终权重 = 基础权重 × 时段 × 天气 × 季节 × 饵料修正，乘数可配置，不写死。保底单独一层：连续未出目标稀有度的计数进存档，达到阈值后对该稀有度乘倾斜系数；测试用固定随机种子跑分布。
- 图鉴即数据库：钓获记录、最大尺寸、条件线索都从同一张鱼种表派生，图鉴页只读表，不做二次维护。

**反馈与表现**

- 咬钩与拉扯的反馈按帧审核：音效、震动、竿的形变、线的松弛与绷紧同帧发出才算合格；延迟超过两帧就很难说服人（方法见《技术实现手册》（⑩））。
- 水面与鱼群可以省：水面用着色器与贴图演出，水下不做真鱼群，用「影子加概率」应付；鱼群行为模拟只在拟真向里立项，成本另算。
- 存档从第一天带版本号：图鉴、尺寸记录、装备与任务进度都是要跨版本迁移的长期数据；联机向的钓获结算须服务端校验随机与数值上界。

## 5. 内容量与工作量参考

成本公式接近乘法：`总内容量 ≈ 鱼种数 × 每鱼资产 + 场景数 × 每场景资产 + 装备件数 × 配置 + 图鉴与任务文本`。

鱼种 × 场景 × 装备的常见量级（用于估算范围，不构成承诺）：

| 体量档 | 鱼种数 | 场景数 | 装备规模 | 定位 |
| --- | --- | --- | --- | --- |
| 原型 | 5-10 | 1 | 竿 1-2 支、饵 2-3 种 | 验证四拍与拉扯手感 |
| 小型完成品 | 30-60 | 3-5 | 四件套各 3-5 档 | 单人或小组 6-12 个月 |
| 常见独立作品 | 60-120 | 6-10 | 装备与消耗品百余件 | 需要内容管线与工具 |
| 拟真向商业作品 | 100-300 | 10-20 | 数百件，持续更新 | 长线运营或系列化摊成本 |

单件成本（量级参考，同上）：

| 内容单元 | 单位成本 | 备注 |
| --- | --- | --- |
| 一种鱼（2D / 3D） | 0.5-2 人日 / 3-10 人日 | 立绘或图标、动画、图鉴卡与文本；3D 另加模型与行为参数 |
| 一个场景 / 水域 | 1-3 周 | 地形、光照、可钓点位与鱼池配置 |
| 一件装备 | 0.5-2 人日 | 数值配置、图标、获取链路 |

- 鱼种数是最灵活的旋钮：先冻结循环与拉扯手感，再按产能扩表；砍鱼种安全，砍拉扯危险。
- 图鉴与任务文本是隐形大头（写作、校对、本地化各过一遍），文本从第一天 ID 化；排期锚点：拉扯原型 2-4 周；垂直切片（一个水域、约 30 种鱼、完整经济）2-4 个月；商用体量按年计。

## 6. 第一个原型怎么起步

第一个原型只做一个水域，2-4 周完成，不碰任务系统，不做装备树，美术全部白盒。

1. **第 1 周：四拍闭环。** 一根竿、3 种鱼（常见、少见、稀有）、一段河岸；抛竿、等待、咬钩、拉扯结算全跑通，随机抽取先用最简加权表。
2. **第 2 周：拉扯调参。** 从绿条式或张力式里选一套实装（时机式太薄，撑不住验证）；把条速、泄力速率与鱼的冲刺行为调出节奏，逐帧录屏，统计单次拉扯时长分布。
3. **第 3 周：等待与信息层。** 环境演出（水面、光影、鱼影）、咬钩前摇、空竿反馈；专门测「等 20 秒不出货」时的反应，这段比参数诚实。
4. **第 4 周：外部测试。** 找 5 个没玩过的人各钓 20 竿，记录三件事：何时走神、何时骂人、何时拍照；回头对着 §3.3 的枯燥边界修等待时长。

成功标准（全部可观察）：

- 测试者主动钓起第 10 条以后的鱼，而不是被请求再来一竿。
- 断线或脱钩之后，测试者能说出原因（张力、时机、装备三者之一）。
- 单竿等待与出货频率形成可复述的节奏感，测试者能预判「快有动静了」。
- 改一个数值（权重或张力上限），能在 10 分钟内量化它对体验的影响。

节奏不达标，先别铺内容：鱼种表扩容便宜，循环返工贵。

## 7. 常见坑

1. **等待做成空白**：没有前摇、没有信息、没有环境演出，玩家在挂机。修订见 §3.3。
2. **拉扯一键化**：长按收线必胜，博弈消失。让鱼有行为、让松手有用（§3.1）。
3. **概率黑箱**：稀有鱼无线索、无保底，努力没有回音。条件可见、保底进存档（§3.2）。
4. **经济与主次失衡**：鱼价与装备曲线脱节，或子系统抢走两倍于主线的收益。按每小时收益并入宿主收益表，并给收益定上限（§3.4）。
5. **拟真入门墙**：术语与钓法把新手挡在门外一小时。分三档教学：先能钓上来，再谈钓得好（§3.5）。
6. **咬钩窗口过窄**：0.1 秒级窗口在触屏与手柄上都是灾难。按最差设备定窗口（§3.1）。
7. **断线惩罚过度**：稀有鱼脱钩还清空饵料与耐久，玩家直接卸载。脱钩留保底，损耗设上限。
8. **水域同质化**：鱼种表堆到 200 条，各地鱼池与条件却无差异，收集退化成抽卡。条件表与场景同批设计（§3.2、§3.5）。
