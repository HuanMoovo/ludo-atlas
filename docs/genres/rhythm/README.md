## 1. 定位与核心循环

一句话定位：音乐节奏是**以时间判定的精准度为第一乐趣**的类型。玩家的每个输入都会被换算成与拍点的偏差，游戏用判定结果回答「你有多准」；敲准本身就是内容，不是赶路的手段。

核心循环用动词环写：

`听 → 预判 → 按键 → 收判定 → 修正手感 → 连击或断连`

这个环以毫秒计量。它成立的前提只有两条：判定可信（§3.1），校准到位（§3.3）。玩家对本类型失败的归因极其敏感，几十毫秒的偏移就能被稳定感知；判定一旦「说不准」，玩家立刻停止投入。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 动作游戏 | 动作游戏里节奏影响手感；节奏游戏里时间是硬规则，判定以毫秒计 |
| 节奏动作（跑酷、体感挥动） | 判定载体从输入时刻转向持续动作，识别不确定性更高，判定窗必须放宽 |
| 舞蹈与健身游戏 | 目标从精准偏向完成与消耗，评分宽容、连续参与优先于判定深度 |
| 内嵌音游小游戏 | 一段 QTE 级玩法撑不起产品；节奏游戏需要判定系统、曲库与谱面工具的长期投入 |

一个自检问题：把音乐静音、只留音符，游戏还能打（目押可行）；把「按在时间点上」换成「按到了就行」，游戏立刻失去意义。后者不成立时，你做的才是音乐节奏。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **可信赖**：同一段输入在任何设备上得到一致判定，误差分布以零为中心。这是生死线，先于爽感。
2. **流畅爽感**：音画同步、命中反馈即时、连击有重量，演奏的错觉来自三者叠加。
3. **成长可见与挑战阶梯**：准确率、评级与成绩曲线把「练」的成果量化；难度分层覆盖新人与高手，曲库的难度分布本身就是可玩内容。
4. **舞台感**：曲目演出、界面氛围与成绩榜，把「一遍遍重打」包装成表演。

标杆作品（建议亲手玩过再拆，判定手感隔着视频学不到）：

| 作品 | 可学的点 |
| --- | --- |
| osu! | 社区谱面生态、多模式共用引擎、自制谱的分发与评级 |
| 太鼓达人 | 极简两键输入、街机与家用双轨设计、判定档位的命名方式 |
| 节奏天国 | 把节拍藏进情景，教学与测试分离；判定宽松但反馈极清晰 |
| 喵斯快跑 | 移动端两键加触屏的减法设计、视觉包装与低门槛 |
| Beat Saber | 体感输入与判定的映射、把动作幅度与时机分开评分 |
| 初音未来：歌姬计划 | 键位组合判定、MV 级演出与曲目美术的绑定 |
| 吉他英雄 | 外设输入的心理契约、乐队幻想的仪式感 |
| 周五夜放克 | 社区曲库与模组生态、低美术成本下的曲目更新节奏 |

## 3. 设计要点

### 3.1 判定系统：窗口、归属与宽严

判定链路固定四步：采集输入时刻（高精度时间戳）→ 换算到音频时钟 → 与该轨道最近一个未判定音符求时间差 → 按档位出结果。四个参数决定全部体验：窗口宽度、窗口对称性、归属规则、连击与分数规则。

判定档位的常见量级：

| 档位 | 窗口（±） | 设计意图 |
| --- | --- | --- |
| 完美 | 20-40ms | 区分高手，竞技计分的主乘区 |
| 良好 | 60-100ms | 大多数玩家的日常区间，反馈要爽，不要羞辱 |
| 及格 | 100-160ms | 保底反馈，避免零收益的挫败 |
| 窗口之外 | 断连 | 偏差大到玩家自己都能听出来 |

三条纪律：

- **宽严按受众选档，稳定性优先于严格**：大众向与移动端整体放宽；竞技向可以收紧，但必须做到一致。严格不等于深度，难度交给谱面。
- **看偏差直方图调窗**：调试器要输出每次判定的偏差分布，直方图以零为中心且不过宽才算调好；整体偏移调 offset，分布发散调窗口。玩家打早与打晚常有系统性倾向，非对称窗口是正当手段。
- **窗口不能和相邻音符打架**：同一轨道上，相邻音符的判定窗不允许重叠（经验做法：最小间隔取窗口全宽的两倍以上），否则一次按键对两个音符都成立，归属只能靠猜。高密连打要么限制细分，要么用整体判定块处理。

音押与目押要分开设计：音押是跟音乐拍点打，目押是跟滚动音符打。低密度段落让两者一致（强拍上放音符并给视觉强调）；高密度段落以目押为主，滚动提前量常见 0.5-2 秒并允许玩家调速。两类失效原因不同（音押怕延迟，目押怕掉帧与滚屏抖动），测试也要分开做：关画面只靠听打一遍，关声音只看音符打一遍。

### 3.2 谱面设计流程

谱面就是这个类型的关卡。固定流程六步：标定 BPM 与 offset → 划分小节 → 铺骨架（主拍与乐句重音）→ 加花（细分、叠键、连打）→ 难度分层 → 可读性检查与试玩调优。低难谱面先做，它决定骨架；高难谱面是骨架上的密度与技巧堆叠。

BPM 与分拍的换算先背下来（以四分音符为一拍，1/4 拍即十六分音符）：

| BPM | 一拍 | 1/2 拍 | 1/3 拍 | 1/4 拍 |
| --- | --- | --- | --- | --- |
| 90 | 667ms | 333ms | 222ms | 167ms |
| 120 | 500ms | 250ms | 167ms | 125ms |
| 150 | 400ms | 200ms | 133ms | 100ms |
| 180 | 333ms | 167ms | 111ms | 83ms |

密度与判定窗的关系是上表最重要的用法：180 BPM 的 1/4 拍间隔 83ms，小于 ±50ms 窗口的全宽（100ms），这种连打要么挪去更慢的段落，要么收窄窗口，要么改用特殊判定。另注意三连音（1/3 拍）与 1/4 拍交替的段落极易读成同一密度，试玩时单独检查。

难度梯度按每曲 3-5 档铺开，分档靠结构而不是删音符：

| 档位 | 内容结构 | 目标人群 |
| --- | --- | --- |
| 入门 | 主拍与长音 | 第一次接触本类型 |
| 常规 | 拍点加少量 1/2 拍 | 能玩但不追成绩 |
| 进阶 | 拍点、1/2 拍与点状 1/4 拍 | 日常主力人群 |
| 专家 | 1/4 拍连打、叠键、跨轨技巧 | 核心玩家与榜单竞争 |

难度评级用测试者实际通过率校准，不用拍脑袋；同一等级内的曲目，目标人群完成率要接近，等级才有信誉。可读性检查清单：视觉分组是否清楚、密度是否有呼吸、有没有物理上打不出的组合（同手跨键冲突、超出单手移动速度）、轨道切换有没有留够时间。谱面以拍数存储，毫秒是派生值，这样变速曲与 BPM 修正都不需要重排全谱；编辑器的最低配置是波形加节拍网格、打点录入、即时试听与热重载，另配一个校验器（重叠、越界、同轨间隔小于窗口），保存时就报警。

### 3.3 音频延迟校准（设备差异处理）

先分清三本账，不要用一个数字糊全部：**谱面 offset**（曲子本身的拍点起点，作者标定）、**设备延迟**（玩家设备链路引入的延迟，校准值）、**视觉延迟**（显示链路，电视与投影尤其明显）。判定基准取「玩家实际听到的时间」，校准测量的就是这条回路的偏差。

校准流程设计成半分钟内完成：用一段稳定的节拍音轨，让玩家跟拍点击 8-16 次，去掉极值后取中位数（比平均值抗手滑），保存后立刻进入一段验证打点，让玩家确认判定居中。首次启动就引导校准，设置里保留手动微调滑条与「重新校准」入口。

设备差异的常见量级：

| 链路 | 额外延迟量级 | 处理方式 |
| --- | --- | --- |
| 有线耳机 | 最小 | 基准场景，默认校准即可 |
| 内置扬声器与普通音箱 | 几毫秒到几十毫秒 | 校准覆盖 |
| 蓝牙与无线耳机 | 数十到数百毫秒，且有波动 | 提示切换有线；允许校准覆盖，同时告知波动 |
| 电视与家庭影院 | 音频链路数十到数百毫秒 | 音频与画面分开校准 |

校准值要跟设备走：输出设备变化时提示重新校准；偏差异常时先怀疑环境（蓝牙、省电模式、系统音效增强）。两条纪律：不许用全局固定偏移糊弄所有人，设备分布比直觉要散；校准只负责外部延迟，代码自己的帧对齐误差必须先在代码里修掉，不能拿校准值掩盖。

### 3.4 玩法变体（轨道数、键位与体感）

| 变体 | 输入 | 判定载体 | 适配场景 | 代价 |
| --- | --- | --- | --- | --- |
| 轨道下落式（4-7 键） | 键盘、手柄、街机台 | 音符抵达判定线 | 桌面与街机，谱面表达最强 | 键数越多读谱负荷与练习成本越高 |
| 触屏多指式 | 拇指与多点触控 | 判定线或触点时刻 | 移动端碎片时间 | 手指遮挡与触点漂移，密度上限低 |
| 无轨道简化式 | 两键（面与边） | 鼓面区域 | 街机与家用，门槛最低 | 表达维度窄，靠曲库与谱面花样补 |
| 自由点击式 | 鼠标或触屏 | 图标出现与消失时机 | PC 社区生态 | 判定公平性与反作弊压力 |
| 体感与 VR | 摄像头、手柄、头显 | 动作轨迹与时机 | 客厅与展示场景 | 识别延迟与不确定性，判定窗必须放宽 |

键数的选择有物理约束：键盘以 4 键为基准（双手中指与食指），6 键与 7 键贴近钢琴布局，练习成本更高；移动端常见 2-4 轨（拇指加食指），再多会碰到遮挡与手位冲突。体感项目把时机与动作幅度分成两项评分：动作的重复精度低于手指，判定窗相应放宽，并用站位与镜头引导控制幅度。一条纪律：一个游戏先把一个模式做透。多模式等于多套谱面体系、编辑器改动与测试成本，放到后期扩张，不要在设计会上就摊开。

## 4. 技术要点

**时钟与判定**

- 以音频时钟为主时钟：输入事件带高精度时间戳，统一换算到音频播放位置再判定；不要用帧时间或系统时间当判定基准。
- 判定挂在输入事件上（按事件时间出结果），不要每帧扫一遍；帧率抖动不该出现在判定结果里。
- 不少平台的播放位置查询有更新粒度（按缓冲块或渲染周期），要做平滑与插值，别把块级抖动当基准。
- 低延迟播放是手段不是目的：桌面用独占或低延迟后端、移动端用低延迟音频路径，缓冲常见取 10-30ms 量级；兜底仍然靠校准与宽容度，别让玩家去调系统缓冲。

**输入**

- 键盘、手柄与触屏分设备实测调校；触屏记录触点时间戳并做多点归属；体感输入按设备实测延迟定判定窗；输入去抖与连击防护，保证单次物理按压只出一次判定，并屏蔽系统级按键重复。

**谱面与工具链**

- 谱面数据以拍数（音乐时间）存储，毫秒是派生值，变速曲支持 BPM 变化点；配套校验器（重叠、越界、同轨间隔小于窗口、不可达组合）在保存时就报警。
- 回放与判定日志：保存输入时间戳、判定结果与音频位置；调窗与查 bug 都以日志为准，不靠回忆。

**性能与手感**

- 音符对象池化、批量绘制，垂直滚动用亚像素或插值渲染；避免垃圾回收尖峰与掉帧，本类型掉一帧就是一次判定事故（目押依赖滚动平滑）；帧率目标按最低配置设备定，不按开发机定。
- 命中反馈与打击音同帧或下一帧到达；打击音与音乐的时间关系要主动设计（重音对齐或反拍点缀，别糊成一片）。

**多平台一致性**

- 同一套校准流程与数据格式跨平台复用；每个平台至少两台真实设备测过再发布。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 曲库与谱面 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 判定原型 | 1-2 曲，各 1 谱面 | 2-4 周 | 无美术；验证判定、校准与编辑器最小版 |
| 小型完整作品 | 8-15 曲，各 2-3 难度 | 3-6 个月 | 一套视觉主题，曲库可控 |
| 常见独立作品 | 20-60 曲，各 3-5 难度 | 6 个月到 2 年 | 编辑器与谱面管线占大头，曲库成本持续 |
| 长线运营型 | 100 曲起，持续更新 | 2 年以上 | 曲库更新即内容运营，授权是长跑 |

单首曲目的边际成本由三块构成：授权或定制费用、谱面制作（初稿常见半天到两天，测试与打磨再加一倍以上）、演出美术与宣发素材。三块都比预估贵，「先买 50 首」是最贵的错误。

编辑器是固定投资：波形、网格、打点、试听、热重载，常见 2-6 周；没有它，谱面成本会随曲库增长失控。曲库难度分布按目标人群铺开，入门区占比别低于三成，否则新人第一小时找不到能玩的曲。每曲的美术（封面、背景、演出）容易悄悄膨胀，先用克制方案验证留存，再逐曲升级。排期锚点：从零到「判定可信、校准可用、一首曲可玩」通常 2-4 周；到垂直切片（3-5 曲、编辑器可用、可交给外部测试）通常 2-3 个月。

曲库与版权（立项前必做，条款核对见《法务手册》（⑦））：

- 一首曲目的权利常分成两笔：录音（母带）与词曲（创作）。授权范围至少覆盖全球、永久、任意平台、可剪辑，并写明宣传物料、玩家直播与录屏的传播权。
- 交付物谈清：母带文件、元数据（BPM、拍号、offset）、是否分轨、是否独家。缺元数据的曲目要先人工标注，这笔工时别漏算。
- 退出与续约写进合同：授权到期、下架、续约价格与流程，以及买断、分成、委托三种合作模式的验收、修改次数与二创限制；逐条核对清单见《法务手册》（⑦）。

## 6. 第一个原型怎么起步

第一个原型只做一首曲，2-4 周完成，不碰曲库、剧情、商店与账号。

**第 1 周：判定循环。** 用一条自己录制或版权清白的简单节拍音轨，实现单轨到 4 轨的下落判定；判定窗可调，偏差直方图可视化；校准页跑通（跟拍 8-16 次、取中位数、验证）。这一周不要美术。

**第 2 周：编辑器最小版。** 波形加节拍网格、打点录入、即时试听、热重载，做出第一张你愿意给别人玩的谱面；顺带把校验器做出来，保存时就提示同轨间隔问题。

**第 3 到 4 周：外部测试与校准压力测试。** 找 3-5 人（含 1-2 个没玩过音游的人）：观察校准流程能否在无指导下完成，换耳机、换设备各试一次，记录断连点与抱怨点。之后再做第二、三首谱面，验证编辑器不是为一张谱面定制的。

成功标准（全部可观察）：

- 拿掉全部美术与音效，测试者仍愿意连打三首以上。
- 校准流程无指导下成功，测试者能复述「刚才在做什么」；换设备后能自己重跑。
- 判定直方图以零为中心、无明显偏移；同参数下重打同一段落，结果稳定。
- 测试者能说出失败原因（「这拍没跟上」），而不是「不知道怎么就断了」；「明明按准了却没判」的抱怨，每人 0 次。

判定与校准不达标，就先停在原型里修，不要开始铺曲库与美术；这两块地基上的返工是这个类型最贵的一笔账。

## 7. 常见坑

1. **拿帧时间或系统时间做判定**：手感时好时坏且查不出原因。判定必须挂在音频时钟上（§4）。
2. **不做校准，或没有重测入口**：无线耳机与家庭影院场景不校准就上线，玩家把设备延迟记在游戏头上，这是本类型最大的差评源。
3. **判定窗与相邻音符间隔冲突**：一次按键两个音符都想要，归属全靠猜（§3.1）。
4. **把判定窗当难度旋钮**：收紧窗口制造的是焦虑，不是深度；难度交给谱面。
5. **判定与反馈不同步**：看到命中但声音拖后、打击音与判定错位，演奏的错觉当场破功。
6. **曲库先买、玩法后定，或只用一首曲做完整个原型**：授权与数据格式都会特化到错误的方向，先跑通「一首曲能玩」再谈批量。
7. **授权范围缺项**：预告片、商店页、玩家直播与录屏、二创剪辑各自需要权利覆盖（⑦）。
8. **谱面只堆密度**：不可读的连打等于背谱，「难」与「不讲理」只隔一线；可读性检查要在试玩前跑。
9. **掉帧与垃圾回收尖峰**：本类型掉一帧就是一次判定事故，池化与帧率稳定是硬要求（§4）。
10. **难度只有一档**：新手第一小时找不到能玩的曲，高手两首就触顶；曲库难度分布就是留存结构。

## 延伸阅读

- 《游戏设计手册》（⑨）：核心循环、反馈与分数系统的通用方法，对应第 3 节。
- 《技术实现手册》（⑩）：音频时钟、输入延迟与性能工程，第 4 节的完整展开。
- 《美术与音频手册》（⑪）：音频设计与实现、响度与循环点规范，曲目交付前对照其规范表。
- 《法务、专利与竞争手册》（⑦）：音乐授权、合同与出海合规，曲库立项前先过一遍。
- 《关卡设计手册》（㉑）：难度曲线与节奏设计，谱面作为关卡时的通用方法。
- 《避坑大全》（⑥）：内容失控与外包类坑位，与第 7 节对照阅读。
