# Ludo Atlas · 类型手册 · 割草无双（Hack and Slash）

> **类型手册 · 第四辑**。定位：把「以一敌百」的扫荡做成第一乐趣的战场动作类型。玩家扮演战力超规格的武将，在成建制的军队里开路，一次攻击扫倒一片，同时推着一个个战场目标向前。
> 配套：《游戏设计手册》（核心循环与手感清单）·《技术实现手册》（战斗判定与同屏性能）·《关卡设计手册》（战场目标与节奏编排）·《独立开发生存手册》（范围与排期）。

## 1. 定位与核心循环

割草无双（Hack and Slash / Musou）以 2000 年《真·三国无双》开启的形态为原型：第三人称近战，玩家是战场上唯一的高战力个体，对手是成建制的军队；打一场战役，清一路杂兵，击破敌将，完成几个战场目标。英文类型名在更广的语境里泛指近战砍杀（含刷装砍杀一路），本页按中文社区主流的「无双」义项展开。

一句话定位：割草无双是**把「以一敌百」的压倒性力量做成第一乐趣**的战场动作类型。单挑没有意义，强弱在进场那一刻就定了；玩家要看的是自己的招式在人群里犁出多宽的一条沟。

核心循环用动词环写：

`进场 → 沿目标推进 → 割草开路 → 击破敌将或占领据点 → 战局变化（士气与增援）→ 完成战役 → 结算强化 → 下一场`

这个环以一场战役为单位，十到三十分钟跑一圈；战役内部的割草以秒为单位，一刀扫一片的反馈要在这个尺度上成立。它成立的前提有两条：爽感要不成比例（§3.1），战场要有骨架（§3.2）。只有割草没有战场，十分钟就腻；只有战场没有割草，就变回了策略游戏。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 清版动作 | 清版同屏三五个敌人，每次交手都要求攻防读解；无双用敌人数量撑场面，一击扫倒一片，压力来自战场目标而非单场群架 |
| 动作 RPG | 动作 RPG 把成长与掉落缝进每一场战斗，变强靠数值曲线；无双的角色强度在战役里是压倒性的，成长是为了放大割草效率，不是为了过关 |
| 幸存者类 | 幸存者类的攻击自动发生，玩家只负责走位与构筑；无双的每一刀都由玩家亲自挥出，方向、招式与镜头演出都是表达 |
| 动作冒险（角色动作） | 角色动作的题目是把连招打到单个强敌身上，考的是兑现精度；无双的连招对象是人群，考的是覆盖与节奏 |

一个自检问题：把同屏敌人砍到个位数，游戏还成立吗？答案若是「成立」，你做的更接近清版或角色动作；无双的爽感必须长在「多」上面，并且要有一张战场来安放这个「多」。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **压倒性爽感**：一次攻击扫倒一片，击飞、连锁、扬尘与数字同步到位；玩家先感到「强」，再理解「为什么强」。
2. **战场推进感**：目标、士气与战况在战斗中途变化，玩家始终知道「现在该去哪、为什么」。割草要有方向，不能原地刷。
3. **成长兑现**：等级、武器与技能带来的提升要能被身体感觉到（同样的连段，更短的击杀时间、更大的清场范围），不是只跳一个数字。
4. **表演性与低门槛**：无双技、处决与敌将登场都是演出事件，每场战役里要有一两个值得截图的瞬间；连按即可打出像样的连段，深度藏在派生与取消里，手生也能赢，高手能赢得更好看。

标杆作品（建议亲手玩过再拆，割草的手感与战场节奏只看视频学不到）：

| 作品 | 可学的点 |
| --- | --- |
| 真·三国无双（2000 年起的系列） | 类型原型：角色与武器的招式矩阵、战场目标（击破、占领、护卫）与士气条 |
| 战国无双（系列） | 同一框架换题材之后的角色差异化，招式个性与叙事演出的结合 |
| 海贼无双（系列） | 动漫联动的做法：原作名场面与招式还原，用割草兑现「原作级战斗力」 |
| 塞尔达无双：灾厄启示录 | 授权联动的现代完成度：同屏数量、招式丰富度与演出规格的平衡 |
| 火焰纹章无双：风花雪月 | 把战棋的兵种与阵营框架转译进战场的另一条思路 |

## 3. 设计要点

### 3.1 爽感公式：击飞、人数、连击数字

割草的爽感不是一个形容词，是一道可配平的算术：

`爽感 ≈ 一次攻击扫到的敌人数 × 击飞质量 × 反馈密度 ÷ 操作成本`

四个因子的含义与做法：

| 因子 | 做法 | 参考量级 |
| --- | --- | --- |
| 扫到的敌人数 | 判定要配得上刀光：普攻扇形覆盖，蓄力与无双覆盖全周；敌人密度按「一队一片」布阵，别拉成散兵线 | 一次普攻扫中三到五个，蓄力与无双上探到两位数 |
| 击飞质量 | 命中即大幅位移，飞出的人撞倒同伴形成连锁；落地扬尘与闷响补足重量 | 杂兵击飞初速度按「飞出两三个身位」调；敌将只退半步、不倒地 |
| 反馈密度 | 连击数字、击破数字、无双槽与音效分层同帧触发；数字要跳出来，别只缩在界面角落 | 连击按命中人数累加，清场后给结算特写 |
| 操作成本 | 连按出连段，派生与取消留给进阶；核心爽感不藏在搓招表里 | 一组攻击键加一个蓄力键起步 |

三条纪律：

- 判定向刀光看齐，宽容留在玩家一侧：刀光扫过的地方判定要中，宁多勿少；「扫过一片却没人倒」比「隔空命中」更伤爽感。
- 击飞要有重量分级：杂兵飞出人群，队长飞得短、爬起来快，敌将退半步但露出破绽，所有兵种一个飞法，人群就没有层次；连击计数要宽容，断连规则（受击、长时间无命中）明确且能被玩家预判，计数一跳一停，观赏性就没了。

### 3.2 战场节奏与目标设计：据点、士气、护卫任务

一场战役是一张地图上的目标清单，割草是走完清单的方式。目标分四类：

| 目标类型 | 典型形态 | 设计与作用 |
| --- | --- | --- |
| 击破 | 敌将在战场活动，击破后其部下动摇；总大将是战役的胜利条件 | 主线目标，串起进军路线 |
| 占领 | 在区域内清空守军，据点易主，改变地图上的进军通道 | 把地图切成阶段，给割草一个方向 |
| 护卫 | 护送友军到指定位置，或阻止友军败走（带倒计时） | 制造时间压力与「两头跑」的决策 |
| 防卫 | 本阵与要害被威胁时回防，倒计时拉响 | 制造危机感，逼玩家离开舒适区 |

士气是把玩家的战果翻译成战局变化的反馈层，也是动态难度的旋钮。常见做法：击破敌将、占领据点推高我方士气，敌方杂兵行动变消极；本阵危急、友军苦战时提示拉响（台词、地图闪烁、警示音）。士气条让玩家一眼读出「现在顺不顺」。

战役节奏按四拍铺：开场行军与热身割草（敌人稀）、中盘目标争夺（据点与敌将，密度上升）、高潮（伏兵、增援或决战级敌将）、收尾（追击残部或抢救败局）。伏兵与增援是成本最低的节奏工具：同一片战场加一组敌人，压力曲线就换了形状。

战场比动作舞台大一个量级，迷路是最大的体验事故。引导三件套缺一不可：小地图与目标图标、方向指引（镜头或箭头）、目标变化时的台词与提示音。目标优先级要动态排序，本阵危急压过支线，别让玩家在两张目标清单之间做无谓的犹豫。

### 3.3 角色与武器的内容矩阵：人物 × 武器 × 招式

这个类型的内容账是一条乘法链，也是它最大的坑：

`可玩角色 × 武器模组 × 招式套 × 敌将 × 战场`

骨架的建法有两条路线（推荐第三条混合路线），先选定再开工：

| 路线 | 做法 | 代价与收益 |
| --- | --- | --- |
| 武器解耦 | 招式跟着武器大类走，全角色共享；角色只做数值、专属无双与演出 | 复用率最高，换武器即换手感；角色个性偏薄 |
| 角色专属 | 每个角色一套完整招式与专属武器 | 个性最强，成本最高；人数上不去 |
| 混合 | 武器大类共享模组打底，主角与招牌角色加专属无双与专属动作 | 内容量可控，宣传点集中在少数角色身上 |

招式体系要「输入浅、派生深」：普通攻击连按出一段连段，蓄力键在不同连段节点接入，派生出范围与属性不同的招式（社区俗称 C 技体系）；无双技是全周解围与爆发，一场放两三次，配镜头演出。玩家的表达欲放在派生、取消与技的组合里，而不是搓招表里。矩阵的账要提前算：每新增一个武器模组，要在全部战场与全部敌将身上过一遍平衡；每新增一名敌将，要与全部可玩武器对拆；参考做法是先做两到三个武器大类打底，把主角做满，其余角色用共享模组加演出填充，玩法验证之后再考虑加人。

### 3.4 敌兵层次与 AI 编排

敌人要有层次，否则一百个同款杂兵也只是沙包：

| 层级 | 行为 | 玩家的应对 |
| --- | --- | --- |
| 杂兵 | 成群推进，出手慢，被击飞就是飞来飞去 | 范围攻击清场，爽感的主要来源 |
| 队长与精锐 | 带护盾或抗性，硬直短，破防前砍不动 | 蓄力攻击破防，教玩家换招 |
| 敌将 | 霸体招式、格挡与反击，会打断无双以外的连段 | 读招、连段与无双，单挑级对手 |
| 总大将 | 阶段化行为与登场演出，战役的结算对象 | 决战目标 |

AI 的编排目标不是聪明，是「上镜又公平」：同一时刻只放少数敌人真正贴身出手（攻击配额），其余在包围位推进与试探；被击飞的方向要散开、要能撞人，别原地打转。杂兵太凶会把玩家围死，太呆会排队送死，两头都要在原型期调平。画面外的敌人不做出手决策，或先入场再出手；无预警的冷刀是差评来源。

### 3.5 收割之后的成长线

战役之间的强化是玩家留下来的理由，等级、武器锻造、技能盘按「让下一场割得更快」设计。成长的可感知指标是清场时间与一次攻击扫到的敌人数，不是面板数字；武器与素材按战场难度分档掉落，给重复刷关一个正当理由。养成保持浅：割草的深度在战场与招式上，不在配装表里。

## 4. 技术要点

工程难点集中在三处：同屏数量与性能、战斗判定的规模化、演出与镜头。以下与引擎无关，点名的是概念与结构。

**同屏数量与性能**

- 同屏预算先压测、后设计：在目标机型的最低配上跑「杂兵数量梯子」（参考：20、50、100、200 各跑一遍），记录帧时与内存，把结论写进设计约束；招式的覆盖范围与敌人密度都在这个预算内做。预算决定手感，不能事后砍。
- 小兵用最便宜的表示：共享动画骨架与材质、按距离分频更新（远处降帧更新动画与转向，画面外冻结或降级）、关掉不必要的物理与粒子。同屏数量是省出来的。
- 大量个体不做完整寻路：导航网格留给主路径与敌将，杂兵群体用编队与流场类批量转向（同一目标点加分离力），挤堆与绕行由引导层处理。
- 对象池覆盖杂兵、特效、伤害数字与掉落物，生成与回收分批进行；音频并发设上限与优先级（命中音高于台词，台词高于环境音），杂兵一多，声音系统是最先崩的子系统。

**战斗判定的规模化**

- 判定盒挂在攻击帧上，每次攻击对同一目标只结算一次；命中查询走空间分区（把杂兵放进网格，只检查判定盒覆盖到的格子），这是上百个目标下判定不崩的关键。
- 杂兵的受击反应要「便宜而好看」：击飞用动画位移或简化弹道，撞人只查附近的几个目标，不上完整刚体物理；连击计数与击破统计集中在一处结算，别散进每个敌人自己的脚本，一百个敌人各维护一份状态，统计迟早对不上。

**演出与镜头**

- 无双技与处决是镜头事件：拉近、慢动作、特效与音效同帧同步；演出期间锁输入并给无敌，收尾留一段保护帧，允许跳过。
- 战场镜头的基本要求是「看得清包围」：距离与角度要覆盖身周威胁；割草密度上来之后，任何晃动运镜都是眩晕源。

**数据化**：角色、武器、招式、敌将与战场目标全部进数据表；战场用脚本文件描述触发点、时序与条件，让非程序也能排战场（方法对照《技术实现手册》）。

## 5. 内容量与工作量参考

先记乘法法则：成本是乘出来的。可玩角色乘以武器模组乘以招式套，敌将再乘一层，战场再乘一层；每个新武器要在所有战场与敌将身上验证，每名敌将要与全部武器对拆。联动题材另开一层账：授权、原作监修与招式还原都是独立预算。

| 项目形态 | 可玩角色 | 战场量级 | 周期量级 | 备注 |
| --- | --- | --- | --- | --- |
| 割草原型 | 1 | 1 张小战场 | 3-6 周 | 只验证爽感公式与同屏预算 |
| 首作 / 小型完整作品 | 2-4 | 5-8 张 | 8-14 个月 | 武器大类复用，敌将 5-8 名 |
| 常见独立规模 | 6-10 | 12-20 张 | 1.5-2.5 年 | 角色与武器两个矩阵都要养 |
| 商业规模 | 20 以上 | 30 张以上 | 3 年以上 | 联动与授权另计，分阶段发布内容 |

动作量级（参考）：一个可玩角色的动作集（普攻连段、蓄力分支、无双、骑乘、受击倒地、登场与胜利演出）通常 50 到 100 组动画，且几乎全部要逐帧调打击帧；武器模组复用是压低这条线的主要手段。杂兵共享一套骨架，用武器、配色与体型做变体；敌将优先从可玩模组裁剪（换武器与数值，行为与 AI 另写）。

小团队的现实切面：

- **武器模组先行，角色个性后置**：先做两到三个武器大类，主角做满，其余角色用共享模组加演出填充；战场主题收在 3 到 5 个，靠地形布局与目标配置做出差异，而不是不停开新美术。
- **敌将分层**：杂兵变体填密度，敌将裁剪加 AI，专属礼遇只给总大将与招牌敌将。
- **首作砍掉四样**：联机、开放世界、多阵营剧情线、深度养成，任意一样都够再吃几个月；开放世界对割草是范围与工程的双重放大器，首作不碰。

排期锚点：爽感原型 3-6 周；到「一张战场达到发行质量」的垂直切片通常 4-6 个月；之后按内容量乘打磨系数外推。这个类型的预算大头在角色动画、战场美术与战斗打磨。

## 6. 第一个原型怎么起步

第一个原型只做一张小战场：一个可玩角色、两种杂兵、一名敌将、三个目标（击破、占领、护卫），3-6 周，不碰美术、剧情、存档与菜单。

**第 1 周：爽感公式。** 一套普攻连段、一个蓄力范围技、一个无双；把击飞、连锁撞击、连击数字与击破数字先做出来。丑是应该的，但「一刀扫倒一片」的瞬间必须成立。

**第 2 周：同屏与层次。** 跑杂兵数量梯子压测，定下同屏预算；加上敌将（霸体与反击），验证「杂兵海里打单挑」的手感。

**第 3 周：战场骨架。** 一张小地图、三个目标、士气条与引导三件套；把「清场之后去哪」写进目标链。

**第 4 到 6 周：调参与测试。** 找 3 到 5 个没玩过的人，各打两遍，记录连击是否被自发追求、无双技是否被主动使用、目标指引是否零口头解释可读。

成功标准（全部可观察）：

- 灰盒加占位音效，测试者仍愿意反复打同一张战场十分钟以上。
- 测试者能自己说出爽点（扫倒一片、连锁击飞、无双收场），而不是「打倒了一些人」。
- 目标与引导在无说明的前提下可读：测试者自己找到下一个目标点。
- 同屏数量达到你压测定下的预算且帧率稳定；改一个手感参数，5 分钟内能在运行的游戏里看到差别。

爽感公式与同屏预算验收不过，就不要开始铺内容：地基上的返工，会乘以全部角色与战场（§5）。

## 7. 常见坑

1. **爽感未成立先铺内容**：角色、武器、战场量产之后才发现「一刀扫倒一片」不成立，全部返工。先冻结爽感公式与同屏预算（§3.1、§4）。
2. **判定跟不上刀光**：视觉扫过一片，判定只中两三个；或反过来隔空命中。判定以刀光为准，宽容留给玩家一侧。
3. **同屏数量事后砍**：招式范围与敌人密度按「能有一百个」设计，压测后发现只能跑三十个，玩法推倒重来。先压测定预算，再定玩法（§4）。
4. **敌人围死或排队送**：全员压上把玩家连死，或呆立排队挨打；攻击配额与轮番出手两头都要配平（§3.4）。
5. **战场无引导**：玩家在本阵与敌阵之间迷路，目标靠猜。小地图、方向指引与台词三件套缺一不可（§3.2）。
6. **内容量按线性估**：角色乘武器乘敌将乘战场（§5），超支通常超在乘号上。
7. **只有割草没有战场**：地图退化成打桩场，清完一堆又一堆，十分钟就腻。目标与士气让割草有方向（§3.2）。
8. **无双技演出失控**：演出过长、不可跳过、结束后被围殴。演出配无敌与保护帧，跳过要允许（§4）。
9. **美术形象照抄现有作品**：历史与神话题材是公共素材，但角色造型与招式演出是各家的资产，照抄是版权风险，不是致敬。
10. **首作押开放世界**：开放世界把内容量与工程复杂度同时放大一个量级，是割草首作的头号范围事故（见《独立开发生存手册》）。
