## 1. 定位与核心循环

模拟经营（Management Sim）让玩家经营一家机构：医院、游乐园、餐厅、动物园、游戏公司都行。玩家不亲自端盘子、扫地、开药，负责的是建什么、雇谁、定什么价；干活的是员工，付钱的是顾客。机构按玩家搭好的规则自己运转，玩家的活儿是把它调成一台现金流为正的机器，再把它做大。

一句话定位：**用建造、雇佣与定价，让一个会自己运转的系统先在账面上活下去，再长大。**

核心循环用动词环写：

`选址与建造 → 招募与培训 → 接待顾客与生产 → 结算收入与满意度 → 解锁与升级 → 扩建与换址 → 客群变大 → 回到第一步`

循环的三层嵌套，每一层的钩子不同：

| 层级 | 时长（现实） | 玩家在做什么 | 结算点 |
| --- | --- | --- | --- |
| 分钟级 | 几秒到几十秒 | 一位顾客走完流程、一笔收入入账 | 即时音效与飘字 |
| 营业日级 | 5-15 分钟 | 一整天的运营与收支 | 日结算报表 |
| 阶段级 | 1-3 小时 | 一张地图或一个星级目标 | 解锁新设施与新地图 |

循环的动力是正反馈：收入带来扩建，扩建带来客流，客流带来更多收入。设计者的活儿是给这条回路装闸门（§3.1），按节奏松开，不放任它在开局两小时里烧完。

与相邻类型的边界：

| 相邻类型 | 边界 |
| --- | --- |
| 农场经营 | 那类管理一个角色与一块地，颗粒度是一天一格；本类管理抽象组织与预算，颗粒度是房间、员工与流水 |
| 城市建造 | 那类的对象是城市本身，布局与分区是主戏；本类的对象是一家机构，员工与顾客的微观流程是主戏 |
| 殖民模拟 | 那类每个个体有人格与故事生成；本类的顾客与员工是统计意义上的人群 |
| 放置增量 | 那类把操作压到最低、把等待做成卖点；本类要求持续决策与调整 |

## 2. 玩家体验目标与标杆作品

玩家来玩这个类型，要的是五样东西，按优先级排：

1. **掌控感**：混乱的机构在玩家手里变得井井有条，瓶颈一个个被消掉。
2. **增长可见**：数字（收入、客流、评级）与空间（新房间、新楼层）同时变大。
3. **优化者的快乐**：同一个目标打出更高的效率，玩家自己找出更好的布局与流程。
4. **危机与救火**：突发事件（设备损坏、投诉潮）带来短暂紧张，解决之后释放。
5. **表达欲**：布置、命名、造景，让机构带上玩家自己的印记。

标杆作品（都能直接玩到，建议先玩后读）：

| 作品 | 学什么 |
| --- | --- |
| 主题医院 | 原型教科书：房间、员工、病症三件套加幽默包装 |
| 双点医院 | 现代版本：科室动线、员工养成、关卡星级与轻剧情 |
| 过山车大亨 | 公园运营加建造表达，设施与游客需求的耦合 |
| 过山车之星 | 3D 化与创作工具，玩家自建内容怎么变成卖点 |
| 动物园之星 | 保育与经营双线，把主题做成机制 |
| 开罗系列 | 轻量高密度：在小屏幕上把投入产出扩张压进几小时 |

## 3. 设计要点

### 3.1 经营循环与正反馈节奏

「投入、产出、扩张」三段按固定节拍循环，每一段都给玩家一个明确的下一步：

| 阶段 | 玩家动作 | 系统回应 | 检查点 |
| --- | --- | --- | --- |
| 投入 | 建造房间、雇佣员工、买设备 | 成本可见、工期可见 | 花出去的每一笔钱都知道买到了什么 |
| 产出 | 观察运营、微调配置 | 收入与满意度实时变化 | 因果链在几秒内可见 |
| 扩张 | 解锁新设施、开新区域 | 客群变大、新需求出现 | 扩张立刻带来新问题，而不是简单放大 |

正反馈的节奏靠三件事控制：

- 解锁闸门：新设施挂在目标上（星级、名气值、任务链），玩家看得见还差什么才能开。
- 成本阶梯：扩张的成本增速高于收入增速（例如升级费涨 50%，收入只涨 20%），逼玩家做优化，别堆房间了事。
- 呼吸段：高强度扩张之后给一段低压运营时间，让玩家在收获里消化新系统；两个阶段目标之间只引进一个新系统。

### 3.2 数值经济架构：资源、汇率与通胀

资源种类的纪律：**一到三种，能一种就不两种**。每多一种资源，就多一条产出线、一个显示位、一课教学。第二种资源的正当理由只有两类：给扩张装限速（声望、资质），或制造二选一的取舍（两套客群各自认自己的货币）。

主货币之外的附属资源，最后都要在玩家脑子里折算成主货币。折算口径写进设计文档：

| 附属资源 | 惯例口径 | 设计作用 |
| --- | --- | --- |
| 满意度 | 折算成客流或收入乘数 | 把服务质量变成看得见的数字 |
| 声望与名气 | 累计值决定客群与设施门槛 | 给扩张装限速 |
| 研究点 | 折算成长期效率乘数 | 引导资金投向长线 |

表里只定口径，系数按自己项目实测。判断一条附属资源该不该存在的标准：它能不能让玩家做出一个别的资源做不出的取舍。

通胀是中期最大的坑：成本不涨、收入线性上涨，游戏会在三分之一处失去挑战。控制手段三类：

- 同步上调：每张新地图或新阶段重置成本结构，旧关卡的解法不能直接搬。
- 边际递减：同类设施重复建造时收益递减（第二间同样的病房效率打折），逼玩家换组合。
- 钱汇：装饰、培训、慈善这类只吃钱不产出的出口，让富余现金有去处。

平衡方法只有一条纪律：先搭表，再实测，顺序反了必翻车。

- 建「每单位时间净收益」表：每个设施、每条产线一行，算净收益，不看单笔售价。
- 标注回报周期：一次投入要几小时回本，玩家能自己算出值不值。
- 每十小时回看一次曲线：钱花不出去（汇不够）或钱不够花（产出太低），都会在这一步暴露。

### 3.3 系统耦合与看板信息设计

耦合是这个类型深度的来源：员工影响服务速度，服务速度影响满意度，满意度影响客流，客流影响收入，收入决定扩建。链条越长越有深度，也越容易变成黑箱。

看板的使命是把黑箱拆开给玩家看。三条原则：

- 关键指标不超过五个：现金、客流、满意度、员工负荷、目标进度。其余数字收进二级界面。
- 因果可追溯：任何异常数字，都能顺着两三次点击找到源头（满意度低 → 某科室排队 12 人 → 缺一间诊断室）。
- 警告分级：同时只推最高优先级的警告，其余排队；二十条红字等于没有警告。

检查表：新玩家进入游戏十分钟，能不能说出「我现在为什么亏钱」？说不出，先修看板，再加系统。

### 3.4 自动化与微操的取舍

玩家亲自做的事应该永远留在决策层，重复劳动交给员工（游戏内的 AI）：

| 层级 | 例子 | 交给谁 |
| --- | --- | --- |
| 高层决策 | 建什么、建在哪、定价、雇谁 | 玩家，永远手动 |
| 中层管理 | 排班、升级、培训、优先级 | 玩家调一次，自动执行 |
| 低层执行 | 打扫、送药、领位、维修 | 员工自动执行 |

自动化的三个平衡点：

- 过早失去参与感，过晚磨掉耐心。常见的分界线是「同一件事做过二十次」，就该出现自动化手段。
- 自动化要给开关或策略选项：玩家能干预自动化的行为（优先级、区域限制），而不是全有或全无。
- 留一类只有玩家能做的紧急处置（突发事件、贵客到访），让微操保留一点手感。

验收方法：让玩家连玩三小时，问「哪一步你觉得自己最像老板」。答不出来，说明决策与微操的边界没画好。

### 3.5 内容量与系统的乘数关系

这个类型的成本结构是乘法，不是加法：系统数 × 内容条目数 × 每关验证轮数。

- 每加一类设施，它要跟所有客群、所有关卡、所有员工职业互相过一遍。
- 每加一种顾客（病人、游客、食客），它要能走通所有设施与所有关卡的目标。
- 组合数量级：3 类设施 × 4 种顾客 × 10 张地图 = 120 个组合，每个组合至少要在表里验证一次。

纪律：**先定系统数量的上限，再往每个系统里填内容**。反过来做，会在中期发现验证成本超过开发预算。

## 4. 技术要点

- 模拟与表现分离：模拟层跑固定步长（常见 10-20 次每秒），表现层订阅事件做动画与音效。好处是能加速、能存档回放、能无渲染批跑。
- 数据驱动到底：设施、设备、职业、顾客类型、关卡目标、经济参数全部进表（CSV、JSON 或引擎表格资产），代码只读表。
- 顾客动线是核心系统：需求状态机（到店、排队、前往、被服务、离开或复诊），配导航网格与排队点管理。
- 员工 AI 从简到繁：第一版用任务队列加优先级（扫描待办、认领、执行），不要一上来就做行为树全家桶。
- 性能：代理多时用时间片与区域激活（远处的顾客降频更新），寻路做缓存与批量重算；先测最差情况（开诊高峰、满员动物园）。
- 调试工具与批跑：时间加速、金币直改、状态标记、单查一位顾客的完整动线，再加一个占位玩家自动建造与雇佣，跑十局输出每关收支曲线，失平的地方会自己浮出来。
- 存档：全量模拟对象序列化加版本号与迁移函数，中途读档不丢状态；数值更新后旧档能继续玩，是这个类型的基本礼貌。

## 5. 内容量与工作量参考

以下是同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容清单 | 周期量级 |
| --- | --- | --- |
| 玩法原型（灰盒） | 1 张平面图、1-2 种设施、1 种顾客、无正式美术 | 2-4 周 |
| 垂直切片 | 1-2 张地图、5-8 种设施、3-5 种顾客、一套关卡目标 | 3-6 个月 |
| 小型商业体量 | 8-15 张地图、15-25 种设施、10-20 种顾客、成就与统计 | 12-24 个月 |
| 完整商业体量 | 数十种设施与顾客、三条以上职业线、持续更新 | 团队起步 1-3 年 |

单个内容单元的常见成本（量级参考）：

| 内容单元 | 单位成本 | 说明 |
| --- | --- | --- |
| 一种设施 | 3-10 天 | 模型、动画、数值、图标、平衡 |
| 一种顾客或需求 | 2-5 天 | 动线、行为、数值、文案 |
| 一种员工职业 | 3-7 天 | 任务逻辑、动画、技能与升级线 |
| 一张地图与目标 | 1-3 周 | 布局、关卡目标、难度调优 |
| 一档反馈音效 | 数小时 | 单个便宜，数量积少成多 |

乘数算例：在视觉上再加一种设施，成本不是 3-10 天，而是要再乘以它过一遍的顾客类型与地图数。估算时先把乘法结果写在纸上，再决定做不做。

## 6. 第一个原型怎么起步

第一个原型只做一条完整链路，2-4 周完成，不碰正式美术与剧情：

1. 一张平面图、一扇入口、一扇出口，先让顾客能进来、能出去。
2. 一种需求：顾客到店 → 排队 → 被服务 → 付钱 → 离开。跑通这一条，游戏就有心跳。
3. 一位员工：自动扫描待办、逐条处理。这是全项目第一个 AI，做最简版本。
4. 现金流：一笔建造费、一笔服务收入、一天一次的结算。连玩三天，看曲线正不正。
5. 一块看板：现金、客流、满意度三个数字加一个目标进度，玩家必须能看懂为什么。
6. 一次扩张：加第二种设施与它带来的新顾客，验证「扩张带来新问题」的循环。
7. 存档：从第一天就带版本号。

验收标准（全部可观察）：

- 玩家十分钟内出现「我要再建一间」的冲动，并说得出钱从哪来。
- 出现一次失败（亏完现金或顾客流失），玩家能说出原因与改进方案。
- 拿走全部美术与音效，测试者仍愿意玩到第三个营业日。

## 7. 常见坑

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| 系统堆太多 | 玩家记不住房间、员工与数值的关系 | 先按 §3.5 定系统上限，再往里填内容 |
| 资源种类泛滥 | 五种货币各占一个显示位，全成了换算题 | 一到三种，其余折算进主货币 |
| 中期通胀失控 | 玩到一半钱没处花，或永远缺钱 | 每十小时回看收支曲线，补钱汇或调阶梯 |
| 看板不可读 | 玩家说「我不知道发生了什么」 | 五指标原则加因果追溯，先修看板再加系统 |
| 自动化节奏错位 | 玩家喊闲，或者喊累 | 以「做过二十次」为自动化登场线 |
| 员工 AI 卡死 | 顾客堵在门口骂街，游戏看起来像坏了 | 死锁检测与兜底处理写进第一版 AI |
| 只调表不动结构 | 数值改了十版，问题依旧 | 结构问题（动线、耦合）先改，再调数值 |
| 内容乘数低估 | 排期后段爆炸，砍什么都没时间 | 用 §5 的乘法算例，砍系统保质量 |
| 轻视视听反馈 | 逻辑是对的，玩家感觉不到 | 收入、成就、投诉都要有画面与声音 |

## 延伸阅读

- 《游戏设计手册》（⑨）：核心循环与嵌套、经济系统的源与汇，本文第 3.1、3.2 节的上位方法。
- 《制作管理手册》（⑫）：估算与排期，配第 5 节使用。先给「一种设施、一种顾客」计时，再做乘法。
- 《案例研究集》（⑳）：经营类作品的复盘，注意「边运营边被数据教育」的迭代节奏。
- 《避坑大全》（⑥）：数值反复横跳与内容量失控属于高频坑位，开工前过一遍。
- 《独立开发生存手册》（⑱）：范围控制。系统数量的上限由团队与预算决定，不由野心决定。
- 练习一：选主题医院的一关，画出顾客从进店到离开的完整动线图，标出每个排队点与阻塞点。
- 练习二：用纸面表格搭一份十天经济模型：两类设施、两种顾客、三种成本，算出每天净收益，对比第一天与第十天的体验差异。
- 练习三：给正在做的原型写一份看板清单，五个关键数字、每个数字的因果来源、异常时的最高优先级警告。

模拟经营的地基是一条能自转的链路：先让它转起来，再谈扩张。
