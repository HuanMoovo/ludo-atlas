# Ludo Atlas · 类型手册 · 抽卡养成（Gacha RPG）

> **类型手册 · 第四辑**。定位：以「收集角色、养成角色、编队作战」三环为骨架、以卡池抽取为收集手段的养成 RPG；内容按版本滚动供给，长线运营是产品形态的一部分。
> 配套：《游戏设计手册》（核心循环与概率数值）·《技术实现手册》（数据驱动与结算）·《运营与增长手册》（长线节奏与变现伦理）·《法务、专利与竞争手册》（概率公示与发行合规）。
> 本文不放外链；标杆只用大众熟知的作品，数字为常见量级，按自己项目的实测校准。

## 1. 定位与核心循环

一句话定位：抽卡养成是**把「收集、养成、编队」三环装进同一个角色池**的养成 RPG。抽卡决定「你拥有谁」，养成决定「谁变强」，编队决定「谁出场解题」；三环共用同一批角色资产，互为弹药。

核心循环用动词环写：`攒资源 → 抽卡收集 → 投入养成 → 编队出战 → 结算奖励 → 回到攒资源`。这个环以版本为长期单位滚动：一次抽卡是几秒的情绪峰值，一次养成是几天的规划，一个版本是几周的等待与兑现。

| 环节 | 玩家在做什么 | 黏性来源 |
| --- | --- | --- |
| 收集 | 攒抽卡资源、抽卡、补图鉴与好感 | 新角色的吸引力、「还差几抽」的接近感 |
| 养成 | 升级、升技能、刷装备、解锁剧情 | 投入的所有权感、可见的强度与内容成长 |
| 编队 | 配队、打副本与主线、调整定位 | 养成成果的验收、「换个人试试」的解题欲 |

三环互为弹药：收集给养成原料（新角色可养），养成给编队强度（可上场可过关），编队给收集理由（打不过、想换解法，就会想要新的角色与强度）。任何一环塌掉，另外两环都会失去意义：没有编队深度，抽卡退化成集邮；没有养成投入，抽到的角色只会躺在仓库里；没有收集驱动，编队退化成纯数值比较。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 怪物收集 | 收集对象靠探索与捕获获取、个体可交换；抽卡养成的角色来自卡池，叙事、演出与人设是角色的主要卖点 |
| 集换式卡牌 | 卡池与开包同源，但对手是真人、构筑在赛前完成；抽卡养成以 PvE 内容为主，编队围绕职能与克制 |
| JRPG | 固定队伍与一次性完结的内容包；抽卡养成把角色当作持续更新的商品，数值与内容按版本滚动 |
| 放置增量 | 放置的成长靠时间自动跑；抽卡养成的成长要玩家主动决策与投入，时间只是资源之一 |

一个自检问题：把卡池与三环替换成「固定队伍加线性通关」，乐趣还剩多少？答案若为「所剩无几」，你做的就是抽卡养成；答案若为「照样好玩」，你要做的可能是传统 RPG，抽卡在这类项目里只是变现层。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **角色吸引力**：抽卡的动机来自角色本身（人设、立绘、配音、剧情地位），强度是第二层。角色立不住的卡池，概率再大方也留不住人。
2. **抽卡的可计算**：保底进度可见、概率与规则公示、重复物有出路；玩家能算出「最坏还差多少」，等待就变成积蓄而不是煎熬。
3. **养成的可见回报**：投入的资源换成看得见的强度与内容（技能质变、新台词、新演出），而不是纯百分比的抬升。
4. **编队的解法空间**：职能与克制让不同阵容过不同关卡，养成成果有验收场，攻略有得聊。
5. **长线的期待感**：每个版本有新角色、新剧情与新玩法，玩家手里永远有下一个目标。

反面感受（出现任意一条都是红灯）：看不到保底尽头、算不出还要多少；养了一个月的角色被新角色全面平替；日常循环像打卡上班。

标杆作品（大众熟知名单，建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 原神 | 大世界加角色卡池的组合、保底与跨池规则的公示口径、版本活动更新引擎 |
| Fate/Grand Order | 剧情与角色塑造当最大卖点：卡面、宝具演出与主线更新构成的长期牵引 |
| 明日方舟 | 塔防战斗与干员收集的结合、克制的数值膨胀、活动叙事与复刻节奏 |
| 崩坏：星穹铁道 | 回合制战斗的轻量化、职能（命途）体系、新手期的保底成长线 |
| 阴阳师 | 国产卡牌 RPG 的范式：御魂刷取的长线循环、公会与活动运营 |
| 赛马娘 Pretty Derby | 单周目育成与卡池的分层：育成剧本、支援卡与大赛，三层目标互相供料 |

玩家对这个类型的默认期待：概率与保底规则透明、抽卡记录可查、重复角色有转化出口、日常负担可控、活动可追赶。缺失任何一条，差评与流失会同时上门。

## 3. 设计要点

### 3.1 三环结构：角色是唯一的通货

收集、养成、编队围着同一批角色转，角色的设计维度要一次想全：

| 维度 | 要回答的问题 | 常见做法 |
| --- | --- | --- |
| 外观 | 玩家为什么第一眼想要 | 立绘或模型、差分表情、专属演出 |
| 战斗定位 | 编队里解决什么问题 | 输出、坦克、治疗、辅助、控制，每人至少一个岗位 |
| 人设与叙事 | 玩家为什么记住并喜欢 | 性格标签、关系网、专属剧情与语音 |
| 获取与稀有度 | 以什么代价拥有 | 稀有度分层挂到卡池档期上 |

四者错位的角色卖不动：立绘好但技能同质，玩家抽完就闲置；机制好但人设平，社群讨论与二创起不来。角色的验收问题只有一个：玩家会不会为「拥有她」本身付钱，而不只是为强度。

养成线按优先级取二到三层做透，堆满会击穿玩家的算账能力：

| 养成层 | 常见形式 | 职责 |
| --- | --- | --- |
| 等级与突破 | 经验道具、突破素材、每周副本 | 数值底盘与进度卡点 |
| 技能 | 升级材料、专属技能 | 机制与倍率的质变点 |
| 装备或词条 | 随机词条装备、专属武器 | 长线刷取循环与上限空间 |
| 好感与羁绊 | 送礼、同行、专属剧情 | 情感回馈与角色内容的兑现 |

重复角色的出路要提前设计：首次获取与重复获取的价值差（转化为碎片、升星素材或专属货币）是抽卡体验的减震器，也是长线收集的目标结构。

### 3.2 卡池与概率设计：结构、保底与公示

卡池结构与概率方法：

- 池子分层：常驻池、限定池、新手池，必要时加装备或武器池；限定池用当期概率提升（UP）制造档期，复刻负责回填空档。
- 概率分两层：基础概率负责稀有度分层，保底负责最坏体验。硬保底是计数到上限必出，软保底是临近上限时概率递增；「当次未中、下次必中」一类规则用确定性换公平感，是近年主流做法。
- 期望值先算后用：用期望与分布（而不是单点概率）平衡商业与体验，改一个参数就用模拟重跑（工具见 §4）。
- 保底要可计算、可接力：玩家能算出最坏情况；保底计数是否跨池继承、跨哪些池继承，写明写死。

合规口径（底线，展开见《法务、专利与竞争手册》）：

- 概率与保底公示是硬性要求：抽取对象的名称、属性、概率与保底规则如实公示，公示与实际一致，不得暗改。
- 抽卡记录可查、可审计：服务器留存全量抽取记录，玩家可查，客诉可回溯。
- 出海逐市场核对：部分海外市场对随机付费（战利品箱）有严格判例与限制，不默认一套方案全球通用。

设计纪律：重复物有出路，别让「又一次重复」变成纯浪费；免费玩家按时间与规划可攒到保底，这是留存的基本盘。概率与保底的数值口径由模拟与商业模型推导，本页只讲结构与纪律。

### 3.3 体力与长线经济：节奏阀门

体力（行动力）是内容消耗的节流阀，同时干三件事：控制推进速度、给内容生产留时间、提供付费点。设计口径是让它服务节奏，而不是把想玩的玩家锁在门外：

- 给缓冲：体力溢出存储、邮件补发、周常补给，避免「上线晚了就亏」的挫败。
- 给选择：体力投向多条线（主线、素材、活动），玩家要为优先级做取舍，而不是无脑清空。
- 给追赶：活动与副本的开放窗口容得下后进玩家，复刻与常驻化是低成本的追赶通道。

经济分三层盘：货币（免费硬通货与付费货币）、抽卡资源（券与等值货币）、养成素材；三层的产出与消耗先落表，再谈投放节奏。

数值膨胀是抽卡产品最大的长期债：新角色靠机制差异与定位互补提供新鲜感，不靠倍率加码；定期复刻、强化与再平衡旧角色，保住老玩家库存的价值。长线节奏由四件事轮转：版本更新、活动排期、日常与周常、周期玩法；留存与付费指标怎么盯、活动怎么排，见《运营与增长手册》。变现伦理的口径同样以《运营与增长手册》为准：为热爱付费，不为焦虑付费。

### 3.4 内容引擎：剧情活动与版本更新

长线产品的生命线是内容产能，不是首包质量。每个版本成套交付「新角色加新剧情加新玩法或活动加新奖励」：

- 剧情活动是文本量的主体，同时承担角色塑造与卡池推销，结构常见三段：剧情段、战斗挑战段、奖励结算段；限时玩法负责调节节奏，复刻负责低成本回填档期，给错过的新玩家补课。
- 角色与活动要解耦：活动不绑死单一角色，角色档期不绑死单一玩法，任何一边延误时不至于连锁垮掉。
- 产能纪律：并行开发多个版本，常备一到两个版本的缓冲；先算清楚团队每月能稳定交付几个角色、多少剧情，再定版本周期（排期方法见《制作管理手册》）。
- 剧情断更或质量滑坡，卡池的吸引力同步下滑；反过来，角色人气也会反哺剧情与社群内容，两边是一条绳。

### 3.5 落地现实：发行与合规前置

抽卡形态把发行复杂度抬高一个量级，以下几件事在立项时就要过一遍（完整流程与材料清单见《全平台上架手册》）：

- 版号：国内正式商业化渠道（应用商店、小游戏虚拟支付、国内 PC 平台）都要求版号；审批周期不可控，等待期必须计入排期，做完不等于能上线。
- 实名与防沉迷：接入实名认证与未成年人保护系统是上架的硬性要求，时段、时长与消费管控口径按渠道最新规则执行。
- 概率公示与出海差异：随机抽取玩法的公示义务（§3.2）是上线合规底线的一环；海外平台不走版号，但要走评级与当地法规，随机付费监管逐市场核对。

小团队的现实：以上每一条都指向持续的合规与运营投入。更现实的形态是先做体量可控的单机版（抽卡作为玩法而非变现），验证三环成立之后，再决定要不要进入运营型赛道。

## 4. 技术要点

工程难点集中在四处：服务器权威、数据驱动、概率可复现、内容管线。通用方法见《技术实现手册》，联机与后端全流程见《联机与后端深入手册》。

**服务器权威与结算**

- 抽卡结果由服务器决定并即时入库，客户端只负责演出；任何「先发客户端、后入库」的写法都会变成刷卡与刷资源的漏洞。
- 抽卡是一次事务：扣资源、抽结果、发物品、写日志四步原子化；请求幂等处理，断线重连不重复扣费也不丢结果。审计能力从第一天就要有：抽取记录、资源流水、客服补发与回滚工具，以及玩家侧的抽卡历史查询。

**数据驱动与配置**

- 角色、技能、卡池、活动全部外置表管理，代码只留公式与流程；配置校验进 CI，防止错表带病上线。卡池档期与概率参数是运营配置，切换不发新版本，每次改动要有记录与复核，防止「配置暗改」演变成事故。

**概率可复现与模拟**

- RNG 可播种、可复现：每次抽取记录种子与保底计数，客诉与 bug 可复盘；蒙特卡洛工具改一个参数就能批量跑百万次抽样，输出期望、保底分布与极端情况，改表即重跑，是概率设计的验收工具。
- 线上监控：实际出货分布与配置对不上就是事故；异常抽取行为（脚本化、异常出货）进监控清单。

**内容与资源管线**

- 角色资产（立绘、模型、语音、演出）分包与按需下载，首包与增量包的边界提前设计；活动开关与卡池切换由服务器控时，客户端预埋资源，精确到分钟的上线时间要提前进管线。
- 演出与结算分层：先算完结果，再播动画；跳过与倍速只影响播放，不影响结果。

若做无付费的单机版（抽卡作为玩法），可以不走服务器，但存档要防修改；一旦引入真实货币支付，服务器权威就是必须项，没有折中方案。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 三环原型 | 1 个卡池、8-12 个角色、5-8 个关卡 | 4-8 周 | 纯本地、零美术，只验证抽卡、养成、编队 |
| 单机小体量 | 15-25 个角色、一条主线、买断制 | 6-12 个月（小团队） | 抽卡是玩法不是变现，合规负担轻 |
| 运营型小体量 | 30-60 个角色、每版本 1-2 个新角色 | 1-2 年起，持续投入 | 内容流水线、服务器与运营是主体 |
| 头部体量 | 100 个角色以上、多地区发行 | 团队多年 | 重资本运营项目，对标前先读 §3.5 |

角色单位成本（粗口径）：一个成套角色是跨职能交付，美术（立绘或模型、差分）、战斗（技能与数值）、演出（必杀动画）、语音、剧情文本、测试与本地化缺一不可；2D 卡面型角色通常以数周计，3D 高品质角色以数月计、多职能并行。复用组件与模板能压低成本，高稀有度角色的演出与美术投入压不掉。

成本结构提醒：抽卡养成是运营型产品，开发只是一部分，另一半是持续的内容生产、服务器、客服与社群投入；预算要按「上线后每月都有稳定产出」编写，而不是按「做完即止」。范围纪律：首发角色数与版本周期按产能倒推，别按愿景倒推。

## 6. 第一个原型怎么起步

目标：4-6 周做出「能抽、能养、能打、能算账」的最小循环。纯本地、零美术、不碰服务器与真实货币。

1. 第 1 周：抽卡骨架。8-12 个占位角色、一个卡池（基础概率分层加保底计数与软保底），抽卡演出先做成逐张揭晓；结果先算完再播，全量写日志。
2. 第 2 周：编队战斗。选一种最简战斗形态（回合制或半自动），3-4 人编队，职能分槽加一条克制关系；验收问题是「换人能不能解决问题」。
3. 第 3 周：养成与资源。两到三层养成线、体力与素材的产出消耗表；跑一遍「一周时间」的模拟，检查进度曲线是陡还是平。
4. 第 4 到 6 周：微缩内容、试玩与调参。先做 5-8 个关卡加一段活动雏形，找 5 个没玩过的人玩两三天，记录抽卡情绪曲线与编队调整行为；再用模拟脚本跑出期望与保底分布，对照试玩记录调整参数，然后决定要不要进入联网与美术投入。

成功标准（全部可观察）：

- 测试者能说清「最坏还差多少抽」，保底结构可计算。
- 拿掉美术与音效，测试者仍愿意为下一抽主动攒资源，单次游玩 30 分钟以上。
- 5 名测试者中至少 3 人主动调整过编队，且能说出调整理由。
- 任意改一个概率或保底参数，你能在 10 分钟内从模拟与日志读出它对期望与体验的影响。
- 测试者对重复角色的反馈不是纯挫败，转化机制成立。

原型期不做：服务器、付费、真实货币、防沉迷接入、多语言。这些是上线工程，不是玩法验证；三环不成立，先修三环。

## 7. 常见坑

1. **概率黑箱或暗改、保底不可计算**：公示口径与实际不符、保底规则含糊，玩家算不清最坏情况。规避：公示写死、记录可审计、计数可见、跨池继承明示（§3.2、§4）。
2. **数值膨胀失控**：新角色一代版本一代神，老玩家的库存变废纸。规避：机制差异优先于倍率加码，复刻与强化托底（§3.3）。
3. **养成层堆砌**：等级、突破、技能、装备、专属武器、好感全叠满，玩家算不过来直接放弃。规避：先两三层做透，按 §3.1 的优先级加层。
4. **体力变闸门**：想玩不能玩，核心玩家被锁在门外。规避：体力服务节奏，配缓冲、选择与追赶机制（§3.3）。
5. **内容断供**：上线后产能跟不上，内容空窗期拖垮留存。规避：版本缓冲与活动复刻，先定产能再定版本周期（§3.4、§5）。
6. **只堆数值不做演出**：抽卡、必杀、结算毫无表现力，情绪没有落点。规避：抽卡演出与关键技能演出单独设预算（《美术与音频手册》）。
7. **重复物无出路**：抽到重复就是纯浪费，负面情绪累积。规避：碎片、升星素材、兑换货币一类转化机制（§3.2）。
8. **编队无深度**：自动战斗加战力碾压，抽卡与养成失去验收场。规避：职能与克制的解法空间，用关卡出「必须换人」的题（§3.1）。
9. **合规与发行后置**：做到一半才发现版号、防沉迷、概率公示没准备。规避：§3.5 的清单立项即过一遍（《法务、专利与竞争手册》、《全平台上架手册》）。
10. **小团队对标头部体量**：角色、剧情、活动按头部节奏铺开，一个都做不完。规避：先做体量可控的完整品，再谈运营化（§5）。
