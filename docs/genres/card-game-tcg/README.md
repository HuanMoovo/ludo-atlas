# Ludo Atlas · 类型手册 · 集换式卡牌（TCG）

> **类型手册 P2 批次**（第 ㊳ 轮扩展）。定位：把「收集」与「对战」做成一对互相供料的循环，两个轮子同时转才叫 TCG；对战给收集理由，收集给对战弹药。

## 1. 定位与核心循环

一句话定位：集换式卡牌是**把「收集」与「对战」拧成一对互相供料的循环**的类型。卡牌在牌桌上是对战工具，在收藏册里是收集品；玩家用开包、合成与交易扩张卡池，再用卡池组出卡组上桌验证。

核心循环用动词环写，两条环同时转：

`收集环：对战与任务赚取货币 → 开包或合成 → 卡池变宽 → 发现新组合 → 想试新卡组 → 回到对战`

`对战环：组牌 → 匹配对手 → 出牌与响应的你来我往 → 胜负结算 → 复盘并调整卡组 → 再排一局`

两个环互为燃料：对战是收集的意义（打完才有货币与目标），收集是对战的弹药（卡池决定卡组的可能性）。只转一个轮子的产品：只有收集，是开包模拟器；只有对战，收集就只是外壳。

成立前提两条：对战要能被复盘（每个关键回合，玩家能说出哪里可以不同），收集要有确定性出口（合成、保底、兑换，让付出有目标）。缺前者，对战退化成比谁的卡齐；缺后者，开包退化成赌博。节奏分三层：一个回合（半分钟到两分钟，资源分配与出牌）、一局（常见 5-20 分钟）、一个赛季（数周到数月，新系列与段位结算），三层都要有决策与新鲜感，任何一层停摆，玩家就会开始快进或离开。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 卡牌构筑（单人卡牌） | 构筑在局内完成，对手是设计好的关卡，平衡对象是自己的关卡曲线；TCG 的构筑在赛前完成，对手是真人，平衡对象是全服环境 |
| 对战卡牌（全解锁竞技型） | 同为真人对战，但收集不做主循环；TCG 的收集环是第二台发动机，卡池本身就是内容 |
| 自走棋 | 有共享牌池与阵容搭配的构筑乐趣，战斗全自动；TCG 的每一手都是手牌、费用与时点的直接决策 |
| 传统扑克与麻将 | 牌副公共且固定，胜负在信息与概率；TCG 的牌是玩家的私人资产，胜负从组牌那一刻就开始积累 |

一个自检问题：把开包与卡池成长拿掉，换成开局全卡解锁，游戏还成立吗？答案若为「不成立」，你做的才是 TCG；若为「仍成立」，收集只是外壳，你对标的是全解锁的竞技卡牌，本页的双循环部分可以整段跳过。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **牌桌表达与掌控**：卡组是玩家自己选的，赢有「这是我组出来的」的满足，输要能复盘出「哪一手可以不同」。
2. **信息博弈的心跳**：手牌、场面与未知的对手构成猜测与试探，留一张牌过回合的悬念是这个类型独有的紧张感。
3. **收集的接近感**：开包的心跳、保底进度逼近、合成目标达成；新卡到手当天就能上桌验证。
4. **公平可归因**：抽牌随机是本体，但翻盘不能全靠随机；输的玩家要能说出「他强在哪」，而不是「他抽得好」。
5. **长期承诺**：新系列与赛季给出「下个月再来」的理由；环境每隔几周有可感知的变化。

反模式：输的玩家普遍把失败归因于「他的卡比我好」，或收集两个月后发现自己追不上主流卡组的成本。这两条一旦成为社区共识，留存会塌方。

标杆作品（建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 万智牌 | 优先权与堆栈的完整设计、五色轮与颜色相克、赛制分层与退环境的鼻祖；实体与线上双生态 |
| 炉石传说 | 低门槛数字化包装、开包与合成的双通道、退环境与平衡补丁的运营节奏 |
| 游戏王 | 高密度卡面文本与 combo 生态、实体赛事运营；也示范了卡池膨胀后的平衡难题 |
| 宝可梦集换式卡牌 | IP 加收集的心智、新手预组与线下活动、实体与电子版并存 |
| 影之诗 | 电子优先的赛季运营、进化机制对资源模型的改造、剧情包装拉新 |
| 漫威终极逆转 | 短局设计（12 张卡、6 回合、三个区域）、每局不同的场地变量、手机优先的节奏 |

## 3. 设计要点

### 3.1 卡牌设计：效果预算与稀有度曲线

先立一把尺子：效果预算。1 点费用约等于 1 个单位的基础价值（一段伤害、一点身材，抽一张牌约值两个单位），每张卡在设计文档里只有三行字：费用、效果量、附带条件。预算表是出厂设置，环境实测数据才是最终裁判。

| 费用 | 效果预算（参考值） | 允许出现的内容 | 附带条件 |
| --- | --- | --- | --- |
| 1 | 1 个单位 | 基础单位、小法术 | 无 |
| 2 | 1.8-2.2 个单位 | 主力件、双效小卡 | 无或轻微 |
| 3-4 | 3-5 个单位 | 节奏件、一换多 | 通常要条件或目标限制 |
| 5 以上 | 高影响、有扭转潜力 | 终结手段、清场 | 必须有前置条件 |

稀有度管三件事：收集难度、复杂度预算、戏剧性。稀有卡允许更复杂、更有演出，但强度与稀有度只能弱耦合：每套主流卡组的核心件获取路径必须可达（合成价格、预组或活动），否则竞技环境变成付费墙，这是这个类型最贵的一条信任债。分布参考（按系列卡数）：普通约一半、稀有约三成、史诗与传说合计约两成；每张最高稀有度卡要有独一无二的机制或演出，不能只是数值更大的普通卡。

文本纪律：一张卡只做一件事（描述超过三行就拆分或收进关键词表）；关键词表先立，全卡池同一套措辞模板；线上没有裁判，卡面必须经得起规则引擎的唯一解读，歧义会在社区放大成争议。

强度曲线跨系列管理：新系列的强度围绕当前环境基线浮动，靠新机制与新组合提供新鲜感，不靠更高的数值。每季强 10%，三年后早期卡池就变成废纸，这笔债几乎不可能还清。

### 3.2 卡池管理：赛制、轮换与禁限表

卡池是 TCG 的长期资产，也是最大的负债；不管理，新玩家进不来，老玩家环境固化。三件工具配齐：

| 工具 | 内容 | 职责 |
| --- | --- | --- |
| 赛制分层 | 标准（近一到两年的卡包）与开放（全部历史卡池）并行 | 标准保平衡与新人入口，开放保玩家资产价值 |
| 轮换（退环境） | 标准赛制按周期轮换掉旧系列 | 给设计腾空间，控制新人学习成本，驱动新卡包 |
| 禁限表 | 观察名单、限一、禁用三个档位 | 环境急救与浓度控制；电子版另有数值热更新这条杠杆 |

轮换的纪律：提前一到两个赛季公布轮换范围，给玩家规划时间；轮换带走的是「卡在标准赛制里的强度」，不是卡的所有权，返还与补偿按承诺执行，一次失信要用一年去补。

禁限表的用法：能被数值调整解决的，不用禁用；禁用是压箱底的急救手段，每次都要配公告，写清为什么、影响谁、后续怎么办。电子版比实体多一条杠杆（热更新数值），所以电子 TCG 的平衡是禁限加补丁双轨。

### 3.3 对战规则与资源系统

资源模型是胜负的基调，也是与竞品最直观的差异点：

| 资源模型 | 代表做法 | 得到什么 | 付出什么 |
| --- | --- | --- | --- |
| 地牌式 | 万智牌 | 资源进构筑与抽牌，深度与表达空间最大 | 卡手与卡爆是设计的一部分，门槛高 |
| 自动成长式 | 炉石传说 | 流畅、移动端友好、上手快 | 资源维度退化，胜负压在卡与场面交换上 |
| 固定费用短局 | 漫威终极逆转 | 单局短、节奏快、适合碎片时间 | 深度靠场地与卡牌效果另想办法补 |

响应时点决定心理博弈的深度，这是一次受众决策：完整堆栈（万智牌式）里，对手的回合也能做事，出牌先入堆栈、双方轮流响应、后进先出，深度最大，规则与界面的工程量也最大；简化响应（炉石式，以己方回合行动为主，配少量触发式机制）节奏明快、好上手，代价是少了「打回去」的博弈层。选之前先定清楚目标玩家是谁。

胜负载体要一眼可懂：主单位血量、牌库耗尽、场地计分、特殊胜利，选一到两个做主线，其余做彩蛋；用「真空回合」检验决策密度，连续几个回合无事可做的对局，先修节奏。随机性纪律：抽牌随机是本体的一部分，对局内随机（随机效果、随机目标）要克制，原则是「随机给选项，不随机给结果」，每个版本审查一次随机效果的存量。

### 3.4 收集经济与开包设计

双通道是地基：开包给随机与惊喜，合成给确定性与目标，两者必须同时存在。只有开包，挫败会累积成流失；只有合成，失去仪式感与心跳。两张账要能互相换算（多少包值多少合成材料），给玩家一条算得清的路。

保底与去重（参考值；公布写死，不得暗改）：每个系列的前 10 包内必出最高稀有度；最高稀有度 20-40 包保底、次高 5-10 包保底；开出已拥有卡的处理规则（去重保护或按稀有度返还材料）事先说清楚。

开包演出是这个类型的「时刻」：逐张揭晓、稀有特效与音效值得投入；同时必须可跳过，老玩家一次开几十包时那是刚需。接近感同样重要：保底进度可见、新卡试用通道（试用场、预组），拿到新卡当天就能上桌。日常循环：每日与每周任务提供稳定的免费收入，让「不付费也能玩」成立；通行证类长期奖励把留存与付费打包，运营方法见《运营与增长手册》（⑬）。

合规红线：开包与抽卡在多地被监管，概率公示是常见硬性要求（含主要应用商店的审核规则）；面向未成年人的付费与时长另有明确限制；部分市场对随机付费机制有更严的框架。发行前按目标市场逐地核对，不要默认一套方案全球通用。

若开放玩家间交易，机器人刷取、盗号销赃与洗钱会立刻上门，经济安全工程见《联机与后端深入手册》（㉖）；多数电子 TCG 用「合成加分解」替代交易，不是偷懒，是风险管理。实体 TCG 的二级市场给卡牌保值与拥有感，电子版要用确定性与承诺来补位。

### 3.5 平衡与测试：环境数据与改动节奏

平衡对象是环境，不是单卡。每个版本至少记录：各卡组的使用率与胜率、单卡胜率贡献、先手胜率、对局长度分布、新系列上线四周后的主流卡组数量。目标区间（参考值）：卡组胜率 45%-55%，先手胜率接近五成，超出区间进入观察名单。

工具组合：天梯数据看板找异常；规则引擎上的机器人对战做回归与崩溃测试，不替代真人数据；封测组（高段位玩家提前打新系列）找设计漏洞与无聊卡组。数据回答「哪里不对」，人回答「哪里不好玩」，两者都要。

改动分级：数值微调（电子版专属）→ 限一（降浓度）→ 禁用（急停）→ 重做（文本级改动，等于重发一张卡）。一次改动只聚焦一个主题，公告写清三件事：改了什么、为什么、接下来看什么数据。

节奏（参考值）：新系列上线后让环境自然收敛 2-6 周，再出第一次平衡调整；过密，玩家不敢投入卡组；过疏，坏环境消耗信任。实体版没有补丁，禁限公告要一次到位。

## 4. 技术要点

工程难点集中在五处：规则引擎、响应系统、服务器与隐藏信息、经济服务、内容管线；以下与引擎无关，通用方法见《技术实现手册》（⑩），联机与后端全流程见《联机与后端深入手册》（㉖）。

**规则引擎：状态、事件与结算**

- 单一状态源加事件队列：游戏状态（场面、手牌、牌库、资源、回合信息）只有一份权威数据；所有卡牌效果挂在事件与时机表上（进场、死亡、回合开始等），按确定的顺序结算。
- 效果原子化：伤害、召唤、抽牌、增益做成数据组合，新卡进表不改代码；全卡池只留极少数需要写代码的唯一机制卡，单独标注维护成本。
- 结算必须确定且可重放：同一种子加同一操作序列产出同一结果，这是回放、断线重连与反作弊共同的地基；逻辑先算完，动画按队列播，允许加速与跳过。

**优先权与堆栈的工程**

- 堆栈是结算循环，不是特效：出牌入栈、双方轮流获得优先权、全部让过后后进先出逐个结算。引擎要能在任意结算点暂停并接受新事件，别写成「伤害立即生效」。
- 响应窗口的网络与界面代价最高：等待回应要有时限与超时策略（自动让过、掉线代管），移动端给通知式响应设计，否则玩家会频繁错过时点。
- 若选简化响应模型（以己方回合行动为主），引擎同样要预留触发式效果的钩子，后续加机制不动地基。

**服务器权威与隐藏信息**

- 客户端只提交意图（出哪张牌、指向哪个目标），裁定全部在服务器；对手手牌、牌库顺序、随机种子不下发到客户端。TCG 的作弊面就三样：看穿手牌、看牌库顶、自动脚本，隐藏信息不下发把前两个堵死。
- 断线重连用种子加操作日志回放恢复，不整段序列化对局状态；对战记录同时供调试、平衡取样、反作弊与社区内容四用。匹配、段位与反作弊的完整账本见《联机与后端深入手册》（㉖）；新手池与低峰期人机兜底的原则是「救体验，不骗人」。

**经济与开包的服务端实现**

- 开包结果由服务器决定并即时入库，客户端只负责演出；每包一次事务、幂等、唯一编号，任何「先发给客户端、后入库」的写法都会变成刷包漏洞。
- 账号资产（卡牌库存、合成材料、货币）要有审计日志与客服工具；交易（若做）是另一条工程线，挂单、撮合、风控与盗号找回缺一不可。

**内容管线与热更新**

- 卡牌数据（数值、文本、规则、卡图引用）全部进表与版本控制；平衡改动走数值热更新，新卡上线走内容包，两件事分开。
- 卡图是资源大头：移动端按需下载与分包，首包只带基础卡；卡面与特效按模板生产，与卡牌构筑的原子化思路同源。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 对战原型 | 40-60 张卡，两副预组 | 2-6 周 | 纸面加灰盒，只验证规则与对局乐趣 |
| 单机对战卡牌 | 150-300 张卡 | 3-9 个月 | 对手是 AI，验证收集环与卡池 |
| 小型线上对战 | 300-500 张卡（首版 2-3 个系列） | 1-3 年 | 服务器、匹配、经济系统全要（㉖） |
| 运营型 TCG | 每系列 100-250 张，年 3-4 个系列 | 持续投入 | 内容流水线与运营节奏是主体 |

换算与暗线：

- 单卡成本：复用机制原子 0.5-2 天走完设计、文案与测试；引入新机制的成本打在机制上，另加数天到一两周。插画按张外包，是卡池最大的外部支出项。
- 规则引擎：最小可玩对战 2-6 周，含响应、触发与回放的完整版 2-4 个月；首个可玩闭环（对战加开包加合成，无赛季）3-6 个月，运营化 1.0 常以年计。
- 人口账：竞技对战的匹配体验随人口下降非线性恶化，上线前先回答「哪些时段能凑出稳定的对局」。
- 范围纪律：第一批卡池只要撑住两三种风格各自的完整卡组；砍卡永远比救平衡便宜。

## 6. 第一个原型怎么起步

目标：一个月左右回答一个问题，这套规则对打好不好玩。纸面先行，不碰联机、排位、交易与赛季。

1. **第 0 步（动手写代码之前，2-3 天）：纸面原型。** 打印 30-50 张卡（或写纸条），两副预组，和同事手动对打。记账慢，但规则歧义与无聊决策会立刻现形；TCG 的规则史本来就是纸面史，先纸后码。
2. **第 1 周：最小规则引擎。** 费用、单位与法术、回合结构、胜负判定，纯文本结算，无美术。丑是应该的。
3. **第 2 周：30-50 张数字卡池加两副预组。** 内部对战，记录三件事：卡手率、没有决策的回合、让人笑出来的瞬间。
4. **第 3 周：收集外壳最小化。** 模拟开包（随机发卡加保底与去重规则）与合成通道，验证「打完想换个卡组」的冲动是否出现。
5. **第 4 周：外部盲测。** 找 5 个没玩过的人，教一次规则，观察：多久打完第一局、有没有人主动改卡组、有没有人想再来一局。

成功标准（全部可观察）：

- 拿掉全部美术与音效，测试者仍愿意连打 5 局以上。
- 5 名测试者中至少 3 人无提示下主动调整卡组。
- 输掉的人能说出「下一局我想换哪张卡」。
- 单局时长落在 10-20 分钟（首次含教规则另算），结算歧义每天收敛，没有悬而未决的裁决。

原型期不做：联机、排位、交易、赛季、剧情、移动端。这些是放大器，不是地基。

## 7. 常见坑

1. **规则引擎写死**：每张新卡配一段代码，卡池扩张即灾难。先建效果原子与触发时机系统（§4）。
2. **先做服务器与开包，规则没验证**：后台全建好了，对战不好玩。先把对局立住（§6）。
3. **稀有度等于强度**：付费即变强，竞技环境被收集碾压。稀有度控收集难度与演出，不控竞技强度（§3.1）。
4. **强度通胀**：每季都比上季强，旧卡池变废纸，信任破产。新卡靠机制翻新，不靠数值加码（§3.2）。
5. **禁用无预告、无补偿**：核心卡突然被禁，玩家投入打水漂。公告、理由、返还三件套一次到位。
6. **开包无保底、概率不透明**：口碑与合规双重风险。概率公示、保底写死、期望可算（§3.4）。
7. **隐藏信息下发到客户端**：改内存就能看穿对手手牌，作弊门槛为零。手牌、牌库顺序、随机种子留在服务器（§4）。
8. **随机效果过量**：为节目效果堆随机，竞技性流失。随机给选项，不随机给结果（§3.3）。
9. **真空回合**：好几个回合无事可做，玩家开始刷手机。决策密度是每张卡与每个机制的验收项。
10. **匹配人口不足**：人少排不到水平相近的对手，天梯体验崩塌。冷启动方案先于上线准备好（§5）。
11. **交易没做经济安全**：机器人刷取、盗号销赃直接毁掉经济。没准备好风控就用合成替代交易（§3.4、㉖）。
12. **抄卡不抄运营**：卡面抄来了，平衡流程、赛季节奏与社区沟通没抄来，上线一年卡池变死水。

## 延伸阅读

- 《游戏设计手册》（⑨）：核心循环、数值表与概率设计的通用方法，对应本文第 1、3 节。
- 《技术实现手册》（⑩）：数据驱动、结算系统与存档的实现细节，对应本文第 4 节。
- 《联机与后端深入手册》（㉖）：服务器权威、匹配、反作弊与经济安全的完整账本；做线上对战前先读。
- 《运营与增长手册》（⑬）：赛季节奏、卡包运营与长线平衡，与 §3.2、§3.5 配合使用。
- 《独立开发生存手册》（⑱）：范围控制与排期；对战卡牌是运营型产品，起步前先把这笔账算清。
- 《避坑大全》（⑥）：设计与内容生产的常见坑位，与第 7 节对照阅读。
- 作业：玩 10 小时万智牌与 10 小时炉石传说（或同类产品），记录三件事：你的第一副卡组是怎么凑出来的（收集环的现实）、哪一次失败你觉得是运气、哪一次失败你觉得是技术（信息博弈与公平感）。
