# Ludo Atlas · 类型手册 · 大型多人在线（MMO）

> **类型手册 P2 批次**（第 ㊱ 轮扩展）。定位：把「许多人长期住在同一个世界里」做成产品。玩法是入口，社区、经济与持续运营才是本体；服务器开着，世界就必须一直有理由让人回来。
> 配套：《联机与后端深入手册》（㉖）·《运营与增长手册》（⑬）·《技术实现手册》（⑩）·《独立开发生存手册》（⑱）。

---

## 1. 定位与核心循环

一句话定位：MMO 是产品形态，不是玩法类型。回合制、动作、射击都能套进 MMO 的壳，决定成败的不是战斗怎么做，而是**一个持续运行的世界能不能同时撑起三笔长期账单**：服务器、运营、内容。

**先说劝退。** 下面三笔成本，任何一笔接不住，都不要开 MMO 的坑：

- **服务器**：7×24 运行，带宽、数据库、值班与客服按月计费；停服的世界是负资产，没有「先做出来看看」这一档。
- **运营**：活动、公告、社区、反外挂与危机公关是常设岗位；MMO 的多数事故是运营事故，不是技术事故。
- **内容**：玩家消耗内容的速度是生产速度的数倍，更新一停，人口开始流失；内容管线是永续工程。

一句话：MMO 是在做「城市」，不是在做「游戏项目」。小团队被在线世界吸引时，先读 §5 的替代方案。

核心循环以「上线」为单位，长线以月与年计：

`上线或回归 → 做今天能做的事（任务、副本、采集、社交）→ 变强、变富、被看见 → 消费与展示（交易、公会活动、外观）→ 定下新目标 → 明天再来`

环里有三个咬合的系统，缺一个就退化成单机加联机大厅：进度负责「变强」，经济负责「变富」，社交负责「被看见」。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 单机 RPG | 单机世界的价值不依赖他人在线；MMO 没有活人，世界就死了 |
| 小型联机（合作、竞技、派对） | 房间制、单局制、可随时结束；MMO 是持久世界，玩家离线时世界继续运转 |
| MOBA 与大逃杀 | 也有赛季与账号积累，但每局在陌生人之间重新开始，不构成「居住」 |
| 生存与沙盒联机（自建服） | 也有持久世界，但服务器由玩家自建自管、规模小、无官方运营承诺 |

自检问题：你的设计里有没有「因为别人也在，所以必须现在来」的时刻？没有，你该做的是小型联机（§5）。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **归属**：有公会、有固定队、有认得出的名字；离开会想念，有人会叫你回来。
2. **积累**：数月到数年的进度肉眼可见，装备、头衔、家园都是时间的证据。
3. **在场**：主城有人、频道有声音、世界有事件；空世界是对 MMO 的否决。
4. **表达**：外观、称号、坐骑、家园是给别人的社交名片。
5. **目标密度**：任何时候打开游戏都有事可做，且分量分层（十分钟、一小时、整晚）。

标杆作品（只列大众熟知的作品，亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 魔兽世界 | 团队副本与公会的组织形态；资料片式版本节奏 |
| 最终幻想 14 | 主线剧情驱动的大型副本演出；把休闲玩法做成常驻内容库 |
| 梦幻西游 | 交易系统与官方交易平台长期稳定的样本 |
| 剑网 3 | 外观经济与国风社区运营；活动节点与版本节奏的配合 |
| 光·遇 | 轻量社交 MMO 的边界：弱数值、强表达、陌生人善意设计 |

## 3. 设计要点

### 3.1 世界形态：先定「多少人住在一起」

关键数字是活人浓度，不是地图面积。单实例（分服或分线）的承载人口、玩家之间的相遇概率、跨服是否允许，三个问题先回答。

| 形态 | 做法 | 代价 |
| --- | --- | --- |
| 分服 | 玩家各选服务器，服与服隔离 | 社交有「邻居感」，但后期要面对鬼服与合服 |
| 分线（镜像） | 一张地图多镜像，满线自动分流 | 峰值好用，代价是同一地点的人可能互相看不见 |
| 单一大世界 | 全服同图或无缝分区 | 对抗与交易最强，工程与治理复杂度最高 |
| 跨服 | 副本、战场或交易有限互通 | 缓解后期稀释，代价是一致性与隔离规则变复杂 |

人口目标按阶段给出：开服期用分线削峰，稳定期保住主城与要塞的相遇概率，末期用跨服、合服或压缩实例续命。等服务器空了再救，是最贵的救法。

### 3.2 社交骨架：公会、队伍与频道

社交不是聊天框，是组织。三件套各回答一个问题：

| 系统 | 要回答 | 常见做法 |
| --- | --- | --- |
| 好友与最近组队 | 怎么找到人，怎么再找到他 | 好友、最近同队、关注与屏蔽 |
| 公会 | 什么理由让大家长期绑在一起 | 权限分级、公会频道、共同目标（副本、活动、战争）、贡献与分配 |
| 队伍与副本 | 一个人做不了的事怎么完成 | 匹配加固定队双轨；难度分层覆盖不同组织规模 |

公会的核心是分配制度：个人拾取、积分或贡献分配各有利弊，规则要在系统层面可执行，不靠道德约束。公会工具（公告、活动日历、招募板）决定组织成本，成本越低，公会存活率越高。

社交的负面同等重要：屏蔽、举报、禁言与客服通道要齐备；社交摩擦以月为单位累积，一次恶性事件不处理，信任会记很久（《运营与增长手册》（⑬）§8）。

### 3.3 交易与市场：让物品流动起来

先定三件事：

- **绑定规则**：账号绑定、装备后绑定、可自由交易，松紧决定经济活性与黑产空间；越自由，越需要安全投入（㉖ §6）。
- **渠道**：面对面交易利于社交但靠人肉撮合；摆摊有地理与在线要求；拍卖行高效，但会拉平价差与地点价值。三者的组合就是经济形态。
- **税与费**：拍卖税既是定价工具，也是货币回收点，税率按经济温度微调（§3.4）。

监测三个指标：分品类成交价中位数、上架量与流拍率、大宗交易的持有人集中度。价格与集中度异常要自动预警，而不是等玩家发图开骂。

### 3.4 经济与通胀治理

MMO 是开放经济：产出端（faucet）与回收端（sink）都要有出口，且回收要随产出同步增长。

| 环节 | 常见做法 | 风险 |
| --- | --- | --- |
| 产出 | 任务、掉落、采集，设每日产出上限 | 产出失控直接制造通胀 |
| 回收 | 修理费、传送费、税、消耗品、外观消费 | 回收不足，货币贬值、物价飞涨 |
| 调节 | 按指标调税率与商店回收价，开限时回收活动 | 硬调要慢，快调会挨骂 |

三个必看仪表盘：人均货币持有量（看结构，不看单点）、核心商品价格指数、货币流速（每角色每天的产出与回收）。通胀发作时，先堵产出漏洞，再用回收与活动疏导，数值调整放在所有手段之后。

慢性病是新人买不起、老人无欲无求：让需求不断换锚（新版本的素材与外观），比冻结货币数量更可行。黑产从经济里吸血——现实货币交易（RMT）、打金工作室、盗号洗货，用审计、风控与法律手段组合处理（㉖ §6、§7）。

### 3.5 内容节奏：运营型产品的更新表

MMO 上线是起点，不是终点。更新通常分三层：大版本（资料片，以年计）、中版本（副本与新系统，以季度计）、活动（节日、限时玩法、联动，按月或按节点排）。三层叠起来就是运营日历，方法见《运营与增长手册》（⑬）§5。

- 内容消耗永远快于生产，结构上供不应求。降速靠可重复内容（副本、战场、收集）、随机词条、多职业重练与赛季重置；提速只能加人加钱。
- 每日与每周任务负责「回来」，长线目标负责「留下」。日常要少、短、可补做；把玩家绑成打卡上班，半年后会集中报应。
- 每个大版本同时是新玩家的入口：新地图与新叙事是重新介绍世界的理由。

### 3.6 新手与追赶：让晚来的人能进场

旧内容越多，新人越像在爬历史包袱。三层设计：

- **追赶通道**：经验加成、直升、追赶装备，让新人的起点贴着当前版本；追赶速度要快于老玩家的积累速度，否则入口越堵越死。
- **老带新激励**：师徒与回归邀请，把老玩家的社交余热变成新人的留存。
- **准入分层**：必经内容压到最短，旧区域转为可选收藏，避免新人把「补课」当成全部体验。

目标是：新人首个晚上就碰到当前版本的核心名场面，并至少遇到一个愿意回他话的人。

## 4. 技术要点

难点集中在四处：世界服务、经济安全、运营工具、成本。同步模型与架构骨架见《联机与后端深入手册》（㉖）与《技术实现手册》（⑩）§5，这里只列 MMO 特有的部分。

**世界服务**

- 服务端权威是默认答案：位置、战斗、掉落、货币全部服务器算，客户端只做表现与预测（㉖ §2）。
- 有状态世界的常态能力：数据分片加载、跨地图迁移、掉线重连、宕机回档。回档粒度与补偿工具要提前设计，不要等第一次事故现场发明。
- 同屏预算是硬约束：主城领奖、世界事件、攻城战最容易爆帧；用分线、镜像、人数上限与特效分级削峰。
- 登录排队比崩溃体面：开服与版本更新当天的容量按预期峰值的倍数准备。

**经济与安全**

- 货币与物品的每笔增减都要有审计日志；随机数服务端生成；对异常流速（单账号产出、跨账号流转）设风控规则（㉖ §6）。
- 交易与邮件是两个主要洗货通道，都要有快照、回溯与冻结工具。
- 反外挂按三层部署（客户端检测、服务端分析、举报复核）；经济犯罪与作弊常是同一批人（㉖ §7）。

**运营工具**

- GM 与运营后台是驾驶舱：封禁、补偿、公告、活动开关、数值热调，第一版就要有，且全部可热更新（㉖ §8）。
- 在线、留存、付费、经济四组指标进实时看板；在线骤降、货币流速异常要自动告警。

**成本**

- 按 CCU 与带宽先做成本表，再谈范围（㉖ §8）；长期不下线的世界，账单没有「暂停」档。
- 容量规划区分日常水位与版本峰值；有状态服务的弹性伸缩要先设计再使用。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 形态 | 内容量级 | 周期量级 | 团队量级 |
| --- | --- | --- | --- |
| 小型在线世界（社群规模） | 1-2 张地图加一条主循环 | 3-6 个月 | 3-8 人 |
| 小规模 MMO | 3-5 张地图、副本与基础经济 | 1-2 年 | 8-20 人 |
| 商业 MMORPG | 持续扩张的世界与版本循环 | 首版 3-5 年，此后按年循环 | 50 人以上 |

内容生产的账：

- **文本与任务**：一条几分钟的剧情任务，制作成本远高于几分钟；商业体量的任务文本合计在数十万字量级（含对白、道具与任务描述）。
- **美术**：角色与怪物按「可复用骨架加更换部件」工业化生产；一个团队副本的场景与怪物成本，可对标一个小型单机作品的主线场景。
- **职业**：每个职业或分支都是一套独立的战斗、动画、平衡与测试成本，职业数量按维护成本定，不按乐趣定。
- **地图**：MMO 的地图要配任务、掉落、事件、导航与性能优化，单位面积的综合成本远高于单机。

**小团队的现实替代：小型联机。** 如果吸引你的是「在线世界」而不是「长期共居」，把小世界换掉：

| 维度 | MMO | 小型联机 |
| --- | --- | --- |
| 世界 | 持久、7×24 运行 | 房间制或主机权威，随开随关 |
| 人口 | 单服同时在线以千计 | 单局 2-8 人或对局匹配 |
| 成本 | 服务器与运营是长期投入 | 成本随峰值对局数走，可关停 |
| 社交 | 公会、交易与关系链 | 好友与最近玩家 |
| 内容驱动 | 更新节奏 | 单局重玩性 |

边界：玩家不需要「住在里面」，只需要「玩得好、约得到朋友」。合作闯关、派对、竞技、联机沙盒都在这个区间；骨架仍复用联机手册（㉖），删掉公会、拍卖行、世界聊天这些重装部件。如果坚持要世界感，可以折中做「小规模持久世界」（几十人级），但要提前为人少时的空场写好运营预案。

## 6. 第一个原型怎么起步

第一个原型不是「小 MMO」，而是一次能在真实网络上跑通的小型在线切片：一个服务器、一张小地图、一条循环（打怪、拾取、变强）、一个社交钩子（组队或聊天）。6-8 周，用现成后端起步（㉖ §5），不要自研全家桶。

- **第 1-2 周：在线骨架。** 账号、登录、角色、移动同步、聊天；服务器权威加客户端预测。目标：两台不同网络环境的机器进入同一场景。
- **第 3-4 周：一条完整循环。** 打怪掉落、背包、货币、商店、一次变强；数值先粗后细。目标：10 个机器人账号连刷 1 小时不掉不崩。
- **第 5-6 周：社交钩子与小规模测试。** 组队与共享经验或公会雏形；找 10-20 个真人连玩三个晚上，观察聊天与自发组织。
- **第 7-8 周：运营演练与压测。** 公告、补偿、封禁、热修各走一遍流程；按预期峰值做三倍压测。

成功标准（全部可观察）：

- 第二周还有人自愿上线，而且不是你提醒的；有人自发等别人上线（组队、约时间）。
- 服务器连续运行 7 天（允许计划内维护）；掉线与回档流程实际演练过至少一次。
- 7 天内人均货币增长可控，没有出现一夜暴富的产出漏洞。
- 你能说清「什么内容让玩家第二天回来」；说不清就回去补，不要加地图。

## 7. 常见坑

1. **按商业 MMO 的规模起步**：服务器、运营、内容三笔账任一笔都够小团队破产；先读 §5 的替代方案。
2. **只做玩法，不做社交与经济**：玩家练满即流失，世界变成没人住的大厅；留存靠组织与关系，不靠数值。
3. **只有产出没有回收**：货币贬值、物价起飞、新人被驱逐；回收设计与产出设计要同一天上线（§3.4）。
4. **客户端权威**：改包、改档、刷金一夜间击穿经济；一切经济结算放服务端（㉖ §6）。
5. **按单机节奏排更新**：上线三个月被玩家玩空；可重复内容与赛季结构要提前进设计。
6. **日常任务膨胀**：玩家被绑成打卡上班，新鲜感与口碑一起耗光；日常要少而可补。
7. **分服与合服没规划**：开服不分线压爆峰值，后期鬼服不合服，活人浓度不足，世界名存实亡。
8. **新手入口越堵越死**：追赶机制是常设系统，不是一次性活动（§3.6）。
9. **没有热修与运营工具**：改一个数值停服半天，补偿靠手工发；运营半径被工具卡死（㉖ §8）。
10. **低估黑产与 RMT**：打金工作室把经济当提款机；审计、风控与法律手段要成体系（⑥ §8）。
11. **迷信「人多」**：买量涌进来的人不是社区，发完就散；资源投给留存与组织，比投给入口划算。

玩法决定玩家为什么进来，运营与社区决定他们为什么留下；MMO 的立项书应该先回答「怎么让人留下」，再回答「怎么让人进来」。
