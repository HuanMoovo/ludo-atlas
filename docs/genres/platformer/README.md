# Ludo Atlas · 类型手册 · 平台跳跃（Platformer）

> **类型手册 P0 批次**（第 ㉛ 轮扩展）。定位：把「跳」这个动作本身做成第一乐趣，用手感与关卡节奏持续制造「再来一次」的冲动。
> 配套：《关卡设计手册》（㉑）·《游戏设计手册》（⑨）·《技术实现手册》（⑩）·《美术与音频手册》（⑪）。

---

## 1. 定位与核心循环

一句话定位：平台跳跃是**以移动和跳跃为第一乐趣**的类型。玩家在跟手的操作反馈里获得掌控感，在关卡节奏里获得征服感；跳跃不是赶路的手段，跳跃本身就是内容。

核心循环用动词环写：

`观察地形 → 预判落点 → 起跳 → 空中微调 → 落地或失败 → 立刻再试`

这个环以秒甚至以帧计量。它成立的前提只有两条：操作要跟手（§3.1），失败要便宜（§3.4）。任何一环的反馈延迟超过 200ms，玩家就会把账记到游戏头上，而不是记到自己手上。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 跑酷（无尽跑者） | 平台跳跃有手工关卡与终点；跑酷通常程序生成、永久向前、一次失误重开 |
| 银河城 | 银河城等于平台跳跃加连通地图与能力门锁；身体爽感同源，骨架换成探索与回访 |
| 硬核平台 | 同一套手感，两种产品定位：一个用死亡密度筛选受众，一个用安全网扩大受众 |
| 动作游戏 | 动作游戏的动作对象是敌人，平台跳跃的动作对象是地形 |

一个自检问题：把跳跃手感调坏，游戏还成立吗？答案若为「不成立」，你做的就是平台跳跃。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **掌控感**：每次跳跃的成败都能被玩家解释，输了怪自己，赢了有重放冲动。
2. **节奏流畅**：操作、镜头、音效落在同一个拍点上，玩家意识不到自己在按哪个键，只想着下一个落点。
3. **渐进挑战**：难度来自新机关与新组合，不来自数值堆叠（更滑的地面、更小的平台要克制使用）。
4. **低压重试**：从失败到重开以秒计，重试本身是玩法的一部分。
5. **惊喜时刻**：允许玩家用机制玩出没设计过的路线，并给这种路线留奖励空间。

标杆作品（建议亲手玩过再拆，只看视频学不到手感）：

| 作品 | 可学的点 |
| --- | --- |
| 超级马力欧兄弟 | 跳跃手感基准、零文字教学、动线引导 |
| 蔚蓝 | 高难关卡的宽容度、难度分层（主线与挑战面分流人群） |
| 超级肉肉哥 | 瞬时重试、把失败做成正反馈 |
| 雷曼传奇 | 关卡节奏与音乐节拍同步 |
| 空洞骑士 | 移动与战斗共用一套身体手感 |
| 星之卡比 | 低门槛跳跃与宽松的空中修正 |

## 3. 设计要点

### 3.1 跳跃手感三要素

手感不是玄学，是可拆可调的零件。先把下面三个装好：

| 要素 | 常见区间 | 作用 | 调坏的后果 |
| --- | --- | --- | --- |
| 土狼时间 | 80-150ms | 离开平台边缘后仍允许起跳的宽限窗口 | 归零则边缘起跳频繁失败；过大则有空中作弊感 |
| 输入缓冲 | 100-200ms | 落地前按下的跳跃会被记住，落地瞬间生效 | 归零则连跳丢指令；过大则空中乱按也自动起跳 |
| 可变跳跃高度 | 点按高度为长按的 1/3 到 1/2 | 松键立刻削减上升速度，或切换更重的下落重力 | 缺失则小跳与大跳没区别，落点只能靠猜 |

两个加分项：上升与下落使用不同的重力（下落重力通常取上升的 1.3 到 2 倍，跳跃更利落）；起跳瞬间直接给初速度而非慢慢加速（爆发感）。

调参纪律：只看逐帧录屏与秒表，不信「感觉差不多」；在目标帧率和目标分辨率下调，别在编辑器默认状态下调。

验收标准：找 5 个人各跳 20 次，记录「明明按了却没跳」的次数，每人 0 到 1 次为合格。

### 3.2 移动曲线：三组旋钮分开调

加速、减速、空中控制是三组独立旋钮，全部进数值表管理（表格方法见《游戏设计手册》（⑨））：

| 旋钮 | 2D 常见区间 | 调参目标 |
| --- | --- | --- |
| 地面加速 | 0.05-0.25 秒达到满速 | 起步干脆，长按不飘 |
| 地面减速 | 松键后 0.05-0.2 秒停下 | 急停不打滑，轻推能走半步 |
| 空中控制 | 地面加速度的 50%-80% | 空中能修正落点，但修正幅度小于地面 |

2D 有两种经典取向：马力欧式带惯性，起步与急停都留滑行感，落点宽容，适合探索；蔚蓝式起停极快，落点即生死，适合单屏高难。选哪种，取决于你的关卡想惩罚还是宽容。

3D 的差异在转向：不是瞬间换向，而是插值身体朝向，转弯半径与停止距离都更长；移动方向通常相对相机，加速度整体调低一档，并给出落点影子或地面标记，补偿立体空间里距离感的缺失。

检查表：方向键连点有没有滑步？满速急停有没有漂移？空中推一格能不能精确到位？这三个答案决定手感档次。

### 3.3 相机设计：第二个玩家

相机是第二个玩家——它替玩家看路，也替玩家预告危险。它要同时满足三件事：角色看得清、前方看得远、晃不晕人。

| 机制 | 常见做法 | 数值直觉 |
| --- | --- | --- |
| 前瞻 | 相机朝移动方向偏移，随速度增加并封顶 | 约等于提前 0.3-0.6 秒的距离，封顶在屏幕宽度的 20%-30% |
| 死区 | 角色在死区内移动时相机不动 | 垂直死区常取屏幕高度的 10%-20%，水平可以更小 |
| 垂直跟随 | 跳跃时不逐跳抽动，越过高差阈值才上推或下移 | 阈值取屏幕高度的 15%-25%，并做缓动 |
| 边界锁定 | 相机不露出关卡外，房间切换平滑过渡 | 每个房间单独定义边界与过渡时长 |

水平软跟随加垂直滞后，适合大多数平台跳跃；高速段要给跟随速度设上限，防止甩镜头。房间切换、被击飞、掉落死亡是最容易穿帮的三类场景，逐条测。

验收标准：连续跳 30 次，画面看不到逐跳抖动；全速冲刺时落点始终在画面内且留有余量；测试者没有「被镜头晃到看不清」的反馈。

### 3.4 关卡节奏：教、考、变奏

新机制的出场固定三段式（teach-test-twist）：

1. **教**：在无死亡代价的环境里展示一次，玩家不思考也能看懂。
2. **考**：在低压场景里让玩家自己用一次，失败重来的代价极小。
3. **变奏**：改变条件再用（加时间压力、换地形、叠加旧机制），检验迁移能力。

一次只教一个新东西；两个新机制塞进同一房间，认知负荷翻倍，玩家一个都记不住。

安全网分两层：微安全网是土狼时间、输入缓冲、落地宽容；关卡安全网是检查点密度、宽平台、可回头的路径。重试跑路时间通常压在 10-20 秒以内，超过 20 秒，挫败感会反噬挑战欲。

死亡惩罚的分布服从强度曲线：段落高潮处可以罚得重，纯操作考验段要罚得轻、回到游戏要快。紧张与释放交替，Boss 或追逐战的前后各留一段呼吸。

每个新房间过一遍检查表：

- 玩家进门第一眼看到什么？目标物在不在视野里？
- 新机制有没有第二用途（熟练之后还能玩出花）？
- 第一次死亡的原因，玩家能不能自己说出来？
- 重试一次要付多少秒？落在哪个数上？

### 3.5 度量：用跳跃半径定平台间距

摆关卡之前，先测出五个数字：平地满速跳跃的水平距离（记为 D）、最大跳高、滞空时间、下落速度、达到满速所需的加速时间。把这几个数字贴在显示器边上，所有间距都从它们推导。

平台间距按 D 分三级：

| 倍率 | 定位 | 使用场景 |
| --- | --- | --- |
| 0.8D | 舒适 | 主路径、教学段、奖励路线 |
| 1.0D | 标准挑战 | 主线难度上限，允许但要求准确 |
| 1.2D | 极限 | 只给可选内容、捷径与熟练回报，不放在必经之路 |

垂直方向同样分档：常见层高取最大跳高的 0.6-0.9 倍，超过 0.9 倍的位置要标注「需要技巧」。间距按「起跳边缘到落地边缘」的净距离量，两端各留半个角色宽的视觉余量；冲刺、反弹、蹬墙等额外机动单独建表，不混用基础表。

检查表：主线上有没有超过 1.0D 的必经跳跃（有则是设计事故）？1.2D 的位置有没有视觉预告？高速段的落点有没有被相机覆盖（§3.3）？

## 4. 技术要点

工程难点集中在三处：角色控制、参数体系、可测性。以下与引擎无关；Godot 与 Unity 都内置了运动学角色控制器组件，2D 与 3D 各有对应方案，起步不必自研，要自研的是参数系统、状态机与相机逻辑。

**角色控制**

- 用运动学方式管理角色：自己算速度、重力与碰撞响应，不要把角色交给完整刚体物理，否则手感会被物理引擎摆布。
- 物理步长固定（常用 60Hz），渲染与物理解耦；单帧位移超过半个碰撞体时做子步进或连续检测，防止高速穿墙。
- 落地判定比视觉更宽容：脚下多采样几个点，允许半只脚悬空也算站稳。玩家相信眼睛，就让物理向眼睛妥协。
- 单向平台、移动平台、可穿越墙体是三个独立系统。移动平台带角色的两种主流做法里，每帧把平台位移加给角色通常比挂载更稳；横移、升降、变向三种情况都要测到不抖不滑。

**参数体系**

- 土狼时间、输入缓冲、可变跳高都以「计时器加状态标志」实现：离地开始倒计时、落地前保留一个待消费的跳跃请求、松键时切换上升速度或加大下落重力。全部放进角色状态机，不要塞进动画事件。
- 手感参数集中到一处（数值表或配置文件），禁止散落的魔法数字；改参数要能立即在运行中的游戏里生效。调整效率决定手感上限。

**可测性**

- 第一个调试工具是跳跃轨迹可视化：速度矢量、弧线预览、当前参数值同屏显示。没有它，调参就是盲人摸象。
- 视觉与听觉反馈是放大器而不是救命药：起跳拉伸、滞空收拢、落地压扁，配尘土粒子与音效层，让好手感被看见、被听见（做法见《美术与音频手册》（⑪））。
- 输入到画面的延迟按帧检查，目标 2-3 帧以内；键盘、手柄、触屏分开测，触屏还要额外设计虚拟按键的位置与大小。
- 若计划支持速通或幽灵回放，物理需可复现（固定步长、可复现随机数）；每次改手感都要重新评估已有成绩的可比性。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 关卡量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 手感原型 | 1 个房间 | 2-4 周 | 零美术，只验证跳跃与相机 |
| 小型完整作品 | 10-20 个短关 | 1-3 个月 | 单一机制，一套主题美术 |
| 常见独立 2D 作品 | 15-30 关，或 6-10 个主题区域 | 1-3 年 | 关卡迭代与打磨占大头 |
| 3D 平台作品 | 8-15 关加收集物 | 2-4 年 | 美术与环境成本远高于 2D |

美术量级：2D 角色一套基础动作（待机、跑、跳、落、受伤、死亡）通常合 30-60 个动画帧组，再加特效与界面图标；一个主题的 tileset 通常几十到几百块，按「先够白盒用，再逐步替换」推进。

关卡量级：白盒产出快、打磨慢，时间比通常是 1:3 到 1:5（排一天，测试与修改三到五天）。关卡数不是目标，密度才是：一段 30 秒的体验里通常要有一个小高潮、一次决策或一个发现。

排期锚点：从零做出可玩的手感原型通常 2-4 周；到垂直切片（一段达到发行质量的内容）通常 2-4 个月；之后按「内容量乘打磨系数」外推。范围失控是这个类型最常见的死因，砍关卡永远比堆关卡安全。

## 6. 第一个原型怎么起步

第一个原型只做一个房间，2-4 周完成，不碰美术、剧情、存档与菜单。

**第 1 周：单房间手感原型。** 一块平地、三到五个平台、一个坑、一面可蹬的墙、一台相机。把 §3.1 的三要素与 §3.2 的三组旋钮全部做成可调、可热改。这个阶段丑是应该的。

**第 2 周：调参与内部测试。** 逐帧录屏调手感；找 3-5 个没玩过的人，观察他们何时停、何时骂、何时笑，记录死亡点与停顿点，不提示、不解释。

**第 3 到 4 周：微缩节奏验证。** 在同一房间加进「教、考、变奏」：一块平台教新机制，一条低压路径考试，一处组合做变奏。验证你调出的手感能否支撑关卡设计，再决定铺不铺量。

成功标准（全部可观察）：

- 拿掉全部美术与音效，测试者仍愿意反复玩，单次通常 10 分钟以上。
- 5 名测试者中至少 4 人无口头指导、3 分钟内完成房间；「明明按了却没跳」类抱怨每人不超过 1 次。
- 任意改一个跳跃参数，你能在 5 分钟内量化它对通关的影响（前提是度量与工具已就位）。
- 测试者是主动重试，而不是被请求再试一次。

手感验收不通过，就不要开始铺关卡。地基上的返工是这个类型最贵的一笔账。

## 7. 常见坑

1. **手感未定先铺关卡**：关卡按错误的跳跃半径搭好，一调参数全部重做。手感冻结之前，关卡一张都别量产。
2. **参数靠感觉调，不看帧**：不录屏、不数帧、不建度量，调几个月也调不出来。手感是逐帧问题。
3. **相机与角色同帧硬绑定**：镜头变成眩晕源，落点信息全丢。相机要软跟随、有前瞻、有死区（§3.3）。
4. **判定与视觉不一致**：看着能站的站不住，看着能过的过不去。玩家信眼睛，不妥协就得吃差评。
5. **用角色像素尺寸量平台间距**：正确的尺子是跳跃半径表（§3.5），不是体型。
6. **惩罚过重**：检查点太远、死亡清空进度、跑路半分钟起步。平台跳跃的死亡应该便宜，重试应该顺滑。
7. **空中控制与地面等强或完全缺失**：前者让跳跃失去重量，后者让空中无法修正。两种极端都毁手感。
8. **移动平台不带动角色，或带动时抖动**：换成位移继承方案重做，不要用「手感补正」硬修。
9. **关卡只有通过性，没有表达**：全对称方格、无地标、无远景，玩家记不住路，也留不下印象。
10. **原型期堆美术**：灰盒还没过测试就做贴图，玩法一改全部作废；美术进场前的每张图都可能是沉没成本。
