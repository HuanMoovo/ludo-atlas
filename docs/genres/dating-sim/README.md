# Ludo Atlas · 类型手册 · 恋爱模拟（Dating Sim）

> **类型手册 · 第四辑**。定位：用数值与日程把「经营一段关系」做成主循环的类型。玩家在有限时间里排行动、攒好感、等事件，把心动做成可规划、可争取、可失去的账本；本页覆盖好感与事件触发、时间管理、路线结构、演出与本地化四块骨架。
> 配套：《游戏设计手册》（核心循环与数值）·《美术与音频手册》（立绘与语音规格）·《案例研究集》（题材案例与复盘）·《独立开发生存手册》（范围控制与内容量账）。
> 本文不放外链；标杆只列大众熟知的作品。文中数字为常见量级，按自己项目的实测校准。

## 1. 定位与核心循环

一句话定位：恋爱模拟是**以「经营一段关系」为第一内容**的类型。文本负责心动，日程与数值负责让它可规划、可争取、可失去；恋爱不是通关后的奖励，恋爱就是主线本身。

核心循环用动词环写：`查看日历与状态 → 安排今日行动 → 触发对话与事件 → 好感与属性结算 → 周与季节结算 → 解锁新事件 → 再安排`。它以「天」或「时段」计量，分三层运转：时段级（几秒到几分钟，靠即时反馈黏人）、周级（排期与结算，靠固定事件压节奏）、周目级（换线重玩，靠多结局与收集）。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 视觉小说 | VN 的推进器是阅读与分支，数值最多是解锁的配菜；恋爱模拟由好感度与日程驱动，文本为数值兑现服务。 |
| 养成 | 养成的对象是玩家培养的角色，恋爱线只是路线之一；恋爱模拟的终点是攻略对象，一切系统向「关系」收束。 |
| 农场经营 | 恋爱在农场经营里是众多系统之一；在恋爱模拟里它是唯一主线。 |
| 乙女与男性向 | 题材与受众维度，不是系统差异；两边要解决的是同一个问题：让玩家感到「被回应」。 |

一个自检问题：把好感度与日程系统整个删掉，故事还能不能读？答案若为「能」，你做的更接近视觉小说；答案若为「不能」，这个类型才成立。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **被回应**：做过的每件事，角色记得住、有反应。这是这个类型最底层的快感，比任何单段剧情都重要。
2. **推进感**：关系的每一步都有台阶（称呼、距离、专属事件与场所），玩家始终知道自己走到哪了。
3. **安排的乐趣**：时间永远不够，每次排期都是取舍；没有抄作业式的唯一解。
4. **心动时刻**：关键场次的演出要舍得投入，目标是让玩家截图、重看、安利。
5. **收集与重开**：多角色、多结局、CG 与事件的清单感，勾着玩家换一条线再来一周目。

标杆作品（大众熟知名单，建议亲手玩过再拆，看视频学不到选择时的犹豫）：

| 作品 | 可学的点 |
| --- | --- |
| 心跳回忆 | 数值驱动叙事的开山锚点：日程管理、属性门槛、负面摩擦（流言与炸弹）、毕业告白的目标结构 |
| 爱相随 | 交往之后才开始的关系维护：实时作息、按时段变化的日常对话复用 |
| 樱花大战 | 好感数值（信赖）与限时选项、战斗段落混合的类型缝合样本 |
| 女神异闻录 5 | 日历与行动槽的现代口径：白天自由时间与夜晚行动，社群收益与推进节奏 |
| 恋与制作人 | 移动端乙女样本：卡牌养成与剧情恋爱绑定，配音与长期更新结构 |

一句提醒：标杆的体量来自多年迭代与工业管线，对标它们的情感落点，不要对标它们的内容量。

## 3. 设计要点

### 3.1 好感度与事件触发：数值驱动的叙事

好感度是主计分板，但不能只是一个数字，它分三层：**好感值**（每角色 0-100 的连续数值，供门槛判定；一次日常互动 +2 到 +6，一次满意约会 +5 到 +15）、**关系阶段**（由阈值切分的 4-6 档：陌生、认识、朋友、在意、恋人，决定台词池与可触发事件集）、**记忆旗标**（布尔集，让后续对话引用过去的选择与经历）。事件触发则是五元组合：`好感区间 × 时段或日期 × 地点 × 前置事件 × 玩家属性`，全部登记进事件表，让条件可查、可测、可改：

| 列 | 内容 | 例 |
| --- | --- | --- |
| 触发条件 | 五元组合的完整写法 | 好感 20-39 且 周三放学 且 图书馆 且 未触发 01-02 |
| 优先级 | 同时段多事件的竞争排序 | 关键剧情 > 纪念日 > 角色事件 > 日常 |
| 差分 | 按阶段或旗标替换的台词与表情 | 三档语气差分 |
| 资产 | 需要的立绘、表情、CG、BGM | 校服立绘 + 惊讶 + bgm_日常_01 |

调度纪律：

- 同一时段多事件同时满足时按优先级排队，关键事件不允许被随机事件挤掉；被挤掉要给可感知的改期或补偿。条件宁可宽松，别让玩家四周目都没见过它。
- 每个阶段挂一条「确认事件」：到达阶段必触发一次，明确告诉玩家关系变了，解决「数值动了但玩家不知道」这个第一号问题；关键事件错过则补发或降级，不制造永久遗憾（除非那是刻意的失败路线）。

可见性与负反馈：

- 可见性用三层代理：表情与动作、语气与称呼、事件权限（能约到哪、能进哪个场所）。不给裸数值面板，但玩家要能回答「她为什么生气」。
- 负反馈（冷落、吃醋、流言）要满足三件事：可预防（有前兆）、可挽回（有明确补救）、有提示（玩家知道发生了什么）。心跳回忆的「炸弹」是经典参照，也是「做过头会烦人」的经典教训。

### 3.2 时间管理与日程设计：行动力、星期与季节

时间粒度决定整个游戏的触感，先选大盘：

| 粒度 | 形态 | 适合 |
| --- | --- | --- |
| 行动力 | 每天 N 点，行动按点标价 | 短局、移动端、轻量作品 |
| 时段制 | 每天 3-4 个时段，每时段一个行动 | 主流；叙事感与取舍最平衡 |
| 星期制 | 固定事件挂星期，玩家排一周 | 偏好规划快感的作品 |
| 季节或学期 | 大盘，划分章节与考核节点 | 包住前几种粒度的长期进度条 |

预算这样量（数字只示意结构）：一学期按 16 周、每周 5 个可支配日、每天 3 个时段算，总格数约 240；扣掉固定课程与休息，自由支配只剩一半左右。玩家想做的事按预算的 1.5-2 倍设计，多出来的欲望就是取舍；每次行动只服务一个目标（一个角色、一条属性或一次休息），排他性是这个类型的紧张感来源。

日程纪律：

- 日历要能预读：考试、学园祭、节日、生日全部提前标在日历上；生日是每个角色的天然倒计时，把「礼物准备」做成提前量决策。大事件前留准备期、后留恢复期，全程紧绷和全程松弛一样无聊。
- 属性行动与社交行动争夺同一批格子，「练自己还是去找她」的拉扯要常驻；用体力、心情或金钱做第三资源，防止无脑堆行动，摩擦立在资源上，不立在随机上。

检查表：想做之事是否显著超过行动格（1.5 倍以上为佳）？收益矩阵里有没有一行全面压制其他行（有则存在唯一解，玩家会去抄作业）？冲刺段与松弛段是否交替出现？

### 3.3 角色路线结构：共通线与个人线

主干结构一句话：`共通线（全员可交互）→ 分流点（路线锁定）→ 个人线（三幕：靠近、确认、考验）→ 个人结局`。文本量按主干分布（常见量级）：

| 段落 | 占比 | 说明 |
| --- | --- | --- |
| 共通线 | 40%-50% | 全体角色共用：初遇、群像互动与世界观 |
| 个人线 | 合计 40%-50% | 分流后的专属剧情；4 个角色时每人约 10%-12% |
| 结局与差分 | 10% | 各结局、失败线、后日谈与共通线差分 |

分流规则三选一：

| 规则 | 做法 | 风险与纪律 |
| --- | --- | --- |
| 显式选择 | 关键节点列出候选角色，玩家明选 | 可控，是主流做法；选项文案不要剧透后果 |
| 阈值锁定 | 到日期后按好感最高者自动锁定 | 两头讨好的玩家会感觉被系统背刺，需要显式预告 |
| 门槛过滤 | 未达门槛则进入单人结局或失败线 | 失败也要当内容做，给完整段落而不是一行字幕 |

成本纪律：每增加一个可攻略角色，等于一条个人线加共通线差分，再加立绘、表情、CG、语音一整套，成本近似线性；先做 2-3 个角色做深，再按 §5 的账决定加不加人。每个角色再按一张清单验收：一条三幕个人线、3-5 个情感高点（配 CG 与演出）、8-15 个路线专属事件、与共通线有差分的日常台词、一个专属结局加一个错过或失败结局。

### 3.4 演出与本地化：立绘、语音与文本的账

资产量级（中篇 4-6 角色口径）：

| 资产 | 规格与量级 | 说明 |
| --- | --- | --- |
| 立绘 | 每人 1-3 套姿态，画布 1200-2000 像素高 | 分层导出，表情差分在引擎里组合 |
| 表情差分 | 每人 8-12 种 | 只画头部区域；惊讶、害羞、生气、失落是刚需 |
| 事件 CG | 每线 5-10 张，1920×1080 起 | 每张锚定一个情感高点，选题要吝啬 |
| BGM 与音效 | BGM 15-30 首可循环；音效 30-80 个 | 点击、转场、礼物等高频音优先做好 |
| 语音 | 差异极大 | 全语音是最大成本变量，策略见下 |
| UI | 一套 | 日历与行动菜单是本类型特有的 UI 工程，不能低估 |

演出的松紧纪律：日常段落快（表情少换、无特效、短停顿）；心动段落慢（拉长停顿、表情细变、BGM 起落）；关键段落超支（CG、演出、语音全上）。每一句都震屏，等于都不震。

语音策略按预算分三档：全语音（成本与文本量线性绑定，最高）；主线与个人线关键场次语音、日常留白（常见折中）；只配标志性台词（称呼、口头禅、结局告白）。先按「关键场次」开工、发行后按数据补，是可进可退的常见路线。成本排序的常见口径：全语音第一，立绘表情与 CG 第二，BGM 与音效相对轻；文本不烧钱，烧人。

本地化要点：文本即产品，翻译量等于全文；从第一天走引擎字符串系统与术语表（称呼体系是重灾区，名字、昵称、敬称在翻译里最容易走样）。字体授权逐款确认（CJK 字体商用授权）；语音通常保留原音加字幕。译本回填后必须跑演出回归：断行、标点禁则、语音与文本错位。

### 3.5 先算后写：数值验证

动笔之前先把经济算通：每个角色的好感曲线、各阶段的时间成本、能分到每人的可用格数，全部先进表格。

至少验证三件事：每条结局在预算内可达；存在多种通解（不是唯一最优）；单周目覆盖率 40%-60%，给重开留空间。模拟与正式数值共用同一套表，改表即可重跑；用脚本跑 1000 次不同打法的模拟，检查结局分布是否落在设计区间。

## 4. 技术要点

工程难点集中在三块：数据与调度、内容管线、工具链。这个类型没有实时性能压力，难的是状态数量与「改内容不改代码」。

**引擎与框架**

- Ren'Py：VN 事实标准，存档、回看、多语言开箱即用，Python 层足够写日程与好感系统；纯 2D 文本演出路线首选，别自制。自制引擎只在演出形态超出所有现成工具时考虑，第一作不要这么做。
- Unity 或 Godot：需要 3D 场景、Live2D 深度整合或混入小游戏时走这两条；日程、事件、好感系统要自建或找插件起步。

**数据与调度**

- 三张外置表（CSV 或 JSON，代码只读表）：事件表存触发条件、优先级、差分与资产，编号贯穿剧本、资产与语音清单；角色表存好感阈值、阶段台词池、喜好与雷点；日程表存时段结构、固定事件挂历、季节节点与行动收益矩阵。
- 结算写成纯函数：输入日期、玩家状态与安排，输出新状态与事件队列，无副作用、可复现；存档、回放与自动化测试都靠它。
- 时间用离散时段驱动一切：行动消耗时段，事件挂在时段上，结算发生在时段边界；调度器每段遍历事件表筛出满足条件的集合，按优先级排队并处理冲突，关键事件带顺延保底。
- 存档序列化日期、各角色好感与旗标、玩家属性、已触发事件集、当前路线与结局状态，带版本号与迁移函数。分支多、旗标多，坏档的代价尤其高。

**工具与测试**

- 调试面板是第一个工具：跳日期、改好感、列出当前可触发事件、强制触发、直通结局；没有它，测一条线要靠手动重复几十个时段。自动化模拟让脚本扮演不同打法的玩家跑上千局，输出结局分布与未触发事件清单；发布前做全事件可达性与全结局遍历回归，译本回填后再跑一遍演出检查。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算与范围决策，不构成承诺。

| 形态 | 可攻略角色 | 文本量级 | 事件量级 | 周期量级 |
| --- | --- | --- | --- | --- |
| 数值原型 | 1 | 1-2 万字 | 15-25 个 | 2-4 周 |
| 小型可发布 | 2-3 | 6-12 万字 | 60-150 个 | 4-8 个月 |
| 商业中篇 | 4-6 | 15-35 万字 | 200-400 个 | 1-2 年 |
| 团队长篇 | 8-12 | 50 万字以上 | 500 个以上 | 2-4 年 |

换算口径：

- 写作速度：熟练写手每天 2000-4000 字初稿，修订再加 0.5-1 倍（与视觉小说同口径）；事件集成平均每个 0.5-2 天（条件、差分、演出、测试）。
- 单角色成本：个人线文本（1.5-3 万字）＋ 8-15 个专属事件 ＋ 立绘表情一套 ＋ 3-5 张 CG ＋ 语音一段 ＋ 集成测试一周以上；角色数每加一，这套成本重来一遍。
- 发布形态影响结构：买断制按「一次完整体验」设计内容量与周目；长线运营按版本节奏投放角色与事件，两套排期逻辑不同。

排期锚点：到「共通线＋一条完整个人线」的垂直切片通常 2-4 个月；之后按角色数线性外推，再乘打磨系数。砍范围顺序：先角色数，再语音层级与差分深度；文本是产品本体，砍文本等于砍产品。

## 6. 第一个原型怎么起步

目标：4 周内做出「一个角色、一个学期、能走到结局」的最小可玩版，一张成品图都不需要。

1. 第 1 周：表格建模。先不碰引擎：一学期压成 10-16 个决策点，1 个角色、3 个地点、约 15 个事件、2 个结局；把行动收益、好感门槛与事件触发全部算通，验证「凑得出结局」。
2. 第 2 周：骨架跑通。用 Ren'Py 把时间推进、行动菜单、好感与旗标、事件调度器连起来；全占位素材，但从第一天就用正式的节拍与文案格式。
3. 第 3 周：内容与演出。写 10-15 个事件，其中 2 个按情感高点的规格做足（停顿、表情、BGM 起落）；调触发手感，让事件像「碰巧遇上」而不是「到点打卡」。
4. 第 4 周：封闭测试。找 3-5 个没读过设定的人玩完整流程，观察三件事：有没有主动规划、错过了什么、想不想重开；不提示、不解释，记录情绪峰值出现在哪。

验收标准（全部可观察）：5 名测试者中至少 3 人主动重开另一条线；测试者能说出角色的至少两个具体偏好，说明数值系统被读懂了；所有路线与事件全部可达，无死锁；你能在 5 分钟内只改表就调整出一条不同结局的路径。

## 7. 常见坑

1. **好感度黑箱**：数值在涨，表情、台词与称呼却毫无变化，玩家不知道自己在推进。规避：三层代理反馈，每阶段挂一条确认事件（§3.1）。
2. **事件不可达**：条件隐晦或互相矛盾，打穿三周目也没见过某些事件。规避：条件表登记，发布前跑全事件可达性模拟（§4）。
3. **日程没有取舍**：行动格多到能全做完，或存在抄作业的唯一最优解。规避：先定预算再定内容；相邻行动收益差控制在 20%-40% 量级（§3.2）。
4. **角色贪多**：每条线都写一半，一个都没做深。规避：先 2-3 个做深，按 §5 的账算清再加人。
5. **假差分**：换一句台词但结果不变，玩家识破后不再认真做选择。规避：差分至少改变一个可见结果，态度、回报或后续事件（§3.3）。
6. **文本与数值脱钩**：剧情写到情深，好感条还停在「朋友」。规避：阶段阈值挂确认事件，让两边同步（§3.1）。
7. **负反馈失控**：冷落惩罚不可挽回，或干脆没有摩擦。规避：可预防、有提示、可挽回（§3.1）。
8. **全语音撑爆预算**：把全语音当默认配置。规避：关键场次先配，发行后按数据补（§3.4）。
9. **本地化后置**：文本硬编码，出海时全量返工。规避：第一天走字符串系统与术语表（§3.4、§4）。
10. **只测主路线**：冷门路线与失败线无人跑过，发布即死锁。规避：发布前跑全结局遍历与模拟回归（§4）。
