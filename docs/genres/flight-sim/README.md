# Ludo Atlas · 类型手册 · 模拟飞行（Flight Sim）

> **类型手册 P3 批次**（第 ㊶ 轮扩展）。定位：把「驾驶飞机、完整飞完一程」做成第一乐趣的品类。飞行模型与仪表是立身之本，任务航线与地景提供长期目标，玩家在驾驶舱里把天空与地面读成一张可征服的地图。
> 配套：《游戏设计手册》（⑨，核心循环与数值）·《技术实现手册》（⑩，飞行物理、流式加载与性能）·《美术与音频手册》（⑪，地景、天光与座舱音频）·《独立开发生存手册》（⑱，范围控制与成本核算）。
> 本文不放外链；标杆只用大众熟知的作品，文中数字为常见量级，按自己项目的实测校准。

## 1. 定位与核心循环

一句话定位：模拟飞行是**以操纵飞机、完成航行为第一乐趣**的类型。玩家在气动、动力与仪表的交互里建立对飞机的掌控，在航线与任务里获得「从 A 到 B 完整飞完」的秩序感；飞行不是赶路的手段，飞行本身就是内容。

核心循环用动词环写：

`选机与选航线 → 冷舱与检查 → 滑行起飞 → 巡航与导航 → 进近与落地 → 结算与解锁 → 再飞一程`

这个环以「一程」计量，一程十几分钟到数小时。它成立的前提只有两条：飞行反馈可信（§3.2），门槛与受众匹配（§3.1）。拟真三档（三种取向共用一副骨架，飞行模型的权重与门槛不同）：

| 档位 | 第一乐趣 | 飞行模型 | 大众标杆 |
| --- | --- | --- | --- |
| 街机 | 即时爽感与可读反馈 | 低，简化气动，大量增稳 | 皇牌空战系列 |
| 半拟真 | 「像真飞机」的手感与流程 | 中，气动骨架成立，辅助可开关 | 战争雷霆 |
| 全拟真 | 还原度与操作流程本身 | 高，气动与系统齐全 | 微软模拟飞行、X-Plane、DCS World |

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 模拟驾驶（地面载具） | 同有驾驶舱与运输循环；地面被路网约束，天空是连续三维空间，多了垂直维度与气动，自由度与难度各高一档 |
| 太空模拟 | 同为载具驾驶；太空没有大气，换成六自由度与跃迁导航；模拟飞行守在大气层逻辑里（爬升、失速、风与云） |
| 竞速与空战 | 一个比圈速，一个比击落；模拟飞行的第一现场始终是操纵与流程，两者都只是它的一部分 |

自检问题：拿掉地图、任务与地景，只剩一架飞机和一片天空，游戏还成立吗？答案若为「成立」，你做的就是模拟飞行；答案若全靠空战缠斗撑着，你的重心已经不在飞行上了。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **掌控感**：俯仰、滚转、油门与配平逐步内化；每次事故都能解释成自己的操作，落地失败是能力问题，不是运气问题。
2. **航程与世界感**：滑行、起飞、巡航、进近串成完整一段，机场、地标与天气拼成一张可信的地球切片；天空与地面是内容，不是两点之间的加载动画。
3. **仪式感**：冷舱启动、检查单、无线电通话与落地拉平，流程本身的严肃感是这类作品独有的情绪价值。
4. **低压失败**：摔了、偏了、迷航了要罚得有分寸；重来便宜、能回放、能复盘。

标杆作品（建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 微软模拟飞行系列 | 真实地理数据与全球地景的规模效应；拟真操作的门槛分层；把观光做成一等一玩法的大众化包装 |
| X-Plane 系列 | 飞行模型的工程做法（叶片单元法）；插件生态与机型扩展的长线经营 |
| DCS World | 单机型深度：座舱交互与检查单流程，study-level 的门槛与回报 |
| 皇牌空战系列 | 街机化包装：任务演出、僚机叙事与低门槛飞行 |
| 战争雷霆 | 多档拟真同服的宽容设计：街机、拟真、全真各玩各的 |

## 3. 设计要点

### 3.1 拟真三档与受众分层

三档的受众规模差一个数量级，选档等于选市场：

| 档位 | 目标受众 | 操作门槛 | 产品风险 |
| --- | --- | --- | --- |
| 街机 | 全体玩家 | 键鼠手柄即玩，镜头好读 | 飞行沦为背景，差异化靠题材与演出 |
| 半拟真 | 主流模拟玩家 | 辅助可开关，流程点到为止 | 两头不靠：拟真玩家嫌浅，大众嫌烦 |
| 全拟真 | 愿意读手册的核心玩家 | 外设加教程，需要认真投入 | 受众窄、单机成本高，容错设计要更细 |

- 一部作品可以覆盖多档：把辅助做成一排开关（自动配平、自动油门、失速保护、简化气动），新手开满、老手全关；开关就是教学阶梯（§3.5），但默认档只有一个，它决定口碑的基调。
- 全拟真的成本不在物理，在系统：每个开关、每条检查单、每种故障都要实现与测试，单机型做到全拟真的工作量常以年计（§5）。

### 3.2 飞行模型与操控：把「像在飞」翻译成直觉

飞行手感与地面驾驶同源（可预测优先于正确），但多了一个垂直维度与一整套气动语法：

| 直觉 | 对应实现 | 调坏的后果 |
| --- | --- | --- |
| 升力与重量 | 升力、阻力、推力、重力四力；升力随迎角与速度变化 | 缺失则飞机像悬浮的贴图，转弯没有坡度与过载感 |
| 惯性与稳定 | 角速度阻尼、重心与配平、增稳辅助 | 太稳像轨道车，太活像陀螺，都无法建立信任 |
| 失速边界 | 包线边缘的抖杆、蜂鸣与操纵变软 | 无预警则玩家永远不知道自己踩线；过软则失去教育意义 |
| 地面操作 | 起降瞬间的滑跑、侧风修正与刹车 | 起飞落地变成过场动画，类型最核心的两分钟失去张力 |

- 先能飞稳，再谈还原：平飞、转弯与进近的稳定性先于机动极限；失速是第一真机制，街机软化或关闭、半拟真给预警、全拟真还原包线与改出流程，三档都要在教程里讲一次。
- 外设生态有罕见的硬件阶梯：最低档是键鼠与手柄，必须能完成巡航与本场起降；进阶是摇杆加油门杆（HOTAS）；全套再叠脚舵、头瞄、多屏或 VR。最低门槛的「能玩」优先于外设的「好玩」，设置菜单（曲线、死区、配平步进、按键映射）给足预设，玩家分享配置就是免费的运营资产。
- 手感参数集中进数值表并支持热改，在固定航线与固定气象上飞同一段、每次只动一组参数；验收：找 5 个人各飞 20 分钟，「不该摔的摔机」每人不超过 2 次，且摔了之后能说出自己错在哪。

### 3.3 任务与航线内容

任务与航线是长期留存的发动机：任务发内容，航线给理由，解锁控制地图的打开顺序。任务按四档拆分：

| 任务档 | 例子 | 设计作用 |
| --- | --- | --- |
| 观光与自由飞行 | 本场地标巡游、山谷穿越 | 门槛最低，展示地景，新手的第一程 |
| 通用航空与运输 | 支线客货、救援、消防与巡查 | 稳定收入与航线覆盖，内容主干 |
| 挑战科目 | 短跑道、侧风落地、夜航与低云进近 | 用操作门槛换成就感，给熟练玩家 |
| 战役与情境 | 历史任务、护航、灾害响应 | 叙事与演出的载体，拉开产品气质 |

- 一程拆成五段：计划、起飞、巡航、进近、落地，每段埋一个操作事件（侧风、改航、夜间进近），并给航线配上看地标的理由与飞它的理由（报酬与解锁）；只有两个机场一条直线的航线，飞第二次就是通勤。
- 任务模板化：起点、终点、机型、气象、时段、目标、报酬七个字段拼装；手写任务留给教学与战役，否则内容量会被手写吃光。
- 用执照与评级串联解锁：科目、机型与机场挂在评级上，门槛写成动作验收（如「连续三次侧风落地」），而不是刷飞行小时。

### 3.4 地景与机场数据：成本大头的规矩

地景是这类项目的最大支出项，开工之前先立规矩，按三层建管线：

| 层 | 内容 | 做法 |
| --- | --- | --- |
| 全球底子 | 地形高程、影像、水系路网、植被 | 用真实地理数据自动生成，负责「看得过去」 |
| 区域精修 | 城市、山脉、海岸与地标 | 手工或半自动处理，负责「记得住」 |
| 手工资产 | 跑道、滑行道、灯光、航站、地标建筑 | 手工制作，负责「贴近看也不穿帮」 |

- 尺度决策与数据管线先行：覆盖范围与精度分配（哪里自动、哪里手工、哪些机场进手工清单）开工前定死，格式、坐标与版本一套标准；两者改晚了都等于全图返工。
- 机场是飞行模拟的「关卡」：玩家对跑道的记忆远超对天空的记忆，换跑道方向、灯光与进近场景就是新关卡；每座手工机场列一张资产清单（跑道、滑行道、灯光标志、航站、周边），按座管理工作量。
- 记忆点密度：把地标当导航路标用，建议每十到十五分钟航程至少一个可识别地标（山峰、河流、大桥、城市天际线）；没有地标的巡航，玩家第二天就想不起来飞过。

### 3.5 教学曲线阶梯：把高门槛翻译成四级台阶

航空是天然的高门槛题材，教学不是附属功能，是留存的生命线。按四级台阶铺：

| 台阶 | 教什么 | 验收动作 |
| --- | --- | --- |
| 起 | 基本操纵：平飞、转弯、爬升下降 | 无提示完成一次定高转弯与一次爬升到指定高度 |
| 承 | 起降：起落航线、进近与拉平 | 连续三次安全落地 |
| 转 | 导航与流程：航路、无线电、自动驾驶 | 独立完成一程无提示航线 |
| 合 | 气象与特情：侧风、低云、故障处置 | 在恶劣条件下安全落地 |

- 一页一技能，动手先于读文：教程以「做一遍」为单位，文字说明能省则省；老手可跳过，跳过不被罚。
- 检查单是教具也是仪式：用高亮与流程化指引教流程；做完的检查单要能复盘（哪一步漏了、后果是什么）。
- 失败要能复盘：回放、遥测与「错在哪」的提示，把摔机翻译成一课；只有惩罚没有解释的失败，教出来的是躲避而不是飞行。
- 受众分层落到教学上：街机档以分钟计，半拟真以小时计，全拟真以「读手册加长期练习」计；对核心受众，学习过程本身就是一等一的内容。

## 4. 技术要点

工程难点集中在三处：飞行物理、地景流式加载、座舱与输入；以下与引擎无关，方法细节见《技术实现手册》（⑩）。

**飞行物理**

- 从简化气动模型出发：四力方程加升力、阻力曲线，先把「能飞稳」当验收，再逐层补增稳、地面效应、失速与系统；物理固定步长并与渲染解耦，高速段的积分误差单独验证。
- 机型做成可继承的模板：同一副气动骨架换参数、动力与座舱即可派生新机（§5）；遥测与回放既是调试工具也是玩法，「摔机能复盘」与「调参能对比」是同一个需求。

**地景与流式加载**

- 地形、影像与建筑按空间分块流式加载：高空用影像与低模、低空切细节，预算按「进近时跑道与地形要清晰」规划，机场数据必须在进近前加载完成；离线可玩范围是产品决策，想清楚再承诺。
- 气象是全局状态机：云、能见度、风与昼夜读同一个气象源；风要进飞行模型（影响地速与油耗），只做视觉的风不算数。

**座舱、仪表与输入**

- 座舱是主要 UI：空速、高度、姿态、航向、垂直速度、转速是核心信息源，先做「可读」再做「像真」；街机档以 HUD 为主、拟真档以座舱仪表与检查单为主，两套都要做可读性测试；全拟真时座舱交互（可点击开关、仪表读数）是成本重头，可交互项要状态、动画与音效三件套，数量成套裁剪。
- 自动驾驶与飞行指引是可玩的简化层：把高度、航向与姿态的管理自动化，玩家从「手忙脚乱」过渡到「管理飞行」，也是教学阶梯的关键道具（§3.5）。
- 输入走设备抽象层：俯仰、滚转、偏航、油门、配平抽象成统一轴与动作，再逐设备做映射与预设；头瞄与 VR 空间感强但性能预算翻倍，按独立里程碑评估，不要塞进原型期。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 手感原型 | 一片天空、一架飞机、一条本场航线 | 2-4 周 | 只验证飞行手感与起降 |
| 小型完整作品 | 一个区域（几十座机场），2-3 架飞机 | 3-9 个月 | 地景与机场是主体成本 |
| 常见独立规模 | 一个国家或地区，10 架以上机型 | 1-2 年 | 数据管线决定成本上限 |
| 全球级作品 | 全球数据加手工机场群 | 团队级、多年 | 只对大团队与大资本成立 |

成本拆解：地景按面积算，每一块「达到发行质量」的区域等于影像与地形处理、植被与建筑、地标，再加昼夜与气象变体；机场按座算，等于跑道滑行道、灯光标志、航站与周边，再加进近场景。机型按架算：外观模型加座舱（全拟真时几乎是半台作品）、气动参数集、发动机与风噪声浪、内外两套听感；同骨架派生能显著降本，但座舱与声浪仍是一机一套。排期锚点：从零做出垂直切片（一小片区域加一程完整任务链路）通常 2-4 个月；之后按「地景面积乘打磨系数」外推。地景是返工最贵的内容：覆盖范围与精度分配定死之前，一张图都不要量产。

## 6. 第一个原型怎么起步

第一个原型只做一片天空、一架飞机、一条本场航线，2-4 周完成，不碰全球地景，不碰任务系统之外的内容。

**前两周：先能稳定起降，再把一程飞完。** 一架飞机、一片可辨认的地面（一条跑道加两三个地标）、一套简化飞行动力学、座舱与追尾两套相机；起飞、爬升、巡航（一个导航点）、进近、落地五段跑通，把「从 A 到 B 完整飞完」的链路闭合。这个阶段丑是应该的。

**后两周：教一个人飞，再调参与验收。** 加最小教学：起飞与落地各一条教程；找 3-5 个没玩过的人，观察他们何时迷向、何时想放弃、落地成功后说了什么，不提示、不解释。随后逐帧调手感与相机，试一遍手柄与一支摇杆，只改参数与航线，不加新系统。

成功标准（全部可观察）：

- 拿掉全部美术与音效，测试者仍愿意反复飞这条本场航线，单次通常 15 分钟以上。
- 5 名测试者中至少 4 人无口头指导完成一次起落航线（含落地）；「这飞机有毛病」类抱怨每人不超过 1 次。
- 任意改一个气动参数，你能在 5 分钟内量化它对飞行的影响；测试者说得出摔机错在哪，有人主动要求再飞一程。

手感与一程链路不通过，就不要开始铺地景；地景是这个类型最贵的地基，返工一次伤筋动骨。

## 7. 常见坑

1. **拟真度先于手感**：一上来就做全套气动与系统清单，结果飞不稳、教不会；先能飞稳，再谈还原（§3.2）。
2. **教学缺席**：航空是天然高门槛，教程只写在手册里、没做进游戏，头十分钟就劝退大多数玩家（§3.5）。
3. **默认档两头不靠**：默认全拟真吓跑大众，默认全街机惹毛核心受众；辅助开关分层，默认档做明确取舍（§3.1）。
4. **只对外设玩家负责**：键鼠与手柄体验凑合甚至不可用，等于把大头受众拒之门外；最低门槛必须成立（§3.2）。
5. **地景开工过早**：核心循环没冷冻就铺图，覆盖范围或精度一改，全部返工；地景是这个类型最贵的一次性投入（§3.4、§5）。
6. **仪表不可读**：座舱做得像真的，但信息读不出来，玩家只能靠猜飞；可读性先于拟真精度。
7. **失速与特情只罚不教**：没有解释的坠机会教出「躲避失速」而不是「理解失速」；复盘工具是教学设计的一部分。
8. **天气只是贴图**：风与能见度不进入飞行模型，气象系统白做，玩家也不再信任气象预告（§4）。
9. **长航程没有存档弹性**：一小时以上的航程中断即清零，玩家不会原谅第二次；断点续飞与自动存档属于底线需求。
10. **范围对标大厂**：直接对标微软模拟飞行的全球数据与 DCS 的单机深度，是这个类型最经典的翻车点；小团队做「一个区域加一种玩法」的切面（§5）。

## 延伸阅读

- 《游戏设计手册》（⑨）：核心循环、体验目标与数值表的写法，本文第 2、3 节的底稿。
- 《技术实现手册》（⑩）：固定步长、流式加载与性能预算的细节。
- 《美术与音频手册》（⑪）：地景资产、天光与座舱音频的工程做法。
- 《独立开发生存手册》（⑱）：范围控制与排期，与第 5 节对照使用。
- 作业：用灰盒做一片天空加一条本场起落航线，写清它的辅助开关与教学阶梯；再挑一款你熟悉的飞行模拟，记录它把「飞行模型、任务、地景」各占几成，以及它怎样教一个新玩家完成第一次落地。

模拟飞行卖的不是速度，是「把一程完整飞完」的秩序感：飞得可信，天空才有重量；教得清楚，跑道才等得到第二次落地。
