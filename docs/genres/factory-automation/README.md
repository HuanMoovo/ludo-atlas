# Ludo Atlas · 类型手册 · 工厂自动化（Factory / Automation）

> **类型手册 · 第四辑**。定位：把「建造一台会自己运转的机器」做成核心乐趣的类型。玩家从手挖第一块矿开始，把采集、运输、加工、再投资四环接成流水线，再把流水线扩成工厂；本页覆盖自动化循环、传送带物流、配方与科技树、蓝图工具与大工厂的性能账。
> 配套：《游戏设计手册》（核心循环与数值）·《技术实现手册》（数据驱动、性能与存档）·《制作管理手册》（内容量估算与范围控制）·《避坑大全》（数值与性能坑位）。
> 本文不放外链；标杆只列大众熟知的作品，数字为常见量级，按自己项目的实测校准。

## 1. 定位与核心循环

一句话定位：工厂自动化是**把「效率」本身做成玩法的类型**。玩家的对手不是敌人，而是自己的产能表：传送带不够快、原料不够采、电不够用，每扩大一次规模，旧瓶颈就会准时浮出来。乐趣来自亲手搭的系统在没有自己参与的情况下照着设计运转。

核心循环用动词环写：

`探矿与开采 → 运输与进场 → 加工与装配 → 交付与研究 → 解锁与扩建 → 更大规模的瓶颈 → 回到第一步`

这个环有三层时间尺度，每一层的钩子不同：

| 层级 | 时长（现实） | 玩家在做什么 | 结算点 |
| --- | --- | --- | --- |
| 机器级 | 秒 | 一台机器走完一个工作周期 | 产出读数与音效 |
| 产线级 | 分钟到小时 | 搭一条从原料到成品的完整链路并测吞吐 | 每分钟产量读数 |
| 工厂级 | 数十小时 | 扩建规模、换更高的物流层级、消瓶颈 | 科技解锁与产能翻倍 |

环成立的前提只有两条：物品守恒（进了多少出了多少对得上账），吞吐量可见（每个数字都能被玩家自己验证）。这两条一破，玩家对系统不再有信任，工厂游戏就退化成体力活。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 模拟经营 | 经营管人、钱与流程，商品常是抽象数字；工厂自动化管物，每件物品在空间里有真实位置与去向，吞吐量就是一切。 |
| 殖民模拟 | 殖民模拟的模拟单位是人（需求、心情、故事），工厂自动化的模拟单位是物品与机器，人只是可选的代理。 |
| 城市建造 | 城市建造的决策对象是土地与分区，考布局与需求；工厂自动化的决策对象是生产链与物流，考配比与吞吐。 |
| 沙盒建造 | 沙盒建造卖自由表达，没有必须完成的产能目标；工厂自动化有清晰的进度压力（研究、爬科技、扩大交付）。 |

一个自检问题：把产能数字全部藏起来、敌人全部拿掉，玩家还有没有理由扩建第二个车间？答案若是「没有」，你做的可能是别的类型。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **从零长出系统**：开局手忙脚乱，收尾机器自转；建设前后的对比就是玩家自己的成就展。
2. **吞吐量的军备竞赛**：每分钟产出、带速利用率、电耗曲线都可见，进步用数字量出来，且没有封顶。
3. **涌现式解谜**：瓶颈不是作者出的题，是玩家自己的工厂长出来的；「为什么堵了」是这个类型最长寿的日常问题。
4. **可传承的效率工具**：蓝图、复制与镜像让一个方案被复用千百次，玩家的经验变成可携带的资产。
5. **长时长、低压力**：没有失败状态，玩多久由产能目标自己决定；「通宵扩建」是这个类型特有的玩家故事。

标杆作品（建议亲手玩过再拆；物流手感与瓶颈直觉在手上，不在视频里）：

| 作品 | 拆什么 |
| --- | --- |
| 异星工厂 | 类型定义者：传送带、配方表、蓝图与性能优化的全套基准 |
| 幸福工厂 | 3D 化的代价与收益：第一人称建造、垂直工厂与探索的耦合 |
| 戴森球计划 | 尺度跨越：从星球内流水线到星际物流，国产出海标杆 |
| 形状工厂 | 极简主义提纯：去掉战斗与美术，暴露物流逻辑本身 |
| 像素工厂 | 与塔防耦合：生产链被直接拉到战场上接受检验 |
| 缺氧 | 流体、气体与热力的拟真层：管道与系统复杂度的上限实验 |

共同点：物品守恒与吞吐量可见是地基；规模、自动化与工具效率承担长期内容，而不是剧情与关卡堆量。

## 3. 设计要点

### 3.1 自动化循环：采集、运输、加工、再投资

四段环每一段都有「手动原型」与「自动化形态」，设计工作是排好两者的交接点：

| 环节 | 手动原型 | 自动化形态 | 交接点设计 |
| --- | --- | --- | --- |
| 采集 | 手挖、手捡 | 采矿机、钻井、自动农场 | 先让玩家手挖固定时长，痛感到位再给解药 |
| 运输 | 背包往返搬运 | 传送带、管道、车队、机器人 | 第一条传送带要明显超过手搬效率 |
| 加工 | 手搓合成 | 加工机与装配机 | 手搓次数按目标限量，尽快退化为投料 |
| 再投资 | 手动升级 | 科技树与研究交付 | 每次扩建都要回答「解锁什么新东西」 |

两条纪律：手动期是设计参数不是凑合，常见做法是每个新环节先手动 5-15 分钟，痛感到了就把自动化解药交出来；每一段自动化都要有可见回报（数字涨了，或车间变整齐了），否则玩家感觉不到自己在变强。再投资的闸门挂在科技树上（§3.3）：新机器、新带速、新配方按节奏发放，让扩产永远有新理由。

### 3.2 传送带与物流：吞吐量思维

物流是这个类型的骨相，全部设计围绕一个数字：**每分钟物品数**。从配方表到界面到玩家交流只用这一个口径，口算配比才成立。

| 物流手段 | 吞吐量量级 | 代价 | 适用场景 |
| --- | --- | --- | --- |
| 初级传送带 | 低 | 便宜、占地 | 开局产线与教学 |
| 升级传送带 | 翻倍级提升 | 成本随档位跳增 | 主总线与中后期主产区 |
| 管道（流体） | 高但有流速上限 | 只运流体，接口要专门设计 | 油、水、气体的专线 |
| 机器人 | 灵活、点对点 | 耗电高，规模大时是性能负担 | 小批量、远距离、临时补货 |
| 运载列车 | 很大 | 站点与轨道基建成本高 | 跨区域大吞吐运输 |

结构上只有两种主玩法：点对点专线（每条线只服务一个用户，好算好拆）与主总线（一条干线上并行输送多类物品，扩建便宜但拥堵会传染）。两种都要答对同一个问题：这一段流量上限是多少、什么时候会被吃满。分流器与合流器是最便宜的设计杠杆：优先级、过滤与均分三件事做好，玩家的工厂就能长出作者没写过的结构。

堵塞做成可见状态（物品在带上堆停），堵本身就是本类型最有效的反馈，它在明确告诉玩家瓶颈在哪。检查表：新产线开工前先算产能数字（下游要多少、这条线给多少）？主总线的每个接口有没有留扩展位？换更高档物流时，旧产线是整体换而不是打补丁？

### 3.3 配方与科技树：数据驱动的配方表

配方表是这个类型的内容本体，全部配方写进一张表：输入、输出、耗时、加工建筑、科技前置。代码只读表，加内容就是加行。

- 每个物品至少有一个来源与一个去向，孤儿物品不写进游戏。
- 副产物要么有用途，要么可回收处理，不允许偷偷消失。
- 生产链深度做到三到五层就够玩家读（原料 → 中间品 → 零件 → 成品 → 交付物），深了就难懂，浅了没有优化空间。

科技树负责节奏：把新机器、新物流、新配方按顺序解锁，初始几小时里每 15-30 分钟给一个新机制，中后期转向「同样的东西更大规模」。解锁节奏失控是这个类型最常见的内容事故：给得太快，后半程无事可做；给得太慢，玩家在无聊里流失。教学的做法是把教程做成目标而不是文字墙：造出第一台矿机、交付第一批研究包、让产能翻倍一次，玩家不看字也在学。

### 3.4 蓝图与复制：把玩家的效率做成工具

蓝图是一段可保存、可粘贴、可分享的建筑与配方配置。它不改变玩法规则，却决定玩家在第二十小时后还愿不愿意扩建：手动摆第五十台机器的人会关游戏，用蓝图把产能整体复制十倍的人会主动开新档。

工具清单按上线顺序排：框选复制与粘贴、镜像与旋转、撤销与重做、蓝图库（存、取、命名）、蓝图字符串分享（跨存档、跨玩家）。分享是社区层面的生命线，但要有版本纪律：蓝图编码带版本号，更新后要么能导入，要么明确拒绝并给出原因，不要静默错乱。两条设计纪律：粘贴要有成本校验（材料、占地、科技前置），把「贴不起」说清楚；蓝图只存建筑与配置，不存运行时状态（在途物品、电量），粘贴语义要简单到玩家能预测。

### 3.5 电力、瓶颈与故障：让系统的问题自己浮出来

电力把全厂耦合成一个整体：发电、蓄电、耗电在同一张网上结算，断电优先级要先定（保生产还是保防御）。它的作用是让分散的产线变成需要统筹的系统，也让扩产有了全局成本。

瓶颈是这一类型的核心内容，作者只需要做好三件事：让瓶颈可测（每段物流的流量计数、每台机器的利用率）、让瓶颈可见（堆停的带、缺料图标）、让解决有梯度（提速、并行、换档、重构，四个选项的成本依次提高）。故障设计从简：断电、堵料、原料枯竭三类就够，每类都要有明确的视觉与声音信号。不要做随机损坏类惩罚，这个类型的玩家把工厂当作品，随机破坏作品是最招恨的难度来源。

## 4. 技术要点

工程难点集中在四处：模拟核心、大工厂性能、蓝图与存档、建造交互与工具。以下与引擎无关；数据驱动与性能预算的通用方法见《技术实现手册》。

### 4.1 模拟核心：固定步长的物品世界

- 全厂跑在固定步长的模拟时钟上（常见 30-60 次每秒，以 60 为常见上限参照），生产、物流、电力在同一时钟结算；渲染与模拟解耦，时间加速与无头批跑都靠它。
- 传送带模拟有两条主流路线：物品实体沿线移动（直观、细节足、规模大时贵）与格子压缩模拟（每格只记数量与去向，快但表现力弱）；大工厂选后者或两者混合（近处实体、远处统计）。
- 物品守恒是第一纪律：任何丢失或复制物品的缺陷都是最高优先级，它会把全部数值平衡变成谣言。
- 配方、物品、科技、电力参数全部进表，启动时构建索引，运行时只读；表要支持热重载，调参效率决定迭代速度。

### 4.2 大工厂的性能工程

- 规模画像：中后期存档常见万级机器与十万级在途物品，目标是模拟速率稳住（常见目标 30-60 次每秒），不是先保渲染帧率。
- 分区与激活：地图按区块切格，静止区域降频或整体冻结，只有「有变化」的区块才消耗计算。
- 统计化模拟：远处与满载段以聚合体计算（一段满带按流量统计，不逐件移动），把成本从物品数压到段数。
- 并行与批处理：物流、电力、生产按系统或区块分到工作线程，读写分离；并行前先做单线程优化，否则只是把瓶颈搬到线程切换上。
- 渲染分离：视野外不建实体，精灵批绘制与层级简化；后期的第一瓶颈通常先出现在模拟侧，性能探针要能同时看到两侧。
- 成本预算：给每类机器与每段物流定义每秒模拟成本，新增任何系统前先算「满厂加它之后慢多少」；调试侧配时间加速、创世模式与稳定读数显示。

### 4.3 蓝图与存档工程

- 蓝图序列化：编码为带版本号与校验的字符串，支持跨存档与跨玩家传输；数据里只含建筑、位置与配置，导入时校验成本与科技前置。
- 存档策略：工厂存档会随规模膨胀到玩家能感知的量级，保存与加载时间都是真实账单；序列化做紧凑，自动存档要快，加载要有进度反馈与版本迁移。
- 统计基建：每分钟产量、历史曲线与流量计数从第一天就埋在数据层，它们是玩家诊断工厂的依据，也是你平衡数值的依据。

### 4.4 建造交互与调试工具

- 建造交互是本类型的第一手感：按住拖线放带、自动吸附与地下带、放置预览与合法性提示、撤销重做；批量建造（区域填充、倍数复制）越早做越好，它直接决定大型工厂的操作成本。
- 蓝图工具集：复制、粘贴、镜像、蓝图库、字符串导入导出，操作要能在秒级完成，不给玩家任何「手动重建」的理由。
- 调试三件套：物品流量探针、电力曲线、瓶颈高亮；再加时间加速与无头批跑（长时间模拟压到秒级跑完），用来做产能表的自动校验，数值回归不靠手测。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 核心原型 | 3-5 种资源、十条上下配方、1 档传送带 | 2-4 周 | 只验证「手搓到自动化」的一个完整环 |
| 小型完整作品 | 30-60 种物品、80-150 条配方、1 张手工地图 | 4-9 个月 | 内容量小、系统深，独立团队的现实区间 |
| 常见商业作品 | 100-300 种物品、科技树几十个节点 | 1-3 年 | 玩法成立后，大头是数值、体验优化与性能 |
| 大型长线作品 | 数百种物品、多星球或多维度、模组生态 | 3 年以上持续运营 | 内容引擎转向社区与模组 |

单个内容单元的常见成本（量级参考）：

| 内容单元 | 单位成本 | 说明 |
| --- | --- | --- |
| 一条配方 | 小时级 | 挂表、配图标、过一遍配比表 |
| 一种机器或建筑 | 2-5 天 | 模型、动画（至少待机与工作两态）、接口与数值 |
| 一类物流层级 | 1-2 周 | 新带速或新载具的数值、美术、交互与性能验证 |
| 一个科技节点 | 数小时到 1 天 | 挂表与文案便宜，难在它牵动的解锁节奏 |
| 蓝图与复制工具 | 1-2 周工程 | 序列化、校验、交互与版本迁移 |

本类型的成本结构与内容型品类相反：内容条目少、系统深，钱花在数值与工具上。排期锚点：可玩的单环原型 2-4 周；到垂直切片（一张图、一条完整科技线、蓝图工具）通常 4-9 个月；之后按内容条目倍增，但每加一条配方都要过全链配比表，数值验证是主要账目。

## 6. 第一个原型怎么起步

第一个原型只做一条完整的小产线，2-4 周完成，不碰蓝图分享、战斗与剧情：

1. （第 1 周）物品与格子系统：一种资源、一台机器、一个箱子，物品能进能出，账目守恒。
2. （第 1 周）手动阶段：手挖 5-10 分钟的量，让测试者先体会搬运的痛。
3. （第 2 周）第一条传送带与采矿机：矿机 → 带 → 炉 → 成品箱，第一个自动化环闭合。
4. （第 2 周）交付目标：一个消费产物的研究或建造目标，给玩家下一步的理由。
5. （第 3 周）配方表数据驱动：哪怕只有十条配方，也全部来自一张表；解锁第二台机器。
6. （第 3 周）吞吐量可见：每分钟产量面板加传送带流量计数，玩家要能自己找到瓶颈。
7. （第 4 周）效率工具最小集：框选复制与粘贴；测试、复盘，再决定铺不铺量。

起步参数（可直接抄来改）：1 种矿、3-5 台机器、2 档传送带、十条左右配方、单张网格地图；单台机器周期以秒计（常见 1-5 秒），先让反馈节奏立住。验收标准（全部可观察）：

- 测试者不看教程，能说清「为什么我的炉子吃不饱」（进料不足还是出料堵）。
- 拿掉全部美术与音效，测试者仍愿意把产能翻倍一次，单次通常 2 小时以上。
- 物品守恒连续运行 30 分钟无异常，数字对得上账。
- 改一条配方的产出速度，你能在 30 分钟内说清它对整条链路的影响。

## 7. 常见坑

1. **传送带不守恒**：物品丢失或复制，玩家对系统的信任当场崩，全部数值平衡作废。这是最高优先级缺陷。
2. **单位与口径不统一**：各处用不同的时间与数量口径，玩家永远算不出配比，工厂变成玄学。全类型统一「每分钟物品数」。
3. **自动化给得太晚**：手搓期拖成主要内容，玩家在疲劳里流失。每个环节的自动化解药按分钟级预算到场。
4. **堵塞不可见**：堵了，但玩家查不出为什么。流量计数、堆停表现与缺料图标是必修项。
5. **配方树只有一条直线**：没有取舍与副产物，两小时之后全是重复劳动；配方表要长出分叉。
6. **蓝图缺席或难用**：中期之后扩建全靠手摆，弃坑率飙升；框选复制要在早期就有。
7. **后期性能崩塌**：规模上来后模拟速率下跌，玩家被迫缩小工厂或退游；性能预算与统计化模拟要开工就算（§4.2）。
8. **科技树节奏断层**：四小时全解锁，或者两天不给新东西；按「初始每 15-30 分钟一个机制」排解锁表。
9. **随机破坏当难度**：随机损坏、天灾式惩罚把玩家的作品当敌人，这个类型的玩家不吃这一套（§3.5）。
10. **存档与蓝图没有版本迁移**：更新后旧工厂与旧蓝图报废，是口碑雷区，也是玩家几千小时的沉没成本。

## 延伸阅读

- 《游戏设计手册》：核心循环、数值表与解锁节奏的底稿，本文第 1、3.1、3.3 节的上位方法。
- 《技术实现手册》：数据驱动、性能预算与存档工程，第 4 节的完整展开。
- 《制作管理手册》：内容量与排期方法，配第 5 节使用；先给「一条配方、一种机器」计时，再做乘法。
- 《避坑大全》：数值与性能属于本类型的高频坑位，开工前过一遍。
- 《案例研究集》：戴森球计划的出海案例，注意「品类真空加工程品质」的组合。
- 练习一：用纸面表格算一条「矿 → 炉 → 零件 → 交付物」链路，算出每级需要的机器数，标出第一处瓶颈出现的时间点。
- 练习二：给正在做的原型写一份「吞吐量字典」：全部物流手段的每分钟流量、成本与电耗，一页纸以内。
- 练习三：找一份自己或别人的大工厂存档，列出三个「如果早一点自动化就不会发生」的时刻，倒推自动化登场线该提前到哪。

工厂自动化卖的不是机器，而是「亲手把混乱变成秩序，再把秩序推向更大混乱」的循环；物品守恒与吞吐量可见是全部信任的地基。
