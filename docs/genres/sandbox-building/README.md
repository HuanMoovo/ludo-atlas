# Ludo Atlas · 类型手册 · 沙盒建造（Sandbox Building）

> **类型手册 · 第二辑**。定位：把「造东西」本身做成核心玩法的类型。工具即玩法，作品即内容，分享即延续；玩家的建造在替游戏生产它自己做不出来的关卡、装置与奇观。
> 配套：《游戏设计手册》·《技术实现手册》·《Mod 与 UGC 手册》·《独立开发生存手册》。

---

## 1. 定位与核心循环

一句话定位：沙盒建造是**以创造工具为核心玩法**的类型。它不是「带建造功能的游戏」，而是「建造工具本身就是游戏」：玩家拿到的每一件工具都是一条玩法，玩家造出的每一件作品都是一份内容。

核心循环用动词环写：

`晃荡看空地 → 放第一块 → 拼出结构 → 发现不够用 → 拆改与扩建 → 造出能用的东西 → 试玩自己造的 → 想要更大更巧的 →（看到别人的作品）回到第一块`

这个类型的节奏有四个层级，每层解决一个不同的动机：秒级的放置反馈给即时爽感，分钟级的「造出可用的东西」给成就感，小时级的基地与装置给项目感，周级的作品打磨与分享给表达欲。四层都要有出口，只做一层留不住人。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 生存建造 | 那类用生存压力组织建造；沙盒建造没有强制压力（或可整体关闭），建造与分享本身就是主循环 |
| 城市建造 | 那类在宏观尺度上管理土地与统计量；沙盒建造在物体尺度上管理结构与形状 |
| 物理沙盒（玩具箱向） | 那类第一乐趣是交互实验本身；沙盒建造第一乐趣是造出可留存、可展示、可玩的作品 |
| 模拟经营 | 那类经营抽象的房间与流程；沙盒建造经营的是玩家手里那套工具的深度 |

一个自检问题：把建造工具全部锁死、只留固定内容，游戏还成立吗？答案若为「不成立」，你做的就是沙盒建造。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **自由表达**：形状、大小、用途全由玩家定；官方提供材料与规则，不给标准答案。
2. **组合精通**：同一套基元，新手摆出小房子，老手造出计算器。精通感来自组合深度，不来自数值。
3. **作品被看见**：作品能出门、能被试玩、能收到回响；被看见是创作者最强的续命药。
4. **长线项目感**：一个世界或一件作品可以持续经营数周，每次回来都有下一处想改的地方。
5. **沉浸与专注**：建造状态下没有强制倒计时，玩家可以安静地待在里面（紧与松的分层见 §3.5）。

标杆作品（只选大众熟知的名字，建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 我的世界 | 基元纯度与组合爆炸（红石）、区块性能体系、创造与生存双模式分层 |
| 泰拉瑞亚 | 建造与战斗的耦合、布线系统、世界文件分享的社区习惯 |
| 盖瑞模组 | 物理约束的组合玩法、创意工坊生态、玩具箱式自由的下限与上限 |
| 罗布乐思 | 平台化路径：创作、发布、试玩、变现一条龙 |
| 超级马力欧制造 2 | 编辑器即产品、分享码与全球关卡库、被玩与被赞的正反馈 |
| 勇者斗恶龙：创世小玩家 2 | 委托式引导：NPC 把「造什么」变成「轮到你了」；岛屿上传分享 |
| 塞尔达传说：王国之泪 | 物理规则的可预测组合，究极手是「少基元、深组合」的现代样本 |
| 集合啦！动物森友会 | 弱压力环境下的岛建与展示、梦境门牌号式的低门槛分享 |

反面经验同样值得看：编辑器开放太晚、分享出口缺失的作品，社区热度往往止步于首发期。拆这类案例时，重点看整个创造链条断在哪一环。

## 3. 设计要点

### 3.1 工具即游戏

在别的类型里，编辑工具是界面；在这个类型里，工具是玩法本身。这个类型的本质是**创造平台**：玩家手里的工具即玩法，工具能做到什么，游戏就能玩到什么。工具的顺手程度就是游戏手感：放置要跟手（预览与吸附即时可见），拆除要便宜（返还材料、可撤销），批量要强（框选、填充、复制、镜像）。

| 工具族 | 要做的功能 | 为什么是玩法 |
| --- | --- | --- |
| 放置与拆除 | 单放、长按连放、吸取方块、范围删除 | 操作次数决定作品尺寸的上限；不跟手就没有大作品 |
| 批量与变换 | 框选、填充、替换、复制粘贴、旋转与镜像 | 大工程的效率工具，玩家用它做「规模」这一步的玩法 |
| 撤销与历史 | 撤销栈、最近 N 步回放、误操作零成本 | 允许实验是创作的前提；怕拆错的人只会造最小的房子 |
| 蓝图与投影 | 存模板、放投影、跨地图复用 | 让「设计」与「施工」分离，是把建造做成工程的前提 |
| 测量与辅助 | 对齐线、计数、比例参考、坐标显示 | 精度是高级作品的需求，也是社区里的炫耀语言 |

平台差异是历史难题：键鼠适合精度与快捷键，手柄需要径向菜单与快速循环，触屏依赖长按与双指手势。手柄或触屏方案没打磨完就上线，该平台的建造留存会明显偏低；先在一个平台把工具做到顺手，再谈移植。

验收习惯：找 3 个人各建一栋小屋，数三个数字：误放置次数、撤销次数、从开工到封顶的操作数。三个数都低于你的预期，工具才算及格。

### 3.2 基元与规则：可预测的组合爆炸

这类游戏的深度不来自内容量，来自**少量精确基元的组合空间**。三条设计律：

- **正交**：每个基元只管一个维度（电、运动、承重、流体），职责重叠的基元互相打架，组合图会乱成一团。
- **确定**：同样输入必须同样输出。物理与逻辑可复现，玩家才会把装置往精密里做；时灵时不灵的模拟只会让所有人退回最保守的造法。
- **可观察**：每个基元的状态要能看见（亮灭、通断、流动），玩家靠眼睛学规则，不靠说明书。

组合从「明显用途」长出来：一个元件至少要有一个人人都懂的基础用法，和两三个需要想一想的高级用法。下面这张表是设计期的自查工具：

| 基元 | 明显用途 | 高级组合（示例） |
| --- | --- | --- |
| 电路元件（通断、延时、脉冲） | 开关灯 | 自动门、陷阱、密码锁、计时装置、逻辑门连成计算器 |
| 运动元件（活塞、转轴、推进器） | 造电梯 | 可动机械、飞行器、流水线、机关迷宫 |
| 流体与重力（水、沙、重力块） | 装饰水池 | 水利装置、传送水道、陷阱、浮力机关 |
| 承重与结构 | 搭桥 | 悬索、拱、可坍塌竞技场、一体化基地 |
| 传感器（压力、光线、坐标） | 自动灯 | 全自动农场、挑战关卡、无人载具 |

组合深度要定期测试：每加一个新基元，做一次「它与全部旧基元两两组合」的脑暴，挑 3 个最有意思的实现进官方模板（§3.3）。规则同时要克制：为每种情况单独写特例，组合空间会碎成一地补丁，玩家学不完也信不过。

### 3.3 引导设计：从空白到第一件作品

这个类型最大的新手敌人不是难度，是空白：面对一片荒野、一张白纸，大多数人的反应是「不知道造什么」。引导要解决的是「造什么」，而不是「怎么造」（后者交给工具与教程）。五种手段配合使用：

| 手段 | 做法 | 解决什么 |
| --- | --- | --- |
| 灵感触发 | 开场就展示可能性：精选作品墙、一封信里的草图、系统内可见的「别人造了什么」 | 第一次进游戏时的空白恐惧 |
| 模板与蓝图 | 半成品框架、可解锁的蓝图、结构投影；只给起点与骨架，不给成品 | 手生但想造大的玩家；兼做官方风格引导 |
| 委托与目标 | NPC 或系统下具体委托：造一间房、修一座桥、点亮一片区域 | 把「自由」变成「轮到你了」，新手创造力的启动器 |
| 成就与挑战 | 成就逐条引出机制：第一次布线、第一次让装置动起来、第一次上传作品 | 把「把所有机制都试一遍」做成可见进度 |
| 社区展示 | 主界面作品入口、每周精选、主题建造活动 | 让回流有理由，让创作者有目标 |

两条纪律。其一，引导用反馈而不是答案：蓝图只画骨架，完成度留给玩家；自动建造只用于教学演示，不放进正式工具。其二，第一个 30 分钟必须让玩家造出「自己的、能用的东西」，一块菜地、一座小桥都行；一个晚上都在临摹官方作品的新手，第二天不会回来。

### 3.4 分享机制：作品要能出门

建造类游戏的寿命与作品的流通量成正比：一件被看见的作品带来下一件作品，一次被试玩带来一次回流。分享设计先选单元，再选通道：

| 分享单元 | 例子 | 传播力与代价 |
| --- | --- | --- |
| 单件作品与蓝图 | 分享码、字符串、小文件 | 传播最快、最轻；适合装置、建筑、小关卡 |
| 整个世界 | 存档文件、种子号 | 传播中等；适合大型存档与生存世界，体积是门槛 |
| 关卡与作品库 | 游戏内上传、搜索、试玩、点赞 | 最重也最有效；需要服务器、推荐位与审核（马力欧制造式） |
| 平台工坊 | Steam 创意工坊、mod.io | 复用平台基础设施与用户习惯，适合 PC 与跨平台 |

作品「出门」要过三道关：**导出**（一键生成可传输的格式，带依赖清单与版本号）、**展示**（浏览、搜索、试玩、评分，好作品要能被翻出来）、**回响**（点赞、评论、游玩次数、精选推荐，让作者知道有人玩过）。三关缺一，创作热情会在几周内熄火。

社区运营的三条底线：精选与推荐要有节奏（每周主题、官方转发、创作者榜单）；二创要允许并署来源（拆改他人的作品是这类社区最健康的循环）；审核与举报要公开（下架标准与申诉通道，合规成本按平台规模预留）。支持层级、创意工坊的版本控制、mod.io 跨平台方案与社区法律条款，已在《Mod 与 UGC 手册》完整展开；游戏内造物比代码级 mod 轻，但审核、推荐位与版本兼容的成本一样存在。

### 3.5 规模管理：把性能做成设计参数

玩家一定会造大的，这是这个类型的基本人性。性能上限不能留到上线前才面对，要在设计期就做成参数与语言：

| 设计决策 | 做法 | 给玩家的说法 |
| --- | --- | --- |
| 区域预算 | 每区块或每区域的实体与逻辑元件有配额，超了显示「负载」 | 不是禁令，是「这里的机器太多了」 |
| 软降级 | 远处装置降频、细节剔除、动画简化 | 世界在远处会「做梦」，走近才醒 |
| 玩法引导 | 官方模板演示「用信号取代实体」的省性能写法 | 把优化做成高级技巧，老手以此炫技 |
| 硬上限 | 只在防崩溃处保留（总实体数、单格堆叠） | 上限写进商店页与教程，避免事后争吵 |

节奏设计上，紧（限时挑战、委托截止）与松（无目标沙盒）要分层给：生存与挑战模式的压力负责拉人回来，创造模式的无压力负责让人留下。只有紧，休闲创作者流失；只有松，回访没有理由。多人空间同样要提前定：访客权限（只看、可玩、可改）、合作建造的冲突处理，以及「别人的作品不要弄崩我的帧数」的隔离；工程路径见《联机与后端深入手册》。

## 4. 技术要点

工程命题一句话：**玩家的创造力没有上限，性能预算有；系统设计的全部工作是把这两件事焊在一起**。难点不在玩法代码，在世界表示、模拟调度与用户内容的生命周期管理。

**世界表示与渲染**

- 三条路线：体素（我的世界式，方块网格）、拼装件（预制件按吸附点组合）、自由物理（盖瑞模组式，任意刚体与约束）。体素适合大体量地形与广袤世界，拼装件适合建筑精度，自由物理适合装置与载具；选型决定渲染、碰撞、存档三条管线，中途换路线等于重写。
- 体素路线要写区块管理与网格合并：按区块生成合并网格，做可见面剔除与渲染距离分级；任何「每个方块一个物体」的写法都会在第一个大建筑上崩掉。
- 光照是体素类的隐形大头：光照传播用队列式扩散，昼夜与光源更新分帧结算，别在放置的同一帧全量重算。
- 社区作品就是测试用例：把作品库里最复杂的十件作品固化成回归测试，每次改动后跑一遍加载与帧率。这比任何合成基准都真实。

**模拟与调度**

- 固定 tick 驱动逻辑（常见 10-30Hz），渲染插值显示；同 tick 内的事件顺序要有确定性，装置才能可复现。
- tick 预算按区域分配：每区块一个预算桶，超预算的装置降频或休眠（静止的机械不算、装满的箱子不查），把「造得越多越慢」变成「造得越多，远处越省」。
- 实体是另一个黑洞：掉落物合并堆叠与自动清理、NPC 与生物按距离降级模拟（模拟 LOD 的做法见《技术实现手册》）、传送带与流水线这类高频件限速。
- 危险的组合要提前设防：大范围流体扩散、连锁爆炸、全场光照重算、递归电路，都是社区一定会造出来的东西；给每个系统定一个「最坏情况预算」，写成自动化测试。

**用户内容生命周期**

- 存档与导出：世界用增量存储加脏块标记；导出单件作品用「局部坐标 + 依赖清单 + 格式版本号」，导入时校验尺寸与引用合法性。格式从第一天带版本号与迁移函数，游戏更新后老作品必须能打开。
- 导入安全：玩家的作品文件按外来数据处理，限制尺寸、校验引用、拒绝未知指令；游戏内造物不执行代码，与代码级 mod保持隔离。
- 联机建造：服务端权威，操作按事件广播（放置、拆除、变换），冲突用房间或区块划分规避，删除与回滚随时可撤销；中途加入先发区块快照，完整路径见《联机与后端深入手册》。
- 工具链：撤销栈与蓝图系统是玩家侧的刚需，性能检查器（让作者看见每件作品的负载成本）是社区侧的护栏；两者都要在第一版工具里出现，事后补等于重做工具。

## 5. 内容量与工作量参考

这个类型横跨极宽的区间：三周能做出可玩的工具原型，而平台级产品是十年工程。以下为常见量级，用于估范围，不构成承诺：

| 项目形态 | 规模 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 工具原型 | 一张平地、放置/拆除/存取 | 3-6 周 | 零美术，只验证工具手感与「想造」的冲动 |
| 小体量完整作品 | 一个世界、一套件、本地分享 | 6-18 个月 | 单人或 2-3 人，美术走低成本风格 |
| 常见商业体量 | 多主题、联机、UGC 平台 | 2-4 年 | 性能打磨与社区功能吞掉可观比例 |
| 平台型产品 | 编辑器加作品库加运营 | 3 年以上加长期运营 | 社区运营本身就是产品的一半（马力欧制造、罗布乐思向） |

内容单元的量级：

| 内容单元 | 最小可发售 | 舒适量 | 备注 |
| --- | --- | --- | --- |
| 方块与建筑件 | 30-60 种 | 150-400 种 | 每件都要在全部已有件的组合环境里过一遍 |
| 机制基元（物理/电路/传感） | 3-5 个 | 8-15 个 | 每个基元配教程位、模板装置与成就条目 |
| 预制模板与官方示范 | 5-10 件 | 30-60 件 | 兼做引导、风格锚点与性能示范 |
| 成就与挑战 | 20-40 条 | 80-150 条 | 每条都是一次「去试试这个机制」的邀请 |
| 环境主题与群系 | 3-5 个 | 8-15 个 | 决定视觉量与素材组合的成本 |
| 引导委托（若有剧情线） | 一条主线 | 主线加支线 | 委托是最便宜的创造力教学内容 |

工作量粗账（按做到 1.0 发行为例）：工具与系统约占 35%，内容生产约占 35%，性能与优化约占 15%，分享平台与社区约占 15%。与传统作品相反，这个类型的工具会反复重做：第一版工具撑起原型，第二版撑起社区，工具迭代次数往往超过内容迭代。范围失控时的砍法排序：先砍环境主题，再砍件数；基元深度与工具质量放在末位，它们是这个类型的命。范围控制的方法见《独立开发生存手册》。

## 6. 第一个原型怎么起步

目标：三到六周做出一个「能造、能存、能给别人看」的最小工具环，占位美术，一个主题。

| 里程碑 | 做什么 | 验收（看行为） | 参考工期 |
| --- | --- | --- | --- |
| M1 放置循环 | 网格、放置/拆除/取色、相机、预览 | 测试者 10 分钟内围出一间房 | 1 周 |
| M2 存与撤 | 存档读档、撤销栈、蓝图复制 | 关掉重开，昨天的建造还在 | 1 周 |
| M3 一组基元 | 2-3 个可组合机制（如开关加门、重力加流体） | 测试者自发做出「有功能」的装置 | 1-2 周 |
| M4 一个玩具 | 用基元封装一个微型玩法（机关、小游戏） | 玩家玩自己造的装置超过 5 分钟 | 1-2 周 |
| M5 分享循环 | 导出与导入分享码，最简作品展示位 | 把作品发给朋友，对方成功打开 | 1 周 |
| M6 陌生人测试 | 拉 3-5 个没看过项目的人 | 有人连续建造 30 分钟且主动回来 | 持续 |

起步的三条规矩：美术一律灰盒与色块，想美化的人先去玩 M1；每次只加一个新基元，加完先把它与全部旧基元的组合过一遍；自己每玩 30 分钟记录一次「想拆哪、想改哪」，那份清单就是你下一个工具需求。

成功标准（全部可观察；达到即冻结工具与手感，开始铺内容）：

- 无美术、无教程文本的情况下，测试者 15 分钟内完成第一个自选结构，并主动开始扩建。
- 30 分钟的观察里每人至少出现 3 次「拆改自己的建造」的行为，说明玩家开始把作品当作品。
- 至少有一名测试者问出「这个能分享吗」或试图录屏、截图。
- 工具不跟手的抱怨（放置失败、误拆、找不到撤销）每人不超过 1 次。

工具环不过关，不要开始铺方块样式与环境主题：那是最贵的一笔返工，玩家的第一印象会死在这里。

## 7. 常见坑

1. **工具不跟手**：放置要瞄准半天、误操作不能撤销、拆除不返还。工具手感是这类游戏的「跳跃手感」，其他所有设计都建立在它上面。
2. **空白恐惧没处理**：进场一片空地，没有委托、没有模板、没有灵感入口，留存死在第一小时。
3. **基元太多或太少**：太少，组合两下就穷尽；太多，互相冲突、教程教不完。每个基元都要能回答「它能和谁组合」，答不出就不做。
4. **物理不可预测**：同样的装置时灵时不灵，玩家退回最保守的造法，深度直接归零。
5. **引导给答案**：成品图纸、自动建造放进正式工具，建造乐趣被官方收走。
6. **分享是死路**：没有导出、没有浏览、没有推荐位，作品出不了门，创作者停止创作，平台梦变成单机梦。
7. **性能被玩家打爆**：不把社区作品当回归测试，上线后大建筑卡顿成为差评主旋律。
8. **性能上限事后面对**：到开发末期才发现必须硬封上限，玩家感知为「限制自由」，信任受损。
9. **版本更新拆作品**：改 ID、改规则让老作品坏掉或行为变化，创作者社群出走一次就很难回来。
10. **联机共建没设计**：两人同改一格、访客拆掉房主的世界、复制漏洞，多人从卖点变事故。
11. **审核缺位**：UGC 会长出违规内容；推荐位与举报通道缺位，等于把风险留给平台与发行商。
12. **范围失控**：件数、群系、联机、平台四线并发。先砍出一条「一件作品的完整旅程」：造、存、晒，一步都不能少。

## 延伸阅读

- 《游戏设计手册》：核心循环分层与系统互锁，是本文「四层节奏」与「基元组合」两节的通用底稿。
- 《技术实现手册》：渲染预算、模拟 LOD 与世界管理，对应本文第 4 节的全部工程细节。
- 《Mod 与 UGC 手册》：支持层级、创意工坊与 mod.io、社区运营与合规，本文 §3.4 的完整展开。
- 《独立开发生存手册》：范围控制与排期；这个类型是范围失控的头号重灾区。
- 《联机与后端深入手册》：多人共建与 UGC 分发的工程路径。
- 练习作业：选一个你最熟的建造游戏，列出它全部基元（不超过 20 个），画出两两组合的用途矩阵，找出官方还没做的三格；再写一份工具清单，从「放置」到「撤销」逐项定义操作步数。
