# Ludo Atlas · 类型手册 · 问答测验（Trivia / Quiz）

> **类型手册 P2 批次**（第 ㊳ 轮扩展）。定位：把「我知道」做成第一乐趣的类型。知识是弹药，题目是舞台；玩家为答对那一刻的确认感而来，为「就差一点」留下不走。
> 配套：《游戏设计手册》（⑨，核心循环与难度曲线）·《技术实现手册》（⑩，题库管线与抽题服务）·《运营与增长手册》（⑬，时效内容与长期维护）·《案例研究集》（⑳，节目形态与产品拆解）。
> 本文不放外链；标杆只用大众熟知的节目与聚会玩法形态，数字为常见量级，落到项目里以实测为准。

## 1. 定位与核心循环

一句话定位：问答测验是**以「知识被验证」为第一乐趣**的类型。玩家在「我好像知道」和「我真的答对了」之间获得确认；题目是知识的最小可玩单位，题库是内容本体，规则、计分与演出都只是题库的外壳。

核心循环用动词环写：

`读题 → 检索记忆（或推理）→ 作答或抢答 → 判定 → 得分与反馈 → 下一题`

这个环以秒计：快节奏抢答单题十秒上下，慢速思考型单题三十秒以上。它成立的前提只有两条：题目公平（答案唯一、可验证，§3.1）；答错也有收获（学到一条新知识或笑一下，§2）。三个尺度的循环：

| 尺度 | 循环 | 玩家得到什么 |
| --- | --- | --- |
| 一道题（5 到 30 秒） | 读题 → 作答 → 判定 | 一次即时的知识验证 |
| 一局（10 到 30 分钟） | 数十道题加计分或淘汰 | 一场知识竞技，或一段一起聊的时间 |
| 一个赛季（数周至数月） | 新题上场、旧题轮换、分段位推进 | 持续的「又来了一批新题」 |

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 解谜 | 解谜的答案靠推理从规则里导出；问答的答案靠检索从记忆里取出，考点是知不知道 |
| 派对游戏 | 问答常借用派对形态（同屏、手机房、主持人）；差别在题库是本体还是道具，答题笑点只是派对的一层壳 |
| 社交推理 | 社交推理的答案在玩家之间流动，没有保底真相；问答的答案躺在题库里，对错由系统裁决 |
| 文字冒险 | 文字冒险的输入推进叙事；问答的输入只兑换分数与反馈，不改变世界 |

一个自检问题：把题目全部换成随机算术题，游戏还成立吗？答案若为「不成立」，你做的才是问答测验；如果换成算术仍然成立，你做的是算术练习，知识只是皮肤。

团队口径：内容型玩法，工程门槛低，成本几乎全在题库与审核上；稀缺能力是能持续产出好题、并且愿意做事实核查与时效维护的人。一句话结论：问答测验卖的不是规则，是题库的密度与新鲜度。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **知道的那一刻**：答对是被验证的快乐。验收的观察点是玩家答对后说的是「我确实知道」而不是「我蒙的」。
2. **公平**：题目可解、答案唯一、无争议；失手只怪自己没想起来，不怪题目过期或偏门。
3. **人人有题答**：难度分梯度，常识题给所有人底气，硬题给知道的人高光；一整局有一两道全场沉默题是彩蛋，连出三道就是事故。
4. **答错也有收获**：揭晓时补一条新知识或一个笑点，错误反馈本身就是内容。
5. **再来一局**：分数接近、新题上场、随时能开下一轮；局与局的门槛要低到不需要下决心。

反面感受（出现任意一条都是红灯）：被羞辱（题目全场没人会，输得没有参与感）；被坑（答案有争议、规则没讲清）；干等（别人答题自己闲着）；被套（重复题、连续同考点的题）。

标杆作品（均为大众熟知的节目与聚会玩法形态，建议完整经历几局再拆）：

| 作品或形态 | 可学的点 |
| --- | --- |
| 电视问答节目形态 | 每题都是一场小戏：锁题、求助、淘汰与揭晓的顺序，就是现成的情绪曲线 |
| 奖励阶梯闯关节目形态 | 阶梯即难度曲线；一次不确定让玩家自己选择继续还是收手，风险自己背 |
| 你演我猜类聚会问答 | 把答案从「说出」改成「表演或描述」，表达限制本身是玩法与笑点 |
| 常识问答棋盘桌游 | 题目挂在进度上：答题是通路，抢位、卡位与反超才是叙事 |
| 好友房手机抢答 | 房间码加短局，把问答做成随时能开、随手能拉人进来的社交内容 |

## 3. 设计要点

### 3.1 题库工程：分类、难度与时效题

题库是本体，先立结构再谈数量。每题一条记录，字段在开工第一周就冻结：

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| 题干 | 一句话提问，不含歧义表述 | 玩家看到的全部 |
| 正解与别名 | 唯一答案加可接受的写法 | 判定宽容度（简称、错拼、口答转写） |
| 干扰项 | 两到三个可信的错误选项 | 多选形式的地基，质量决定难度 |
| 分类标签 | 两到三级领域树，一题可挂多标签 | 抽题权重与内容体检 |
| 难度 | 初始估定加正确率校准 | 整局难度曲线 |
| 来源依据 | 出题时写下的可查证依据 | 复核与争议仲裁 |
| 时效 | 常青或时效，时效题标明过期点 | 到期自动下架或改写 |

- 分类是抽题的索引，也是内容体检的听诊器：八成题目集中在同一个领域的库，抽出来的卷子必然难看，上架前先过一遍分类占比。
- 难度不由作者拍板，用数据校准：正确率、作答时长、弃答率三件套。正确率落在三成到七成之间的题才算有区分度；九成以上的题用来暖场；两成以下的题只配当彩蛋，先检查题目本身有没有问题。
- 难度曲线按一局排：开场两道必须全场会，中段高低交替，终盘放最难的题和「答错不伤分」的彩蛋题。
- 时效题单列并打标签：年份、冠军、新片、新版本类题目标明过期点，到期自动下架或改写成常青版本。常青与时效的配比常见 8:2；全常青的库会发旧，全时效的库维护不起。
- 答案可验证是入库门槛：出题时就写来源依据，写不出依据的题不进库。这条对 AI 出的题同样有效（§3.6）。

### 3.2 抽题：公平性与重复控制

抽题器的目标不是「随机」，是「看起来公平、实际也公平」。三条原则：均匀（分类与难度按权重出现）、无近重复（同一考点一局只考一次）、可审计（一局抽了哪些题、为什么抽到，能回放）。

- 权重轮询起步：每个分类一个权重，按权重轮转抽题，连续两道同分类就强制换池。简单规则好维护，也向玩家解释得清。
- 重复控制三档：玩家个人近况表按「未见过优先、久未再见、任意」降级；同一局内取全体玩家的已见并集，保证桌面上没有人刚答过原题。
- 难度配额：整局按难度曲线配额抽题，不做纯随机；排位、闯关等强对抗模式先枚举配额再填充。
- 题池见底策略提前定：重复率放宽容、提示维护者补题、还是切限定模式。不提前定好，玩家会先你一步说「又是这题」。
- 自检方法：随机抽一天的对局日志回放，检查重复考点、分类失衡、以及全场零正确率的题。

### 3.3 作答交互：形式与判定宽容度

主流作答形式各有脾气：

| 形式 | 玩家动作 | 优点 | 风险 |
| --- | --- | --- | --- |
| 单选 | 四选一 | 最便宜、宽容度高、蒙对率可控 | 干扰项质量差就退化为送分 |
| 抢答 | 抢先拍下再作答 | 紧张感与观赏性最强 | 只评手速的判定会惩罚慢网络与谨慎的人 |
| 口答或拼写 | 说出或输入答案 | 防蒙，知识感最强 | 判定不接受别名与错拼就憋屈 |
| 排序或连线 | 把元素排成序 | 一题考多层知识，观赏性强 | 操作成本高，触屏、手柄、鼠标要分开调 |
| 下注 | 先押分再作答 | 把「知道」变成风险管理 | 分数波动大，要防梭哈式失衡 |

判定纪律：休闲与聚会场合只评「答没答对」，不评「手速」（判定窗口的工程口径见 §4）；答案接受别名、简称与常见错拼，判定表不写死在脚本里；错误反馈先揭晓正确答案加一句来源补注，再走扣分动画，先喂养再惩罚。

### 3.4 多人对抗与直播式综艺形态

问答的多人形态有三种常见骨架：

| 骨架 | 结构 | 适合场景 | 主要风险 |
| --- | --- | --- | --- |
| 同屏或好友房对战 | 同一题面，抢答或轮流，即时计分 | 客厅与线上好友局 | 抢答判定不公；慢的人全程陪跑 |
| 阶梯闯关 | 单人或组队，难度与奖励逐级上升，允许保底退出 | 单人长局与直播 | 一次失误清空进度会劝退 |
| 大房间直播式 | 同一题面同步到全员，统一倒计时，公共榜 | 直播与综艺活动 | 搜题作弊；掉线体验差 |

- 直播式综艺的四件套：题面同步、倒计时可视化、评论或弹幕互动、结算的公共榜与存活曲线。每一件都在放大「我也在场上」的感觉。
- 等待窗口是多人问答最大的浪费：轮流答题时其他人干等原题。给等待者第二任务（下注、预测、助威加分），或把结构改成全员同题同答。
- 主持人可以由程序兼任：读题、停顿、揭晓、锁题、求助、淘汰，把节目动作做成系统事件；演出预算有限时，音效与停顿的收益高于动画。
- 与《类型手册 · 派对游戏》同一套纪律：低门槛、笑点优先、单人等待不超过三十秒；同屏与手机房的设备账（控制器、房间码、热插拔）直接照那一页的做法。
- 作弊与搜题：线下局靠彼此监督；线上靠限时（来不及搜）、题库轮换与异常作答模式上报，压低搜题收益。

### 3.5 内容成本与审核：现实压力

- 写题的真实速度：一题从选题、考证、撰写、配干扰项到复核，常见十到三十分钟；成本的大头是考证，不是打字。数据题与人名归属题最费时。
- 审核是双闸：事实核对（数字、年份、拼写、别称、归属）与合规核对（时政与宗教、地域与族群、在世人物与隐私、商标与品牌）。两闸都过才能入库，任一闸存疑就搁置或弃题。
- 现实世界的压力全落在题目上：疾病、灾难、逝者、争议事件做成题目会持续被重新解释，旧题会随时间从「快乐一问」变成事故。纪律：不蹭灾难时效，涉人题目定期巡检。
- 题库是月费不是买断：维护、下架、改写、补题是长期账单。一局二十题的重复率、玩家每周平均见题数，共同决定补题节奏，运营化的节奏安排见《运营与增长手册》（⑬）。
- 排期换算：常见每工作日出题十五到三十道（含复盘与改题），加上审核人力的三到五成，一千题的干净题库常见一到三个月单人投入，时效题另算每周固定产线。
- 退役纪律：争议题、过期题、重复题直接退役，救一道坏题的代价高于写一道新题。

### 3.6 AI 出题的边界

- 位置：AI 适合做初稿与流水线杂活，包括题目草稿、干扰项、分类打标、近重复检测、多语言转写；不适合做最终事实的裁决者。
- 三个常见错误：知识过时（答案在产出之后变了）、幻觉编造（答案、数字、归属凭空生成）、口径漂移（同一事实两个答案）。数字、年份、人名、归属每一条都要回源，不能凭「看起来对」入库。
- 流程：AI 出草稿，人工事实核对，第二人复核或按比例抽检，标注来源后入库；AI 草稿统一打标签，日后按批次复查。
- 红线：未经核验的 AI 题不上线；上线后发现争议先下架再议；对外披露与台账口径按《AI 工作流手册》（⑲）的合规框架执行。
- 判断标准回到那张判断表：产出好不好验证、出错代价高不高。知识题验证成本低、出错代价高（信誉），配置就是「多用草稿、必做核对、留好记录」。

## 4. 技术要点

工程难点集中在两块：题库管线与多人同步。问答没有实时手感要求，网页、移动、PC 都能承载；以下与引擎无关。

**题目即数据**

- 题目记录结构第一天冻结（字段见 §3.1），用表格或 JSON 管理，内容改题不动代码。
- 题库文件进版本控制：改题留痕、可回滚；批量改动用脚本，手工改一千道题做不长。
- 有多语言计划就按字符串表组织，题干、选项、反馈文案全部分离，术语表先立。

**题库管线与质量工具**

- 导入校验器是第一个要写的工具：字段完整、答案唯一、分类合法、干扰项不重复、时效到期提醒。
- 近重复检测：题干相似度加考点指纹（同一事实的不同表述），防一库两题。
- 争议题队列：正确率畸低、投诉多、选项切换率高的题自动进队列，人工裁决。

**抽题服务**

- 权重、排除表、难度配额、审计日志四项能力（§3.2）；对局日志可回放，用来验证公平性。
- 验证用例写死：同一玩家连开十局无重复；分类占比达标；题池见底有降级策略。

**多人同步与判定**

- 抢答判定放服务器：时间戳统一、延迟补偿、判定窗口一致，客户端只负责显示；高延迟玩家给补偿窗或不参与抢答的模式。
- 回合同步三事件即可：题面广播、答案提交、统一步进；断线重连把当前题与分数一次性下发。
- 直播大房间：题量有限、并发大，答案提交做批量写入，排行榜做近似即可。

**埋点与验证**

- 每题记录正确率、作答时长分布、弃答率、选项分布；样本过千后按数据重新标定难度（§3.1）。
- 玩家侧记录强弱项与已见题标记，复用抽题排除表，不再单独维护。
- 工程攻坚顺序清楚：题库管线与工具优先，多人同步按模式需要再上；两端都没有手感类风险。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 形态 | 题库量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 原型 | 50 到 100 题 | 1 到 2 周 | 只验证循环与判定，题库手写 |
| 小型完整作品 | 500 到 1500 题 | 1 到 3 个月 | 单人开发常见起点，含一次全库复查 |
| 运营型产品 | 数千题加时效题产线 | 持续投入 | 题库量决定留存，维护是月费 |

换算口径与暗线：

- 出题速度按每工作日十五到三十道（含复核）估算，一题十到三十分钟；审核与复查按出题人力的三到五成另计。
- 时效题产线：每周或每赛季固定补题窗口，常见一到两成的库属于时效题，到期改写或退役。
- 美术与演出是小头：题面、选项、反馈动画、结算界面与一段主题音乐，一套模板撑全库；成本永远在题库。
- 范围纪律：砍题永远比救题便宜；题库验收看「随机抽二十题，有几道值得截图发群」，不看总数。

## 6. 第一个原型怎么起步

目标：一到两周，回答一个问题：这个循环烦不烦。不碰美术、账号、赛季。

1. **第 1 到 3 天：五十道题加最小抽题器。** 手写题库，先不管分类平衡；乱序抽题、排除已答，单选判定加对错反馈。丑是应该的。
2. **第 4 到 7 天：计分与揭晓。** 连击、难度权重、揭晓动画与音效；一局十到二十题，打完出一张结算。
3. **第 8 到 14 天：盲测两轮。** 找五个人各答一局，记录答对率分布、争议题、全场沉默的题、以及有没有人主动开第二局。第二轮修掉争议题与难度断点。

成功标准（全部可观察）：

- 五名测试者里至少三人主动开第二局。
- 全场零正确率的题不超过两道，且都能归因（太偏、题干歧义、答案有争议），而不是「他们太菜」。
- 没有任何一题被判为「答案是错的」；争议题的裁决记录在案。
- 测试者能用「我知道」解释自己的得分，蒙对蒙错心里有数。

预算允许的话，把第二周的一半用来做一个两人同屏抢答版本：同一台设备、同一个键盘，验证对抗是否比单人更紧张。对抗成立，再谈多人形态与题库铺量。

## 7. 常见坑

1. **题库太小**：几百道题被玩家刷穿，第二天全是旧题。题池见底前先做重复控制与补题计划（§3.2、§5）。
2. **难度靠刁难**：冷门到没人会、答案靠死记。冷知识是彩蛋配额，不是难度主轴。
3. **答案有争议**：多解、过期、别称不认。一题一答案加来源，判定表接受别名（§3.3）。
4. **近重复失控**：一局内同考点重复出现，或换皮重出。考点指纹加排除表（§3.2）。
5. **抢答只评手速**：延迟吃亏、谨慎的人被惩罚。休闲局只评对错，判定窗要宽容（§3.3、§4）。
6. **时效题不维护**：年份题、冠军题过期后挂在库里，玩家替你发现错误。
7. **AI 题直接上线**：幻觉答案没有复核就进库，信誉一次赔光（§3.6）。
8. **干等窗口**：轮流答题时其他人长时间无事可做。改成同题同答，或给等待者第二任务（§3.4）。
9. **题目以外全缺**：只有题库，没有节奏、演出与结算。问答的节目感有一半在题目之外。
10. **受众假设单一**：只按自己的知识结构出题，题目对目标人群全是死角（代际、地域、行业）。出完题先找目标人群之外的人答一遍。
