# Ludo Atlas · 类型手册 · JRPG（日式角色扮演）

> **类型手册 P1 批次**（第 ㉝ 轮扩展）。定位：以剧情为牵引、以指令化战斗为骨架的队伍 RPG，胜负由资源、克制与行动顺序的决策决定，内容量是这个类型的最大成本。
> 配套：《游戏设计手册》（⑨，战斗与成长系统）·《技术实现手册》（⑩，数据管线与存档）·《关卡设计手册》（㉑，城镇与迷宫空间）·《案例研究集》（⑳，拆解与复盘方法）。

---

## 1. 定位与核心循环

一句话定位：JRPG 是**叙事驱动的队伍 RPG**。战斗以指令结算（回合制或半即时）完成，玩家的成败主要由资源管理、属性克制与行动顺序一类决策决定，而不是操作精度。划边界的方法很直接：把实时操作全部撤掉，战斗仍然成立，而且败因能在菜单里复盘，那就是 JRPG。

核心循环用动词环写：`推进地图 → 触发战斗 → 指令博弈 → 结算奖励 → 成长补强 → 解锁新区域与新剧情`

循环分四层看：

| 层级 | 循环 | 黏性来源 |
| --- | --- | --- |
| 秒级 | 下达指令 → 结算反馈 | 伤害数字、打击音效、动作演出 |
| 战斗级 | 遭遇 → 决策 → 胜负结算 | 以弱胜强的复盘感、资源消耗的紧张感 |
| 章节级 | 城镇补给 → 迷宫探索 → 剧情节点 | 「想知道后面发生什么」的牵引 |
| 周目级 | 通关 → 收集与隐藏内容 | 二周目、图鉴、隐藏 Boss |

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 动作 RPG（ARPG） | 战斗靠实时操作与打击感；JRPG 的胜负在菜单里决定 |
| 战棋（SRPG） | 战棋把战斗摊到网格与站位上；JRPG 的空间层在城镇与迷宫上 |
| 怪物收集类 | 收集与培养是主轴；JRPG 用固定队伍与剧情驱动 |
| 视觉小说 | 推进靠阅读与选择；JRPG 的叙事必须穿过战斗与探索才能推进 |
| 欧美 RPG（CRPG） | 角色构筑自由度与分支结局更重；JRPG 更接近单主线加可选支线 |

一个自检问题：把战斗动画全部关掉、只留文字结算，战斗还好玩吗？答案若为「是」，说明你的决策层立住了；答案若为「不」，你做的其实不是战斗，是演出。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **成长可见**：升级、新技能、新装备的收益能被玩家立刻感知，数字与能力同步变强。
2. **策略取胜**：赢是因为想对了（克制、顺序、资源），输也能复盘；挫败感的出口是「下一把换个打法」。
3. **叙事牵引**：每个阶段结尾都留一个「想知道下文」的理由。
4. **队伍养成与探索回报**：角色有个性与专属能力；宝箱、支线、隐藏 Boss 给愿意绕路的玩家真实奖励。

标杆作品（大众熟知名单，建议亲手玩过再拆）：

| 作品 | 可学的点 |
| --- | --- |
| 勇者斗恶龙系列 | 指令极简、节奏王道、让任何玩家都看得懂下一步 |
| 最终幻想系列 | 战斗系统的迭代史：时间条、职业、成长盘与演出升级的边界 |
| 宝可梦系列 | 收集与养成驱动的循环、克制矩阵、零门槛上手 |
| 女神异闻录 5 | 日历与日常节奏、日常与迷宫的双循环、风格化演出的标杆 |
| 歧路旅人 | 现代量级下的像素 JRPG：破防机制与多角色队伍结构 |
| 时空之轮 | 无随机遇敌、多结局与节奏控制的黄金样本 |

玩家对这个类型的默认期待（缺失会直接吃差评）：随时可中断的存档、战斗动画可跳过或倍速、清晰的目标指引、失败惩罚不过重。现代作品普遍把「自动战斗、遇敌开关、快速传送」做进标配，原型期就该留好位置。

## 3. 设计要点

### 3.1 战斗系统：行动顺序、资源与决策空间

战斗是 JRPG 的骨架，先定三件事：行动顺序怎么排、资源是什么、每回合有几条值得走的路。

行动顺序的四种主流模型：

| 模型 | 做法 | 代表 | 代价 |
| --- | --- | --- | --- |
| 固定回合制 | 每回合按速度重排顺序，全员行动一轮 | 勇者斗恶龙、宝可梦 | 无时间压力，张力全押在资源与克制 |
| 时间条（ATB） | 按填充速度决定行动时机，选指令可暂停 | 最终幻想系列 | UI 与暂停规则复杂，新手易慌 |
| 可预测顺序制 | 行动顺序完全展示，技能可推迟或提前行动 | 现代回合制常见做法 | 需要顺序干预类技能支撑 |
| 半即时混合 | 回合骨架加即时要素（追加行动、连携） | 女神异闻录系列的追加行动 | 规则解释成本上升，教学压力大 |

顺序设计的三条纪律：

- 速度是隐性强势属性（先手、行动次数、治疗时机）：要么压缩速度区间并设上限，要么把「抢速度」做成技能效果，而不是纯属性堆料。
- 同速处理规则必须确定性且可见：固定优先级或固定随机规则，写死，不摇摆。
- 行动顺序要可视化，让玩家能算出「再挨一下，治疗来不来得及」；再留一组延迟与加速技能当节奏阀门，让顺序本身成为玩法。

资源模型：资源是战斗的货币，主流结构是 HP 加一个资源池（MP、SP 一类）再加消耗品。

- 变体做法：技能充能（每 N 回合可用）、代价型资源（消耗 HP 或物品）、回合资源（限时、限回合数）。
- 设计三问：这场战斗里最稀缺的是什么？哪些技能值得为此付费？资源见底后还有什么选择？验收标准只有一条：资源要制造「大招用不用」的两难，答案永远是用、或永远是不用，都算没设计。

属性克制与时长预算：

- 元素数量克制在 4-8 个；倍率常见区间为克制 1.5-2 倍、被克 0.5 倍、免疫 0 倍（宝可梦式为 2 倍与 0.5 倍两档）；克制必须可见，不做只有攻略网站才知道的隐藏倍率。
- 时长参考：普通战 3-5 回合（约 30-90 秒），精英战 5-8 回合，Boss 战 10-20 回合、分 2-3 个阶段。演出服从这个预算，超过一半时间在看动画的战斗，玩家会开始躲。

### 3.2 队伍与成长：职业、技能树与曲线

- 出战规模常见 3-4 人；替补吃部分经验（常见五成上下），防止板凳成员永远进不了队。
- 职业系统三条路线，看清代价再选：

| 路线 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| 固定职责 | 角色专属技能与人设绑定 | 角色辨识度高，机制与叙事一体 | 编队自由度低 |
| 可换职业 | 全员职业池，自由转职（最终幻想、勇者斗恶龙的系列传统） | 构筑自由度与重复可玩性 | 角色同质化，平衡面数倍扩大 |
| 混合式 | 角色专属基底加可学的副职业 | 兼顾人设与构筑（歧路旅人式） | 解锁与教学流程更复杂 |

- 技能树粒度：每角色 15-30 个技能（含被动），同屏可用控制在 4-8 个（受指令栏限制）；按功能分槽：输出（单体与群体）、恢复、增益减益、控制、被动。
- 升级奖励要轮换出质变节点：新技能、新指令、合击解锁。连续多级只有数值成长的曲线，玩家会中途失去期待。
- 等级上限常见 50-99，每张地图留 2-4 级的成长空间，把「期望等级 = 地图序号 × 系数」写死进表；自由加点慎做，玩家会点出坏档 build，要么低成本洗点，要么用固定成长加技能树替代。
- 攻击与 HP 同速增长，战斗回合数才能稳定：只堆攻击会变成互相秒杀，只堆 HP 会变成拖时间。
- 装备从简：武器、防具、饰品三槽就够。装备的职责是奖励节奏（宝箱、商店、Boss 掉落）与少量定位功能，不是数值堆料场。

### 3.3 世界结构与叙事节奏：城镇、迷宫、剧情节点

结构单元固定成公式：`城镇 → 野外遭遇 → 迷宫 → Boss → 剧情节点 → 新区域`。每个单元各司其职：

| 单元 | 功能 | 设计要点 |
| --- | --- | --- |
| 城镇 | 补给、情报、商店、剧情推进 | 每个城镇至少给一条新情报；回访时对话要更新 |
| 野外 | 遭遇、资源、小事件 | 给绕行路线，不是每格都逼你打 |
| 迷宫 | 探索、宝箱、解谜、Boss | 首次通过控制在 15-40 分钟，10-15 分钟一个存档点；价值在密度不在面积，空间设计按《关卡设计手册》（㉑）做 |
| 剧情节点 | 推动主线与角色弧线 | 每区域 1-2 个；节点结束立刻给「下一步去哪」 |

节奏目标（可按项目调，但四项都要盯）：

- 目标永远清晰：任何时刻玩家都能说出「下一步去哪、为什么」。
- 三线交替：探索（含 2-4 场战斗）、事件或新技能、迷宫、剧情节点轮转，避免长时间单一活动。
- 钩子节奏：每个区域结尾留悬念，主线节点之间不空窗超过一两小时；前 30 分钟里就要有一次战斗胜利与一个钩子，不用大段文字讲世界观。
- 支线是节奏缓冲：放在主线低谷，奖励指向成长与伙伴剧情，不做纯填充。

### 3.4 文本与演出量级：最大成本的正面账

- 估算口径：玩家净阅读时间按总流程的两到三成算，阅读速度按每分钟 200-300 字，得出每小时约 2500-5500 字的主线文本；再乘 1.5-2.5 倍，得到含支线、菜单、图鉴的总文本量。
- 按这个口径外推：

| 流程时长 | 主线剧情文本（口径估算） | 总量级（含支线与菜单） |
| --- | --- | --- |
| 1 小时 | 3000-6000 字 | 1 万字上下 |
| 5 小时 | 1.5-3 万字 | 3-6 万字 |
| 10 小时 | 3-5 万字 | 6-12 万字 |
| 20 小时 | 6-11 万字 | 15-25 万字 |
| 30 小时以上 | 10-16 万字 | 25 万字以上 |

- 演出分级配给：S 级（全动画过场或大 CG）、A 级（镜头运动加角色演出）、B 级（对话框加表情变化）。S 级按「全篇个位数」限额，只给主线里程碑；九成信息量交给 B 级承担。没有限额的演出预算必然失控。
- 配音通常是量级最高的一项音频成本，常见折中做法是关键场次配音；BGM 量级参考 20-60 首。技能说明、道具描述、图鉴、教程与 UI 文案都要写作、校对与翻译，漏算这一块是常态。

### 3.5 战斗平衡与数值调参流程

五步流程，顺序不要跳：

1. **纸面推演**：把伤害公式、成长曲线、技能倍率做成一张可计算的表；先用期望值口算「普通战几回合倒下」。
2. **脚本模拟**：把公式搬进表格或 Python，批量跑 1000-10000 场战斗，统计胜率、平均回合数、资源消耗。改一个变量重跑一次，几分钟出一组结论。
3. **游戏内日志**：记录每场战斗的输入、随机数与结算；失败时给复盘面板（谁被什么技能打死的、差多少）。
4. **真人试玩**：观察技能使用率、药水消耗、死亡点与弃坑点；数据与直觉冲突时，以数据为准再找原因。
5. **冻结与回归**：数值冻结后，每次改动走记录并重跑基准战斗集（固定阵容打同样的 5 场），防止修一处崩一片。

验收指标（可观察）：

- 没有「过半场次都在用」的唯一解招式；长期使用率低于 5% 的技能进入修剪或重做清单。
- 普通战平均回合数落在 3-5，Boss 战 10-20 回合；三套阵容（均衡、爆发、防御）都能用模拟脚本打通主线。
- 测试者能说清最近一次失败的败因，且与设计意图一致。

## 4. 技术要点

### 4.1 数据驱动与公式

- 数值全部进表：等级曲线、敌人、技能、装备、掉落；代码里只留公式函数，表用 CSV 或 JSON 管理，导出脚本生成游戏资源，禁止手改生成物。
- 引用完整性进 CI：技能 ID、掉落表、本地化键互相引用，跑校验脚本；表上千行后，拼写错误是最大 bug 来源。战斗公式集中在单独模块并写注释，改动有迹可循。

### 4.2 结算与演出分层

- 把一回合先算成事件列表（谁对谁、做了什么、多少伤害、是否倒下），再按列表播放动画；跳过与倍速只影响播放器，不影响结算。这是战斗系统最重要的架构决定。
- 战斗状态机与地图场景解耦：进入 → 指令收集 → 顺序结算 → 事件播放 → 胜负判定 → 回场；状态清晰，存档与调试工具才挂得上去。
- 随机数用可播种的确定性 RNG：暴击、命中、掉落走同一个种子管理器，bug 战斗可以复现。

### 4.3 存档与调试工具

- 世界状态单表化：剧情进度、宝箱、NPC 状态、支线旗标放同一张表；存档 = 队伍数据 + 世界状态 + 版本号。
- 从第一天就做存档版本迁移：发布后更新是常态，旧档打不开是伤害最大的低级事故。
- 自动存档与中断存档：触发点固定（进城、进迷宫、Boss 前、剧情节点后）；中断存档对掌机与碎片时间的游玩场景是底线。
- 开发面板必备：跳级、加钱加物、强制遇敌与关遇敌、一击必杀、跳战斗、跳剧情、播放任意演出；战斗回放记录种子加输入序列，一键复现问题战斗；菜单与图鉴的响应也按帧检查，确认、翻页、滚动都要即时。

### 4.4 文本与本地化

- 字符串 ID 化，禁止硬编码；人名、地名、招式名先立术语表，再写正文。
- 从第一天按「要翻译」组织：导出翻译表 → 翻译 → 回填 → 术语校验；每加一门语言都要全流程跑一遍，看断行与字体。
- CJK 字体商用授权逐款确认；UI 宽度按最长目标语言预留三成余量。

## 5. 内容量与工作量参考

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 原型（垂直切片） | 1 城镇 + 1 迷宫 + 3 场普通战 + 1 Boss + 开场剧情 | 3-6 周 | 只验证战斗与成长闭环 |
| 小型完成品 | 4-6 个区域、8-12 种敌人、6-10 小时流程 | 8-12 个月（单人） | 一套战斗系统加一条主线 |
| 中型作品 | 10-15 个区域、30-50 种敌人、15-25 小时流程 | 2-3 年（小团队） | 内容量产与打磨各占一半 |
| 大型作品 | 30 个区域以上、100 种敌人以上、30 小时以上流程 | 团队多年 | 系列化才摊得平成本 |

成本构成（四块内容都要单独设预算行）：

| 内容块 | 量级锚点 | 成本特征 |
| --- | --- | --- |
| 战斗内容 | 敌人 30-80 种、技能 100-300 条 | 每种敌人等于数值、技能、动画与出场配置一整套 |
| 文本与叙事 | 见 §3.4 的口径表 | 不可压缩的最大单项 |
| 地图与场景 | 每区域 5-10 个场景区块 | 城镇与迷宫两套美术规格并行 |
| 演出与音频 | S 级演出按分钟计价 | 单位成本最高，限额配给 |
| 界面与系统 | 菜单、图鉴、存档、战斗 UI | 最容易被低估，排期单列 |

以上量级用于估算范围，不构成承诺。排期锚点：战斗原型 2-4 周；到垂直切片 2-4 个月；之后按内容量外推，后段内容按 0.6-0.8 的产出系数打折保守排。范围失控是这个类型最常见的死因，砍区域永远比砍战斗深度安全。

## 6. 第一个原型怎么起步

目标：3-4 周做出「能打、能成长、能存档、有一小段剧情」的最小闭环，不碰美术、支线、世界地图与合成系统。引擎两条路线：RPG Maker（RPG 制作大师）提供完整的战斗与地图框架，起手最快；要深度定制战斗系统就走 Godot 或 Unity，用数据表加自建战斗状态机。

- 第 1 周：战斗循环。3 人队伍对 1 种敌人，4 个技能（单体输出、群攻、治疗、增益），按速度排序的行动顺序，胜利结算经验。
- 第 2 周：成长闭环。升级解锁新技能、存档读档、地图遇敌与战斗切换、一个只有回血点与商店占位的城镇。
- 第 3 周：微缩内容。白盒迷宫（10 分钟走完）加 3 场普通战加 1 个 Boss，配 5 分钟开场剧情。
- 第 4 周：试玩与判断。找 5 个人打完整个流程，记录战斗时长、技能使用、卡点与重试意愿。

成功标准（全部可观察）：

- 零美术零音效的前提下，测试者愿意打完 Boss，并且想继续下一段。
- 普通战平均不超过 3 回合；Boss 战 5-10 分钟，允许失败一到两次。
- 测试者能说清一场失败的败因，与设计意图一致；改一个数值（Boss 攻击上下 10%）能在 10 分钟内量化影响，前提是模拟脚本与日志就位。

决策门：战斗循环没通过试玩，就不要开始量产内容。先换战斗系统，再谈堆内容，顺序反了就是给地基返工付学费。

## 7. 常见坑

1. **战斗系统堆叠过度**：连携、合体技、地形、召唤一口气全做，没有一个打磨到好玩。规避：一个核心系统加一个变奏先立住，其余进待办。
2. **动画不可跳过、没有倍速**：玩家从第 3 小时开始躲战斗。规避：跳过、倍速、自动战斗在原型期就做，成本极低收益极高。
3. **数值靠感觉、只测一套配置**：没有模拟与日志，Boss 不是必输就是必胜；平衡只覆盖默认队伍。规避：按 §3.5 的五步流程走，模拟脚本跑三套阵容。
4. **废招与唯一解**：菜单里一半技能无人使用，或一招吃遍天。规避：用使用率数据修剪，改机制优先于改数值。
5. **内容量低估**：文本、地图、战斗配置、演出四样都按功能开发的速度估，必然翻车。规避：立项时先做 §5 的四块预算行，文本从第一天 ID 化。
6. **遇敌折磨**：高遇敌率加上不可跳过的战斗与逃跑动画。规避：可见遇敌或遇敌率可调，后期地图降低遇敌密度。
7. **剧情断档或倾倒**：开场 30 分钟纯设定，或几小时没有剧情节点。规避：开局半小时内给一次胜利与一个钩子；每区域 1-2 个节点。
8. **成长无感**：升级只加百分比，没有质变。规避：把新技能、新指令、合击作为升级奖励的主体。
9. **存档期望缺失**：没有自动存档、Boss 前没有存档点、不支持中断存档。规避：把存档当体验设计，按触发点清单逐条落实。
10. **迷宫贪大**：40 分钟直走廊，无地标、无奖励、无节奏。规避：按《关卡设计手册》（㉑）的度量与地标方法做。
