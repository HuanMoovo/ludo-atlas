# Ludo Atlas · 类型手册 · 大战略（Grand Strategy）

> **类型手册 · 第四辑**。定位：把「经营一个国家穿越历史」做成第一内容的策略类型。玩家在可暂停的连续时间里读盘、定策、推进，政治、经济、军事、外交几叠系统互相喂养；地图与开局多是既定的，历史剧本提供舞台，探索与扩张退居配角，经营既成的局面才是主角。
> 配套：《游戏设计手册》（系统耦合与数值方法）·《技术实现手册》（模拟架构、AI 与性能）·《制作管理手册》（内容量估算与范围控制）·《案例研究集》（拆解与复盘方法）。
> 本文不放外链；标杆只用大众熟知的作品，数字为常见量级，按自己项目的实测校准。

---

## 1. 定位与核心循环

一句话定位：大战略是**把「一个国家的历史」做成模拟**的类型。玩家接手的是一个有来历的局面：既定的地理、既定的邻居、既定的家底。要做的不是发明文明，而是读懂这个局面，再用几代人的时间把它推到自己想要的位置；战斗可以委托给将军，决策不能。

核心循环用动词环写：

`读盘（地图、账本、人物、外交棋盘） → 定策（结盟、开战、改革、联姻） → 派执行（军队、使者、间谍） → 时间推进（可暂停） → 世界回弹（战报、叛乱、继承、行情） → 重估，回到下一轮`

这个环以「月」与「年」计量：一次推进是小型承诺，一段国策是长期赌注。与回合制的结构差异在时间模型：连续流动、可暂停、可调速；暂停是这类游戏的默认阅读姿势，不是高级功能。

与相邻类型划边界：

| 相邻类型 | 边界 |
| --- | --- |
| 4X | 4X 从零开始、以探索与扩张为主轴；大战略的探索扩张环被削薄：地图与开局既定，少有真正的无主地，重心让给历史推演与角色扮演，经营的是既成的国家与人物关系 |
| RTS | 也是实时，但可暂停、无操作上限；拼的是决策与调度，不是手速 |
| 兵棋 | 兵棋对一场战争或战役做军事推演；大战略把军事放进政治、经济与外交的更大盘子，战争只是手段之一 |
| 模拟经营 | 模拟经营盯收支与产能曲线；大战略的对手是活的历史势力，输赢写在国运里，不只写在报表上 |

一个自检问题：把地图生成与从零扩张拿掉，循环还转得动吗？转得动，玩家关心的是「这段历史会怎么走」，你做的是大战略；转不动，回去做 4X。

## 2. 玩家体验目标与标杆作品

体验目标（按优先级排序）：

1. **历史在场感**：开局不是空白地图，而是有来历的舞台；每一步决策都能和历史对账，「在史实里我会怎么选」是玩家自带的乐趣。
2. **系统叙事**：一局打完，玩家能讲出一个国家走到今天的故事，故事由系统生成、由玩家亲手写下；角色与家族是故事的线头。
3. **慢节奏掌控**：信息与规划换来掌控感，时间随需暂停或加速；读得懂局面，就赢了一半。
4. **长线规划兑现**：跨代计划最终落地，延迟满足的跨度比 4X 更长。
5. **「还能这样」的发现**：系统耦合会在玩家手里长出教程没写过的招数（联姻吃继承权、封锁挤垮邻居），发现本身就是内容。

标杆作品（只列大众熟知的作品，建议各玩到一局中期再谈拆解）：

| 作品 | 可学的点 |
| --- | --- |
| 十字军之王 3 | 角色层：把「人」做成系统的接口；事件叙事的密度；继承、派系与密谋自发生成剧情 |
| 欧陆风云 4 | 国家层：外交棋盘、贸易与殖民、数百年跨度的国策经营；小事件串起大历史 |
| 钢铁雄心 4 | 战争机器：工业动员、生产线与作战计划，把一场大战做成全国级的压力测试 |
| 维多利亚 3 | 经济与政治：人口、市场、改革互相咬合，国运弧线从农业社会拉到工业强国 |
| 群星 | 大战略骨架与 4X 开局搭桥：探索起点、事件链与银河政治 |
| 全面战争：三国 | 另一条架构路线：大战略战役层与实时战斗拼接 |

拆这些作品的统一问题只有一个：它们怎么让玩家在第一百个小时仍然有想做的事。

## 3. 设计要点

### 3.1 系统嵌套：四个系统互相喂养

大战略的立身之本在耦合：政治、经济、军事、外交不是四个并列面板，而是一台互相喂料的机器；单看任何一个都平淡，咬合起来才成立。

| 系统 | 玩家的动作 | 输出去向 | 典型回路 |
| --- | --- | --- | --- |
| 政治 | 任命、改革、压派系 | 稳定、合法性、人力 | 稳定喂税收与战争耐受 |
| 经济 | 征税、贸易、建设 | 钱粮、产能、补员 | 钱喂军队、外交与工程 |
| 军事 | 造兵、行军、作战 | 领土、威慑、伤亡 | 战争消耗反噬钱粮与稳定 |
| 外交 | 联姻、结盟、威胁、背叛 | 安全、条约、继承权 | 实力喂筹码，孤立限制选项 |

设计纪律：

- **每个系统至少输出去两个、接受自两个**：只进不出是装饰，只出不进是外挂。
- **雪球要配刹车**：强者越强必须有天然阻力（过扩、厌战、叛乱、继承危机），否则中期就锁死结局，剩下几十小时全是走流程。
- **耦合要能被看见**：面板上写清数字从哪来、到哪去（§3.5）；看不见的耦合等于不存在。
- 调参纪律：拆开调、合起来测；单个系统的数值好看没有意义，要看它跑过十几个小时的模拟后会不会失控。

### 3.2 时间与节奏：连续时间，按月结算

时间常见两级：日是结算底层（行军、工地、围城），月是玩家面对的账本（税、补给、事件池），年做节拍（科技、改革、人物成长）；玩家看见的最小刻度是月，界面上永远有一行「今天几月几日」。

- **暂停是阅读姿势**：速度档、事件自动暂停、开战自动减速，全部做成可配置；让人来得及读完再决定。
- **节奏靠事件密度调**：和平期用低频、高重量的事件维持在场感；战争期交给系统自身的高频反馈。
- **单局时长要设计**：完整一局几十小时起步，马拉松可达上百小时；标准不是总时长，而是「每一小时仍有新决策」，靠每个时代段发放新动词来兑现，而不是把同样的选择堆得更大。

### 3.3 事件与脚本：历史钩子加条件触发

事件系统是叙事引擎，也是内容性价比之王：一段文本加几个数值，就能让抽象的系统长出具体的记忆点。事件按职责分四种，分开做：

| 类型 | 触发方式 | 职责 | 例子 |
| --- | --- | --- | --- |
| 历史钩子 | 时间、地点、人物条件 | 让历史按剧本走的锚点 | 某年某地开战、某位君主即位 |
| 条件事件 | 状态阈值或权重随机 | 让系统自己长出故事 | 粮价飞涨、叛乱前夜、继承争议 |
| 决议与任务 | 玩家主动触发 | 把长期目标折成可执行清单 | 改革、迁都、立国教 |
| 风味事件 | 低频、轻效果 | 维持世界的质感与人味 | 宫廷逸闻、地方风物 |

- **触发要可读**：玩家看到事件时，要能回答「为什么是现在、为什么是我」；答不上来的行为会被记成 bug。
- **事件必须回写系统**：只弹文本不改状态的事件是广告牌；每条至少动一个数值、加一个状态或开一个开关。
- **两条管线分开**：历史主线保证叙事弧，随机池制造方差；主线事件带一次性标记，池内事件带权重与冷却。
- **脚本要像内容、不像代码**：触发条件与效果分层的声明式脚本，策划能独立写完一条事件（§4）；文本按「标题、正文、选项、后果」固定结构交付。
- **角色层量力而行**：人物是重型内容（肖像、特质、事件适配），产能不够就缩回「国家加一个首脑」；产能足够时，一套继承与关系规则就是最好的事件发生器，比手写一百条剧情便宜。

### 3.4 对手 AI：可信比聪明重要

大战略的 AI 是公认难题：它要同时扮演君主、参谋、经济官与外交家，而人类玩家用一颗脑子统管这些部门。目标定成**可读、可对抗、有性格**，别去追「像人」：

- **一套规则接口，多张参数表**：AI 与玩家走同一套规则入口，只加公开的难度参数；不同势力用不同性格档（侵略、贸易、复仇、保守），比写几套算法便宜且可控。
- **决策要能解释**：态度列表、宣战理由、威胁评估都摊在界面上；玩家看不懂 AI 行为一次，之后所有 AI 行为都会被怀疑。
- **难度公开调**：改资源与速度，暗改信息极度克制；被抓住一次暗改，信任就没了。
- **分层降频**：战略层低频重算（野心、联盟），战役层数年一次（下一个打谁），战术层每次交战（这一仗怎么打）；频率越高，单次思考必须越便宜。
- **用 AI 验系统**：AI 对 AI 批量跑局，是唯一能回答「这个系统会不会失控、锁死、退化」的现实手段；行为日志从第一天就记。

### 3.5 UI 与信息呈现：复杂性的可读性管理

UI 的任务不是把数字摆满屏幕，而是把复杂度压成可读的形状；这一节是设计题，工程见 §4。

- **总览加下钻**：一块「现在最该关心的事」入口（警报、机遇、失效条约），点进去层层追到原因；信息按「要不要现在处理」分级，不按系统分类堆列。
- **地图是第一界面**：势力、补给、地形、补员分层画在地图上，切一层换一个视角；表格负责核对，地图负责直觉。
- **提示可嵌套**：从数字查到公式，再查到修正来源；重玩家核对到爽，轻玩家一眼跳过。
- **开局要铺平**：建议系统、目标卡与友好的新手势力，把第一小时的门槛压到能进门；复杂是卖点，不能是入场费。

## 4. 技术要点

工程命题一句话：**技术难点不在实时性，而在模拟的规模、AI 的预算与内容的脚本化**。以下与引擎无关，细节见《技术实现手册》。

- **模拟内核**：固定步长结算，系统结算顺序写进规格并保持稳定；顺序一变，存档与战报都会对不上。逻辑与表现解耦，界面读结算快照，演出可以延迟、加速或跳过。
- **模拟粒度**：划分抽象层级，该用统计的用统计（人口、市场用队列与分布），该有名字的有名字（君主、大臣、将军）；个体模拟只留给会影响叙事的实体，粒度和性能预算一起定。
- **确定性**：随机数走可复现的种子体系，逻辑随机的调用顺序固定；回放、批量模拟与调试都依赖它，「同存档同结果」是平衡工作的地基。
- **数据与脚本驱动**：省份、势力、事件、决议全部外置成数据与脚本，代码只读表；脚本引擎提供触发与效果两层声明，配套校验器查引用、查冲突；Mod 与官方内容共用同一层，热重载让内容侧改字不等编译。
- **AI 预算**：分层调用、独立预算，摊帧或异步执行；超预算宁可降频降智，不卡顿。AI 状态必须能序列化进存档。
- **平衡工具**：遥测统计（各国发展曲线与结局分布）、隐藏调试面板与批量模拟（AI 对 AI 跑几百局）是调平衡的唯一现实手段；手测用来发现问题，批跑用来验证修复。
- **UI 工程**：提示框由数据生成（数字加公式加来源，支持嵌套）、长列表虚拟化（几百块省份、上千个人物）、地图分层渲染与切换；文本全部外置，本地化的字数预算是排期项（§5）。
- **后期性能**：实体随局数增长，每 tick 成本水涨船高；用增量更新、脏标记、把远处次要系统降精度、把最贵的寻路与评估摊销。把「第 X 年后的模拟耗时上限」写进规格，别等玩家投诉。
- **存档与版本**：几十小时的局，坏档是最重的一类差评；存档带版本号、迁移函数与轮换备份，Mod 存档记录脚本版本，更新前先过一遍旧档。

## 5. 内容量与工作量参考

以下为同类项目的常见量级，用于估算范围，不构成承诺。

| 项目形态 | 内容量级 | 周期量级 | 备注 |
| --- | --- | --- | --- |
| 系统原型 | 1 张区域图，2 到 4 个势力 | 2-3 个月 | 零美术，验证月结算、外交与最小 AI |
| 单剧本作品 | 1 个剧本，几十个势力，数百条事件 | 1-2 年 | 事件与 UI 是隐形大头 |
| 多剧本规模 | 3-5 个剧本，上百个势力，上千条事件 | 3 年以上 | 对标经典系列的起步量级 |
| 长期运营 | 多剧本加内容更新管线 | 5 年以上 | 内容按月产，寿命靠迭代 |

内容单元的成本结构：

| 内容单元 | 单位成本（量级） | 起步量 | 完整体量 | 备注 |
| --- | --- | --- | --- | --- |
| 事件 | 半天到 2 天/条 | 50-150 条 | 数百到数千条 | 含文本、脚本与测试 |
| 势力 | 1-3 天/个（数值档） | 4-6 个 | 几十到上百个 | 规则层差异另行计价 |
| 剧本 | 1-2 个月/个 | 1 个 | 3-5 个 | 地图切片、布局与史实核对 |
| 省份 | 数据按小时计，地形美术另算 | 50-100 块 | 数百到数千块 | 数量乘单价，尺度问题的源头 |
| 角色（可选） | 系统建设为主，逐条成本低 | 可选 | 视队伍而定 | 肖像与动画是美术大头 |

两条量级结论：AI 与平衡是隐性大头，给「调 AI 与平衡」预留总工期两成以上，且从原型期就要有批量模拟工具（§4）；事件单条便宜、总量吓人，玩家一局真正读到的事件往往不到库存的一半，先把主线钩子铺对，再铺池子。砍范围的优先顺序：剧本数量、势力数量、人物层深度；AI 与事件系统排末位，砍掉它们这个类型就不成立了。

## 6. 第一个原型怎么起步

第一个原型 2-3 个月：一张小区域图、2 到 4 个势力、零美术，只验证一件事：月结算加外交加一个会动的 AI，能不能抓住人。

1. **地图与省份**：50 到 100 块省份，每块带人力、税收、补给三种数值；四个可玩势力加若干小邻居。
2. **时间与结算**：连续时间加月结算，两三个速度档；暂停时能读全屏信息。
3. **最小系统环**：税收与人力支撑造兵，行军与战斗能割地；加一种外交动作（同盟或联姻二选一）；补一条耦合回路（战争消耗稳定，稳定影响税收）。
4. **事件与钩子**：30 到 50 条事件脚本，其中 5 到 10 条条件触发（继承、叛乱、边境摩擦），顺带验证校验器。
5. **一个粗糙 AI**：会评估实力、会宣战与求和、会捡便宜；行为日志从第一天开始记。
6. **收束条件**：一个可判定的结局（活到某年份或达成某个目标），让「一局」有终点。

验收（全部可观察）：

- 拿掉美术与音效，只留地图、数字与文本，测试者仍愿意连玩一小时以上。
- 找 3 到 5 名没玩过的人，无指导情况下能在半小时内说出「我现在最担心的三件事」与「我打算怎么活下去」。
- 玩家不出手时，AI 能把局势推着走（结盟、开战、割地），不卡死、不静止。
- 每条触发的事件，测试者能回答「为什么是现在」。

反例：先做全地图、先做完整事件库、先做肖像美术、先做联机。系统循环没立起来之前，这些都是沉没成本。

## 7. 常见坑

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| AI 留到收尾才做 | 内容做完了 AI 还是木桩，游戏立不起来 | AI 是玩法的一半，立项就排期，原型期就有最小版（§3.4） |
| 系统只摆不咬 | 几个面板各自为政，玩哪个都行、怎么玩都行 | 每系统至少两进两出（§3.1），耦合写了就要测 |
| 雪球没有刹车 | 中期领先者锁定胜负，剩下几十小时走流程 | 过扩、厌战、叛乱、继承危机都做成真机制 |
| 事件只会弹窗 | 文本读完没有变化，或变化没人看见 | 每条事件至少回写一个可见状态（§3.3） |
| 中后期没有新问题 | 旧选择的放大重复，决策密度掉底 | 每个时代段发新动词，收口时钟从设计期就做（§3.2） |
| 后期性能崩 | 越玩越慢，存档越滚越大 | 预算、增量更新、降精度抽象（§4） |
| 坏档 | 更新一次坏一档，「几十小时白搭」 | 版本迁移、备份轮换、Mod 标记（§4） |
| 暗改信息做难度 | AI 看穿迷雾被抓包，此后所有行为被怀疑 | 难度用公开参数，作弊极度克制（§3.4） |
